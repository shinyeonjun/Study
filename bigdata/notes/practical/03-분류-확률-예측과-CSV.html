5-03

양성 확률을 만들어 평가 행 순서로 제출한다

고장 알림을 내는 0과 1을 제출할 때도 있고, 고장일 확률을 제출해야 할 때도 있습니다. 이번 연습은 확률을 요구하는 지시를 읽고 점수·예측 열·원본 순서를 확인합니다.

이 장을 읽고 나면

  • 확률 점수와 임계값으로 고른 분류 라벨을 구별한다.
  • 검증 자료의 ROC AUC와 기준선을 비교한다.
  • 평가용 자료 위치와 같은 순서의 예측 CSV를 생성한다.

연습 문제에서 요구할 출력부터 고른다

2026년 11월에 확인한 공식 제2유형 체험은 회귀 예측을 CSV로 만드는 예시입니다(회차마다 바뀔 수 있으니 공식 공지로 확인). 이 장은 같은 제출 구조를 이진 분류에 적용한 합성 연습입니다. 설비 점검 전 센서값 하나로 고장 라벨 fault가 1일 점수를 예측합니다. 연습 요구사항은 result.csv에 pred 한 열로 양성 확률 추정치만 쓰고, 원본 평가 행의 순서와 행 수를 유지하는 것입니다. 내부 검증 지표는 ROC AUC로 정합니다.

양성의 확률 추정치가 0.66이라면 임계값 0.5에서 분류 라벨 1을 고를 수 있습니다. 하지만 파일에 넣을 값은 여기서 0.66에 해당하는 연속 점수입니다. 라벨을 넣으면 0.51과 0.99의 순서 정보가 사라집니다. AUC는 양성에 음성보다 높은 점수를 매기는 능력을 비교합니다. AUC가 높다고 확률 수치의 보정이 자동으로 잘 되었다는 뜻은 아닙니다.

세 가까운 학습 사례에 들어 있는 양성 비율을 쓴다

간단히 센서값의 차가 작은 학습 사례 세 개를 고릅니다. 세 사례에서 양성 수를 3으로 나눠 양성 확률 추정치로 씁니다. 훈련 센서값은 0,2,4,6,8,10이고 라벨은 [0,0,1,0,1,1]입니다. 거리가 같으면 앞쪽에 있던 학습 행을 먼저 선택합니다. 입력을 여러 특성으로 바꾸어 이 방법을 쓸 경우, 큰 단위의 열이 거리를 차지하지 않게 학습 부분에서 척도 변환을 적합하는 방법을 함께 고려합니다.

검증 센서값실제 라벨가까운 세 사례의 라벨양성 비율
100, 0, 11/3
310, 1, 01/3
710, 1, 12/3
911, 1, 02/3

이 검증에는 음성이 한 개이고 양성이 세 개입니다. 양성의 두 점수는 음성보다 높고 나머지 하나는 동점입니다. 더 크면 1, 같으면 0.5씩 더해 가능한 세 쌍으로 나누면 AUC는 (1+1+0.5)÷3=5/6입니다. 양성과 음성에 모두 같은 점수를 주는 기준선은 모든 쌍이 동점이라 0.5입니다. 양성과 음성 중 한 종류만 있는 검증에서는 이 정의로 AUC를 구할 쌍이 없습니다. 큰 자료에서는 모든 쌍을 직접 만들기보다 검증된 지표 함수로 계산합니다.

검증에서 규칙을 고른 뒤 쓰이는 순서를 확인한다

예시는 검증 점수가 높았던 세 이웃 방법을 전체 라벨 있는 자료에 다시 적용합니다. 평가 행의 라벨은 쓰지 않습니다. 이웃 방법의 경우에는 기존 훈련 데이터와 검증 데이터를 합쳐 비교 대상 사례를 늘립니다. 실제 과제의 후보를 고를 때 검증 자료가 시간이나 고객 그룹을 넘나들지 않게 제출 환경과 비슷한 분할을 먼저 정합니다. 검증에서 본 수치는 최종 평가 점수와 구별합니다.

평가 순서의 설비 ID는 912, 901, 930입니다. 숫자순으로 정렬하지 않습니다. 양성 클래스가 무엇인지 문제에서 확인합니다. 예를 들어 predict_proba를 쓰는 분류기에서는 반환 배열의 열 번호에 대응하는 클래스가 classes_에 있습니다. 이 장의 코드는 라벨 1의 빈도를 직접 계산합니다.

scikit-learn으로 같은 흐름을 쓰면 model = KNeighborsClassifier(n_neighbors=3).fit(X, y)로 적합하고, model.predict_proba(X_new)[:, list(model.classes_).index(1)]로 클래스 1 열을 고르며, 검증 점수는 roc_auc_score(y_valid, score)로 구합니다. X는 한 특성이라도 (행, 1) 모양의 2차원이어야 합니다. 거리가 같은 이웃을 고르는 순서는 아래 직접 구현과 다를 수 있어 동점이 있는 이 작은 예에서는 점수가 달라질 수 있습니다.

검증과 파일 검사까지 연속으로 실행한다

from pathlib import Path
from tempfile import TemporaryDirectory

import numpy as np
import pandas as pd

train_x = np.array([0, 2, 4, 6, 8, 10])
train_y = np.array([0, 0, 1, 0, 1, 1])
valid_x = np.array([1, 3, 7, 9])
valid_y = np.array([0, 1, 1, 1])

def positive_score(query, x, y, k=3):
    distance = np.abs(query[:, None] - x[None, :])
    near = np.argsort(distance, axis=1, kind="stable")[:, :k]
    return y[near].mean(axis=1)

def auc_small(y, score):
    pos, neg = score[y == 1], score[y == 0]
    assert len(pos) and len(neg)
    difference = pos[:, None] - neg[None, :]
    return ((difference > 0) + 0.5 * (difference == 0)).mean()

valid_score = positive_score(valid_x, train_x, train_y)
print(f"AUC constant: {auc_small(valid_y, np.full(len(valid_y), 0.5)):.3f}")
print(f"AUC neighbors: {auc_small(valid_y, valid_score):.3f}")

test = pd.DataFrame({"unit_id": [912, 901, 930], "sensor": [8.5, 0.5, 4.5]})
all_x = np.concatenate([train_x, valid_x])
all_y = np.concatenate([train_y, valid_y])
pred = positive_score(test["sensor"].to_numpy(), all_x, all_y)
submission = pd.DataFrame({"pred": pred})

def write_checked(frame, path="result.csv"):
    frame.to_csv(path, index=False)
    saved = pd.read_csv(path)
    assert list(saved.columns) == ["pred"] and len(saved) == len(test)
    assert np.isfinite(saved["pred"]).all() and saved["pred"].between(0, 1).all()
    assert np.allclose(saved["pred"], pred)
    return saved

with TemporaryDirectory() as folder:
    saved = write_checked(submission, Path(folder) / "result.csv")
    for unit, value in zip(test["unit_id"], saved["pred"], strict=True):
        print(f"{unit}: {value:.3f}")
AUC constant: 0.500
AUC neighbors: 0.833
912: 1.000
901: 0.000
930: 0.667

코드는 연습 파일을 임시 폴더에 저장해 읽은 다음 지웁니다. 시험 지시가 파일명을 result.csv로 요구하면 실제 제출 코드에서는 write_checked(submission)처럼 경로 없이 그 이름을 씁니다. 출력에서만 세 자리까지 표시했고 파일의 예측은 반올림하지 않았습니다. ID는 출력에서 순서를 확인하는 용도로만 이용했습니다.
