03

분석 과제의 목표·성공 기준·우선순위 정하기

‘데이터로 운영을 개선하자’라는 목표를 바로 구현하기는 어렵습니다. 무엇을 바꿀지, 어떤 순간에 어떤 정보를 사용할지, 어떤 결과면 성공인지 결정해야 과제가 됩니다.

이 장을 읽고 나면

  • 현장 목표를 관측 단위·입력·출력이 있는 분석 질문으로 옮긴다.
  • 하향식과 상향식 과제 발굴을 비교한다.
  • 분석 기획 유형(최적화·솔루션·통찰·발견)을 분석 대상·방법으로 분류한다.
  • 시급성과 난이도로 우선순위를 정하고, 필수 제약(권한 등)은 따로 확인한다.

업무 문제를 정확히 적는다

현장의 목표는 ‘도서관 이용 대기를 줄인다’입니다. 이 문장만으로 어느 자료에 모형을 맞출지 정할 수 없습니다. 운영자가 직전에 할 수 있는 결정 하나를 골라 ‘다음 15분이 혼잡할 때 보조 창구를 열지 결정한다’고 적습니다. 이제 자료가 어떤 순간에 필요하고, 틀린 예측 때문에 어떤 일이 생길지 생각할 수 있습니다.

정할 것예
관측 단위한 지점의 연속된 15분 구간 하나
예측 시점그 구간이 시작되기 직전
입력 후보직전 15분 입장 수, 예약 수, 요일
정답다음 15분 안에 대기열이 12명을 넘으면 혼잡
업무 조치당직 인원이 있는 경우 보조 창구를 열지 검토
확인할 값혼잡을 놓친 비율, 불필요한 인력 투입 횟수, 실제 평균 대기시간

예측 기준과 업무 결과는 따로 기록합니다. 혼잡 분류를 잘해도 대응이 늦으면 대기시간이 줄지 않을 수 있습니다. 또 평가에 쓸 미래 15분의 실제 입장 수를 예측 입력으로 넣으면 실행할 때 그 값이 아직 없습니다. 정확해 보이는 모델이 만들어져도 실제로 사용할 수 없게 됩니다.

분석 기획의 네 가지 유형 외우기

과제를 정할 때 "무엇을 분석할지(분석 대상, What)"와 "어떻게 분석할지(분석 방법, How)"를 각각 알고 있는지에 따라 기획의 성격이 달라집니다. 시험에서는 이 두 축으로 만든 2×2 분류를 묻습니다.

분석 대상을 안다 (Known)분석 대상을 모른다 (Un-Known)
분석 방법을 안다최적화(Optimization): 대상과 방법이 모두 정해져 있어 개선·최적화에 집중통찰(Insight): 방법은 있지만 대상이 정해지지 않아, 기존 방법으로 새 시사점을 찾음
분석 방법을 모른다솔루션(Solution): 풀 문제는 알지만 방법을 몰라 해법을 찾아야 함발견(Discovery): 대상도 방법도 몰라 새로운 대상 자체를 찾아냄

도서관 예로 바꾸면, "다음 15분 혼잡"을 이미 쓰는 회귀식으로 더 잘 맞히려는 일은 최적화, 혼잡을 줄여야 하는데 어떤 방법이 통할지 모르는 상태는 솔루션입니다. 분석 기획 단계에서는 이 밖에 가용 데이터(어떤 유형의 데이터를 쓸 수 있는지), 적절한 유스케이스(비슷한 기존 사례), 장애 요소(비용, 사용자 교육, 조직 문화 등)를 함께 고려합니다.

과제를 찾는 두 방향

하향식(top-down)은 현장의 목표나 문제에서 출발합니다. ‘어떤 때 창구를 더 열어야 하는가’처럼 의사결정을 먼저 정하고 그 결정을 돕는 분석 문제와 필요한 자료를 찾습니다. 필요한 자료를 실제로 구할 수 있는지, 결과를 맡을 사람이 있는지도 점검합니다.

상향식(bottom-up)은 모은 자료를 먼저 살펴 반복되는 모습이나 예상과 다른 값을 발견합니다. 예를 들어 달력의 휴일만으로 설명되지 않는 계단식 방문 패턴을 발견하고, 특정 행사 시간에 혼잡 안내가 필요하다는 과제를 세울 수 있습니다. 처음 발견에 쓴 기간과 새 기간을 구별해 같은 패턴이 나타나는지 확인합니다.

교재는 두 방식의 절차와 도구를 다음처럼 정리합니다. 외우기

방식절차·도구어울리는 상황
하향식문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토. 문제 탐색에는 비즈니스 모델 캔버스(업무·제품·고객·규제와 감사·지원 인프라) 같은 틀을 쓰고, 타당성 검토는 경제적 타당성과 데이터·기술적 타당성을 본다문제가 주어져 있고 해법을 찾는 경우
상향식데이터를 먼저 보며 비지도 학습(정답 없이 군집·연관 등을 찾는 방법)으로 패턴을 찾고, 디자인 사고(발산과 수렴을 반복)와 프로토타이핑(일단 작게 만들어 보고 고쳐 가는 방식)으로 문제를 구체화한다문제 정의 자체가 어렵거나, 필요한 데이터가 무엇인지 처음부터 알기 어려운 경우

문제 정의 단계에서는 "대기를 줄인다" 같은 비즈니스 문제를 "다음 15분 혼잡 여부를 맞힌다" 같은 데이터 분석 문제로 바꿉니다. 이 장 첫 절에서 한 일이 바로 이것입니다. 실제 프로젝트에서는 두 방식을 섞어 씁니다.

점수와 반드시 확인할 제약을 구별한다

팀에서 예시용으로 효과와 실행 가능성을 각각 1~5점으로 매기고 효과에 두 배의 무게를 줍니다. 이 수식은 이 사례를 위한 가정입니다. 효과는 개선을 기대하는 정도, 실행 가능성은 자료·담당 인력·일정이 갖추어진 정도를 뜻합니다. 점수는 후보끼리 같은 방식으로 비교할 때 의미가 있습니다.

candidates = [
    ("A", 4, 3, True),
    ("B", 3, 4, True),
    ("C", 5, 1, False),
]
eligible = []
for name, impact, feasibility, permission in candidates:
    score = 2 * impact + feasibility
    decision = "비교 대상" if permission else "보류"
    print(name, score, decision)
    if permission:
        eligible.append((score, name))
print("먼저 검토", max(eligible)[1])

실행 결과

A 11 비교 대상
B 10 비교 대상
C 11 보류
먼저 검토 A

C는 점수가 높더라도 실제 수집 권한이 확인되지 않았습니다. 별도 제약을 만족할 방법이 정해진 뒤 점수를 다시 비교합니다. 가중치를 바꾸면 순위도 바뀔 수 있으므로 선택 근거를 남기고, 아주 작은 시범으로 가장 불확실한 가정을 먼저 확인하는 것이 좋습니다.

시험에서 쓰는 우선순위 틀: 시급성과 난이도 외우기

위 점수식은 이 사례를 위해 만든 것입니다. 빅분기 교재에서 표준으로 다루는 틀은 시급성과 난이도 두 기준입니다. 이 두 기준은 빅데이터의 4V를 투자 대비 효과(ROI) 관점으로 나눈 데서 나옵니다.

ROI 관점4V 요소우선순위 기준
투자 비용 측면Volume(크기), Variety(다양성), Velocity(속도)난이도: 데이터 획득·저장·가공 비용, 분석 적용 비용, 분석 수준(쉬움 / 어려움)
비즈니스 효과 측면Value(가치)시급성: 전략적 중요도, 목표 가치(KPI)에 비춰 지금 필요한가(현재 / 미래)

두 기준을 축으로 과제를 네 칸(사분면)에 놓는 것을 포트폴리오 사분면 분석이라고 합니다.

양 끝은 분명합니다. 시급성이 현재이고 난이도가 쉬운 과제를 가장 먼저, 시급성이 미래이고 난이도가 어려운 과제를 가장 나중에 합니다. 가운데 두 칸(현재·어려움, 미래·쉬움)의 순서는 시급성과 난이도 중 무엇을 더 중시하느냐에 따라 달라집니다. 현재·어려움 과제는 데이터 양·범위를 줄여 난이도를 낮추면 앞으로 당길 수 있습니다.

시험 함정

교재는 이 칸들에 Ⅰ~Ⅳ 번호를 붙여 "시급성 기준이면 Ⅲ→Ⅳ→Ⅱ, 난이도 기준이면 Ⅲ→Ⅰ→Ⅱ"처럼 번호 순서로 묻는 경우가 많습니다. 번호를 붙이는 방식이 그림마다 다를 수 있으므로, 번호만 외우지 말고 각 번호가 어떤 칸(현재/미래 × 쉬움/어려움)인지를 공식 출제기준·교재 그림으로 확인해 함께 외웁니다.
