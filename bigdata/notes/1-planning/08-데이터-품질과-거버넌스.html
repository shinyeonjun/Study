데이터 품질·거버넌스·개인정보를 관리하기

빠진 값 없는 표라도 잘못 측정된 숫자가 들어갈 수 있습니다. 어떤 품질을 검사하는지 구별하고, 누가 정의를 정하며 어떤 자료를 사용할지 결정하는 과정으로 연결합니다.

이 장을 읽고 나면

  • 완전성·유일성·일관성·적시성·유효성·정확성을 구별한다.
  • 검사마다 관측 대상과 분모를 명시한다.
  • 데이터 거버넌스의 구성 요소(원칙·조직·프로세스)와 책임·권한·보존을 설명한다.
  • 개인정보·가명정보·익명정보를 구별하고, 비식별 기법 다섯 가지와 k-익명성·l-다양성·t-근접성을 적용한다.

좋은 품질의 뜻은 사용 목적에 따라 달라진다

도서관 혼잡을 안내하려면 최근 기록이 필요합니다. 월말 보고에는 누락을 모두 정정한 자료가 중요합니다. 이처럼 같은 표도 사용 목적에 따라 품질 기준이 달라집니다. 품질을 숫자로 계산하기 전에 어떤 기록과 시각을 세는지 정합니다.

품질 관점무엇을 검사하는가예
완전성기대하는 행이나 필수 항목이 들어 있는가?예정된 센서 구간이 빠져 있음
유일성서로 달라야 하는 단위가 중복되지 않는가?같은 이벤트 ID가 다시 수신됨
일관성합의한 정의와 관련 자료의 값이 충돌하지 않는가?두 집계에서 같은 지점 코드와 시간 기준 사용
적시성필요한 판단 시점까지 최신 자료인가?10:12에 난 사건을 10:19에 알게 됨
유효성형식과 허용 범위를 지키는가?입장 인원은 0 이상의 정수
정확성실제 현상과 일치하는가?기록은 12명이지만 직접 관측한 사람은 10명

12라는 값은 인원 범위에 맞지만 실제 10명이었다면 정확하지 않습니다. 또 필수 값이 빈칸 없이 모두 들어 있어도 모두 맞았다고 볼 근거는 없습니다. 검사의 대상에 맞는 자료나 업무 검증으로 각각 확인합니다.

시험용 분류

빅분기 교재는 정형 데이터의 품질 기준으로 완전성·유일성·유효성·일관성·정확성을 듭니다(위 표의 적시성은 실무 지침에서 자주 함께 쓰는 관점입니다). 비정형 데이터는 값 하나하나를 검사하기 어려워 소프트웨어 품질 특성처럼 기능성·신뢰성·사용성·효율성·이식성으로 봅니다. 교재·연도에 따라 항목 수와 이름이 다를 수 있으므로 공식 출제기준·교재로 확인합니다.

같은 표에서 품질 지표를 따로 계산한다

ID 다섯 개가 올 것으로 예상했는데 아래처럼 기록됐습니다. e2는 정확한 재전송으로 두 번 들어왔고, e3은 아직 전혀 오지 않았습니다. e4와 e5는 도착했지만 필수 인원 조건을 만족하지 않습니다.

expected_ids = {"e1", "e2", "e3", "e4", "e5"}
raw = [("e1", 12), ("e2", 9), ("e2", 9), ("e4", -1), ("e5", None)]
seen_ids = {event for event, count in raw}
present = sum(count is not None for event, count in raw)
valid_ids = {event for event, count in raw
             if type(count) is int and count >= 0}
print(f"ID delivery {len(seen_ids & expected_ids)}/{len(expected_ids)}")
print(f"filled field among received rows {present}/{len(raw)}")
print(f"valid IDs among expected {len(valid_ids & expected_ids)}/{len(expected_ids)}")

실행 결과

ID delivery 4/5
filled field among received rows 4/5
valid IDs among expected 2/5

첫 줄은 기대 ID가 도착했는지, 둘째 줄은 수신한 행에 값이 들어 있는지를 봅니다. 원시 행에는 중복이 있어 두 비율의 4가 세는 대상이 서로 다릅니다. 마지막은 기대 이벤트 중 허용 값까지 확인한 ID를 셉니다. 기준과 분모를 함께 적어, 숫자가 우연히 같아도 뜻을 구별할 수 있게 합니다.

누가 기준과 변경을 승인하는가

데이터 거버넌스는 데이터의 의미, 품질, 권한과 수명에 관해 누가 결정하고 누가 책임질지를 정하는 운영 체계입니다. 예를 들어 ‘하루’의 경계와 입장 수의 정의를 합의하고, 변경 담당자를 정하고, 적용된 도구와 산출물을 연결해 기록합니다.

용어와 데이터 항목의 뜻을 모아 찾을 수 있게 한 목록은 데이터 카탈로그에 둘 수 있습니다. 집계가 어느 원본과 어떤 변환에서 왔는지 추적하는 데이터 계보는 수치가 달라진 원인을 찾을 때 쓰입니다. 검사 프로그램이 오류를 표시할 수는 있어도 어떤 사용을 승인하고 어느 기준을 채택할지까지 혼자 정하는 것은 아닙니다.

교재는 데이터 거버넌스의 구성 요소를 원칙(Principle: 데이터를 유지·관리하는 지침과 가이드, 예: 보안·품질 기준), 조직(Organization: 데이터 관리자, 데이터베이스 관리자, 데이터 아키텍트 등 역할과 책임), 프로세스(Process: 데이터 관리를 위한 활동과 체계, 예: 작업 절차·측정 활동) 세 가지로 정리합니다. 거버넌스 체계로는 데이터 표준화(용어·명명 규칙·메타데이터·사전 구축), 데이터 관리 체계(메타데이터와 사전의 관리 원칙, 수명 주기 관리), 데이터 저장소 관리(저장소 구성·변경 영향도 평가), 표준화 활동(준수 여부 점검과 개선)을 듭니다. 빅데이터 거버넌스는 여기에 개인정보 보호·보안, 데이터 수명 주기에 따른 보존·폐기 같은 관리를 더 강조합니다.

목적과 권한을 확인하고 필요한 범위만 사용한다

요일별 입장 수를 집계하는 데 개인 이름과 연락처가 필요하지 않다면, 처음부터 그 항목을 요청하지 않는 방식이 가능합니다. 보관할 기간과 접근할 역할을 정해 두고, 외부에 제공할 때에는 원본과 집계 표 각각의 이용 조건을 확인합니다. 개인의 이용 기록이 매우 드문 조합을 포함하면 이름을 뺀 자료에서도 개인이 드러날 가능성이 있습니다.

가명처리는 개인정보의 일부를 지우거나 다른 값으로 바꾸는 등, 추가 정보 없이 특정 개인을 알아볼 수 없도록 하는 처리입니다. 원본 식별정보를 다른 코드로 바꾸고 대응 정보를 별도로 관리하는 경우가 예입니다. 익명정보인지 판단하려면 다른 자료를 합칠 가능성, 식별에 드는 시간과 비용, 현재 기술을 합리적으로 고려해 개인이 드러날 가능성을 살핍니다. 단순히 이름 칸을 지운 것만으로 익명이라고 할 수는 없습니다.

구분뜻법의 적용
개인정보살아 있는 개인을 알아볼 수 있는 정보(다른 정보와 쉽게 결합해 알아볼 수 있는 것 포함)개인정보 보호법 적용
가명정보가명처리해 추가 정보 없이는 특정 개인을 알아볼 수 없게 한 정보여전히 개인정보. 다만 통계 작성, 과학적 연구, 공익적 기록 보존 등을 위해 정보주체의 동의 없이 처리할 수 있는 특례가 있다(안전조치 등 의무가 따름)
익명정보시간·비용·기술을 합리적으로 고려할 때 다른 정보를 써도 더 이상 개인을 알아볼 수 없는 정보개인정보 보호법을 적용하지 않음

가명정보 개념과 특례는 2020년 8월 시행된 이른바 데이터 3법(개인정보 보호법, 정보통신망법, 신용정보법) 개정으로 들어왔습니다. 서로 다른 처리자의 가명정보를 결합할 때는 지정된 전문기관을 거쳐야 합니다. 법령과 가이드라인은 계속 개정되므로(예: 개인정보보호위원회는 2026년 3월 가명정보 처리 가이드라인을 전면 개정했습니다), 세부 절차와 조문은 국가법령정보센터와 개인정보보호위원회의 최신 공식 안내로 확인합니다.

비식별 조치 기법 외우기

개인을 알아볼 수 없게 만드는 처리를 비식별 조치라고 합니다. 빅분기 교재는 2016년 「개인정보 비식별 조치 가이드라인」에 실린 다섯 가지 기법을 기준으로 묻습니다. 이 가이드라인은 이후 가명정보 처리 가이드라인 체계로 대체되었지만, 시험에서는 이 분류가 여전히 기본으로 나옵니다(출제 범위는 공식 출제기준으로 확인).

기법뜻예
가명처리식별자를 다른 값으로 바꾼다홍길동 → 이용자A, 회원번호 → 임의 코드
총계처리개별 값 대신 합계·평균 같은 통계값으로 보여 준다각 이용자의 대출 수 → 지점 전체 평균 대출 수
데이터 삭제식별자나 민감한 항목을 지운다주민등록번호 열 삭제, 연락처 뒷자리 삭제
데이터 범주화값을 구간이나 상위 범주로 바꾼다나이 34세 → 30대, 상세 주소 → 시·구
데이터 마스킹값의 일부를 다른 문자로 가린다010-1234-5678 → 010-****-5678, 홍길동 → 홍**

비식별 처리가 충분한지 평가하는 프라이버시 보호 모델도 함께 나옵니다. 먼저 낱말 하나: 준식별자는 하나만으로는 개인을 가리키지 못하지만 여러 개를 조합하면 개인을 특정할 수 있는 항목(나이대, 우편번호, 성별 등)입니다. 준식별자 값이 같은 레코드 묶음을 동질 집합이라고 합니다.

모델조건막으려는 공격
k-익명성모든 동질 집합에 레코드가 k개 이상 있다연결 공격(다른 자료와 결합해 특정 개인 찾기)
l-다양성각 동질 집합의 민감 정보가 서로 다른 값 l개 이상을 가진다동질성 공격(집합 안의 민감 정보가 모두 같아 바로 드러남), 배경지식 공격
t-근접성각 동질 집합의 민감 정보 분포가 전체 분포와 t 이하로만 차이 난다쏠림 공격, 유사성 공격(값은 달라도 뜻이 비슷해 드러남)

풀이 예제

준식별자가 (나이대, 우편번호 앞 세 자리)인 표에 (30대, 135)가 3명, (40대, 136)이 3명 있습니다. 가장 작은 동질 집합의 크기가 3이므로 이 표는 3-익명성을 만족합니다. 그런데 (40대, 136) 세 명의 진단명이 모두 "당뇨"라면, 이웃이 그 묶음에 속한다는 것만 알아도 진단명이 드러납니다. 이 집합의 서로 다른 민감 값은 1개뿐이므로 2-다양성을 만족하지 않습니다. k-익명성만으로는 부족한 이유입니다.

중복, 누락, 단위 점검의 좀 더 긴 예는 데이터 구조와 품질을 살피는 공부 교재에서 읽습니다.
