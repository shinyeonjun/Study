04

CRISP-DM과 분석 방법론의 단계 구분하기

문제를 정하고 자료를 받았더라도, 언제 데이터를 정리하고 모형을 검증하며 결과를 현장으로 넘길까요? 방법론의 이름을 외우기 전에 각 단계에서 어떤 판단과 산출물이 필요한지 사례로 봅니다.

이 장을 읽고 나면

  • CRISP-DM 여섯 단계와 주요 산출물을 읽는다.
  • KDD, SEMMA, CRISP-DM의 초점을 비교한다.
  • 빅데이터 분석 방법론 5단계와 폭포수·나선형·프로토타입 모델을 구별한다.
  • 검증 중 발견한 문제에 따라 되돌아갈 단계를 고른다.

단계는 무엇을 확인하기 위한 것인가

같은 도서관 사례를 사용합니다. ‘다음 15분에 혼잡을 놓치지 않도록 안내한다’는 목표를 정한 뒤 곧바로 모델부터 만들면, 센서가 장애를 일으킨 시각이나 실제 창구를 추가할 수 없는 기간이 빠질 수 있습니다. CRISP-DM은 업무 목표부터 결과 전개까지 분석 작업을 나눠 확인할 수 있게 하는 방법론입니다.

단계질문이 사례의 산출물
업무 이해
Business Understanding		누가 무엇을 결정하고 어떤 결과가 필요한가?예측 시점, 인력 제약, 성공 판단 기준
데이터 이해
Data Understanding		자료는 어디서 오고 무엇을 담는가?초기 자료 목록, 이력·단위·누락 현황
데이터 준비
Data Preparation		분석에 필요한 한 행과 사용할 특성을 어떻게 구성하나?15분별 표, 조인·결측 처리 기록, 분할
모형화
Modeling		어떤 규칙이나 모형이 맞는지 어떻게 비교하나?단순 기준과 후보의 설정, 훈련 결과
평가
Evaluation		자료의 평가와 실제 업무 목표를 만족하나?독립된 평가 결과 및 사용 여부 판단
전개
Deployment		누가 어디에서 사용하고 무엇을 감시하나?업무 안내, 보고서 또는 배포·모니터링 절차

예를 들어 데이터 이해 단계에서 야간 장애가 반복됨을 발견하면, 준비 단계에서는 장애 여부를 남기거나 자료를 다시 확보합니다. 나중에 평가 점수가 좋아도 기존 업무보다 오경보가 많이 생기면 평가 결과를 업무 기준과 비교하고, 준비·모형화·기획 등을 다시 검토할 수 있습니다.

CRISP-DM 원문 그림에서 양방향 화살표로 그려진 곳은 업무 이해 ↔ 데이터 이해, 데이터 준비 ↔ 모형화이고, 평가 → 업무 이해로 돌아가는 화살표도 있습니다. 시험에서 "피드백이 일어나는 단계"를 물으면 이 세 곳을 떠올립니다. 또 CRISP-DM은 단계(Phase) → 일반화 태스크(Generic Task) → 세분화 태스크(Specialized Task) → 프로세스 실행(Process Instance)의 4레벨 계층으로 구성됩니다.

비슷한 이름을 비교할 때 각 범위를 읽는다

방법·과정핵심 흐름구별할 점
KDD데이터셋 선택(Selection) → 전처리(Preprocessing) → 변환(Transformation) → 데이터 마이닝(Data Mining) → 해석·평가(Interpretation/Evaluation)데이터에서 유용한 지식을 얻는 전체를 뜻한다. 데이터 마이닝은 그 과정에서 패턴을 찾는 단계다.
SEMMASample → Explore → Modify → Model → Assess자료를 뽑고 살피고 바꾸고 모형을 맞춘 뒤 평가하는 SAS의 데이터 마이닝 작업 흐름이다.
CRISP-DM업무 이해부터 데이터 이해·준비·모형화·평가·전개까지업무 목표와 결과를 사용할 절차를 이름에 직접 포함한다. 단계 사이를 되돌아갈 수 있다.

KDD 표는 핵심 데이터 단계를 요약한 것입니다. 실제 지식 발견에서는 목적과 분야 지식 이해, 발견한 결과의 활용도 중요합니다. 방법론을 비교할 때 비슷한 활동이 어디에 놓이는지 살피고, 표에 빠진 활동도 프로젝트에서 점검합니다.

빅데이터 분석 방법론(국내 교재 기준) 외우기

빅분기 교재는 CRISP-DM 외에 국내 표준처럼 쓰이는 빅데이터 분석 방법론을 따로 다룹니다. 방법론은 단계(Phase) → 태스크(Task) → 스텝(Step)의 3계층으로 짜여 있고, 단계마다 기준선(baseline)이 되는 산출물을 만듭니다.

단계주요 태스크
1 분석 기획비즈니스 이해 및 범위 설정, 프로젝트 정의 및 수행 계획 수립, 프로젝트 위험 계획 수립
2 데이터 준비필요 데이터 정의, 데이터 스토어 설계, 데이터 수집 및 정합성 점검
3 데이터 분석분석용 데이터 준비, 텍스트 분석, 탐색적 분석, 모델링, 모델 평가 및 검증, 모델 적용 및 운영 방안 수립
4 시스템 구현설계 및 구현, 시스템 테스트 및 운영
5 평가 및 전개모델 발전 계획 수립, 프로젝트 평가 및 보고

데이터 분석 단계에서 준비가 부족하면 데이터 준비 단계로 되돌아가는 피드백이 있다는 점은 CRISP-DM과 같습니다. 세부 태스크 이름은 교재마다 조금씩 다르므로 공식 출제기준·교재로 확인합니다.

방법론이 갖춰야 할 구성 요소는 상세한 절차, 방법, 도구와 기법, 템플릿과 산출물입니다. 방법론을 적용하는 모델은 세 가지를 구별합니다.

모델특징
폭포수 모델단계를 순차적으로 진행하고, 이전 단계가 끝나야 다음 단계로 간다. 문제가 생기면 피드백으로 돌아간다
나선형 모델반복하며 점진적으로 개발한다. 처음 하는 프로젝트의 위험을 줄이기 좋지만 관리 체계가 없으면 복잡도가 커진다
프로토타입 모델일부를 먼저 만들어 보고 결과로 개선해 간다. 상향식 접근과 잘 맞는다

시범 사용 전 평가 결과를 판단한다

팀이 예시용으로 다음 두 기준을 함께 정했습니다. 평가 구간 30개 중 센서 상태를 정상으로 확인한 구간이 95% 이상이어야 합니다. 운영 모의로 잰 불필요한 경보는 4건 이하여야 합니다. 이 두 수치는 교육용 기준입니다.

intervals = 30
available = 29
false_alerts = 5

coverage = available / intervals
checks = [coverage >= .95, false_alerts <= 4]
print(f"{coverage:.1%}", "coverage")
print(false_alerts, "false alerts")
print("pilot" if all(checks) else "review required")

실행 결과

96.7% coverage
5 false alerts
review required

첫 기준은 통과했지만 두 번째는 충족하지 못했습니다. 배포 날짜만 정해 두고 평가를 마치는 대신, 오경보가 어떤 조건에서 발생했는지 검토하고 필요하면 모형이나 운영 조건을 조정합니다. 조정의 근거로 같은 데이터를 여러 번 사용했다면 별도로 남긴 평가 자료에서 최종 결과를 확인합니다.
