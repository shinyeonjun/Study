Java① 객체와 상속

Java 문제는 문법보다 '누구의 것이 불리느냐'를 묻습니다. 참조가 화살표라는 것에서 시작해서, 상속 규칙, 생성자 순서, 오버로딩 예외 순으로 쌓아 올리면 대부분의 출력 문제가 같은 방식으로 풀립니다.

J-1객체 변수는 화살표기출 빈출

Java에는 *나 &가 없지만, 객체를 담는 변수는 전부 C의 포인터처럼 주소를 들고 있습니다. new가 객체를 만들고, 변수는 그 객체를 가리키는 화살표일 뿐입니다. 이 한 문장으로 참조 전달, 상속, == 비교가 모두 설명됩니다.

  • 점(.)이나 대괄호로 안을 고치면 원본이 바뀝니다.
  • =로 변수 자체를 다른 것에 붙이면 원본은 그대로입니다. C의 값 복사와 같은 원리입니다.
  • int, double, char, boolean 같은 기본형은 화살표가 아니라 값 자체가 복사됩니다.
  • String은 객체지만 안을 고치는 메서드가 없어서(불변) 넘겨도 원본이 바뀔 일이 없습니다.

J-2상속의 네 가지 규칙기출 빈출

A obj = new B();에서 왼쪽 A를 선언 타입, 오른쪽 B를 실제 객체라고 부르겠습니다. 실제 객체 안에는 부모 부분과 자식 부분이 함께 들어 있고, 무엇을 부르느냐에 따라 어느 쪽을 보는지가 정해져 있습니다. Java 기출의 4분의 1이 이 규칙으로 풀립니다. 아래 버튼을 하나씩 눌러 보세요.

무엇을 부르나어디를 보나이유
오버라이딩한 인스턴스 메서드실제 객체 (new 뒤)실행할 때 객체를 보고 고름 (동적 바인딩)
필드(변수)선언 타입 (왼쪽)필드는 재정의되지 않고 숨겨질 뿐
static 메서드선언 타입 (왼쪽)객체가 아니라 클래스에 붙어 있음
오버로딩 중 어떤 메서드인지선언 타입과 인자 타입 (컴파일 때)고른 다음, 실행할 때 오버라이딩 적용

부모 메서드 안에서 다른 메서드를 부를 때도 같은 규칙입니다. super.paint()로 부모 코드에 들어가도, 그 안의 draw()는 this.draw()이고 this는 여전히 B 객체입니다.

class A { void paint() { System.out.print("A.paint "); draw(); }
          void draw()  { System.out.print("A.draw "); } }
class B extends A { void paint() { super.paint(); System.out.print("B.paint "); }
                    void draw()  { System.out.print("B.draw "); } }

A a = new B();
a.paint();
출력
A.paint B.draw B.paint

함정

  • 재정의된 메서드가 재귀하면 매번 자식 버전으로 갑니다. 부모 공식으로 계산하면 틀립니다.
  • 필드 값을 돌려주는 메서드는, 그 메서드가 정의된 클래스의 필드를 읽습니다. 부모에만 있는 getX()는 부모 x를 반환합니다.
  • 선언 타입에 없는 메서드는 실제 객체에 있어도 부를 수 없습니다(컴파일 오류). 형변환이 필요합니다.

J-3생성자는 부모부터기출 빈출

new C()를 하면 C 생성자의 첫 줄에서 부모 생성자(super())가 먼저 실행됩니다. 직접 쓰지 않아도 컴파일러가 넣습니다. 자식 필드의 초기값(int v = 7)은 부모 생성자가 끝난 다음에 들어갑니다.

  1. 객체 공간이 생기고 모든 필드가 기본값(0, null, false)으로 채워진다.
  2. 자식 생성자가 호출된다. this(...)가 있으면 같은 클래스의 다른 생성자로 먼저 간다.
  3. super(...)로 부모 생성자 전체를 실행한다 (부모도 같은 순서를 밟음).
  4. 자식 필드 초기화와 인스턴스 블록 { }을 실행한다.
  5. 자식 생성자 본문의 나머지를 실행한다.

static 블록과 인스턴스 블록

class P { static { System.out.print("S1 "); }
          { System.out.print("I1 "); }
          P() { System.out.print("P "); } }
class C extends P { static { System.out.print("S2 "); }
                    { System.out.print("I2 "); }
                    C() { System.out.print("C "); } }
new C(); new C();
출력
S1 S2 I1 P I2 C I1 P I2 C

static 블록은 클래스가 처음 쓰일 때 부모부터 한 번만 실행됩니다. 인스턴스 블록은 객체를 만들 때마다 생성자 본문 바로 앞에서 실행됩니다.

J-4오버로딩은 컴파일 때, 오버라이딩은 실행 때기출 빈출

이름이 같고 매개변수가 다르면 오버로딩, 매개변수까지 같으면 오버라이딩입니다. 오버로딩은 컴파일러가 선언 타입에 어떤 메서드가 있는지만 보고 미리 고릅니다. 그렇게 고른 메서드가 자식에서 재정의돼 있으면, 실행할 때 자식 것이 불립니다.

class A { void f(Object o) { System.out.print("A-O "); }
          void g() { f("hi"); } }
class B extends A { void f(Object o) { System.out.print("B-O "); }
                    void f(String s) { System.out.print("B-S "); } }

A a = new B();
a.g();
a.f("hi");
((B) a).f("hi");
출력
B-O B-O B-S

A 안의 f("hi")는 A에 f(Object)밖에 없으니 그걸로 확정되고, 실행 때 B가 재정의한 f(Object)로 갑니다. 선언 타입이 A인 a.f("hi")도 같습니다. B로 형변환해야 비로소 f(String)이 후보에 들어옵니다.

오버로딩오버라이딩
조건이름 같고 매개변수(개수·타입) 다름이름·매개변수·반환형 같음, 상속 관계
결정 시점컴파일 때 (선언 타입 기준)실행 때 (실제 객체 기준)
반환형만 다르면오버로딩 아님 (컴파일 오류)
접근 제어자상관없음부모보다 좁게 못 함

함정

  • 제네릭 T는 컴파일 때 Object로 취급됩니다. print(T값)은 print(Object)가 골라집니다 (2024-3 19번).
  • 인자 "5"는 String, 5는 int. 어느 버전으로 가는지 인자 타입부터 확인하세요 (2025-1 20번).

J-5static은 클래스에 하나기출 빈출

static 변수는 객체마다 생기지 않고 클래스에 딱 하나 있습니다. 객체를 몇 개 만들든 같은 칸을 같이 씁니다. static 메서드는 객체 없이 클래스명.메서드()로 부르고, 그 안에는 this가 없어서 인스턴스 필드를 쓸 수 없습니다.

class Counter { static int n = 0; int m = 0; Counter() { n++; m++; } }

Counter c1 = new Counter(), c2 = new Counter(), c3 = new Counter();
System.out.print(c3.n + " " + c3.m);
출력
3 1

싱글톤도 이 원리입니다. static 필드에 객체 하나를 저장해 두고 get()이 그걸 돌려주면, 변수를 몇 개 만들어도 전부 같은 객체라 count가 누적됩니다.

class Connection {
    private static Connection inst = null;
    private int count = 0;
    static Connection get() { if (inst == null) inst = new Connection(); return inst; }
    void count() { count++; }
    int getCount() { return count; }
}
Connection a = Connection.get(); a.count();
Connection b = Connection.get(); b.count();
Connection c = Connection.get(); c.count();
System.out.print(a.getCount());
출력
3

J-7추상 클래스와 인터페이스필수 보강

둘 다 "몸체 없는 메서드"를 자식에게 구현하라고 강제하는 틀입니다. 직접 new로 만들 수 없다는 점도 같습니다.

interface Shape {
    double PI = 3.14;                       // 자동으로 public static final
    double area();                          // 자동으로 public abstract
    default String name() { return "shape"; }
}
abstract class Base implements Shape {
    int n;
    Base(int n) { this.n = n; }
    public String name() { return "base" + n; }
}
class Sq extends Base {
    Sq(int n) { super(n); }
    public double area() { return n * n; }
}
Shape s = new Sq(3);
System.out.print(s.area() + " " + s.name() + " " + Shape.PI);
출력
9.0 base3 3.14
추상 클래스인터페이스
선언abstract classinterface
물려받기extends, 하나만implements, 여러 개 가능
필드일반 필드 가능상수만 (public static final)
생성자있음 (자식이 super로 호출)없음
메서드일반 + abstractabstract + default + static

함정

  • area()가 int 곱셈이어도 반환형이 double이라 9.0으로 찍힙니다.
  • 인터페이스가 인터페이스를 물려받을 때는 extends입니다.

J-8형변환과 instanceof필수 보강

class Animal { String sound() { return "..."; } }
class Dog extends Animal { String sound() { return "멍"; }
                           String fetch() { return "공"; } }

Animal a = new Dog();                   // 업캐스팅: 자동
System.out.println(a.sound() + " " + ((Dog) a).fetch());
System.out.println((a instanceof Dog) + " " + (a instanceof Animal));
Animal b = new Animal();
Dog d = (Dog) b;                        // 실행 중 ClassCastException
출력
멍 공
true true
ClassCastException
  • 자식 → 부모(업캐스팅)는 자동. 부모 → 자식(다운캐스팅)은 (Dog)처럼 직접 써야 하고, 실제 객체가 그 타입일 때만 성공
  • a.fetch()는 컴파일 오류. 선언 타입 Animal에 fetch가 없기 때문
  • x instanceof T는 실제 객체가 T이거나 T의 자식이면 true
