공부·컴퓨터의 출발점 · U02 파일과 폴더

U02·3

저장·열기·복사·백업

두 시간 동안 정리한 메모를 닫으려는데 "변경 내용을 저장하시겠습니까?"라는 창이 뜹니다. 무심코 "저장 안 함"을 누르면 두 시간이 사라집니다. 반대로 꼬박꼬박 저장했는데 노트북이 고장 나도 모두 사라집니다. 이 장에서는 저장과 열기가 실제로 무엇을 옮기는지, 복사와 이동은 어떻게 다른지, 그리고 왜 백업은 "다른 곳에 둔 복사본"이어야 하는지를 다룹니다.

이 장을 읽고 나면

  • 저장과 열기를 메모리와 저장 장치 사이의 이동으로 설명할 수 있다.
  • "저장"과 "다른 이름으로 저장"이 원래 파일에 각각 어떤 일을 하는지 말할 수 있다.
  • 복사·이동·바로 가기의 차이를 말하고, 파일 탐색기에서 원하는 쪽으로 할 수 있다.
  • 백업이 막아 주는 위험과 막지 못하는 위험을 장소별로 가려낼 수 있다.
  • 동기화와 백업이 왜 다른지 지운 파일의 예로 설명할 수 있다.

저장: 메모리에서 저장 장치로

컴퓨터가 일하는 동안 쓰는 메모리(RAM)와 나중을 위해 남겨 두는 저장 장치(SSD·하드디스크·USB 메모리)는 다릅니다(U03-2 "부품과 프로그램"). 메모리는 빠르지만 전원이 꺼지면 내용이 사라지고, 저장 장치는 전원이 꺼져도 내용이 남습니다.

메모장에 글을 쓰고 있을 때, 화면에 보이는 글은 메모리에 있습니다. 아직 파일이 아닙니다. 저장 단추를 눌러야 그 내용이 저장 장치에 파일로 적힙니다.

정의 외우기

저장(save): 프로그램이 메모리에서 다루고 있는 내용을 저장 장치의 파일로 적는 일.

열기(open): 저장 장치의 파일 내용을 메모리로 읽어 와 프로그램이 다룰 수 있게 하는 일. 여는 것만으로는 파일이 바뀌지 않는다.

그림처럼 메모.txt를 열어(hello) 뒤에 " world"를 덧붙였다고 합시다. 이 순간 창에는 "hello world"가, 파일에는 여전히 "hello"가 있습니다. 여기서 저장 없이 창을 닫거나 전원이 나가면, 메모리의 "hello world"는 사라지고 파일에는 "hello"만 남습니다. 많은 프로그램이 창 제목 옆에 *나 점(●) 같은 표시를 띄워 "저장하지 않은 변경이 있다"고 알려 주는데, 바로 이 "둘이 다른 상태"를 알리는 것입니다.

흔한 실수

"화면에 보이니 저장된 것이다." 화면에 보이는 것은 메모리의 내용입니다. 파일에 적혔는지는 저장했는지에 달려 있습니다.

"프로그램이 알아서 저장해 준다." 일부 프로그램은 자동 저장을 합니다. 예를 들어 최근 Windows 11 메모장은 설정에 따라 저장하지 않은 내용을 다음에 열 때 되살려 주기도 합니다. 하지만 자동 저장을 하는지, 어디에 하는지는 프로그램과 설정마다 다르고, 되살려 준 내용이 원하는 폴더의 파일로 저장된 것도 아닙니다. 작업을 마쳤거나 잠시 손을 뗄 때는 직접 Ctrl + S를 누르는 습관이 가장 확실합니다.

저장 창에서 정하는 세 가지

새 글을 처음 저장하거나 "다른 이름으로 저장"을 고르면 저장 창이 뜹니다. 이 창에서 정하는 것은 세 가지입니다.

  • 위치: 어느 폴더에 둘지. 창 위쪽의 주소 표시줄과 왼쪽 목록에 보입니다. 앞 장에서 본 경로가 바로 이것입니다. 여기를 확인하지 않고 저장하면, 나중에 파일이 어디 갔는지 몰라 헤매게 됩니다.
  • 파일 이름: 기본 이름. 확장자는 보통 프로그램이 붙여 줍니다.
  • 파일 형식: 어떤 형식으로 적을지. 메모장은 텍스트 문서(*.txt), Word는 Word 문서(*.docx)가 기본이고, 여기서 PDF 같은 다른 형식을 고르면 앞 장(U02-1)에서 본 변환이 일어납니다. 메모장 저장 창에는 문자 인코딩을 고르는 칸도 있는데, 처음 값인 UTF-8을 그대로 두면 됩니다.

인터넷에서 받은 파일은 대부분 브라우저가 묻지 않고 다운로드 폴더(C:\Users\(사용자 이름)\Downloads)에 저장합니다. "받았는데 어디 있는지 모르겠다"면 먼저 여기를 봅니다.

"저장"과 "다른 이름으로 저장" 이해하기

이미 파일로 저장된 글을 고친 뒤에는 두 가지 선택이 있습니다. 둘은 원래 파일에 전혀 다른 일을 합니다.

  • 저장(Ctrl + S): 지금 열려 있는 그 파일에 덮어씁니다. 옛 내용은 사라집니다.
  • 다른 이름으로 저장(많은 프로그램에서 Ctrl + Shift + S, 또는 파일 메뉴): 새 이름(또는 새 위치)으로 새 파일을 만듭니다. 원래 파일은 손대지 않은 채 그대로 남습니다.

(나)에서 놓치기 쉬운 점이 있습니다. "다른 이름으로 저장"을 한 뒤에는 프로그램 창이 새 파일을 가리킵니다. 이어서 글을 더 쓰고 Ctrl + S를 누르면 보고서_2.txt에 저장되지, 보고서.txt에 저장되지 않습니다. 창 제목 줄의 파일 이름을 보면 지금 어느 파일을 고치고 있는지 알 수 있습니다.

이 성질을 이용하면, 크게 고치기 전에 "다른 이름으로 저장"으로 새 판을 만들어 옛 판을 지켜 둘 수 있습니다. 이것은 아래에서 볼 백업과도 이어집니다.

열기: 두 가지 길

파일을 여는 길은 두 가지입니다.

  • 파일 탐색기에서 두 번 누르기: Windows가 확장자를 보고 연결 프로그램을 골라 엽니다(U02-1).
  • 프로그램 안에서 열기: 프로그램을 먼저 켜고 "파일 → 열기"(Ctrl + O)로 파일을 고릅니다. 연결 프로그램과 다른 프로그램으로 열고 싶을 때 씁니다. 예를 들어 메모장을 켜고 열기 창에서 .csv 파일을 고르면, Excel 대신 메모장으로 CSV의 실제 글자를 볼 수 있습니다. 열기 창에 원하는 파일이 안 보이면 오른쪽 아래의 형식 칸을 "모든 파일"로 바꿉니다.

풀이 예제

메모.txt(내용: hello)를 두고 아래 순서대로 했습니다. 각 단계 뒤에 창의 내용과 파일의 내용을 적어 봅니다.

① 메모장으로 연다. → 창: hello / 파일: hello (열기는 파일을 바꾸지 않는다)
② " world"를 덧붙인다. → 창: hello world / 파일: hello (아직 메모리에서만 바뀜)
③ Ctrl + S를 누른다. → 창: hello world / 파일: hello world (저장으로 같아짐)
④ "!!!"를 덧붙인다. → 창: hello world!!! / 파일: hello world
⑤ 닫기를 누르고 저장하겠느냐는 물음에 "저장 안 함"을 고른다. → 창: 없음 / 파일: hello world
⑥ 다시 연다. → 창: hello world / 파일: hello world

⑤에서 "!!!"만 사라지고 ③에서 저장한 내용은 남았습니다. 저장은 "그 순간의 메모리 내용"을 파일에 적는 것이고, 그 뒤의 변경은 다시 저장해야 남습니다.

복사·이동·바로 가기

파일을 다른 폴더에 두고 싶을 때 하는 일은 세 가지로 나뉩니다. 결과가 다르니 정확히 구분합니다.

정의

복사(copy): 같은 내용의 파일을 하나 더 만든다. 만들어진 뒤에는 두 파일이 서로 독립이다.

이동(move): 파일을 다른 폴더로 옮긴다. 파일 수는 그대로이고 경로만 바뀐다.

바로 가기(shortcut): 원본 파일의 위치를 가리키는 작은 표시 파일. 내용을 담고 있지 않다. 바로 가기를 지워도 원본은 남고, 원본을 지우면 바로 가기는 쓸모없어진다.

파일 탐색기에서 하는 법

하고 싶은 일키보드끌어다 놓기
복사파일 고르고 Ctrl + C → 대상 폴더에서 Ctrl + V다른 드라이브로 끌면 복사. 같은 드라이브에서는 Ctrl을 누른 채 끌기
이동Ctrl + X(잘라내기) → 대상 폴더에서 Ctrl + V같은 드라이브 안에서 끌면 이동. 다른 드라이브로는 Shift를 누른 채 끌기
방금 한 일 되돌리기Ctrl + Z
휴지통으로 지우기Delete휴지통 아이콘에 끌기
휴지통을 거치지 않고 지우기Shift + Delete

끌어다 놓기는 같은 동작인데 결과가 달라서 헷갈립니다. 규칙은 이렇습니다. 같은 드라이브 안(예: C: 안의 두 폴더)에서 끌면 이동, 다른 드라이브(예: C:에서 USB 메모리 E:로)로 끌면 복사입니다. 끄는 도중 마우스 옆에 "이동" 또는 "복사"라는 작은 글자가 뜨니, 놓기 전에 확인합니다.

흔한 실수

대상 폴더에 같은 이름이 있는데 "바꾸기"를 누른다. 붙여 넣을 곳에 같은 이름의 파일이 있으면 Windows가 바꿀지, 건너뛸지 묻습니다. "바꾸기"는 대상 폴더의 파일을 덮어씁니다. 덮어쓴 파일은 휴지통에도 가지 않아 되살리기 어렵습니다. 어느 쪽이 최신인지 모르면 건너뛰거나 이름을 바꿔 둘 다 남깁니다.

USB 메모리에서 지운 것도 휴지통에 있다. 휴지통은 대개 컴퓨터 안의 드라이브에서 지운 파일만 받아 줍니다. USB 메모리나 네트워크 폴더에서 지운 파일은 보통 휴지통을 거치지 않고 바로 지워집니다. Shift + Delete도 마찬가지입니다.

바탕화면의 바로 가기를 USB에 복사해 간다. 바로 가기에는 내용이 없으니, 다른 컴퓨터에서는 아무것도 열리지 않습니다. 아이콘 왼쪽 아래의 작은 화살표가 바로 가기 표시입니다.

백업: 다른 곳에 둔 복사본

꼬박꼬박 저장해도 파일이 사라지는 일은 생깁니다. 저장 장치가 고장 날 수 있고, 노트북을 잃어버릴 수 있고, 실수로 덮어쓰거나 지울 수 있으며, 파일을 망가뜨리는 악성 프로그램에 걸릴 수도 있습니다. 저장은 메모리의 내용을 저장 장치로 옮겨 줄 뿐, 그 저장 장치에 생기는 일까지 막아 주지는 않습니다.

정의 외우기

백업(backup): 원본이 망가지거나 사라졌을 때 되살리려고, 원본과 떨어진 곳에 따로 만들어 둔 복사본.

정의의 두 조건이 중요합니다. 첫째, 떨어진 곳이어야 합니다. 같은 폴더나 같은 디스크 안의 복사본은 그 디스크가 고장 나면 원본과 함께 사라집니다. 둘째, 되살릴 수 있어야 합니다. 만들어만 두고 한 번도 열어 본 적 없는 백업은, 막상 필요할 때 비어 있거나 망가져 있을 수 있습니다.

어디에 둔 복사본이 무엇을 막아 주나

표를 보면 장소마다 막는 위험이 다릅니다. 같은 폴더의 복사본은 "방금 실수로 덮어썼다" 정도만 막고, 외장 USB는 디스크 고장까지 막지만 노트북과 함께 도둑맞거나 불에 타면 소용없습니다. 그래서 흔히 쓰는 기준이 다음과 같습니다.

외우는 법 · 3-2-1 규칙

3-2-1: 원본을 포함해 3개의 사본을, 2가지 서로 다른 저장 매체에, 그중 1개는 다른 장소에 둔다. 법이나 표준이 아니라 백업을 계획할 때 널리 쓰는 어림 기준이다.

풀이 예제

공부 폴더를 이렇게 두고 있습니다. 3-2-1을 지키는지 따져 봅니다.

상황: 원본은 노트북 SSD에 있다. 매주 일요일 외장 USB에 폴더째 복사해 책상 서랍에 둔다. 클라우드 백업 서비스에도 매일 자동으로 올라간다.

① 사본 수: 노트북 원본 1 + USB 1 + 클라우드 1 = 3개 → "3" 만족.
② 매체 종류: 노트북 SSD, 외장 USB, 클라우드 서버의 저장 장치 → 2가지 이상 → "2" 만족.
③ 다른 장소: 클라우드는 집 밖에 있다 → "1" 만족.
④ 남은 확인: 되살릴 수 있는가? 한 달에 한 번 USB와 클라우드에서 파일 하나를 꺼내 열어 본다.

만약 클라우드가 없다면 사본은 2개, 다른 장소에 둔 것은 0개가 됩니다. 이때는 USB를 하나 더 두어 회사나 가족 집에 보관하는 식으로 채울 수 있습니다.

동기화는 백업과 같지 않다

OneDrive, Google 드라이브 같은 서비스는 흔히 동기화(sync) 방식으로 동작합니다. 동기화는 두 곳의 폴더를 늘 똑같은 상태로 맞추는 것입니다. 노트북에서 파일을 고치면 클라우드도 고쳐지고, 노트북에서 지우면 클라우드에서도 지워집니다. 편리하지만, 바로 그 성질 때문에 백업과 다릅니다.

(가)에서 실수로 파일을 지우거나 잘못 덮어쓰면 그 실수가 클라우드까지 그대로 퍼집니다. (나)의 백업은 한 방향으로, 시점마다 따로 사본을 남기므로 오늘 지운 파일을 지난주 사본에서 되살릴 수 있습니다. 동기화 서비스에 "휴지통"이나 "버전 기록" 기능이 있다면 그 기능이 백업 역할을 일부 해 주는 것이지, 동기화 자체가 백업인 것은 아닙니다. OneDrive의 "폴더 백업"처럼 이름에 "백업"이 붙어 있어도 실제 동작은 동기화인 경우가 있으니, 이름이 아니라 지운 파일이 어떻게 되는지로 판단합니다.

왜 그럴까?

어떤 사람이 "내 파일은 전부 클라우드와 동기화되니까 백업은 따로 필요 없다"고 말합니다. 이 말이 위험한 경우를 하나 들어 보세요.

모범 답 보기

실수로 폴더를 통째로 지우거나, 악성 프로그램이 파일을 모두 망가뜨린 경우입니다. 동기화는 두 곳을 같게 맞추는 것이 목적이라, 노트북에서 일어난 삭제나 망가짐을 클라우드에도 그대로 옮깁니다. 서비스가 지운 파일이나 지난 판을 보관해 주지 않거나 보관 기간이 지났다면 되살릴 곳이 없습니다. 그래서 동기화와 별개로, 시점별 사본이 남는 백업을 두는 것이 안전합니다.

판 이름 붙이기

백업까지는 아니어도, 중요한 파일을 크게 고치기 전에는 "다른 이름으로 저장"으로 옛 판을 남겨 둘 수 있습니다. 이때 이름은 앞 장에서 본 대로 날짜를 연-월-일 순서로 붙입니다.

나쁜 이름좋은 이름
보고서_최종.docx, 보고서_진짜최종.docx, 보고서_최종2.docx보고서_2026-11-11.docx, 보고서_2026-11-18.docx

"최종"은 언제든 또 고칠 수 있어서 금방 의미를 잃습니다. 날짜 이름은 순서가 분명하고 이름순 정렬이 곧 시간순입니다. 코드와 문서의 고친 이력을 체계적으로 남기는 도구(Git)는 SY07 "Git와 재현 가능한 작업"에서 다룹니다.

직접 해 보기

① 파일 탐색기에서 "문서" 안에 공부 폴더를 만든다.
② 앞 장에서 만든 메모.txt를 Ctrl + X, 공부 폴더 안에서 Ctrl + V로 옮긴다. 문서 폴더에서 사라지고 공부 폴더에 생겼는지 본다.
③ 메모.txt를 고르고 Ctrl + C, 같은 폴더에서 Ctrl + V를 누른다. "메모 - 복사본.txt"처럼 이름이 바뀐 복사본이 생긴다.
④ 원본 메모.txt를 열어 한 줄을 덧붙이고 저장한다. 복사본을 열어 그 줄이 없는지 확인한다(복사본은 독립).
⑤ USB 메모리가 있다면 공부 폴더를 USB로 끌어다 놓는다. 끄는 동안 "복사"라고 뜨는지 본다.
⑥ USB에 복사된 메모.txt를 열어 내용이 그대로인지 확인한다. 이것이 가장 작은 백업과 되살리기 확인이다.

한눈에 정리

묻는 것답
저장메모리의 내용을 저장 장치의 파일로 적기 (Ctrl + S)
열기파일 내용을 메모리로 읽어 오기. 파일은 바뀌지 않음 (Ctrl + O)
저장 vs 다른 이름으로 저장같은 파일 덮어쓰기 vs 새 파일 만들기(원래 파일은 그대로, 창은 새 파일을 가리킴)
복사 · 이동 · 바로 가기하나 더 만듦 · 자리만 바꿈 · 원본을 가리키는 표시
끌어다 놓기같은 드라이브 = 이동, 다른 드라이브 = 복사
휴지통을 거치지 않는 삭제Shift + Delete, 대개 USB·네트워크 폴더에서의 삭제
백업되살리려고 떨어진 곳에 둔 복사본. 되살려 보기까지 해야 완성
3-2-1사본 3개, 매체 2가지, 1개는 다른 장소
동기화두 곳을 같게 맞춤. 지운 것도 따라가므로 백업과 다르다

한 줄 정리

저장은 메모리를 파일로 적는 일이고, 복사는 독립된 파일을 하나 더 만드는 일이며, 백업은 원본과 떨어진 곳에 둔 되살릴 수 있는 복사본이다.
