U03·3

브라우저와 서버

주소창에 뉴스 사이트 주소를 치고 Enter를 누르면 1초쯤 뒤에 기사가 뜹니다. 그 기사는 내 컴퓨터에 있던 것이 아닙니다. 멀리 있는 다른 컴퓨터가 보내 준 것입니다. 이 장에서는 그 1초 동안 두 컴퓨터가 주고받는 일, 곧 웹 요청 한 번의 큰 그림을 그려 봅니다.

이 장을 읽고 나면

  • 클라이언트·서버·브라우저가 각각 무엇인지 설명할 수 있다.
  • 인터넷과 웹의 차이를 말할 수 있다.
  • 주소(URL)를 프로토콜·호스트 이름·경로로 나눠 읽을 수 있다.
  • 웹 페이지 하나가 뜨기까지 요청과 응답이 오가는 순서를 그릴 수 있다.
  • 페이지 하나에 요청이 몇 번 필요한지 셀 수 있다.

부탁하는 쪽과 들어주는 쪽

식당을 떠올려 봅시다. 손님이 "김치찌개 하나 주세요"라고 주문하면, 주방은 그 주문을 받아 음식을 만들어 내어 줍니다. 손님은 부탁하는 쪽, 주방은 부탁을 들어주는 쪽입니다. 웹 페이지를 볼 때 두 컴퓨터 사이에서도 똑같은 일이 일어납니다.

정의

클라이언트(client): 다른 컴퓨터에게 무언가를 요청하는 쪽. 영어로 "손님, 의뢰인"이라는 뜻입니다.
서버(server): 요청을 받아 그에 맞는 것을 응답으로 돌려주는 쪽. 영어로 "시중드는 사람"이라는 뜻입니다.
요청(request)과 응답(response): 클라이언트가 보내는 부탁과, 서버가 돌려주는 답.

웹 페이지를 볼 때 클라이언트 역할을 하는 프로그램이 브라우저(browser)입니다. Chrome, Edge, Safari, Firefox, 휴대폰의 삼성 인터넷이 모두 브라우저입니다. 브라우저는 두 가지 일을 합니다.

  1. 주소를 받아 그 주소의 서버에 페이지를 요청한다.
  2. 서버가 보내 준 응답(글자·그림·모양 정보)을 읽어 화면에 그린다.

흔한 실수

"서버는 특별하게 생긴 거대한 기계다"는 반만 맞습니다. 서버는 역할의 이름입니다. 요청을 받아 응답하는 프로그램이 돌고 있으면, 평범한 노트북도 서버가 될 수 있습니다. 실제 서비스의 서버는 하루 종일 켜 두고 많은 요청을 받아야 해서 전용 기계를 데이터 센터에 모아 두는 경우가 많을 뿐입니다. 또 "서버"라는 말은 그 컴퓨터를 가리킬 때도, 그 안에서 요청을 받는 프로그램을 가리킬 때도 씁니다. 앞뒤 말을 보고 가립니다.

더 알아보기 · 식당 비유의 한계

식당 주방은 한 번에 손님 몇 명만 상대하지만, 서버는 같은 순간에 수천 명의 요청을 동시에 받아 처리하기도 합니다. 또 주방은 음식을 내주면 그 음식이 없어지지만, 서버는 파일을 복사해서 보내므로 원본은 그대로 남고 다음 사람에게도 똑같이 보낼 수 있습니다.

인터넷과 웹은 같은 말이 아니다

일상에서는 "인터넷 한다"와 "웹 서핑 한다"를 섞어 쓰지만 두 낱말의 뜻은 다릅니다.

정의

인터넷(Internet): 전 세계의 컴퓨터 네트워크를 서로 이어 놓은 거대한 연결망. 데이터가 오가는 길입니다.
웹(Web, World Wide Web): 인터넷이라는 길 위에서 브라우저로 페이지를 주고받는 서비스 하나.

도로와 택배에 빗대면, 인터넷은 전국을 잇는 도로망이고 웹은 그 도로 위를 다니는 택배 서비스 하나입니다. 같은 도로 위로 다른 서비스(전자우편, 메신저, 온라인 게임, 파일 전송)도 다닙니다. 카카오톡으로 메시지를 보낼 때도 인터넷을 쓰지만 브라우저로 웹 페이지를 보는 것은 아닙니다.

용어 네트워크(network)는 여러 컴퓨터를 선이나 전파로 이어 데이터를 주고받게 한 것입니다. 집 안의 공유기에 휴대폰과 노트북이 함께 붙어 있으면 그것도 작은 네트워크입니다. 네트워크는 NW 단원에서 자세히 다룹니다.

주소 읽기: URL

브라우저가 서버에게 요청하려면 어느 컴퓨터의 어느 파일을 달라고 할지 알아야 합니다. 그것을 한 줄로 적은 것이 주소창의 주소, 곧 URL(Uniform Resource Locator, 자원의 위치를 적는 통일된 형식)입니다.

  • 프로토콜(protocol): 두 컴퓨터가 어떤 약속(형식과 순서)으로 주고받을지. 웹은 HTTP(HyperText Transfer Protocol)라는 약속을 쓰고, 오가는 내용을 암호로 감싼 것이 HTTPS입니다. 지금 대부분의 사이트는 https를 씁니다.
  • 호스트 이름(host name): 요청을 받을 컴퓨터의 이름. 도메인 이름이라고도 합니다. 사람이 외우기 쉬운 글자 이름입니다.
  • 경로(path): 그 컴퓨터 안에서 어느 파일(또는 어느 페이지)인지. 빗금(/)으로 폴더를 나눠 적습니다. 폴더와 경로는 U02에서 자세히 봅니다.

풀이 예제

주소 https://data.example.org/2026/sales.csv를 세 부분으로 나눠 봅시다.

① 맨 앞에서 ://까지: https:// → 프로토콜은 HTTPS
② :// 뒤부터 다음 빗금(/) 앞까지: data.example.org → 호스트 이름
③ 그 빗금부터 끝까지: /2026/sales.csv → 경로. 2026 폴더 안의 sales.csv 파일

이 주소로 요청하면 data.example.org라는 컴퓨터에게 "2026 폴더의 sales.csv를 주세요"라고 부탁하는 셈입니다. 끝이 .csv이므로 받은 것은 화면에 그릴 페이지가 아니라 표 데이터 파일입니다. 이렇게 웹으로 데이터 파일을 받아 오는 것은 데이터 분석에서 자주 하는 일입니다.

요청 한 번 따라가기 이해하기

이제 주소창에 https://www.example.com/news/today.html을 치고 Enter를 누른 뒤 일어나는 일을 순서대로 따라갑니다. 실제로는 이보다 단계가 많지만, 큰 줄기는 다음과 같습니다.

①② 이름을 번호로 바꾸기

인터넷에 붙은 컴퓨터는 저마다 IP 주소라는 번호를 가집니다. 203.0.113.10처럼 점으로 나뉜 숫자입니다. 사람은 www.example.com 같은 이름이 외우기 쉽지만, 인터넷의 길은 번호로 찾아갑니다. 그래서 브라우저는 먼저 DNS(Domain Name System, 도메인 이름 체계)에게 "이 이름의 번호가 뭐죠?"라고 묻습니다. 전화번호부에서 이름으로 번호를 찾는 것과 같습니다. 한번 알아낸 번호는 한동안 기억해 두고 다시 묻지 않습니다.

③ 요청 보내기

번호를 알았으니 그 컴퓨터에게 요청을 보냅니다. 요청은 HTTP라는 약속에 맞춘 글자 몇 줄입니다. 핵심만 간추리면 이렇게 생겼습니다.

GET /news/today.html HTTP/1.1
Host: www.example.com

첫 줄은 "가져다주세요(GET), 경로는 /news/today.html, HTTP 1.1 약속으로"라는 뜻이고, 둘째 줄은 받을 컴퓨터의 이름입니다. 앞에서 나눈 URL의 호스트 이름과 경로가 그대로 들어가 있습니다.

④⑤ 서버가 찾아서 돌려주기

요청을 받은 웹 서버는 자기 저장 장치에서 news 폴더의 today.html을 찾습니다(페이지를 그 자리에서 만들어 내는 서버도 있습니다). 찾으면 응답을 돌려줍니다. 응답도 글자로 시작합니다.

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<!doctype html>
<html lang="ko">
… (페이지 내용) …

첫 줄의 200은 상태 코드로, "잘 찾아서 보낸다"는 뜻입니다. 둘째 줄은 보내는 것이 HTML 문서라는 안내이고, 빈 줄 다음부터가 실제 내용입니다. 없는 파일을 요청하면 200 대신 404(Not Found, 찾을 수 없음)가 돌아옵니다. 잘못된 주소를 쳤을 때 보는 "404 페이지"가 이것입니다. 상태 코드의 종류는 NW02에서 자세히 봅니다.

용어 HTML(HyperText Markup Language)은 웹 페이지의 글과 구조(제목, 문단, 그림 자리)를 적는 형식입니다. CSS는 글자 크기·색·배치 같은 모양을 적는 형식입니다. 자바스크립트(JavaScript) 파일은 페이지 안에서 브라우저가 실행하는 프로그램(명령)을 적은 파일로, 단추를 누르면 정답이 나오는 것 같은 움직임을 맡습니다. 지금 읽는 이 페이지도 HTML 파일, style.css 파일, 그리고 확인 문제를 움직이는 자바스크립트 파일 몇 개로 되어 있습니다.

⑥~⑨ 화면 그리기와 추가 요청

브라우저는 받은 HTML을 위에서부터 읽으며 화면을 그립니다. 읽다 보면 "모양은 style.css에 있다", "여기에 logo.png 그림을 넣어라" 같은 표시가 나옵니다. 브라우저는 그 파일들을 각각 따로 다시 요청합니다. 모든 응답이 도착해야 페이지가 완성됩니다.

페이지 하나에 요청은 몇 번?

풀이 예제

위 그림의 today.html을 처음 열 때 브라우저가 서버에 보내는 요청은 모두 몇 번일까요? (DNS에 묻는 것은 세지 않습니다.)

① 페이지 자체(today.html): 1번
② HTML 안에서 가리키는 모양 파일(style.css): 1번
③ HTML 안에서 가리키는 그림(logo.png, chart.png, photo.jpg): 3번
④ 합계: 1 + 1 + 3 = 5번

같은 페이지를 다시 열면 브라우저가 전에 받은 파일을 기억해 두었다가(이것을 캐시, cache라고 합니다) 다시 받지 않을 수 있어서, 요청 수가 줄어들 수 있습니다. 위의 5번은 "처음 열 때"의 수입니다. 또 실제 브라우저는 CSS 파일 안에서 가리키는 글꼴·그림이나 탭에 보이는 작은 사이트 아이콘(favicon)을 더 요청하기도 합니다. 이 장의 문제에서는 HTML 안에서 직접 가리키는 파일만 셉니다.

두 컴퓨터의 입력·처리·출력 이해하기

U03·1의 입력·처리·출력을 두 컴퓨터에 함께 대어 보면, 한 컴퓨터의 출력이 다른 컴퓨터의 입력이 되는 것을 볼 수 있습니다.

서버 쪽 처리(파일 찾기)에는 U03·2의 세 부품이 그대로 쓰입니다. 서버의 저장 장치에 있던 today.html을 메모리로 올리고, CPU가 웹 서버 프로그램의 명령에 따라 응답을 만들어 보냅니다. 서버도 결국 입력·처리·출력·저장을 하는 컴퓨터 한 대입니다.

이 교재와 빅데이터에서 다시 보기

이 교재는 어디에 있나

이 교재의 페이지를 내 컴퓨터의 파일로 직접 열면 주소창이 file:///D:/…/u03-3.html처럼 file로 시작합니다. 이때는 서버가 없습니다. 브라우저가 내 저장 장치의 파일을 바로 읽습니다. 같은 파일을 GitHub Pages 같은 곳에 올리면 주소가 https://로 시작하고, 그때부터는 그곳의 서버가 요청을 받아 이 HTML과 style.css를 보내 줍니다.

한 가지 더. 이 교재에서 푼 문제 기록은 서버가 아니라 내 브라우저 안에 저장됩니다(브라우저가 가진 작은 저장 공간을 씁니다). 그래서 다른 기기나 다른 브라우저에서 열면 기록이 보이지 않습니다. 서버는 페이지를 보내 주기만 하고, 내가 무엇을 풀었는지는 받지 않습니다.

서버가 남기는 기록: 웹 로그

많은 웹 서버는 요청을 받을 때마다 한 줄씩 기록을 남깁니다. 이것을 웹 로그(web log)라고 합니다. 흔한 모양은 이렇습니다.

203.0.113.25 - - [18/Nov/2026:09:15:02 +0900] "GET /news/today.html HTTP/1.1" 200 5120
부분뜻
203.0.113.25요청한 쪽(클라이언트)의 IP 주소
[18/Nov/2026:09:15:02 +0900]요청을 받은 날짜와 시각 (+0900은 한국 시간)
"GET /news/today.html HTTP/1.1"요청의 첫 줄 그대로
200상태 코드 (잘 보냈다)
5120보낸 내용의 크기 (바이트, U04·3)

빅데이터 노트 1-01에서 웹 로그를 반정형 데이터의 예로 봤습니다. 칸이 정해진 표는 아니지만 자리마다 뜻이 정해져 있어 나눠 읽을 수 있기 때문입니다. 인기 있는 사이트는 이런 줄이 하루에 아주 많이 쌓입니다. "어느 페이지가 몇 시에 많이 읽혔나" 같은 질문은 이 줄들을 모아 세는 데서 시작합니다.

왜 그럴까?

인터넷 선을 뽑은 상태에서도, 내 컴퓨터에 저장해 둔 이 교재의 HTML 파일은 브라우저로 열립니다. 그런데 뉴스 사이트는 열리지 않습니다. 둘의 차이는 무엇일까요?

모범 답 보기

내 컴퓨터의 파일은 브라우저가 내 저장 장치에서 바로 읽으므로 서버도 인터넷도 필요 없습니다. 뉴스 사이트의 페이지는 멀리 있는 서버의 저장 장치에 있으므로, 인터넷을 통해 요청을 보내고 응답을 받아야 볼 수 있습니다. 길(인터넷)이 끊기면 요청이 서버에 닿지 않습니다.

한눈에 정리

낱말뜻
클라이언트요청하는 쪽. 웹에서는 브라우저
서버요청을 받아 응답하는 쪽. 기계가 아니라 역할의 이름
브라우저페이지를 요청하고, 받은 HTML·CSS·그림으로 화면을 그리는 프로그램
인터넷 / 웹컴퓨터를 잇는 연결망(길) / 그 위에서 페이지를 주고받는 서비스 하나
URL프로토콜(https://) + 호스트 이름(www.example.com) + 경로(/news/today.html)
DNS호스트 이름을 IP 주소(번호)로 바꿔 알려 준다
상태 코드200 = 잘 보냄, 404 = 찾을 수 없음
요청 수HTML 1번 + 그 안에서 가리키는 파일마다 1번씩

한 줄 정리
