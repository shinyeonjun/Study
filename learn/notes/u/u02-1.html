U02·1

파일과 확장자

바탕화면에 "메모"라는 이름의 파일이 두 개 있습니다. 하나를 두 번 누르면 메모장이 열리고, 다른 하나를 누르면 Word가 열립니다. 이름이 같은데 왜 다른 프로그램이 열릴까요? 이 장에서는 파일이 무엇인지, 파일 이름 끝에 숨어 있는 확장자가 무슨 일을 하는지, 그리고 데이터와 코드를 다룰 때 가장 많이 쓰는 텍스트 파일이 Word 문서와 어떻게 다른지를 Windows 화면을 기준으로 살펴봅니다.

이 장을 읽고 나면

  • 파일이 무엇인지, 파일 하나에 어떤 정보가 붙어 있는지 설명할 수 있다.
  • 파일 이름을 기본 이름과 확장자로 나누고, 점이 여러 개인 이름에서도 확장자를 찾을 수 있다.
  • Windows 파일 탐색기에서 확장자가 보이게 설정할 수 있다.
  • 확장자를 바꾸어도 내용은 바뀌지 않는다는 것을 예로 설명할 수 있다.
  • 텍스트 파일과 .docx 파일의 차이를 말하고, 짧은 텍스트 파일의 크기를 바이트로 셀 수 있다.

이름이 같은 두 파일

처음 장면으로 돌아가 봅시다. 바탕화면의 두 "메모"는 사실 이름이 같지 않습니다. 하나는 메모.txt이고 다른 하나는 메모.docx입니다. Windows는 처음 설치했을 때 이름 끝의 .txt, .docx 부분을 화면에 보여 주지 않도록 설정되어 있어서, 둘 다 "메모"로만 보였던 것입니다.

이 숨은 꼬리가 확장자입니다. 확장자는 작아 보이지만, 컴퓨터로 공부하고 데이터를 다루기 시작하면 매일 마주칩니다. 데이터 파일 점수.csv, 코드 파일 계산.py, 이 교재의 페이지 u02-1.html이 모두 확장자로 자기 종류를 알립니다. 그래서 이 장은 확장자를 항상 보이게 설정하는 것으로 시작해, 확장자가 정확히 무엇을 하고 무엇을 하지 않는지까지 다룹니다.

파일이란 무엇인가 외우기

컴퓨터가 하는 일 가운데 하나가 나중에 다시 쓰려고 남겨 두는 저장입니다(U03 "컴퓨터의 큰 그림"). 저장 장치(하드디스크, SSD, USB 메모리 등)에 데이터를 남기는 단위가 파일입니다.

바이트(byte) 파일 크기를 셀 때 쓰는 기본 단위. 영어 글자 하나가 보통 1바이트를 차지합니다. 바이트와 KB·MB 같은 단위는 U04 "기호와 단위 읽기"에서 자세히 다룹니다.

정의

파일(file): 저장 장치에 이름을 붙여 한 덩어리로 남긴 데이터. 안에 든 것은 결국 바이트들이 한 줄로 늘어선 것이다.

파일에는 내용 말고도 이름, 크기(바이트 수), 만든 날짜, 고친 날짜 같은 정보가 따라붙는다. 파일 탐색기의 "자세히" 보기나 파일의 "속성" 창에서 볼 수 있다.

"안에 든 것은 바이트들이 한 줄로 늘어선 것"이라는 말이 중요합니다. 사진 파일이든 문서 파일이든 프로그램 파일이든, 저장 장치 입장에서는 모두 똑같이 바이트의 줄입니다. 그 줄을 어떻게 읽어야 사진이 되고 글이 되는지는 파일을 여는 프로그램이 압니다. 이 점은 아래에서 확장자를 바꿔 볼 때 다시 확인합니다.

파일 이름을 나누어 보기

정의 외우기

확장자(extension, Windows 화면에서는 "확장명"): 파일 이름에서 마지막 점(.) 뒤에 붙은 글자. 그 파일이 어떤 종류인지 알리는 표시다. 앞의 나머지 부분은 기본 이름이라고 한다.

"마지막 점"이라는 조건이 중요합니다. 보고서.final.docx에서 확장자는 final.docx가 아니라 docx 하나입니다. 첫째 점은 사람이 이름을 꾸미려고 넣은 것일 뿐, 컴퓨터는 마지막 점 뒤만 확장자로 봅니다. 확장자는 보통 3~4글자지만 꼭 그래야 하는 것은 아니고(.py는 2글자, .html은 4글자), 아예 없는 파일도 있습니다.

이름에 쓸 수 없는 글자

Windows에서 파일 이름에는 다음 아홉 글자를 쓸 수 없습니다. 이름을 바꾸다가 이 글자를 치면 Windows가 경고를 띄우고 받아 주지 않습니다.

\  /  :  *  ?  "  <  >  |

이 글자들은 대부분 컴퓨터가 다른 뜻으로 쓰기 때문에 막혀 있습니다. 예를 들어 \는 다음 장에서 볼 "경로"에서 폴더를 나누는 글자이고, :는 C: 같은 드라이브 이름에 씁니다. 그 밖에 띄어쓰기와 한글은 쓸 수 있지만, 뒤에서 코드로 파일을 다룰 때는 띄어쓰기 대신 _(밑줄)이나 -를 쓰는 편이 덜 번거롭습니다.

또 Windows는 파일 이름의 대문자와 소문자를 구별하지 않습니다. Memo.txt와 memo.txt는 같은 폴더에 함께 둘 수 없는 같은 이름입니다. 반면 Linux에서는 이 둘이 서로 다른 파일입니다. 나중에 서버나 Linux에서 작업할 때 이 차이로 헷갈릴 수 있으니 기억해 둡니다(macOS는 기본 설정에서 Windows처럼 구별하지 않습니다).

확장자가 하는 일

파일을 두 번 누르면 Windows는 어떤 프로그램으로 열지 정해야 합니다. 이때 Windows가 보는 것이 바로 확장자입니다. Windows 안에는 "이 확장자는 이 프로그램으로 연다"는 짝을 적은 표가 있고, 이 짝을 연결 프로그램이라고 부릅니다. 파일 아이콘 모양도 이 짝에 따라 정해집니다.

짝은 바꿀 수 있습니다. 파일에서 마우스 오른쪽 단추를 누르고 "연결 프로그램"을 고르면, 이번 한 번만 다른 프로그램으로 열거나 앞으로 계속 그 프로그램으로 열도록 정할 수 있습니다. 예를 들어 .csv 파일은 Excel이 있는 컴퓨터에서는 Excel로 열리지만, 연결 프로그램에서 메모장을 고르면 메모장으로도 열 수 있습니다.

자주 만나는 확장자를 정리하면 다음과 같습니다. 모두 외울 필요는 없고, 굵게 표시한 줄은 이 교재에서 계속 나오니 익혀 둡니다.

확장자가 보이게 설정하기

Windows 처음 설정에서는 확장자가 숨겨져 있습니다. 공부와 작업을 하려면 항상 보이게 해 두는 것이 좋습니다. 이름만 보고 파일 종류를 알 수 있고, 아래에서 볼 위험한 파일도 알아챌 수 있기 때문입니다.

따라 하기 · Windows 11

① 파일 탐색기를 연다(Windows 로고 키 + E).
② 창 위쪽 줄에서 보기를 누른다.
③ 펼쳐진 메뉴 맨 아래쪽의 표시에 마우스를 올린다.
④ 파일 확장명을 누른다. 앞에 체크 표시가 생기면 켜진 것이다.
⑤ 아무 폴더나 열어 파일 이름 끝에 .txt, .jpg 같은 글자가 보이는지 확인한다.

Windows 10에서는 파일 탐색기 위쪽의 보기 탭을 누르고, 오른쪽의 "표시/숨기기" 묶음에서 파일 확장명 상자에 체크합니다.

업데이트에 따라 메뉴 위치가 조금 다를 수 있습니다. 메뉴를 못 찾으면 시작 메뉴에서 "파일 탐색기 옵션"을 검색해 열고, 보기 탭에서 "알려진 파일 형식의 파일 확장명 숨기기"의 체크를 끈 뒤 확인을 누릅니다. (macOS에서는 Finder 설정의 "고급"에서 "모든 파일 확장자 보기"를 켭니다.)

흔한 실수

"사진.jpg"라고 보이니 사진이다. 확장자가 숨겨진 상태에서는 마지막 확장자만 사라집니다. 그래서 실제 이름이 사진.jpg.exe인 파일은 화면에 사진.jpg로 보입니다. 이 파일의 진짜 확장자는 .exe, 곧 실행되는 프로그램입니다. 남에게 받은 파일을 사진인 줄 알고 두 번 누르면 그 프로그램이 실행됩니다. 이메일이나 메신저로 받은 파일을 이렇게 위장시키는 일이 실제로 있기 때문에, 확장자를 항상 보이게 해 두는 것이 안전합니다.

확장자는 이름표일 뿐이다 이해하기

확장자를 보이게 했으면, 이름을 바꿀 때 확장자도 바꿀 수 있게 됩니다. 그렇다면 메모.txt의 이름을 메모.jpg로 바꾸면 메모가 사진이 될까요? 되지 않습니다.

이름을 바꾼 순간 바뀐 것은 이름표뿐입니다. 안에 든 바이트 다섯 개는 그대로입니다. 그런데 Windows는 이제 .jpg를 보고 사진 앱에 파일을 넘깁니다. 사진 앱은 이 바이트들을 사진 규칙대로 읽으려 하지만, 이것은 사진 규칙으로 짜인 바이트가 아니므로 "열 수 없다"는 오류를 냅니다. 이름을 다시 메모.txt로 돌리면 아무 일 없었다는 듯 메모장에서 잘 열립니다. 내용은 한 번도 바뀌지 않았기 때문입니다.

그래서 확장자와 구별해서 알아 둘 낱말이 있습니다.

정의 · 비슷한 말과의 차이

파일 형식(file format): 파일 내용의 바이트가 실제로 짜여 있는 규칙. 예를 들어 JPEG 형식은 사진을 바이트로 적는 규칙이다.

확장자는 파일 이름에 붙은 표시로, "이 파일은 이런 형식이다"라고 알릴 뿐이다. 보통은 둘이 일치하지만, 이름을 바꾸면 얼마든지 어긋날 수 있다.

파일의 형식을 정말로 바꾸려면 이름이 아니라 내용을 바꾸어야 합니다. 그 일은 프로그램이 합니다. 예를 들어 Word에서 문서를 연 뒤 "다른 이름으로 저장"에서 파일 형식을 PDF로 고르면, Word가 내용을 PDF 규칙대로 다시 써서 새 파일을 만듭니다. 이것을 변환이라고 합니다.

Windows도 이 위험을 알기 때문에, 이름 바꾸기에서 확장자를 바꾸려 하면 "파일을 사용할 수 없게 될 수도 있다"는 취지의 경고 창을 띄웁니다. 무엇을 하는지 알 때만 "예"를 누릅니다.

텍스트 파일과 그렇지 않은 파일

앞의 확장자 표에서 "텍스트 파일인가"라는 열을 보았습니다. 이 구분은 데이터와 코드를 다룰 때 아주 중요합니다.

정의 외우기

텍스트 파일(text file, 일반 텍스트 plain text): 내용이 글자와 줄바꿈만으로 이루어진 파일. 글꼴·크기·색·굵게 같은 꾸밈 정보는 들어 있지 않다. 메모장 같은 아무 텍스트 편집기로 열어도 쓴 글자가 그대로 보인다.

텍스트 파일이 아닌 파일을 흔히 바이너리 파일(binary file)이라고 한다. 사진·소리·영상·실행 파일·Word 문서가 여기에 든다. 메모장으로 열면 알아볼 수 없는 글자들이 뒤섞여 보인다.

.txt와 .docx는 무엇이 다른가

둘 다 "글을 쓴 파일"이라서 비슷해 보이지만, 안을 열어 보면 전혀 다릅니다.

(가)의 메모.txt에는 "hello" 다섯 글자가 바이트 다섯 개로 들어 있을 뿐입니다. 반면 (나)의 .docx는 여러 파일을 ZIP이라는 방식으로 하나로 묶어 줄인 것입니다. 그 안에 본문 글자, 글꼴·크기 같은 꾸밈, 넣은 그림, 쪽 설정이 각각 따로 들어 있습니다. 메모장으로 .docx를 열면 맨 앞에 PK라는 두 글자가 보이고 그 뒤로 알아볼 수 없는 글자가 이어지는데, PK는 ZIP 묶음이 늘 이 두 글자로 시작하기 때문에 보이는 것입니다.

메모장으로 열면쓴 그대로 보인다PK로 시작하는 깨진 글자
잘 맞는 쓰임코드, 데이터, 설정, 간단한 메모꾸민 문서, 인쇄할 보고서
프로그램이 읽기쉽다. 대부분의 언어가 바로 읽는다.docx 규칙을 아는 도구가 따로 필요하다

왜 데이터와 코드는 텍스트 파일인가

Python 코드(.py), 표 데이터(.csv), 웹 페이지(.html)가 모두 텍스트 파일인 데는 이유가 있습니다. 텍스트 파일은 어떤 프로그램으로도 열고, 읽고, 고칠 수 있습니다. 특정 회사의 프로그램이 없어도, 20년 뒤에도, 다른 운영체제에서도 그대로 열립니다. 또 꾸밈 정보가 섞여 있지 않으니 프로그램이 내용을 읽을 때 걸러 낼 것이 없습니다.

흔한 실수

코드를 Word에 써서 복사해 붙인다. Word 같은 문서 프로그램은 보기 좋게 하려고 곧은 따옴표 "를 둥근 따옴표 “ ”로 저절로 바꿉니다. 사람 눈에는 비슷하지만 컴퓨터에게는 다른 글자라서, Python은 둥근 따옴표가 든 코드를 실행하지 못하고 오류를 냅니다. 코드는 처음부터 메모장이나 코드 편집기 같은 텍스트 편집기에 씁니다.

.docx로 저장한 표를 데이터 파일로 쓴다. 분석 프로그램에 줄 표는 .csv 같은 텍스트 파일로 저장합니다. CSV를 읽고 쓰는 법은 PY07 "파일과 자료 교환"에서 다룹니다.

텍스트 파일의 크기 세어 보기

텍스트 파일은 글자만 들어 있으니, 글자 수로 크기를 셀 수 있습니다. 다만 글자마다 차지하는 바이트 수가 다릅니다. 글자를 바이트로 바꾸는 규칙을 문자 인코딩(character encoding)이라고 하는데, 요즘 가장 널리 쓰는 규칙인 UTF-8에서는 다음과 같습니다. Windows 11의 메모장도 처음 설정에서 UTF-8로 저장합니다.

  • 영어 글자, 숫자, 띄어쓰기, 대부분의 기호: 한 글자에 1바이트
  • 한글 한 글자(가, 안, 녕 등 완성된 글자): 3바이트
  • Windows 메모장에서 Enter로 바꾼 줄 하나: 2바이트 (줄바꿈도 보이지 않는 글자 두 개로 저장된다)

풀이 예제

메모장에 우유 40개라고 쓰고, Enter 없이 UTF-8로 저장했습니다. 파일 크기는 몇 바이트일까요?

① 글자를 종류별로 센다. 한글: 우, 유, 개 → 3글자. 숫자: 4, 0 → 2글자. 띄어쓰기: 1글자.
② 한글은 3바이트씩: 3 × 3 = 9바이트.
③ 숫자와 띄어쓰기는 1바이트씩: 2 + 1 = 3바이트.
④ 더한다: 9 + 3 = 12바이트.

이 값은 Python으로 실제 바이트 수를 세어 확인한 것과 같습니다. 같은 방법으로 hello는 5바이트, 안녕은 3 × 2 = 6바이트입니다. 마지막에 Enter를 한 번 쳤다면 2바이트가 더해집니다. 예를 들어 hello 뒤에 Enter를 치고 저장하면 5 + 2 = 7바이트입니다.

이렇게 만든 파일을 파일 탐색기의 "자세히" 보기로 보면 크기가 1KB로 나옵니다. 탐색기 목록은 크기를 KB 단위로, 끝수를 올려서 보여 주기 때문입니다(0바이트 파일만 0KB). 정확한 바이트 수는 파일을 마우스 오른쪽 단추로 눌러 속성을 열면 "크기" 줄에 나옵니다. KB가 몇 바이트인지는 U04에서 정확히 다룹니다.

Enter가 2바이트인 것은 Windows의 관례이고, macOS와 Linux에서는 보통 1바이트로 저장합니다. 이 차이는 나중에 운영체제가 다른 컴퓨터끼리 텍스트 파일을 주고받을 때 가끔 문제를 일으킵니다. 인코딩과 줄바꿈은 PY07과 SY01에서 더 자세히 다룹니다.

직접 해 보기

① 메모장을 연다.
② hello라고 쓴다. Enter는 치지 않는다.
③ Ctrl + S를 누른다. 저장 창에서 왼쪽의 "문서"를 고르고, 파일 이름에 메모를 쓰고 저장한다. 메모장이 이름 끝에 .txt를 붙여 준다.
④ 메모장을 닫는다.
⑤ 파일 탐색기에서 "문서" 폴더를 열어 메모.txt가 있는지 본다. 확장자가 보이는지도 확인한다.
⑥ 메모.txt를 마우스 오른쪽 단추로 눌러 "속성"을 열고 크기가 5바이트인지 확인한다.
⑦ 메모.txt를 두 번 눌러 다시 열고 hello가 그대로 있는지 확인한다.

파일이 어디에 저장되었는지(문서 폴더가 실제로 어디인지)는 다음 장 U02-2 "폴더와 경로"에서 정확히 짚습니다.

한 줄 정리

파일은 이름 붙은 바이트 덩어리이고, 확장자는 마지막 점 뒤의 이름표일 뿐 내용을 바꾸지 않으며, 데이터와 코드는 글자만 든 텍스트 파일로 다룬다.
