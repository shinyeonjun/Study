U05·3

노트북의 실행 순서와 오류 메시지 읽기

데이터 분석 강의나 빅데이터분석기사 실기 연습에서는 .py 파일 대신 "노트북"이라는 화면을 자주 씁니다. 코드와 결과가 한 장에 나란히 남아 편하지만, 화면 순서와 실행 순서가 어긋나면 같은 화면에서 다른 답이 나옵니다. 이 장에서는 그 함정을 실제로 따라가 보고, 오류가 났을 때 나오는 긴 영어 메시지(traceback)를 한 줄씩 읽는 법을 익힙니다.

이 장을 읽고 나면

  • 노트북의 셀, 실행 번호, 커널이 무엇인지 설명할 수 있다.
  • 셀을 화면 순서와 다르게 실행했을 때 변수의 값이 어떻게 바뀌는지 따라갈 수 있다.
  • "커널 재시작 후 모두 실행"이 왜 필요한지 설명할 수 있다.
  • traceback을 맨 아래 줄부터 읽어 오류의 종류, 위치, 원인을 찾을 수 있다.
  • SyntaxError, NameError, ZeroDivisionError, TypeError를 메시지만 보고 구분할 수 있다.

노트북: 코드와 결과를 한 장에

U05·2의 파일 실행은 결과가 터미널에 나왔다가 창을 닫으면 사라집니다. 대화형 실행은 한 줄씩 바로 볼 수 있지만 기록이 남지 않습니다. 노트북은 둘의 장점을 섞은 모양입니다. 코드를 칸(셀)에 나눠 적고, 칸마다 실행하면 결과가 그 칸 바로 아래에 붙어서 파일로 함께 저장됩니다.

정의 외우기

노트북(notebook): 코드 칸과 설명 글 칸, 그리고 실행 결과를 한 문서에 담는 형식. 가장 널리 쓰이는 것이 Jupyter 노트북이고 파일 이름 끝이 .ipynb입니다.
셀(cell): 노트북의 한 칸. 코드를 넣는 코드 셀과 글을 쓰는 마크다운(Markdown) 셀이 있습니다.
커널(kernel): 노트북 뒤에서 코드를 실제로 실행하는 Python. 실행한 셀의 변수를 모두 기억합니다.

노트북은 브라우저 안에서 여는 JupyterLab, 코드 편집기 VS Code, 구글이 제공하는 Colab 같은 여러 도구에서 열 수 있습니다. 모양은 도구마다 조금 다르지만 규칙은 같습니다. 셀을 고른 뒤 Shift+Enter를 누르면 그 셀이 실행되고 다음 셀로 넘어갑니다. 내 컴퓨터에 Jupyter를 설치하는 일은 패키지 설치를 다루는 PY09 이후로 미룹니다. 이 장에서는 생김새와 규칙만 봅니다.

셀 왼쪽의 [1], [2], [3]은 실행 번호입니다. 커널이 셀을 실행할 때마다 1씩 늘어나는 번호를 붙입니다. 화면에서 몇째 칸인지가 아니라, 몇째로 실행되었는지를 뜻합니다. 아직 실행하지 않은 셀은 [ ]처럼 비어 있습니다.

커널은 U05·1의 대화형 실행과 같은 일을 합니다. 셀을 실행할 때마다 그 코드를 하나의 긴 대화형 실행에 이어서 친 것처럼 처리하고, 만든 변수를 끝까지 기억합니다. 그래서 셀 [1]에서 만든 points를 셀 [2]에서 쓸 수 있습니다. 또 대화형 실행처럼, 셀의 마지막 줄이 값이면 print 없이도 그 값을 셀 아래에 보여 줍니다.

셀 실행 순서의 함정 이해하기

위 그림의 세 셀을 셀 A, 셀 B, 셀 C라고 부르겠습니다. 셀 B는 포인트를 100점 쌓는 코드입니다. 등호(=)는 "같다"가 아니라 "오른쪽을 계산해서 왼쪽 이름에 넣어라"라는 뜻입니다(PY01·1에서 자세히). 그래서 points = points + 100은 "지금 points에 100을 더한 값을 다시 points에 넣어라"입니다.

이 세 셀을 세 가지 방식으로 실행해 봅니다. 노트북 대신 같은 코드를 같은 순서로 Python에 실행해 결과를 확인했습니다.

풀이 예제

(가)를 실행한 뒤 이어서 셀 B, 셀 C를 한 번 더 실행했습니다. 커널이 기억하는 points를 한 단계씩 따라가 봅시다.

① [1] 셀 A: points = 0 → 커널의 points는 0
② [2] 셀 B: 0 + 100 = 100 → points는 100
③ [3] 셀 C: print(points) → 화면에 100
④ [4] 셀 B (다시): 지금 points가 100이므로 100 + 100 = 200 → points는 200
⑤ [5] 셀 C (다시): print(points) → 화면에 200

④가 핵심입니다. 셀 B는 "처음 값 0에서 시작"하지 않습니다. 그 순간 커널이 기억하는 값에서 시작합니다. 화면만 보면 "0을 넣고 100을 더했으니 100"이어야 할 것 같지만, 실제로 커널 안의 값은 200입니다.

(다)의 커널 재시작(restart)은 커널을 껐다 켜서 기억을 모두 지우는 일입니다. 화면의 셀과 지난 출력은 그대로 남을 수 있지만, 커널 안의 points는 사라집니다. 이 상태에서 셀 A를 건너뛰고 셀 B부터 실행하면, B의 오른쪽 points + 100을 계산하려는 순간 points라는 이름이 아직 없어서 NameError가 납니다. 같은 코드를 Python에 그 순서로 실행한 실제 마지막 줄은 이렇습니다.

실제 오류의 마지막 줄 (파일로 실행한 결과)

NameError: name 'points' is not defined. Did you mean: 'print'?

뒤에 붙은 Did you mean: 'print'?("print를 말한 건가요?")는 Python이 철자가 비슷한 이름을 골라 내놓는 추측입니다. 여기서는 엉뚱한 추측입니다. 진짜 원인은 철자가 아니라 셀 A를 실행하지 않은 것입니다. 추측은 참고만 합니다.

지운 셀의 유령

더 알아채기 어려운 함정도 있습니다. 셀 A를 실행한 뒤에 셀 A를 지워 버리면, 화면에는 points = 0이 어디에도 없는데 커널은 여전히 points를 기억합니다. 그래서 그날은 노트북이 잘 돌아갑니다. 다음 날 노트북을 다시 열어 처음부터 실행하면 그제야 NameError가 납니다. 다른 사람에게 노트북을 보내도 마찬가지입니다.

흔한 실수

"화면에 보이는 대로 실행되었다"고 믿기. 노트북의 결과는 화면 순서가 아니라 실행 순서를 따릅니다. 출력이 이상하면 먼저 실행 번호를 봅니다. 위에서 아래로 1, 2, 3 … 으로 늘어나지 않고 건너뛰거나(1, 4, 5) 거꾸로 되어 있으면, 셀을 다른 순서로 실행했거나 여러 번 실행한 것입니다.

외우는 법: 끝내기 전 점검

노트북을 저장하거나 남에게 보내기 전에 "커널 재시작 후 모든 셀 실행"을 한 번 합니다. JupyterLab에서는 Kernel 메뉴의 "Restart Kernel and Run All Cells…"입니다. Colab에서는 런타임(Runtime) 메뉴에 같은 기능이 있는데, 판에 따라 "Restart and run all", "Restart session and run all"처럼 이름이 바뀌어 왔고 한국어 화면의 이름도 다르니 메뉴에서 "다시 시작"과 "모두 실행"이 함께 든 항목을 찾으세요. 기억을 비우고 위에서 아래로 한 번에 실행해서 오류 없이 같은 결과가 나오면, 그 노트북은 화면 순서만으로 다시 만들 수 있는 노트북입니다.

왜 그럴까?

순서가 어긋나면 이렇게 위험한데, 노트북은 왜 셀을 아무 순서로나 실행하게 해 둘까요?

모범 답 보기

데이터를 살펴볼 때는 앞에서 불러온 데이터를 그대로 둔 채, 그래프를 그리는 셀 하나만 고쳐서 여러 번 다시 실행하는 일이 많습니다. 매번 처음부터 다시 실행하면 데이터를 불러오는 데만 오래 걸릴 수 있습니다. 그래서 커널이 기억을 유지하고 셀을 골라 실행할 수 있게 한 것입니다. 편리함의 대가로 순서를 관리하는 책임이 사용자에게 넘어온 셈이고, 그것을 마지막에 "재시작 후 모두 실행"으로 점검합니다.

오류 메시지 읽기: traceback

코드가 실행 중에 더 나아갈 수 없는 일을 만나면 Python은 실행을 멈추고 긴 메시지를 남깁니다. 모양이 정해져 있으므로 읽는 순서를 알면 빠르게 원인에 닿습니다. 점수 합계를 사람 수로 나눠 평균을 내는 파일을 예로 듭니다.

코드 (average.py, 왼쪽 숫자는 줄 번호이고 파일에는 없다)

1  total = 240
2  count = 0
3  average = total / count
4  print("평균:", average)

실행 결과 (경로만 이 책의 예시 폴더로 바꿈)

PS C:\Users\me\Documents\python-study> python average.py
Traceback (most recent call last):
  File "C:\Users\me\Documents\python-study\average.py", line 3, in <module>
    average = total / count
              ~~~~~~^~~~~~~
ZeroDivisionError: division by zero
용어 실행 도중에 일어나 프로그램을 멈추게 하는 오류를 예외(exception)라고 합니다. "예외가 발생했다(raise)"는 "이 오류가 났다"와 같은 말입니다.

정의

traceback(트레이스백): 예외가 났을 때 Python이 남기는 기록. "어디서 출발해 어디를 거쳐 어디에서 멈췄는지"를 차례로 적고, 맨 아래 줄에 오류의 종류와 설명을 적습니다. trace(자취) + back(거슬러 올라감)이라는 뜻입니다.

네 단계로 읽기 외우기

  1. 맨 아래 줄부터. ZeroDivisionError: division by zero. 콜론 앞이 오류 종류(ZeroDivisionError: 0으로 나누기 오류), 뒤가 설명(0으로 나눴다)입니다. 영어가 낯설면 종류 이름만 기억해도 반은 푼 것입니다.
  2. 바로 위 File 줄. average.py 파일의 line 3(셋째 줄)에서 멈췄습니다. in <module>은 "파일의 맨 바깥 부분에서"라는 뜻으로, 지금은 신경 쓰지 않아도 됩니다.
  3. 코드 줄과 표시. ~~~~~~^~~~~~~는 total / count 부분을 밑줄 긋고, ^로 나누기 기호를 가리킵니다. "이 나눗셈에서 났다"는 뜻입니다.
  4. 원인 거슬러 찾기. 셋째 줄 자체는 평범한 나눗셈입니다. 문제는 재료인 count가 0이라는 것이고, 0이 된 곳은 둘째 줄입니다. 고칠 곳은 둘째 줄입니다.

넷째 단계가 중요합니다. traceback이 알려 주는 줄은 오류가 드러난 곳이지, 언제나 잘못을 저지른 곳은 아닙니다. 둘째 줄 count = 0은 그 자체로는 잘못이 없어서 Python이 멈추지 않았고, 셋째 줄에 가서야 문제가 드러났습니다. 넷째 줄 print는 실행되지 않았습니다. 예외가 나면 그 자리에서 멈추기 때문입니다.

이름을 잘못 쳤을 때: NameError

평균 계산에서 total을 totl로 잘못 친 실제 결과입니다.

코드 (typo.py)

1  total = 240
2  count = 3
3  print("평균:", totl / count)

실행 결과

Traceback (most recent call last):
  File "C:\Users\me\Documents\python-study\typo.py", line 3, in <module>
    print("평균:", totl / count)
                   ^^^^
NameError: name 'totl' is not defined. Did you mean: 'total'?

맨 아래 줄: NameError, "totl이라는 이름은 정해진 적이 없다". File 줄: 셋째 줄. 표시 ^^^^: totl. 이번에는 Python의 추측 Did you mean: 'total'?이 정확히 맞았습니다. 앞의 노트북 예처럼 추측이 빗나갈 때도 있으니, 추측을 따르기 전에 "정말 철자 문제인가, 아니면 그 이름을 만드는 줄을 실행하지 않았나"를 먼저 따집니다.

여러 곳을 거쳐 온 오류

코드가 다른 곳에 있는 코드를 불러 쓰면 traceback에 File 줄이 여러 개 생깁니다. 아래 파일의 def는 여러 줄을 묶어 이름(average)을 붙여 두는 문법인데, 자세한 것은 PY05 "함수와 분해"에서 배웁니다. 지금은 "5번 줄이 1~2번 줄을 불러 쓴다"만 알면 됩니다.

코드 (twoframe.py)

1  def average(total, count):
2      return total / count
3
4  print("시작")
5  result = average(240, 0)
6  print("평균:", result)

실행 결과

시작
Traceback (most recent call last):
  File "C:\Users\me\Documents\python-study\twoframe.py", line 5, in <module>
    result = average(240, 0)
  File "C:\Users\me\Documents\python-study\twoframe.py", line 2, in average
    return total / count
           ~~~~~~^~~~~~~
ZeroDivisionError: division by zero

머리줄의 most recent call last는 "가장 최근에 부른 것이 마지막에"라는 뜻입니다. 위의 File 줄(5번 줄)은 출발한 곳, 아래 File 줄(2번 줄)은 거기서 불려 들어가 실제로 멈춘 곳입니다. 그래서 여기서도 아래에서 위로 읽습니다. 맨 아래 줄로 종류를 알고, 바로 위 File 줄로 멈춘 자리를 찾고, 더 위 File 줄로 "누가 0을 넘겼나"를 거슬러 갑니다. 0을 넘긴 것은 5번 줄의 average(240, 0)입니다. 그리고 첫 줄 시작은 출력되었습니다. 4번 줄까지는 잘 실행되었다는 증거입니다.

실행조차 안 되는 오류: SyntaxError

괄호를 닫지 않은 파일을 실행한 실제 결과입니다.

코드 (syntax.py)

1  print("안녕하세요"
2  print(2 + 3)

실행 결과

  File "C:\Users\me\Documents\python-study\syntax.py", line 1
    print("안녕하세요"
         ^
SyntaxError: '(' was never closed

두 가지가 다릅니다. 첫째, 맨 위에 Traceback (most recent call last): 머리줄이 없습니다. 둘째, 둘째 줄의 print(2 + 3)은 문법이 멀쩡한데도 5가 출력되지 않았습니다. U05·1의 "더 알아보기"에서 본 것처럼 Python은 파일 전체를 먼저 읽어 문법을 확인하고, 문법이 틀리면 한 줄도 실행하지 않기 때문입니다. 표시 ^는 닫히지 않은 여는 괄호 (를 가리킵니다. 고치는 법: 첫 줄 끝에 )를 붙입니다.

맨 아래 줄의 종류뜻이 책의 실제 예먼저 볼 곳
SyntaxError문법 오류. 실행 전에 걸린다'(' was never closed괄호·따옴표 짝, ^ 자리와 그 앞 줄
NameError정해진 적 없는 이름을 썼다name 'totl' is not defined철자, 그 이름을 만드는 줄(셀)을 실행했는가
ZeroDivisionError0으로 나눴다division by zero나누는 수가 0이 된 곳
TypeError그 종류의 값끼리는 할 수 없는 계산unsupported operand type(s) for +: 'int' and 'str' (숫자 + 글자)값의 종류(PY01·2, PY02)

흔한 실수

traceback을 위에서부터 읽다가 지치기. 첫 줄 Traceback (most recent call last):은 매번 똑같은 머리줄이라 정보가 없습니다. 눈을 바로 맨 아래 줄로 내리세요. 그리고 노트북의 traceback은 색이 칠해지거나 화살표(---->)로 줄을 가리키는 등 모양이 조금 다르지만, "맨 아래 줄이 종류와 설명"이라는 규칙은 같습니다.

다음에 이어지는 곳

  • PY01: 이제 코드를 실행할 자리(대화형 실행, 파일, 노트북)와 오류를 읽는 법을 알았으니 첫 프로그램을 씁니다.
  • PY02: 흔한 문법 오류와 TypeError를 값의 종류와 함께 더 자세히 봅니다.
  • PY08 디버깅과 검증: 오류를 일부러 다시 일으켜 원인을 좁히는 법, traceback을 이용한 디버깅을 다룹니다.
  • PY09 패키지와 환경: Jupyter 같은 도구를 설치하고, 다른 컴퓨터에서도 같은 결과가 나오게 환경을 기록합니다.

묻는 것답
노트북코드 셀·글 셀·결과를 한 문서에 담는 형식. Jupyter, 파일은 .ipynb (노트북)
커널셀을 실제로 실행하고 변수를 기억하는 Python
실행 번호 [n]화면 순서가 아니라 실행된 순서
순서 함정같은 셀을 다시 실행하면 지금 기억하는 값에서 이어진다 (100 → 200)
점검커널 재시작 후 모두 실행
traceback 읽는 순서맨 아래 줄(종류: 설명) → File 줄(파일·줄 번호) → 코드와 ^ → 원인 거슬러 찾기
여러 File 줄위가 출발한 곳, 아래가 실제로 멈춘 곳 (most recent call last)
SyntaxError머리줄 없음, 한 줄도 실행되지 않음

한 줄 정리

노트북의 결과는 화면 순서가 아니라 커널이 실행한 순서를 따르므로 재시작 후 모두 실행으로 점검하고, 오류가 나면 traceback의 맨 아래 줄부터 거꾸로 읽는다.
