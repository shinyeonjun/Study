경과시간·CPU 시간·최고 메모리 측정하기

같은 계산이라도 데이터를 기다리는 시간과 CPU가 사용된 시간은 다를 수 있습니다. 어느 범위를 재었는지 밝히고 결과 검산과 성능 숫자를 구분합니다.

이 장을 읽고 나면

  • 경과시간, CPU 시간, GPU 완료 시각을 구분한다.
  • 최고 메모리의 측정 범위와 도구를 설명한다.
  • 입력·준비 실행·반복·장치가 같은지 확인한다.

어떤 작업의 시작부터 끝까지?

파일 읽기, 변환, 계산, 출력 저장에서 어디까지 시간이 필요한지 정합니다. 사용자 입장에서 전체 결과가 준비되는 시간이면 모두 포함합니다. 한 알고리즘의 연산만 보고 싶으면 같은 준비가 끝난 상태에서 시작을 정합니다.

perf_counter()로 두 시각의 차이를 재면 경과시간을 얻습니다. process_time()의 차이는 현재 프로세스에서 사용한 사용자와 시스템 CPU 시간을 합친 값입니다. 잠들거나 응답을 기다리는 경과시간은 그 CPU 시간에 들어가지 않습니다. 여러 코어를 사용하는 경우 전체 CPU 시간과 경과시간을 같은 값으로 읽지 않습니다.

장치의 계산과 데이터 이동, 메모리 최고점

별도 메모리를 가진 GPU에 입력을 옮기고 결과를 가져온다면, 연산만의 시간과 이동까지 포함한 시간을 나눕니다. GPU 실행 요청이 빨리 반환되더라도 장치가 계산을 마칠 때까지 기다리는 동기화가 필요한 측정도 있습니다. 어떤 런타임·장치에서 어떤 범위를 쟀는지 기록합니다.

tracemalloc은 Python이 추적하는 할당을 확인합니다. 프로세스 전체의 거주 메모리나 GPU 메모리 전체와 같은 수치가 아닙니다. 최고량은 추적을 시작한 시각과 입력 크기, 어떤 구간에서 최대를 기록했는지와 함께 봅니다.

값과 시간 측정을 섞지 않고 실행

예제는 저장소의 최상위 폴더에서 실행합니다. 실습에 사용하는 30개 연도의 CSV와 출처와 변환 기록을 함께 확인할 수 있습니다.

실행 예제

import csv
from decimal import Decimal
from pathlib import Path

source = Path("learn/labs/mauna-loa/annual_co2.csv")
with source.open(encoding="utf-8", newline="") as stream:
    records = list(csv.DictReader(stream))
series = {int(row["year"]): Decimal(row["mean_ppm"]) for row in records}
assert len(records) == len(series) == 30 and sorted(series) == list(range(1990, 2020))
from statistics import median
from time import perf_counter, process_time
import tracemalloc

wall_start = perf_counter()
cpu_start = process_time()
actual_change = series[2019] - series[1990]
cpu_seconds = process_time() - cpu_start
wall_seconds = perf_counter() - wall_start
print("result ppm:", actual_change)
print("measured nonnegative wall / CPU:", wall_seconds >= 0, cpu_seconds >= 0)

tracemalloc.start()
buffer = bytearray(1024)
_, peak = tracemalloc.get_traced_memory()
print("tracked peak includes payload:", peak >= len(buffer))
tracemalloc.stop()

example_ms = [20, 22, 51]
print("illustrative median ms:", median(example_ms))

실행 결과

result ppm: 57.20
measured nonnegative wall / CPU: True True
tracked peak includes payload: True
illustrative median ms: 22

이 실측 구간은 파일을 읽은 뒤 차이 한 번을 구하는 범위입니다. 실제 측정 숫자는 환경에 따라 다르므로 출력은 결과값과 측정 조건의 간단한 검사만 고정합니다. 마지막 세 시간값은 중앙값 계산을 보여 주는 모의 로그입니다.

실측값을 비교할 수 있게 남기기

같은 입력, 장치, 동시 작업, 캐시와 준비 실행 조건에서 여러 번 측정할 수 있습니다. 첫 실행이 유독 느리면 초기화나 데이터 로드를 별도로 살핍니다. 중앙값을 보고해도 최대 지연과 실패를 함께 남깁니다. 프로파일러를 쓰면 느린 구간을 찾을 수 있지만 관찰 도구의 비용은 성능 기록에서 구분합니다.
