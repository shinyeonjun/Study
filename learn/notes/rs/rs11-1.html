연구 방법 · 선행연구

RS11·1

검색과 포함 기준을 다시 실행할 수 있게 기록하기

검색창에서 먼저 보인 논문을 읽는 일에서 출발해, 어떤 연구가 자료에 들어갔는지 다른 사람도 다시 확인할 수 있는 수집 절차를 만듭니다.

이 장을 읽고 나면

  • 질문을 검색어와 포함 조건으로 각각 옮길 수 있다.
  • 서지 레코드, 문서 판본, 실험 단위를 구분해 중복을 정리할 수 있다.
  • 단계별 제외 이유를 공개하고 남은 연구 수를 손과 코드로 검산할 수 있다.

찾으려는 질문과 채택 조건부터 쓴다

연구 질문을 “작은 수의 반복 훈련을 사용한 심층 강화학습 비교에서, 난수 시드에 따른 변동은 어떻게 보고되는가?”로 좁힙니다. “강화학습 논문 모으기”만 써 두면 방법론 논문, 단일 시드 실험, 탐색 알고리즘 설명 중 무엇을 골라야 할지 나중에 알 수 없습니다. 질문은 알고 싶은 내용이고, 포함 기준은 실제 자료를 어떤 규칙으로 뽑을지 정합니다.

연습에서는 2020년 이후에 공개된 연구 중 원 논문이 독립 훈련 실행을 두 번 이상 했고, 실행 수나 시드 단위를 확인할 수 있는 경우만 포함한다고 가정합니다. 이미 있는 연구를 정리한 글은 후보를 더 찾기 위한 출발점으로 쓰되, 같은 원 실험을 다시 한 건으로 세지 않습니다. 원문을 얻을 수 없어 조건을 판단할 수 없는 경우는 ‘부적합’과 다른 상태로 둡니다.

검색 기록의 네 항목

검색한 데이터베이스 이름, 조회한 날짜와 시간대, 실행한 검색식과 필터, 결과를 옮긴 파일과 원본 건수를 남깁니다. 같은 개념이라도 데이터베이스마다 제목·초록 필드 지정과 따옴표 해석이 다릅니다. 어떤 연구를 포함할지는 화면 순위가 아니라 사전에 정한 기준으로 판단합니다.

검색어는 동의어를 넓히고 개념 묶음을 좁힌다

개념 하나에 여러 표현이 있을 수 있습니다. "random seed" OR "number of runs" OR "training seed"는 실행 반복 표현을 넓힙니다. 이 괄호를 ("deep reinforcement learning" OR "deep RL")과 AND로 잇습니다. 실제 검색을 하면 검색식과 조회 필드 그대로를 보관합니다. 제목이 다른 넓은 분야의 표본을 놓칠 수 있으니 기준 논문 몇 편이 결과에 있는지 먼저 보는 점검도 가능합니다. 이 점검을 했다고 검색에서 모든 관련 논문을 찾았다고 결론 내릴 수는 없습니다.

검색어를 고쳤다면 전후의 버전과 바꾼 이유를 기록합니다. 날짜에 따라 새 항목이 색인될 수 있으므로 재실행 값이 달라도 당시 저장본으로 기존 결론을 검산할 수 있게 합니다. 참조 목록과 인용후속 검색을 이용할 때도 어느 논문에서 출발해 어떤 방식으로 붙였는지 따로 기록합니다.

버전이 여럿인 문서를 한 연구로 묶는다

서지 레코드는 어떤 검색 서비스가 보여 준 항목 한 줄입니다. 문서는 arXiv 원고나 학회에 실린 최종판처럼 내용과 식별자를 가진 산출물입니다. 원 연구의 실험을 추출할 때 같은 작업의 원고와 최종판을 서로 독립인 연구 두 건으로 세면 증거가 중복됩니다. 제목과 저자, DOI와 버전 연결 정보, 본문의 실험 내용을 확인하고, 묶은 이유를 기록합니다. DOI가 다르다는 이유만으로 서로 다른 원 실험이라고 단정하기 어렵습니다. 데이터가 겹치는 후속 연구는 문서는 다르더라도 분석 단위에서 추가 관계를 남깁니다.

아래 가상 자료에는 검색 기록 7개와 확인된 연구 키 6개가 있습니다. W01은 공개 초안과 최종판이 같은 연구라는 것을 사람이 확인했습니다. 2020년 이후만 두고, 원 실험인지 확인한 뒤, 실행 수가 두 번 이상인지 판정합니다. 각 단계에서 빠지는 이유를 한 번씩만 셉니다.

단계남은 수줄어든 이유
두 자료원 원본 레코드7같은 연구의 판본도 포함
연구 키로 버전 정리6W01 초안과 최종판을 연결
2020년 이후5연도 기준 1건
원 실험 논문4정리 글 1건
반복 실행 수 확인3독립 실행 1회인 논문 1건

가상 검색 장부를 코드로 검산한다

records = [
    ("A", "W01", 1, 2021, "experiment", 4),
    ("B", "W01", 2, 2023, "experiment", 5),
    ("A", "W02", 1, 2020, "experiment", 3),
    ("A", "W03", 1, 2023, "review", None),
    ("B", "W04", 1, 2024, "experiment", 1),
    ("B", "W05", 1, 2019, "experiment", 5),
    ("A", "W06", 1, 2022, "experiment", 4),
]
canonical = {}
for row in records:
    _, key, version, *_ = row
    if key not in canonical or canonical[key][2] < version:
        canonical[key] = row

recent = [row for row in canonical.values() if row[3] >= 2020]
originals = [row for row in recent if row[4] == "experiment"]
eligible = [row[1] for row in originals if row[5] is not None and row[5] >= 2]
assert eligible == ["W01", "W02", "W06"]
print("각 단계 건수:", [len(data) for data in (records, canonical, recent, originals, eligible)])
print("포함:", ", ".join(eligible))

실행 결과

각 단계 건수: [7, 6, 5, 4, 3]
포함: W01, W02, W06

코드는 확인된 키로 판본을 묶고 조건을 적용합니다. 제목만 비교해서 자동으로 같은 연구라고 결정하는 코드가 아닙니다. 새 학회판에서 표가 달라졌다면 어느 판본의 결과를 인용했는지 장부에 남깁니다. 아래 표본에서는 판단할 수 없는 연구가 없었지만, 실제 기록에는 ‘원문 미확보’, ‘실행 수 미기재’처럼 제외 또는 보류 이유를 구분해 둡니다.

같은 장부를 넘겨받은 사람이 검산할 수 있는가

연구 장부를 전달받은 사람에게 원본 건수에서 하나씩 뺀 수와 최종 포함 키가 일치하는지 확인해 달라고 할 수 있습니다. 경계에 걸린 문서에서는 판단 근거를 그 문서의 절·표·페이지에 연결합니다. PRISMA-S는 체계적 문헌고찰에서 검색 내용을 보고할 때 참고할 수 있는 지침입니다. 이 장의 연습은 그 기록 원리를 빌린 가상 자료 수집이며, 특정 분야의 체계적 고찰을 완료했다는 주장에는 더 넓은 방법과 검증이 필요합니다.
