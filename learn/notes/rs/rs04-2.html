RS04·2

난수 시드와 작은 재현 검사

같은 시드로 난수열을 다시 만들고 다른 시드는 어떤 용도로 쓰는지 구분합니다. 결과가 조금 달라졌을 때 비교 기준을 실행 전에 정합니다.

이 장을 읽고 나면

  • 시드, 생성기, 호출 순서의 역할을 말한다.
  • 하나의 실행 재현과 여러 반복으로 산포를 확인하는 일을 구별한다.
  • 작은 검산과 허용 오차, 실행 기록을 재현 절차에 넣는다.

난수표를 재현할 조건

시드는 의사난수 생성기의 시작 상태를 정하는 입력입니다. 같은 생성기와 초기화 방식에서 같은 시드와 호출 순서로 시작하면 난수열을 재현할 수 있습니다. 첫 번째 난수 호출을 추가하면 뒤에서 쓰는 값들의 순서가 바뀔 수 있습니다. 라이브러리와 호출 종류에 따라 버전 때문에 생기는 차이도 확인합니다.

분할, 가중치 초기화, 데이터 순서 등 여러 곳에서 난수를 쓸 수 있습니다. 환경·장치에 따라 병렬 연산의 순서가 달라질 수도 있습니다. 시드 하나를 적는 것으로 모든 장치에서 모든 비트의 재현이 보장되지는 않습니다.

다시 계산하기와 변동을 보기

실패한 실행 하나를 다시 보려면 같은 입력과 설정·생성기·시드를 사용합니다. 시드가 바뀔 때 점수의 산포를 살피려면 미리 정한 여러 시드에서 다시 학습합니다. 그 결과 중 좋은 시드만 골라 기록하면 계획한 반복의 변동을 대표하기 어렵습니다.

문자열이나 정수 개수 등은 같아야 하는지 미리 정하고, 부동소수점 결과는 목적에 맞는 자릿수나 절대·상대 오차의 기준을 정합니다. 예로 일치해야 하는 입력 행 수와 소수 출력의 비교 기준은 다를 수 있습니다. 오류와 제외도 실행 기록을 남깁니다.

난수 두 번과 정해진 값의 손계산

실행 예제

from random import Random

def draws(seed):
    generator = Random(seed)
    return [f"{generator.random():.4f}" for _ in range(3)]

for label, seed in (("A", 7), ("A again", 7), ("B", 11)):
    print(label, "seed", seed, ":", " ".join(draws(seed)))

truth = [2, 4, 6]
prediction = [3, 3, 3]
errors = [abs(y - p) for y, p in zip(truth, prediction, strict=True)]
assert errors == [1, 1, 3]
print("errors:", errors, "sum:", sum(errors))

실행 결과

A seed 7 : 0.3238 0.1508 0.6509
A again seed 7 : 0.3238 0.1508 0.6509
B seed 11 : 0.4524 0.5598 0.9242
errors: [1, 1, 3] sum: 5

같은 시드 두 줄을 얻을 때 생성기를 다시 초기화했습니다. 하나의 생성기에서 이어 뽑으면 상태가 진행되므로 처음 세 값과 달라집니다. 마지막 줄의 작은 대조는 평균 절대오차의 분자 5와 분모 3을 손으로 확인할 수 있게 합니다.

실제 반복의 조건 남기기

설정 묶음마다 같은 자료와 평가 절차를 사용했는지 기록합니다. 여러 시드 결과를 각각 적고 어떤 실행이 중단됐는지도 남깁니다. 정해진 수치와 다르면 먼저 코드와 입력 버전·설정·환경을 대조합니다. 서로 다른 난수 순서를 비교할 목적이었다면 그 분포의 변동도 보고합니다.

왜 그럴까?

결정적인 분석 예제에서 시드를 적지 않았는데도 다시 실행할 수 있는 이유는?

모범 답 보기

계산에서 난수를 사용하지 않았으므로 시드가 계산을 바꾸지 않습니다. 그 경우 난수 없음으로 기록할 수 있습니다.
