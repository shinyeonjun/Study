AI03·3

사실을 바꾸는 행동으로 계획 만들기

받은 자료를 요약해 보낸다. 현재 사실, 행동을 할 수 있는 조건, 행동 뒤에 달라지는 사실을 구분한다.

이 장을 읽고 나면

  • 상태를 참인 사실의 집합으로 표시한다.
  • 행동의 전제, 추가 목록, 삭제 목록으로 새 상태를 구한다.
  • 목표가 참이 되는 행동 순서를 탐색한다.

계획은 상태를 바꾸는 행동 순서다

첫 상태에서 받은 편지함에 자료가 있다. 할 일은 자료를 꺼내고, 요약하고, 보내는 것이다. 자료를 보관하는 행동도 가능하다고 하자. 보관함에서 자료를 꺼내는 행동은 이 모형의 행동 목록에 없다. 일을 진행하기 전에 현재 어떤 사실이 참인지, 각각의 행동이 가능해지려면 무엇이 참이어야 하는지 적는다.

모형의 사실 이름은 inbox(자료가 받은 편지함에 있음), raw(작업 중인 원본이 있음), summary(요약이 있음), archived(원본을 보관함), sent(보냄)이다. 시작 상태는 {inbox}다. 목표 조건은 sent가 참인 상태라는 뜻의 {sent}다. 이 유한 합성 모형에서는 현재 참인 사실만 집합에 넣고, 빠진 사실은 거짓으로 해석한다. 실제 자료의 ‘아직 모름’까지 거짓으로 취급하려면 별도 가정이 필요하다.

행동전제추가삭제
receive (꺼내기)inboxrawinbox
process (요약)rawsummaryraw
send (보내기)summarysent없음
store (보관)rawarchivedraw

전제가 충족되면 사실을 교체한다

행동의 전제 집합이 현재 상태의 부분집합일 때 그 행동을 할 수 있다. 다음 상태는 (현재 상태 − 삭제 집합) ∪ 추가 집합이다. 두 효과 목록에 없는 사실은 유지한다. 여기서는 전제와 목표를 긍정 사실의 집합으로 나타내는 간단한 STRIPS식 표현을 사용한다. 행동은 성공 여부가 확률로 갈리지 않는다고 가정한다.

상태 {raw}에서 요약과 보관이 모두 가능하다. 요약하면 {summary}, 보관하면 {archived}가 된다. 보관은 현재 가능한 행동이지만 목표를 이루는 계획의 첫 부분으로는 적합하지 않다. 계획 문제를 풀려면 현재 행동의 가능성과 이후 목표까지의 거리를 함께 본다.

같은 상태를 다시 넣지 않는 너비 우선 탐색

모든 행동의 비용을 한 번으로 센다. AI02의 BFS로 가장 짧은 행동 순서를 찾을 수 있다. 상태를 변경 불가능한 frozenset으로 만들면 seen에 넣고 중복 여부를 확인할 수 있다. 이 모형은 현재 상태가 같으면 이후 가능한 행동과 목표 판정도 같다.

from collections import deque

actions = {
    "receive": ({"inbox"}, {"raw"}, {"inbox"}),
    "process": ({"raw"}, {"summary"}, {"raw"}),
    "send": ({"summary"}, {"sent"}, set()),
    "store": ({"raw"}, {"archived"}, {"raw"}),
}
start = frozenset({"inbox"})
goal = {"sent"}
queue = deque([(start, [])])
seen = {start}
while queue:
    state, path = queue.popleft()
    if goal <= state:
        print(" -> ".join(path))
        print("actions:", len(path))
        print("final facts:", ", ".join(sorted(state)))
        break
    for name, (before, add, remove) in actions.items():
        if before <= state:
            child = (state - remove) | add
            if child not in seen:
                seen.add(child)
                queue.append((child, path + [name]))
else:
    print("no plan")
receive -> process -> send
actions: 3
final facts: sent, summary

행동 비용이 달라지면 UCS로 최소 비용 계획을 찾을 수 있다. 실행 후 상황을 관측해 그때마다 다음 행동을 바꿔야 하는 문제에서는 하나의 고정 목록 대신 관측에 따른 선택 규칙이 필요하다. AI06의 순차 결정에서 그 차이를 계산한다.
