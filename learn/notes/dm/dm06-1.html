DM06·1

입력이 커질 때 증가 속도와 큰 O 표기 읽기

같은 입력에서 빠른 코드와 입력이 커져도 비용이 천천히 늘어나는 코드는 다를 수 있습니다. 비용을 직접 세고, 어느 구간부터 한 가지 성장률이 상한을 주는지 확인합니다.

이 장을 읽고 나면

  • 로그·다항·지수의 성장 차이를 작은 표에서 비교한다.
  • 큰 O의 상수와 시작 지점을 실제 식으로 찾는다.
  • O와 Θ, 수학적 비용과 실제 실행 시간을 구분한다.

입력 크기를 두 배로 하면 비교 횟수도 두 배가 될까

목록 길이를 n이라고 합시다. 한 값을 보는 횟수, 모든 항목을 한 번씩 보는 횟수, 순서를 구분해 가능한 모든 쌍을 보는 횟수는 각각 1, n, n²입니다. 매번 후보를 반으로 줄여 하나가 될 때까지 반복하면 n이 2의 거듭제곱일 때 log₂ n번 줄입니다. 모든 부분집합을 출력하려면 원소마다 포함과 제외 두 가지를 고르므로 출력 수만 2ⁿ입니다.

큰 O에 필요한 상수와 시작점

음이 아닌 비용 T(n)에 대해 T(n)=O(g(n))은 양의 상수 c와 시작 크기 n₀를 골라 모든 n≥n₀에 대해 T(n)≤c·g(n)을 만족시킬 수 있다는 뜻입니다. c와 n₀는 입력에 따라 바꾸지 않습니다. T(n)=3n²+2n+7에서 n≥1이면 n≤n²이고 1≤n²입니다. 따라서 T(n)≤(3+2+7)n²=12n²이고 c=12, n₀=1을 쓸 수 있습니다.

n≥1에서 3n²≤T(n)도 성립합니다. 한 함수의 상수배로 위와 아래를 둘 다 제한하면 Θ로 적습니다. 따라서 이 비용은 Θ(n²)입니다. O는 위쪽만 제한하므로 O(n³)이라는 말 역시 참입니다. 어느 함수와 같은 증가율인지 밝힐 때는 Θ가 더 정확합니다. 아래쪽만 제한하는 표기는 Ω(빅 오메가)입니다. T(n)=Ω(g(n))은 양의 상수 c와 n₀가 있어 모든 n≥n₀에서 T(n)≥c·g(n)이라는 뜻이고, Θ는 O와 Ω가 함께 성립하는 경우입니다. 로그의 밑을 바꾸는 것은 상수배(log₂ n = log₁₀ n ÷ log₁₀ 2)이므로 O·Θ 안에서는 밑을 생략해 O(log n)으로 씁니다.

from math import log2

for n in (4, 8, 16):
    log_steps = int(log2(n))
    print(n, log_steps, n*log_steps, n*n, 2**n)
for n in range(1, 101):
    cost = 3*n*n + 2*n + 7
    assert 3*n*n <= cost <= 12*n*n
print("1~100의 경계 확인")

프로그램 시간은 언어와 자료구조, 메모리, 파일 접근의 영향을 받습니다. 증가율을 계산할 때는 먼저 n이 무엇이고 어떤 연산을 세는지 정합니다. 예를 들어 목록 원소가 지나치게 큰 정수라면 두 수를 비교하는 비용도 자리 수에 따라 달라질 수 있습니다. 실제로 짧게 재 보는 일과 충분히 큰 입력의 함수를 제한하는 일은 각각 다른 정보를 줍니다.

한 줄 정리

입력 크기와 셀 연산을 정한 뒤, 정해 둔 상수배가 어느 크기부터 계속 상한인지 확인합니다.
