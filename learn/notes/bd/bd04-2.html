모형 평가 결과를 운영 결정으로 바꾸기

후보 알림이 비용을 줄였는지와 담당자가 처리할 수 있는지를 같은 시험 기록에서 확인합니다. 결과 표를 실제 도입 계획과 연결합니다.

이 장을 읽고 나면

  • 평가 표에서 예상 손실과 검토량을 계산한다.
  • 성능 비교와 사용 가능 조건을 함께 판단한다.
  • 파일럿 이후 확인할 지표와 이전 절차로 돌아갈 기준을 적는다.

같은 시험 주문에 두 규칙을 적용한다

확정 라벨이 있는 주문 200건을 같은 하루 조건의 연습 표로 둡니다. 실제 지연 20건에 대해 현재 규칙과 후보 규칙의 판정을 비교합니다. 미탐은 4점, 오탐은 1점이고, 업무팀은 주문을 최대 20건까지 추가 검토할 수 있습니다. 예측이 양성인 건을 모두 검토한다고 둡니다.

TP·FN·FP·TN 실제 지연을 지연으로 맞힘(TP, 참양성), 실제 지연을 놓침(FN, 거짓음성=미탐), 정상을 지연으로 알림(FP, 거짓양성=오탐), 정상을 정상으로 맞힘(TN, 참음성).
규칙TPFNFPTN
현재10105175
후보16410170

현재 규칙의 예상 비용은 4×10+5=45점이고 검토 요청은 10+5=15건입니다. 후보는 4×4+10=26점으로 비용이 19점 줄지만, 요청이 16+10=26건이어서 처리 한도보다 6건 많습니다. 오탐 비용에 담당 인원의 추가 업무를 포함하더라도, 한도를 넘기는 경우는 별도의 제약으로 처리합니다.

익숙한 지표로 바꾸면 현재 규칙은 재현율 10/20=0.50, 정밀도 10/15≈0.67이고, 후보는 재현율 16/20=0.80, 정밀도 16/26≈0.62입니다. 재현율은 오르고 정밀도는 조금 내려갔습니다. 어느 지표를 앞세울지는 미탐과 오탐의 비용 비율이 정하며, 이 사례에서는 비용(4:1)과 검토 한도를 직접 계산했습니다.

rules = {"현재": (10, 10, 5), "후보": (16, 4, 10)}
for name, (tp, fn, fp) in rules.items():
    cost = 4*fn + fp
    reviews = tp + fp
    print(name, "비용", cost, "검토", reviews, "한도 충족", reviews <= 20)

실행 결과

현재 비용 45 검토 15 한도 충족 True
후보 비용 26 검토 26 한도 충족 False

제약 안에서 다시 시도하고 별도로 평가한다

후보의 임계값을 높이거나 매일 상위 20건까지 확인하는 규칙을 검토할 수 있습니다. 두 규칙은 같은 알림 건수를 따르지 않을 수 있습니다. 임계값은 점수 기준이고 상위 20건 규칙은 당일 순위와 물량을 기준으로 삼습니다. 선택 규칙을 바꾸면 미탐 비용도 변할 수 있으므로 한도만 확인하고 결과를 이전과 동일하다고 볼 수 없습니다.

팀이 나중에 판단을 다시 내릴 수 있도록 적는다

보고는 예측 시점, 비용의 산정 근거, 사용한 기간과 지연 주문 분모, 후보의 예상 비용과 알림 수로 시작합니다. 현재 조건의 예시라면 “비용은 45→26점으로 낮았으나 하루 20건 한도를 넘겼습니다. 한도 안의 규칙을 검증에서 선택해 별도 기간에 평가하겠습니다”라고 쓸 수 있습니다. 도입 뒤에는 확정 라벨 기준 비용과 검토 대기 누적을 함께 봅니다. 한도 위반 또는 입력 오류가 반복될 때 기본 절차로 돌아갈 조건과 책임자를 정합니다.

한 줄 정리

업무 비용과 처리 능력을 동시에 만족할 수 있는 예측 규칙을 다시 평가합니다.
