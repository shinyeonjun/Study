SP11·1

물리 시계 없이 메시지의 선후관계 읽기

한 프로세스가 쓴 기록과 다른 프로세스가 받은 기록을 연결합니다. 인과 순서가 있는 두 사건에 논리 시계를 적용하면 앞선 사건의 번호가 더 작습니다.

이 장을 읽고 나면

  • 프로세스 내부 순서와 메시지의 인과관계를 그린다.
  • Lamport 논리 시계를 송신·수신에서 갱신한다.
  • 논리 시계 순서와 실제 인과관계를 구분한다.

사건이 영향을 줄 수 있었는지부터 봅니다

두 합성 기록기 A와 B가 각각 자기 기록을 남기고 한 메시지를 주고받습니다. A의 로컬 기록 a, 송신 b, 다음 로컬 기록 c는 이 순서로 발생합니다. B에는 로컬 기록 d, b의 메시지를 수신한 e가 이 순서로 발생합니다. 한 프로세스 안의 앞 사건은 뒤 사건에 영향을 줄 수 있습니다. 송신도 그 메시지의 수신보다 앞섭니다.

이 두 규칙과 추이성으로 연결되는 관계를 happened-before라고 부릅니다. 예에서 a→b→e이므로 a는 e에 인과적으로 앞섭니다. d와 b 사이에는 어느 방향으로도 인과 경로가 없습니다. 이런 사건을 동시적이라고 합니다. 두 사건이 같은 물리 시각에 일어났음을 요구하는 정의는 아닙니다.

로컬 카운터를 한 칸 옮기고 메시지의 번호를 봅니다

Lamport 시계는 각 프로세스가 정수 카운터 하나를 유지합니다. 초기값은 0입니다. 로컬 사건과 송신 직전에는 1을 더하고, 송신에는 그때의 카운터를 붙입니다. 수신에서는 현재 카운터와 받은 번호 가운데 큰 값에 1을 더합니다. B는 d 뒤에 1이고 b의 메시지 번호는 2이므로 e의 번호는 max(1,2)+1=3입니다.

인과 경로가 있으면 논리 시계 번호가 엄격히 증가합니다. 번호가 더 작다는 사실만으로 인과 경로가 생기지는 않습니다. d는 1, b는 2지만 이 둘은 동시적입니다. c와 e의 번호는 둘 다 3입니다. 로그를 비교용으로 한 순서에 놓고 싶으면 번호 다음에 프로세스 식별자를 붙여 동률을 깨는 규칙을 만들 수 있습니다. 이 규칙으로 정한 순서가 실제 통신이나 동의의 증거가 되는 것은 아닙니다.

한 프로세스의 로컬 계산으로 시계를 흉내 냅니다

clock = {"A": 0, "B": 0}
stamp = {}
events = [("A", "a", None), ("A", "b", None), ("B", "d", None),
          ("B", "e", "b"), ("A", "c", None)]
for worker, name, sender in events:
    received = 0 if sender is None else stamp[sender]
    clock[worker] = max(clock[worker], received) + 1
    stamp[name] = clock[worker]
    print(worker, name, stamp[name])

ordered = sorted(events, key=lambda row: (stamp[row[1]], row[0]))
print("tie break:", " ".join(row[1] for row in ordered))
A a 1
A b 2
B d 1
B e 3
A c 3
tie break: a d b c e

코드의 입력 나열 순서는 시뮬레이터가 사건을 처리하는 순서입니다. A와 B가 모두 같은 전역 시계를 읽는다는 가정을 둔 것은 아닙니다. 분산 저장에서 여러 복제본이 같은 쓰기 기록을 확정하는 데에는 별도의 합의 과정이 필요합니다.
