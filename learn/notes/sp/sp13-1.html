SP13·1

문자를 토큰과 구문 트리로 바꾸고 타입을 검사하기

같은 ‘2 + 3 * 4’도 문자 목록, 구문 트리, 정수 결과로 각각 다르게 나타납니다. 처리 단계마다 무엇이 달라지는지 확인합니다.

이 장을 읽고 나면

  • 어휘 분석, 구문 분석, 타입 검사, 평가를 구분한다.
  • 곱셈이 덧셈보다 우선하는 구문 트리를 읽는다.
  • 구문이 맞는 식에 타입 오류가 날 수 있음을 작은 언어로 보인다.

글자를 분류하고 중첩된 구조를 만듭니다

소스 2 + 3 * 4에는 공백도 있지만 핵심 순서는 숫자 2, 연산자 +, 숫자 3, 연산자 *, 숫자 4입니다. 문자들을 의미 있는 단위로 묶는 어휘 분석이 이 토큰 열을 만듭니다. 여러 글자의 숫자 23도 숫자 토큰 한 개가 될 수 있습니다. 토큰의 분류와 원래 위치를 알고 있으면 오류가 어디서 생겼는지 표시할 수 있습니다.

구문 분석은 토큰들이 언어의 문법에 어떻게 들어가는지 결정합니다. 이 식은 곱셈을 먼저 묶어 2 + (3 * 4)로 읽습니다. 추상 구문 트리(AST)에는 평가에 필요한 구조가 남습니다. 꼭대기는 +, 왼쪽은 2, 오른쪽은 *이고 그 두 입력은 3과 4입니다. 괄호를 바꾼 (2 + 3) * 4의 트리 꼭대기는 *입니다.

형식이 맞아도 타입 규칙을 위반할 수 있습니다

언어는 어떤 종류의 값에 어떤 연산을 적용할 수 있는지 규칙을 둡니다. 여기서는 int와 bool을 구별하며 +와 *는 두 피연산자가 정수일 때만 허용하는 학습용 언어를 사용합니다. 2 + True는 덧셈이라는 구문을 만들 수 있지만 이 규칙으로는 타입 검사에서 거절됩니다. Python의 실제 bool 연산 규약과 다르므로 학습용 검사에서 type(value) is int로 정확히 구분합니다.

구문은 어떤 구조의 문장이 될 수 있는지, 의미는 그 문장이 어떤 값 또는 실행을 나타내는지 정합니다. 여기서 의미 규칙은 자식을 먼저 평가하고 해당 연산을 수행하는 것입니다. 정적 타입 검사는 AST에서 연산의 입력 종류를 실행 전에 확인합니다. 반환 정수의 값까지 정해주는 단계는 평가입니다. 컴파일러를 만들 때는 타입이 맞는 트리를 중간 표현이나 대상 코드로 바꿀 수 있고, 작은 인터프리터는 트리를 직접 평가할 수도 있습니다.

파이썬으로 고정된 세 식을 안전하게 읽습니다

Python 표준 라이브러리로 세 합성 문자열의 토큰과 AST를 얻고, 이 장이 지원하는 정수·불리언 상수와 두 연산을 검사합니다. AST 검사와 값 계산을 각각 함수로 나눕니다.

import ast
import io
import token
import tokenize

source = "2 + 3 * 4"
lexed = tokenize.generate_tokens(io.StringIO(source).readline)
print("tokens:", [(token.tok_name[t.type], t.string) for t in lexed
                  if t.type in (token.NUMBER, token.OP)])

def type_of(node):
    if isinstance(node, ast.Constant) and type(node.value) in (bool, int):
        return type(node.value)
    if isinstance(node, ast.BinOp) and type(node.op) in (ast.Add, ast.Mult):
        if type_of(node.left) is int and type_of(node.right) is int:
            return int
    raise TypeError("integer operands required")

def value_of(node):
    if isinstance(node, ast.Constant):
        return node.value
    a, b = value_of(node.left), value_of(node.right)
    return a + b if isinstance(node.op, ast.Add) else a * b

for example in [source, "(2 + 3) * 4", "2 + True"]:
    tree = ast.parse(example, mode="eval").body
    try:
        result_type = type_of(tree)
        operation = type(tree.op).__name__ if isinstance(tree, ast.BinOp) else "Constant"
        print(example, operation, result_type.__name__, value_of(tree))
    except TypeError as problem:
        print(example, problem)
tokens: [('NUMBER', '2'), ('OP', '+'), ('NUMBER', '3'), ('OP', '*'), ('NUMBER', '4')]
2 + 3 * 4 Add int 14
(2 + 3) * 4 Mult int 20
2 + True integer operands required

식의 결과 14가 예상과 다르다면 소스의 모양이 잘못되었는지, 타입 규칙이 달랐는지, 평가 순서가 달랐는지 순서대로 확인합니다. 소스와 실행에서는 언어가 실행되기 전 다른 표현으로 바뀌는 흐름을 다룹니다.
