토큰의 조건부 확률에서 생성 규칙과 퍼플렉서티 읽기

문장을 토큰으로 나누고 다음 토큰의 확률을 해석합니다. 같은 모델 분포에서 무엇을 고를지와, 정답열을 어떻게 채점할지를 구분합니다.

이 장을 읽고 나면

  • 토큰화가 토큰 수와 로그손실을 어떻게 바꾸는지 설명한다.
  • greedy, top-k, top-p, 온도의 역할을 구분한다.
  • 고정된 정답열의 퍼플렉서티를 계산한다.

문자열을 어떤 단위로 바꿨는지 적는다

같은 문자열 ‘비가 온다’를 간단한 규칙은 [비가, 온다] 두 토큰으로, 다른 규칙은 [비, 가, 온다] 세 토큰으로 만들 수 있습니다. 실제 토크나이저는 어휘와 분할 규칙이 더 복잡하고 공백 앞뒤를 다르게 표현할 수 있습니다. 토큰화의 결과가 모델의 입력과 평가에서 세는 단위입니다. 같은 제목을 비교해도 토크나이저와 시작·끝 기호 포함 여부가 다르면 표본당 토큰 수가 달라집니다.

다음 토큰 언어모델은 지금까지 제공한 토큰을 조건으로 다음 토큰 분포를 줍니다. 정답 토큰이 세 개이고 각 정답의 조건부 확률이 1/2, 1/4, 1/2라면 앞 문맥을 조건으로 세 토큰을 모두 내는 확률은 곱 1/16입니다. 토큰당 음의 자연로그 확률의 평균은 ln(16)/3≈0.924196입니다. 그 값의 지수가 퍼플렉서티로 약 2.519842입니다.

확률을 만들고 고르는 규칙은 따로 둘 수 있다

토큰 A,B,C,D의 다음 확률을 [0.5,0.3,0.15,0.05]로 둡니다. 탐욕 디코딩은 이번 단계에서 최대인 A를 고릅니다. A를 택하면 다음 단계의 문맥이 바뀌므로, 이번 최댓값이 완성된 문장 전체의 최고 점수를 보장하는 것은 아닙니다.

top-k는 높은 순으로 k개, top-p는 높은 쪽부터 누적확률이 p 이상이 되는 최소 접두를 남깁니다. 여기서는 k=2와 p=0.75가 각각 A,B를 남깁니다. 누적이 처음으로 0.75 이상이 되는 곳은 0.5+0.3=0.8이기 때문입니다. 남긴 값을 합 0.8로 나누면 [0.625,0.375]에서 다시 추출할 수 있습니다. 실제 구현의 동점 정리나 최소 유지 항목 수는 해당 규칙을 확인합니다.

온도와 평가 조건을 기록한다

양의 온도 T를 쓰면 softmax에 넣는 로짓을 T로 나눕니다. 낮을수록 기존 순위에서 높은 로짓이 상대적으로 더 큰 비중을 받습니다. 이 예의 확률을 p^(1/T)에 비례하게 바꾸면 T=0.5에서 [0.25,0.09,0.0225,0.0025]를 합으로 나눈 분포입니다. 서로 다른 생성 규칙은 같은 언어모델의 평가용 정답열 확률과 구별합니다.

from math import exp, log
from random import Random

choices = ["A", "B", "C", "D"]
p = [0.5, 0.3, 0.15, 0.05]
size = 1
while sum(p[:size]) < 0.75:
    size += 1
remaining = [value / sum(p[:size]) for value in p[:size]]
tempered = [value**2 for value in p]
draw = Random(23).choices(choices[:size], weights=remaining, k=1)[0]
mean_loss = -sum(log(x) for x in (0.5, 0.25, 0.5)) / 3
print("greedy:", choices[0], "top-p:", choices[:size], remaining)
print("seed 23 draw:", draw)
print("T=0.5 probability A:", f"{tempered[0] / sum(tempered):.6f}")
print("mean nll:", f"{mean_loss:.6f}", "perplexity:", f"{exp(mean_loss):.6f}")
greedy: A top-p: ['A', 'B'] [0.625, 0.37499999999999994]
seed 23 draw: B
T=0.5 probability A: 0.684932
mean nll: 0.924196 perplexity: 2.519842

출력의 0.37499999999999994는 이진 실수의 반올림을 보입니다. 퍼플렉서티 비교에서는 같은 원문뿐 아니라 토큰화, 시퀀스 자르는 방법, 초기 문맥, 실제 채점 토큰을 맞춥니다. 낮은 퍼플렉서티는 채점된 다음 토큰의 확률을 설명하는 값이므로 사실성이나 사용자 선호는 별도 기준으로 평가합니다.
