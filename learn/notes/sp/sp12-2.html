입력값을 검증하고 데이터가 해석되는 위치를 구분하기

이름 ‘A&B’가 데이터베이스에서는 한 개의 값이고 웹에서는 화면 글자여야 합니다. 배열의 숫자도 유효한 위치에서만 읽을 수 있습니다. 값이 경계를 넘는 곳마다 맡길 검사와 API를 고릅니다.

이 장을 읽고 나면

  • 형식과 업무상 범위를 구분해 입력을 확인할 수 있다.
  • SQL 매개변수 바인딩과 HTML 텍스트 이스케이프가 맡는 역할을 설명할 수 있다.
  • 0부터 시작하는 배열의 경계를 확인할 수 있다.

값을 읽을 때와 사용할 때 필요한 조건

서비스의 한 페이지에 표시할 결과 수를 입력받는다고 합시다. 숫자로 읽을 수 있는지 먼저 확인하고, 읽은 수가 1부터 50까지인지 확인합니다. 첫째는 형식 조건, 둘째는 업무상 의미에 따른 범위 조건입니다. 외부에서 온 값은 실제로 계산하거나 저장하기 전에 이 조건을 만족하는지 서버에서 확인합니다. 아래 예제는 0–9로 쓴 글자 1~2개만 받고, 그중 1~50인 값만 받아들이는 작은 규약입니다.

형식과 범위를 확인해도 이름 같은 일반 문자열에는 &처럼 표현에 필요한 문자가 들어갑니다. 무엇을 정상 이름으로 인정할지와 정상 이름을 SQL 또는 웹 페이지에 어떤 API로 넘길지는 별개입니다.

SQL 문과 HTML 문에서 값의 자리를 정하기

SQL 조회를 작성할 때 조건의 값 자리에 ?를 남기고 실제 이름을 별도 인수로 넘깁니다. 드라이버가 SQL의 문장 구조와 값을 구분합니다. 이 예제는 SQLite를 사용합니다. 값을 바인딩하는 API의 표시 방식은 드라이버마다 다를 수 있습니다.

이 분리를 안 하면 생기는 공격

SQL 삽입(SQL injection): 입력을 문자열 덧셈으로 SQL 본문에 붙이면, 입력이 값이 아니라 문장의 일부로 해석됩니다. 이름 칸에 x' OR '1'='1을 넣으면 SELECT name FROM study_group WHERE name = 'x' OR '1'='1'이 되어 조건이 항상 참이 되고 모든 행이 나옵니다. 같은 입력을 ? 자리에 바인딩하면 “그런 이름인 행”을 찾을 뿐이라 결과가 비어 있습니다.

XSS(교차 사이트 스크립팅): 사용자가 넣은 글을 이스케이프 없이 HTML에 넣으면 <script>…</script> 같은 입력이 다른 사용자의 브라우저에서 코드로 실행됩니다. 이스케이프하면 &lt;script&gt;가 되어 글자로만 보입니다.

두 공격 모두 원인은 같습니다. 데이터가 코드(SQL 문, HTML 구조)로 해석되는 자리에 들어갔다는 것입니다. 그래서 막는 방법도 “그 자리의 문법에 맞게 값을 분리”하는 것입니다.

화면의 HTML 텍스트 자리에 같은 이름을 표시할 때는 템플릿 엔진의 문맥에 맞는 이스케이프나 텍스트 삽입 API에 맡깁니다. 아래의 html.escape는 텍스트를 HTML 문자열로 만드는 한 경우를 보여 줍니다. URL이나 자바스크립트 문맥에는 거기에 맞는 다른 API와 검증이 필요합니다.

메모리 경계의 예. 짧은 배열에서 한 값 읽기

길이 N의 0부터 세는 배열은 0≤i<N일 때 i번째 원소가 있습니다. 예를 들어 길이 3이면 첨자 0~2만 받습니다. 파이썬 리스트는 음수 첨자를 끝에서부터 해석하지만, 외부 요청에 공개하는 규약이 0부터 N−1까지라면 음수 값도 검사합니다. 경계를 검사하는 컨테이너는 프로그램이 할당된 범위 밖을 읽거나 쓰는 일을 막는 데 도움이 됩니다. 수동으로 메모리를 사용할 때는 배열 범위뿐 아니라 그 값을 아직 사용해도 되는 수명도 관리해야 합니다.

C처럼 첨자를 검사하지 않는 언어에서 범위 밖에 쓰면 옆 메모리를 덮어쓰는 버퍼 오버플로가 되고, 이미 해제한 메모리를 다시 쓰면 해제 후 사용(use-after-free)이 됩니다. 둘 다 C 표준에서 정의되지 않은 동작이라 오류 없이 지나가거나 공격에 쓰일 수 있습니다. 반면 파이썬 리스트는 범위 밖 첨자에서 IndexError를 내고, Rust는 벡터 첨자를 실행 중에 검사하며(범위 밖이면 패닉으로 중단) 참조의 수명은 컴파일할 때 검사합니다. 이렇게 언어 규칙으로 이런 오류를 막는 성질을 메모리 안전이라고 부릅니다.

from contextlib import closing
from html import escape
import re
import sqlite3

def page_size(text):
    if re.fullmatch(r"[0-9]{1,2}", text):
        value = int(text)
        if 1 <= value <= 50:
            return value
    return None

def item_at(values, index):
    return values[index] if 0 <= index < len(values) else None

name = "A&B"
with closing(sqlite3.connect(":memory:")) as database:
    database.execute("CREATE TABLE study_group (name TEXT)")
    database.execute("INSERT INTO study_group VALUES (?)", (name,))
    row = database.execute(
        "SELECT name FROM study_group WHERE name = ?", (name,)
    ).fetchone()

assert row == (name,)
assert page_size("1") == 1 and page_size("50") == 50
assert page_size("0") is None and page_size("51") is None
assert item_at(["수학", "통계", "코딩"], -1) is None
print(f"허용 개수: {page_size('12')}")
print(f"범위 밖 개수: {page_size('51')}")
print(f"SQL 값: {row[0]}")
print(f"HTML 텍스트: {escape(row[0])}")
print(f"마지막 첨자: {item_at(['수학', '통계', '코딩'], 2)}")
print(f"범위 밖 첨자: {item_at(['수학', '통계', '코딩'], 3)}")

실행 결과

허용 개수: 12
범위 밖 개수: None
SQL 값: A&B
HTML 텍스트: A&amp;B
마지막 첨자: 코딩
범위 밖 첨자: None

브라우저에서 HTML 텍스트 A&amp;B를 해석하면 사용자에게는 A&B가 보입니다. 데이터베이스에 넣은 원래 이름은 그대로 보존됩니다. 예제에서 None은 거부 또는 범위 밖을 알리는 반환값이며, 화면이 있다면 어떤 조건을 충족해야 하는지 보여 줍니다.

실습. 경계값 세 쌍을 고르기

결과 수의 경계에는 0과 1, 50과 51이 있습니다. 여기에 두 글자와 세 글자의 경계도 확인합니다. 데이터베이스에 넘긴 이름과 화면이 표시한 이름이 의미상 같아야 하지만, 중간의 HTML 표현은 달라질 수 있습니다.
