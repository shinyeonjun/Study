공부 교재

보안·암호

SP12·1

공부 기록의 자산과 권한 경계를 그리기

가상의 공부 서비스에서 내 기록은 수정할 수 있고 공개 교재는 누구나 읽을 수 있습니다. 이 규칙이 매 요청에 적용되는지 작은 권한 표와 테스트로 확인합니다.

이 장을 읽고 나면

  • 자산, 진입점, 신뢰 경계를 가상의 서비스에서 구별할 수 있다.
  • 인증과 인가가 확인하는 질문을 설명할 수 있다.
  • 최소 권한과 기본 거부를 권한 테스트에 반영할 수 있다.

보호하려는 내용을 먼저 적기

가상의 공부 서비스에는 누구나 읽을 수 있는 교재, 로그인한 학생만 접근하는 개인 기록, 편집자가 고치는 공개 교재 원고가 있습니다. 세 항목은 각각 보호할 자산입니다. 개인 기록은 다른 학생에게 보이지 않아야 하고(기밀성), 개인 기록과 원고의 내용은 권한이 있는 사람이 바꿀 때만 바뀌어야 하며(무결성), 공개 교재는 필요할 때 열려야 합니다(가용성). 이 세 요구를 묶어 흔히 CIA(Confidentiality·Integrity·Availability)라고 부릅니다.

위협 모델은 무엇을 지킬지(자산), 누가 어떤 능력으로 공격할 수 있는지(공격자), 외부 입력이 어디로 들어오는지(진입점: 로그인 화면, 기록 수정 요청 주소 등)를 적은 문서입니다. 위협 모델을 만들 때는 자료가 어디서 어디로 흐르고 어느 지점에서 믿을 수 있는 정보의 종류가 바뀌는지 그립니다. 브라우저에서 서버로 넘어가는 요청은 신뢰 경계를 넘습니다. 요청의 학생 이름이나 화면에 그려진 버튼 유무는 서버의 권한 증거로 쓰기 어렵습니다. 서버가 검증한 세션에서 사용자 식별자를 가져오고, 저장소가 알고 있는 기록 소유자와 비교합니다.

로그인과 기록 수정 권한을 따로 검사한다

인증은 요청하는 사람이 누구인지 확인하는 과정입니다. 인가, 또는 권한 검사는 확인한 사람이 이 자료에 이 동작을 해도 되는지 판단합니다. 로그인한 학생에게 자신의 기록 수정만 필요하다면 다른 학생의 기록이나 공개 원고를 수정할 권한까지 주지 않습니다. 이 설계 원칙을 최소 권한이라고 부릅니다.

대상과 동작허용 조건금지의 예
공개 교재 읽기누구나동작이 교재 수정으로 바뀌면 별도 검사
공개 교재 수정검증된 편집자 역할일반 학생의 원고 수정
개인 기록 읽기·수정기록 소유자로 확인된 로그인 사용자다른 학생의 기록 접근
정의하지 않은 동작기본 거부개인 기록 내보내기 정책이 아직 없음

같은 사용자라도 대상이나 동작이 바뀌면 결론이 달라집니다. 그래서 매 요청에서 실제 대상과 동작을 검사합니다. 표에 없는 요청은 거부한 뒤, 새로운 기능이 생기면 표와 검사를 함께 업데이트합니다. 로그인하지 않은 사람에게도 교재 읽기처럼 명시적으로 허용된 동작이 있습니다.

정책을 작은 입력 표로 실행하기

아래 예제는 역할과 소유자를 서버에서 이미 결정한 값으로 간주하는 순수 함수입니다. 외부 시스템에 접속하지 않고 여섯 가지 기대 결과를 확인합니다. 실제 서비스라면 세션 검증, 대상 조회, 권한 검사와 저장을 일관되게 연결해야 합니다.

def allowed(actor, role, action, resource, owner=None):
    if resource == "chapter":
        return action == "read" or (
            action == "edit" and actor is not None and role == "editor"
        )
    if resource == "record":
        return action in {"read", "edit"} and actor is not None and actor == owner
    return False

cases = [
    ("공개 열람", (None, None, "read", "chapter"), True),
    ("본인 기록", ("a", "student", "edit", "record", "a"), True),
    ("다른 사람 기록", ("a", "student", "edit", "record", "b"), False),
    ("편집자의 교재 수정", ("e", "editor", "edit", "chapter"), True),
    ("학생의 교재 수정", ("a", "student", "edit", "chapter"), False),
    ("미정의 동작", ("a", "student", "export", "record", "a"), False),
]
for label, args, expected in cases:
    actual = allowed(*args)
    assert actual == expected
    print(f"{label}: {'허용' if actual else '거부'}")

실행 결과

공개 열람: 허용
본인 기록: 허용
다른 사람 기록: 거부
편집자의 교재 수정: 허용
학생의 교재 수정: 거부
미정의 동작: 거부

규칙이 커질 때 다시 살펴볼 것

공동 학습의 기록을 추가한다면 개인 기록과 달리 어떤 구성원이 열람하고 편집할지를 결정해야 합니다. 기존의 소유자 검사와 새 공동 기록의 참여자 검사를 구분합니다. 기록 소유자가 없는 경우나 로그인 정보가 만료된 경우도 기대 결과를 명시해 두면, 정책을 바꿀 때 이전 자산의 권한을 함께 확인할 수 있습니다.
