실행 전의 근사 분석과 모든 반복에 대한 검증

실행 사례를 몇 개 맞혀도 모든 입력에서 올바르다는 결론은 따로 필요합니다. 변수의 범위를 보수적으로 추적하고, 반복문에는 계속 참인 조건을 세웁니다.

이 장을 읽고 나면

  • 정적 분석에서 실제 값의 집합을 포함하는 범위를 계산한다.
  • 거짓 경고의 원인이 되는 변수 간 관계 손실을 찾는다.
  • 루프 불변식과 종료 척도로 사전조건과 사후조건을 연결한다.

정적 분석은 실제 실행의 여러 경우를 한꺼번에 다룹니다

정수 x가 0부터 3까지이고 y = x + 2, z = y - x를 계산합니다. 정적 분석은 프로그램을 특정 입력으로 직접 실행하는 대신 프로그램 구조에서 가능한 성질을 추론합니다. 변수별 가능한 값들을 하한과 상한으로 감싸는 구간 추상 해석이 한 예입니다. x의 범위 [0,3]에서 y의 범위는 [2,5]입니다.

y와 x를 각각의 범위 안에서 독립적으로 골라도 된다고 근사하면, z의 하한은 2−3=−1이고 상한은 5−0=5입니다. 실제 식은 y=x+2이므로 네 경우 모두 z=2입니다. 구간 [−1,5]에는 실제값 2가 들어 있지만 서로 함께 생길 수 없는 y=2, x=3 조합도 허용했습니다. 분석이 z 음수를 배제하지 못하면 경고가 날 수 있습니다. 이 경고만 가지고 실제 음수의 반례를 얻었다고 볼 수는 없습니다.

왜 정확한 값을 구하지 않고 근사할까요? 앞 장의 정지 문제와 같은 논리로, “이 프로그램이 실행 중 음수를 만드는가” 같은 실행 동작에 관한 자명하지 않은 성질은 모든 프로그램에 대해 늘 정확히 답하는 알고리즘이 없습니다(라이스 정리). 그래서 정적 분석은 늘 끝나는 대신 답을 근사합니다. 실제로 가능한 값을 빠짐없이 포함하도록 근사하는 분석을 건전한(sound) 분석이라고 합니다. 건전한 분석은 실제 문제를 놓치지 않지만, 이 예처럼 실제로는 없는 문제를 경고하는 거짓 경고를 낼 수 있습니다.

실제로 가능한 모든 값을 포함한다는 보수성은 검사하려는 성질과 분석 규칙에 대해 증명해야 합니다. 범위의 모든 값이 0 이상이라면 실제 값도 0 이상이라고 결론낼 수 있습니다. 경고를 줄이려면 변수 관계를 표현하는 더 정밀한 분석을 쓸 수 있지만 계산량이 늘 수 있습니다.

반복할 때마다 참으로 돌아오는 조건을 세웁니다

프로그램 조각 C를 실행하기 전에 참이라고 가정하는 조건을 사전조건 P, 실행이 끝난 뒤 참이어야 하는 조건을 사후조건 Q라고 합니다. “P가 참인 상태에서 C를 실행해 끝나면 Q가 참”이라는 주장을 {P} C {Q}로 적습니다(호어 삼중쌍). 반복문 하나로 이런 주장을 증명해 봅니다.

1부터 n까지의 합을 구합니다. 사전조건은 n이 음이 아닌 정수라는 것입니다. 처음 i=0, s=0을 두고 i < n이면 i=i+1과 s=s+i를 차례로 적용합니다. 보이고 싶은 사후조건은 2s=n(n+1)입니다. 반복마다 0≤i≤n와 2s=i(i+1)가 참인 루프 불변식을 둡니다.

초기 i=s=0에서 조건이 성립합니다. 기존 i에 대해 2s=i(i+1)이고 루프에 들어갈 수 있다면, 새 i′=i+1이고 새 s′=s+i′입니다. 그러면 2s′=i(i+1)+2(i+1)=(i+1)(i+2)=i′(i′+1)입니다. i′≤n도 유지됩니다. 루프를 벗어나면 i≥n이고 불변식에서 i≤n이므로 i=n입니다. 종료도 보이려면 음이 아닌 정수 n−i가 반복마다 정확히 1씩 줄어든다는 사실을 씁니다.

예제의 실행 범위와 증명의 범위를 구분합니다

pairs = [(x, x + 2) for x in range(4)]
x_range, y_range = (0, 3), (2, 5)
z_bounds = (y_range[0] - x_range[1], y_range[1] - x_range[0])
print("interval:", z_bounds, "actual:", sorted({y - x for x, y in pairs}))

def add_up(n):
    i = s = 0
    while i < n:
        i += 1
        s += i
        assert 0 <= i <= n and 2*s == i*(i+1)
    return s

for n in (0, 1, 4):
    print("sum up to", n, "=", add_up(n))
interval: (-1, 5) actual: [2]
sum up to 0 = 0
sum up to 1 = 1
sum up to 4 = 10

위 코드의 assert는 실행한 n에서만 검사합니다. 초기 조건, 불변식 보존, 종료 뒤 결과를 수식으로 확인하면 전제하의 모든 n에 대해 설명할 수 있습니다. 종료했을 때 결과가 맞는 성질을 부분 정확성, 종료까지 포함한 것을 전체 정확성이라고 합니다. 정수 오버플로가 생기는 고정 폭 환경에서는 같은 수식의 정수 연산 가정이 그대로 맞는지도 확인합니다.

검증 도구는 모형의 모든 도달 상태를 탐색하거나 증명을 검사할 수 있습니다. 상태 수가 유한하면 전체 탐색을 끝낼 수 있지만 규모가 빠르게 커질 수 있습니다. 검증 결과는 프로그램에 대해 적어 둔 전이 모형과 검사한 성질의 범위에서 해석합니다.
