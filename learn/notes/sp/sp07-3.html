SP07·3

유한 시간의 비용을 비교해 제어 입력 고르기

목표에 가까워지는 비용과 입력을 쓰는 부담을 더합니다. 어느 두 단계 계획이 비용이 가장 작은지 계산한 뒤, 같은 문제를 RL과 연결합니다.

이 장을 읽고 나면

  • 상태 전이, 행동 제약, 단계 비용, 끝 비용을 구분한다.
  • 작은 유한 시간 최적제어 문제의 해를 후보 열거로 찾는다.
  • 매번 계획을 다시 푸는 제어와 경험에서 정책을 학습하는 RL의 관계를 설명한다.

바꿀 수 있는 값과 줄일 비용을 적습니다

가상 표시의 위치가 2이고 목표는 0입니다. 두 단계 동안 위치를 xₜ₊₁=xₜ+uₜ로 바꿀 수 있습니다. 어떤 시점이든 입력은 −1, 0, 1 중 하나입니다. 훨씬 큰 입력을 보내 단숨에 끝내는 선택은 이 모형에 없습니다. 각 입력을 쓰는 비용은 uₜ², 두 단계가 지난 끝 위치 비용은 2x₂²로 정합니다. 가능한 계획 중 총비용 J=u₀²+u₁²+2x₂²가 가장 작은 것을 찾습니다.

입력을 전부 0으로 두면 위치는 2 그대로이고 비용은 8입니다. 첫 단계에서 −1, 두 번째에서 0이면 끝 위치가 1이므로 비용은 입력 1과 끝 2를 합친 3입니다. 두 단계 모두 −1이면 끝 위치는 0이고 비용은 2입니다. 중간 위치에 비용이 없다는 모형 선택에서, (0,−1)도 (−1,0)과 같은 비용 3을 얻습니다.

최적 행동은 남은 시간과 상태에 따라 달라집니다

마지막 시점에 위치 1이면 입력 −1을 주는 비용 1이 최선입니다. 위치 2라면 같은 −1을 줘도 끝 위치가 1이라 비용 3입니다. 동적 계획법에서는 각 상태에서 남은 한 단계의 최소 비용을 먼저 계산합니다. 처음 행동의 비용에 그 다음 상태에서의 최소 비용을 더해 다시 비교하면 두 단계 전체의 최선이 됩니다.

유한 시간 동적 계획의 식

끝 시점 N에서 VN(x)=끝 비용으로 시작해, k=N−1, …, 0 순서로 Vk(x)=minu [ℓ(x,u)+Vk+1(f(x,u))]를 계산합니다. ℓ는 단계 비용, f는 전이 식, Vk(x)는 시점 k에 상태 x에서 남은 최소 비용입니다. 이 예에서는 N=2, V2(x)=2x², ℓ(x,u)=u², f(x,u)=x+u이고 V1(1)=1, V1(2)=3, V0(2)=2입니다.

선형 상태 식과 상태·입력의 이차 비용에 연속값 입력 제약이 없는 표준 경우에는 선형 이차 조절기(LQR)처럼 선형 피드백을 구하는 해법을 쓸 수 있습니다. 입력이 정수 세 값으로 제한된 이 예에서는 주어진 후보 집합으로 직접 풀었습니다. 모델 예측 제어(MPC)는 현재 상태에서 앞으로의 유한 계획을 풀고 첫 입력만 적용한 뒤, 다음 관측을 반영해 새 상태에서 다시 풉니다. 계산이 정해진 시간에 끝나는지, 제약이 실현 가능한지, 닫힌 고리가 안정한지는 별도의 설계 기준입니다.

아홉 계획과 한 단계 표적을 각각 검산합니다

from itertools import product

actions = (-1, 0, 1)
plans = {(a, b): a*a + b*b + 2 * (2+a+b)**2
         for a, b in product(actions, repeat=2)}
for a in actions:
    print(a, [plans[a, b] for b in actions])
best = min(plans, key=plans.get)
print("best:", best, plans[best])

def remaining(x):
    return min(u*u + 2 * (x+u)**2 for u in actions)

print("backward:", [a*a + remaining(2+a) for a in actions])
-1 [2, 3, 10]
0 [3, 8, 19]
1 [10, 19, 34]
best: (-1, -1) 2
backward: [2, 3, 10]

강화학습에서는 같은 비용의 음수를 보상으로 두고, 여기처럼 할인 없는 정해진 기간 안에서 반환값 최대화로 바꿀 수 있습니다. 모형을 알면 위처럼 계산할 수 있습니다. 모형을 직접 모르고 상호작용 기록으로 정책이나 값을 배울 수 있으며, 경험으로 모형을 근사한 뒤 그 안에서 계획하는 경우도 있습니다. 모델을 쓰는 RL이 이 접점을 다룹니다.
