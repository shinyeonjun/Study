유한 자동자에서 정지 문제까지

1이 짝수 번 나오는지는 상태 두 개로 알 수 있습니다. 언어의 규칙이 복잡해지면 필요한 기억이 달라지며, 아무리 강력한 계산 모형에서도 결정할 수 없는 질문이 있습니다.

이 장을 읽고 나면

  • 결정적 유한 자동자의 상태와 전이, 수용 조건을 구분한다.
  • 임의 깊이의 괄호 짝에서 유한 상태가 부족한 이유를 설명한다.
  • 결정 가능성과 계산 비용을 구분하고 정지 문제의 모순을 따라간다.

앞에서 읽은 정보를 상태 두 개에 담습니다

입력 알파벳은 0과 1입니다. 모든 글자를 읽었을 때 1의 개수가 짝수인지 확인합니다. 지금까지 1을 짝수 번 봤으면 E, 홀수 번 봤으면 O입니다. 처음에는 1을 0번 봤으므로 E입니다. 0을 읽으면 그대로 있고, 1을 읽으면 상태를 반대로 바꿉니다. 끝에서 E면 수용합니다. 결정적 유한 자동자(DFA)는 상태와 입력 기호마다 정해진 다음 상태가 하나인 모형입니다.

어떤 입력은 길이에 따라 더 많은 기억이 필요합니다

괄호 종류가 하나일 때는 여는 괄호에서 개수를 하나 늘리고, 닫는 괄호에서 하나 줄입니다. 중간에 음수가 되면 이전에 열린 괄호가 없었으므로 실패입니다. 끝에서 0이면 모두 맞았습니다. 깊이 제한이 없다면 여는 괄호를 n개 읽은 경우와 m개 읽은 경우(n≠m)를 서로 구별해야 합니다. 닫는 괄호를 n개 이어 붙이면 첫째만 맞기 때문입니다. 유한한 상태에 이 모든 경우를 서로 다르게 넣을 수 없습니다.

스택에 여는 괄호를 쌓고 닫힐 때 꺼내는 푸시다운 자동자는 이런 규칙을 나타낼 수 있습니다. 여러 괄호 종류가 있을 때는 스택에서 가장 최근의 여는 종류도 검사해야 합니다. 기호를 읽는 위치를 전후로 옮기고 테이프에 쓸 수 있는 튜링 기계는 더 일반적인 알고리즘 모형입니다. 사용 가능한 기억의 모양에 따라 판정할 수 있는 언어의 범위가 달라집니다.

정지 문제에서는 모든 입력에 답하는 알고리즘을 가정할 수 없습니다

판정 문제가 결정 가능하다는 말은 모든 유효 입력에서 유한 시간 안에 참·거짓으로 답하는 방법이 있다는 뜻입니다. 예를 들어 앞의 DFA는 입력 길이만큼 상태를 바꾸고 답합니다. 오래 걸리는 판정 문제에서는 정답을 내는 알고리즘이 있으나 필요한 계산이 큽니다. 결정 불가능은 모든 입력에 대해 늘 종료하며 정확하게 답하는 알고리즘이 없다는 뜻입니다.

정지 문제는 프로그램 P와 입력 x를 보고 P(x)가 끝나는지 판정하는 문제입니다. 모든 P,x에 답하는 완벽한 H가 있다고 가정해 봅시다. 프로그램 D(P)는 H가 ‘P(P)가 끝난다’고 하면 끝나지 않고, ‘끝나지 않는다’고 하면 즉시 끝나게 만듭니다. D에 자신의 코드 D를 넣으면, H가 어느 쪽으로 답해도 실제 D(D)는 그 반대로 동작합니다. 이 모순 때문에 그런 범용 H는 없습니다. 특정 반복을 분석하거나 정해진 스텝만 실행하는 도구는 여전히 만들 수 있습니다.

def even_ones(bits):
    state = 0  # 0: E, 1: O
    for bit in bits:
        state ^= int(bit)
    return state == 0

def balanced(text):
    depth = 0
    for symbol in text:
        depth += 1 if symbol == "(" else -1
        if depth < 0:
            return False
    return depth == 0

for text in ["", "1010", "1011"]:
    print("bits:", repr(text), even_ones(text))
for text in ["(()())", ")(", "(()"]:
    print("parentheses:", text, balanced(text))
bits: '' True
bits: '1010' True
bits: '1011' False
parentheses: (()()) True
parentheses: )( False
parentheses: (() False

두 함수의 입력은 각각 설명한 알파벳만 사용합니다. 어떤 규칙을 이미 판정할 수 있는지와 그 알고리즘이 어느 정도 자원을 쓰는지는 다른 질문입니다. 문제 난이도와 환원의 구분과 함께 읽을 수 있습니다.
