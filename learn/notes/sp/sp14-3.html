전문 경로 · SP14 그래픽스·사람과 컴퓨터

SP14·3

사람이 화면을 쓰는 과제를 설계하고 사용성을 확인하기

화면을 볼 수 있는지, 키보드로 쓸 수 있는지, 목적을 달성할 수 있는지를 각각 평가합니다. 소규모 짝 실험의 성공률과 시간을 직접 계산합니다.

이 장을 읽고 나면

  • 화면의 상태·조작·피드백을 과제 흐름 안에서 확인한다.
  • 명도 대비를 계산하고 접근성 검사의 범위를 설명한다.
  • 조건 순서와 실패를 기록해 사용성 실험 결과를 해석한다.

사용자가 화면에서 무엇을 하려는지부터 적는다

HCI(인간과 컴퓨터의 상호작용)는 사람들이 어떤 환경에서 시스템을 쓰고 과제를 어떻게 수행하는지 설계하고 관찰하는 분야입니다. 예로 연구 기록 사이트에서 ‘실험 하나의 결과를 내려받아 저장한다’를 과제로 둡니다. 버튼 이름만이 아니라 상태가 바뀌었는지, 작업 중인지, 실패했다면 어떻게 다시 시도하는지에 대한 피드백이 필요합니다.

키보드로 도달하고 활성화할 수 있는지, 포커스 순서가 화면의 과제 순서와 맞는지, 보조 기술이 버튼의 이름과 상태를 읽는지 확인합니다. 실패와 성공을 구분할 때 색상 외에 글이나 기호로도 뜻을 줍니다. 예를 들어 버튼은 ‘내려받기’처럼 목적이 드러나는 이름과 적합한 기본 HTML 요소를 사용할 수 있습니다.

색은 숫자로 읽을 수 있지만 그 숫자로 사용성 전체를 알 수 없다

접근성은 시각·청각·운동 능력 등이 다른 사람도 같은 기능을 쓸 수 있는 정도입니다. 웹에서는 W3C의 웹 콘텐츠 접근성 지침 WCAG가 기준으로 널리 쓰이며, 성공 기준마다 A·AA·AAA 등급이 있습니다. WCAG 2.2의 AA 대비 기준에서 일반 크기 텍스트의 대비는 4.5:1 이상입니다. 밝은 상대 휘도 L₁과 어두운 L₂를 써 (L₁+0.05)/(L₂+0.05)로 계산합니다. 이 예에서는 흰색 휘도 1과 회색을 비교합니다. 표준 sRGB의 각 성분을 선형값으로 바꿔 R,G,B에 0.2126,0.7152,0.0722를 곱해 더합니다. 회색은 세 성분이 같아 합이 선형 성분 하나와 같습니다. 4.4781은 반올림해서 표시한 값이며 기준 판정에서 4.5로 올려 계산하지 않습니다. 큰 글자(18pt 이상, 굵게는 14pt 이상)에는 AA에서 3:1을 요구합니다.

ISO 9241-11은 사용성을 정해진 사용자가 정해진 사용 맥락에서 목표를 효과성(목표를 정확·완전하게 달성하는가), 효율성(그러는 데 드는 시간·노력), 만족도로 달성하는 정도로 정의합니다. 그래서 사용성을 비교한다면 대상 사용자가 정한 과제를 성공하는지, 얼마나 시간이 들고 얼마나 만족하는지 따로 정의합니다. 성공률, 오류, 소요시간을 같은 조건으로 재고 과제 완료 도중 무엇이 혼란이었는지 기록합니다. 대비 검사에 통과했다고 과제 성공을 가정할 필요는 없습니다.

평가 방법도 여럿입니다. 실제 사용자에게 과제를 주고 관찰하는 사용성 테스트(과제 중 생각을 소리 내어 말하게 하는 방식을 자주 함께 씀), 전문가가 정해진 원칙 목록에 비추어 화면을 점검하는 휴리스틱 평가, 이 장처럼 조건을 나눠 시간·성공률을 재는 비교 실험이 있습니다. 앞의 둘은 문제를 찾는 데, 비교 실험은 두 설계의 차이를 재는 데 맞습니다.

순서를 배정하고 실패한 기록도 집계한다

한 사람이 두 조건을 모두 수행하는 설계를 참가자 내 설계, 사람마다 한 조건만 수행하는 설계를 참가자 간 설계라고 합니다. 참가자 내 설계는 개인차가 상쇄되어 적은 인원으로 비교하기 좋지만, 같은 사람이 A와 B를 수행하므로 두 번째 화면에 익숙해져 더 빨라질 수 있습니다(순서 효과). 그래서 비교 시작 전에 AB와 BA 순서를 같은 수로 나누어 배정하고(역균형화), 과제와 제한시간, 힌트와 기기를 맞춥니다. 예제의 A 성공률은 3/4, B는 4/4입니다. 두 화면에서 모두 성공한 세 사람끼리 A−B 시간 차의 중앙값을 내면 7초입니다. 실패를 성공 0초로 처리하면 결과가 왜곡됩니다. 시간 제한과 실패 정의를 미리 정하고 성공률과 성공한 짝의 시간 통계를 함께 명시합니다.

from statistics import median

def gray_luminance(c):
    s = c/255
    return s/12.92 if s <= 0.04045 else ((s+0.055)/1.055)**2.4

for channel in (119, 118):
    ratio = 1.05/(gray_luminance(channel)+0.05)
    print("#"+f"{channel:02x}"*3, f"{ratio:.4f}", "pass:", ratio >= 4.5)

a = [30, 36, 24, None]
b = [18, 29, 19, 26]
successes = lambda rows: sum(v is not None for v in rows)
paired = [x-y for x,y in zip(a,b) if x is not None and y is not None]
print("success A/B:", successes(a), successes(b), "out of", len(a))
print("paired seconds:", paired, "median:", median(paired))
#777777 4.4781 pass: False
#767676 4.5422 pass: True
success A/B: 3 4 out of 4
paired seconds: [12, 7, 5] median: 7

이 숫자는 네 명으로 만든 계산 예입니다. 실제 평가에서는 사용자와 장소의 범위, 과제와 표본 수, 입력 방식과 접근성 지원, 실패 사례, 동의받은 기록만 보고합니다. 순서를 나눠 배정했어도 이전 화면을 기억하는 효과가 남을 수 있으므로 보고할 때 보존된 비교 조건과 제한을 적습니다.
