로그: 몇 번 곱했는지 거꾸로 찾기

값이 100에서 800이 되었습니다. 매 단계 두 배라면 몇 단계가 지났을까요? 로그를 지수함수의 역함수로 읽고, 곱의 로그와 로그 눈금이 분석에서 왜 쓰이는지 확인합니다.

이 장을 읽고 나면

  • 로그 식을 지수 식으로 되돌려 계산한다.
  • 로그의 정의역과 밑의 조건을 적용한다.
  • 곱의 로그·밑 변환·로그 축의 비율 해석을 설명한다.

지수와 밑, 로그 식을 읽는 법

100에서 800이 되었다면 배수는 800/100 = 8입니다. 밑 2를 몇 제곱해야 8이 되는지 묻는 식 2ᵗ = 8의 답은 3입니다. 이를 log₂(8) = 3으로 씁니다.

정의와 조건

logₐ(x) = y ⇔ aʸ = x입니다. 실수 로그에서 밑 a는 양수이고 1이 아니어야 하며, 입력 x는 양수여야 합니다. 그래야 aʸ가 서로 다른 y마다 다른 양수 값으로 대응합니다. 밑 1이면 항상 1만 나와 거꾸로 y를 하나로 정할 수 없습니다.

예를 들어 log₂(1) = 0, log₂(1/8) = −3입니다. 음수인 로그 출력은 가능합니다. x = 0이나 −1처럼 양수가 아닌 입력에는 실수 로그를 쓸 수 없습니다. 자연로그 ln은 밑이 e인 로그입니다. Python의 math.log(x)는 밑을 생략하면 자연로그를 계산합니다.

흔한 실수: 밑 없는 log

밑을 적지 않은 log x의 뜻은 분야마다 다릅니다. 한국 고등학교 교과서에서는 밑 10인 상용로그, 수학·통계·머신러닝 논문과 Python·NumPy에서는 대개 자연로그 ln, 정보이론·알고리즘에서는 자주 밑 2입니다. 처음 보는 자료에서는 밑을 먼저 확인합니다.

지수함수와 로그함수는 서로 역함수

정의를 두 번 쓰면 두 항등식이 나옵니다. alogₐ x = x (x > 0), logₐ(aʸ) = y (y는 모든 실수). 하나를 한 뒤 다른 하나를 하면 원래 값으로 돌아오므로 y = logₐ x는 y = aˣ의 역함수입니다. 입력과 출력의 자리가 바뀌므로 정의역과 치역도 서로 바뀝니다. 지수함수는 실수 전체 → 양수, 로그함수는 양수 → 실수 전체입니다. 그래프는 직선 y = x에 대해 대칭입니다.

곱은 로그에서 합이 된다

u = ar, v = as라면 uv = ar+s이므로 logₐ(uv) = logₐ(u) + logₐ(v)입니다. u와 v가 양수일 때의 법칙입니다. 나눗셈은 뺄셈, 양수 u의 거듭제곱 ur은 r을 곱하는 형태가 됩니다.

원래 계산로그로 바꾸면밑 2로 확인
곱 uvlogₐ(u)+logₐ(v)log₂(8×4)=3+2=5
몫 u/vlogₐ(u)−logₐ(v)log₂(8/4)=3−2=1
거듭제곱 uʳr·logₐ(u)log₂(8²)=2×3=6

흔한 오개념

로그는 합을 나누어 계산하지 않습니다. log₂(4 + 4) = 3이지만 log₂(4) + log₂(4) = 4입니다. 확률 모형에서 로그를 쓰더라도 ‘곱’으로 구성됐는지 먼저 확인합니다.

배수에서 경과 시간을 구하기

시작값 100개가 단계당 1.2배가 되어 200개 이상이 되는 첫 정수 단계를 구합니다. 연속 지수 식 100 × 1.2t = 200을 100으로 나누면 1.2t = 2이므로 t = log₁.₂(2)입니다. 계산기와 Python에는 밑 1.2인 로그 버튼이 없으므로 밑을 바꿉니다.

밑 변환 공식 외우기

logₐ(x) = ln(x)/ln(a) = logc(x)/logc(a) (a, c는 양수이고 1이 아님, x > 0)
이유: aʸ = x의 양변에 ln을 취하면 y·ln(a) = ln(x)이고, a ≠ 1이라 ln(a) ≠ 0이므로 나눌 수 있습니다.
따라서 t = ln(2)/ln(1.2) ≈ 0.6931/0.1823 ≈ 3.802입니다.

from math import ceil, log

steps = log(2) / log(1.2)
k = ceil(steps)
print(f"{steps:.3f}", k)
print(f"{100 * 1.2 ** (k - 1):.2f}")
print(f"{100 * 1.2 ** k:.2f}")

실행 결과

3.802 4
172.80
207.36

연속 모델에서는 약 3.802단계이지만 단계가 정수일 때 처음 넘는 값은 4단계입니다. 바로 앞인 3단계도 계산해 경계를 확인합니다. ceil은 수 이상인 정수 중 가장 작은 값으로 올립니다.

로그 눈금 위에서 배수 읽기

log₁₀(1000) − log₁₀(100) = 1입니다. log₁₀(10) − log₁₀(1)도 1입니다. 원래 값의 차이는 900과 9로 다르지만 배수는 둘 다 10입니다. 축의 라벨을 원래 값으로 적었는지 변환값으로 적었는지 확인합니다. 로그 축에서는 0을 양의 관측값처럼 찍을 수 없으므로 데이터를 숨기거나 상수를 더하기 전에 왜 그렇게 표현하는지 기록합니다.

통계로 이어지는 지점

확률을 곱하던 식에 로그를 취하면 양수인 항의 곱이 합으로 바뀝니다. 밑이 e인 로그는 증가함수라 양수 영역에서 큰 값과 작은 값의 순서도 유지합니다. 통계의 우도를 계산할 때 이 두 성질을 함께 씁니다. 값이 0인 확률에 일반적인 실수 로그 함수를 그대로 적용하는 경우는 별도로 다뤄야 합니다.
