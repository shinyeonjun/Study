검색할 때는 탐색 트리, 가장 작은 값은 힙

검색 대상과 가장 작은 항목은 서로 다른 방식으로 찾습니다. 이진 탐색 트리와 최소 힙에서 지키는 규칙을 손으로 확인합니다.

이 장을 읽고 나면

  • 이진 탐색 트리에서 값에 따라 내려갈 방향을 고른다.
  • 인덱스로 최소 힙의 부모와 자식을 찾는다.
  • 탐색 트리의 높이와 힙의 우선순위 동작을 비교한다.

탐색 트리는 왼쪽 전체와 오른쪽 전체를 나눈다

이 장에서는 서로 다른 정수를 키로 씁니다. 이진 탐색 트리의 모든 노드에서 왼쪽 하위 트리의 키는 현재 키보다 작고, 오른쪽 하위 트리의 키는 더 큽니다. 즉 바로 옆의 자식뿐 아니라 그 아래 모든 키까지 비교 규칙이 적용됩니다. 중복 키를 허용하는 구현은 저장하거나 세는 정책을 따로 정합니다.

루트 8에서 6을 찾으려면 6<8이어서 왼쪽 3으로, 다시 6>3이어서 오른쪽 6으로 갑니다. 세 노드를 비교했습니다. 11을 찾으면 8→12→10까지 간 뒤 10의 빈 오른쪽에서 끝납니다. 중위 순회는 작은 쪽 전체, 현재 키, 큰 쪽 전체를 읽으므로 오름차순입니다.

최소 힙은 루트에 항상 최소값을 둔다

최소 힙은 왼쪽부터 채운 완전 이진 트리로 생각할 수 있습니다. 마지막 층을 제외하고 모두 차 있으며, 마지막 층은 왼쪽부터 채웁니다. 빈칸 없는 배열의 0번이 루트라면 i의 자식은 존재할 때 2i+1과 2i+2이고, 거꾸로 i≥1의 부모는 ⌊(i−1)/2⌋(Python으로 (i - 1) // 2)입니다. 부모 키는 각 자식 키 이하입니다. 이 규칙을 부모에서 자식으로 거듭 적용하면 루트 1이 전체에서 가장 작습니다.

아래 배열에서 1, 4, 3의 순서로 나와도 최소 힙입니다. 4와 3은 서로의 조상과 자식 관계가 아니므로 순서를 강제하지 않습니다. 루트에서 최솟값을 읽는 일은 O(1)입니다. 새 값은 끝에 놓고 부모와 비교하며 올립니다. 최솟값을 꺼내고 나면 끝값을 루트에 놓아 더 작은 자식 쪽으로 내려 규칙을 복구합니다. 배열의 용량을 바꾸는 비용을 따로 두면, 두 연산은 최악에도 길이가 O(log n)인 경로 하나만 이동합니다.

같은 데이터라도 자주 할 연산을 보고 고른다

탐색 트리에서 특정 키 하나를 찾는 시간은 한 경로에서 비교한 노드 수에 비례합니다. 균형을 유지해 높이가 로그 규모라면 O(log n)입니다. 평범한 이진 탐색 트리에 키가 늘 한쪽으로만 붙으면 높이에 n개의 노드가 놓여 최악 O(n)입니다. 최소 힙은 최소값을 자주 꺼내는 우선순위 큐에 쓰입니다. 임의의 키를 힙 전체에서 찾는 일은 이 장의 부모 규칙만으로는 최악 O(n)이 걸립니다.

from heapq import heappop

tree = (8, (3, (1, None, None), (6, None, None)),
           (12, (10, None, None), (14, None, None)))

def trace_search(node, target):
    path = []
    while node is not None:
        key, left, right = node
        path.append(key)
        if target == key:
            return True, path
        node = left if target < key else right
    return False, path

heap = [1, 4, 3, 9, 7, 6, 8]
assert all(heap[(i - 1) // 2] <= heap[i] for i in range(1, len(heap)))
print("find 6:", trace_search(tree, 6))
print("find 11:", trace_search(tree, 11))
print("pop:", [heappop(heap) for _ in range(len(heap))])
find 6: (True, [8, 3, 6])
find 11: (False, [8, 12, 10])
pop: [1, 3, 4, 6, 7, 8, 9]
