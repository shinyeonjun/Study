CS05·3

분할 정복으로 작은 답을 합쳐 최댓값 찾기

구간을 둘로 나누고 각각의 최댓값만 가져옵니다. 두 문제를 다시 합치는 비용과 재귀 깊이를 직접 셉니다.

이 장을 읽고 나면

  • 분할·정복·결합 단계에 해당하는 코드를 가리킨다.
  • 배열을 복사하지 않고 인덱스 범위로 나눈다.
  • 깊이와 비교 횟수가 서로 다른 이유를 설명한다.

전체 문제를 같은 방식의 작은 문제로 나눈다

[3,8,2,7,1,4]에서 가장 큰 값 하나가 필요합니다. 분할 정복에서는 먼저 앞 세 칸과 뒤 세 칸으로 분할하고, 각 구간 안에서 다시 같은 최댓값 문제를 풉니다. 왼쪽의 답 8과 오른쪽의 답 7을 비교해 전체 답 8을 얻습니다. 원소가 한 개면 더 나눌 필요가 없고 그 값이 바로 답입니다.

범위를 [lo,hi)로 적어 lo는 포함하고 hi는 제외합니다. mid=(lo+hi)//2로 나누면 [lo,mid)와 [mid,hi)가 겹치지 않고 원래 범위 전체를 덮습니다. [0,6)은 [0,3), [3,6)으로 갈립니다. Python 슬라이스로 배열을 복사하지 않고 원본과 구간의 숫자만 전달할 수 있습니다.

각 결합에서 비교는 한 번이다

왼쪽 [3,8,2]는 [3]과 [8,2]로 나뉩니다. 8과 2를 한 번 비교하고 그 결과 8을 3과 비교하므로 두 번입니다. 오른쪽 [7,1,4]에서도 같은 방식으로 두 번 비교합니다. 마지막 결합을 한 번 더 해 총 5번입니다.

n개를 두 구간으로 나누었을 때 각 구간 길이를 a와 b라 합시다. a+b=n이고, 작은 구간의 비교 수가 a−1과 b−1이면 결합까지 더해 (a−1)+(b−1)+1=n−1입니다. n=1에서 비교 0회인 기저 조건부터 적용되므로 모든 양의 n에서 맞습니다. 층마다 문제의 반을 남기는 한 경로는 로그 규모지만, 두 가지를 모두 풀기 때문에 전체 비교는 선형입니다.

계약에 맞는 빈 입력의 행동을 따로 정한다

아래 구현은 비교 가능한 숫자가 하나 이상 있어야 한다고 정했습니다. 빈 목록에서 0을 대신 반환하면 입력의 모든 값이 음수일 때도 0이 답이라고 혼동하기 쉽습니다. 코드에서는 빈 목록을 명시적으로 거절하고 길이 1부터 재귀를 시작합니다.

def max_with_count(values):
    if not values:
        raise ValueError("need at least one value")

    def solve(lo, hi):
        if hi - lo == 1:
            return values[lo], 0
        mid = (lo + hi) // 2
        left, left_count = solve(lo, mid)
        right, right_count = solve(mid, hi)
        bigger = left if left >= right else right
        return bigger, left_count + right_count + 1

    return solve(0, len(values))

for values in ([3, 8, 2, 7, 1, 4], [-5], [-8, -4, -6]):
    result = max_with_count(values)
    assert result == (max(values), len(values) - 1)
    print(values, "->", result)
[3, 8, 2, 7, 1, 4] -> (8, 5)
[-5] -> (-5, 0)
[-8, -4, -6] -> (-4, 2)

호출 한 번에서 범위 계산과 두 답 합치기가 상수 비용이라 전체 시간은 Θ(n)입니다. 입력과 출력 이외의 공간은 두 자식을 차례로 부를 때 동시에 열려 있는 경로의 길이인 Θ(log n) 규모입니다. 단순한 선형 최댓값 찾기도 비교는 n−1회입니다. 여기서는 분할 정복을 적용하더라도 전체 일이 자동으로 줄지 않는다는 점을 함께 확인합니다. 다음 단원에서는 두 정렬 결과를 합칩니다.
