CS01·2

추적표로 반복문과 개수 세기 검증하기

현재까지 센 값과 아직 읽지 않은 칸을 구분합니다. 반복마다 값이 어떻게 바뀌는지 적고, 마지막 결과가 계약에 맞는 이유를 설명합니다.

이 장을 읽고 나면

  • 반복문에서 바뀌는 값을 추적표에 한 줄씩 기록한다.
  • 아직 확인하지 않은 범위와 이미 맞는 조건을 구분해 정확성을 설명한다.
  • 빈 입력, 경계값, 잘못된 범위를 작은 입력으로 검증한다.

이번에는 끝까지 세고 돌아온다

센서 기록 가운데 기준 범위 안의 값을 모두 셉니다. 정수 하한 lo와 상한 hi가 있을 때 lo ≤ 값 ≤ hi면 한 개를 더합니다. 예로 [2,5,1,4]에서 lo=2, hi=4라면 2와 4가 조건을 만족해 결과는 2입니다. 범위의 끝값도 포함합니다.

먼저 lo>hi이면 범위를 거꾸로 지정한 오류로 처리합니다. 범위가 올바르고 목록이 비어 있다면 0을 반환합니다. 0은 올바른 범위에서 조건에 맞는 값이 없을 때 나오는 정상 결과입니다.

하한이 상한보다 크면 입력 오류로 끝낸다.
count를 0으로 시작한다.
각 값을 앞에서부터 하나씩 읽는다.
    하한 이상이고 상한 이하이면 count에 1을 더한다.
모두 확인한 뒤 count를 반환한다.

추적표에서 반복 전후의 값을 나란히 적는다

추적표는 각 반복에서 어떤 입력을 읽었고 변수에 무슨 변화가 일어났는지 적는 표입니다. i=0에서 첫 2가 범위 안이므로 count는 0에서 1이 됩니다. i=1의 5와 i=2의 1은 지나가고, i=3의 4에서 count는 2가 됩니다.

첫 참에서 반환했던 앞 장과 달리, 이 함수는 참을 찾아도 다음 칸을 봅니다. 안쪽의 조건문에 반환을 넣으면 뒤쪽에 있는 값을 놓칩니다. 마지막 원소 뒤에 반환하는 이유는 입력의 모든 위치를 센다는 약속 때문입니다.

매 반복 앞에서 무엇이 올바른지 확인한다

반복에서 유지되는 조건을 불변식이라 합니다. 이 예에서는 “i번째 칸을 검사하기 직전, count는 이미 본 i개 중 조건을 만족한 개수”입니다. i=0에서는 아직 본 것이 없고 count=0이라 성립합니다. i번째 값이 범위 안이면 1을 더하고, 밖이면 그대로 둡니다. 어느 쪽에서도 이제 본 i+1개의 개수를 올바르게 셉니다. 그렇게 모든 칸을 보면 count가 전체의 정답입니다.

가능한 모든 목록을 시험해 볼 필요 없이 절차가 약속을 지키는 이유를 설명할 수 있습니다. 작은 예제의 추적표로 실수는 찾을 수 있지만 예 몇 개가 구현 전체의 정확성을 대신하는 것은 아닙니다. 빠짐없이 끝나는지도 따로 확인합니다. 이 경우에는 반복에서 새 칸을 하나씩 보고 목록이 유한하므로 끝납니다.

경계 사례와 추적값을 실행해 확인한다

def count_in_band(values, lo, hi):
    if lo > hi:
        raise ValueError("reversed interval")
    count = 0
    trace = []
    for index, value in enumerate(values):
        before = count
        matched = lo <= value <= hi
        if matched:
            count += 1
        trace.append((index, value, matched, before, count))
    return count, trace

result, trace = count_in_band([2, 5, 1, 4], 2, 4)
for row in trace:
    print(*row)
print("total:", result)
assert count_in_band([], 2, 4)[0] == 0
assert count_in_band([2, 2, 1], 2, 2)[0] == 2
try:
    count_in_band([2, 5], 4, 2)
except ValueError as error:
    print(error)
0 2 True 0 1
1 5 False 1 1
2 1 False 1 1
3 4 True 1 2
total: 2
reversed interval

예제는 디버깅을 보여 주려고 추적 기록도 반환합니다. 결과 개수만 필요하다면 trace에 줄을 계속 추가할 필요는 없습니다. 작은 기록으로 중간 상태가 예상한 순서인지 비교합니다.
