공부 교재

자료구조·알고리즘 · CS02 시간과 공간

CS02·1

입력 크기와 비교 횟수, 보조 공간 세기

같은 길이의 자료에서도 어느 칸에서 멈추느냐에 따라 실행 횟수가 달라집니다. 다른 두 값을 짝짓는 반복까지 직접 세고, 실행 횟수와 저장 공간을 나눠 적습니다.

이 장을 읽고 나면

  • 입력 크기 n과 셀 연산의 단위를 먼저 정한다.
  • 같은 길이에서도 첫 일치 찾기의 최선·최악 비교 횟수를 구한다.
  • 겹친 반복에서 실제 실행되는 횟수와 보조 공간을 계산한다.

몇 초가 아니라 어떤 연산을 몇 번 하는지 먼저 정한다

앞 장의 절차처럼 처음으로 기준 이상인 값을 찾습니다. 여기서는 목록 원소 수를 n, 값과 기준을 한 번 대조하는 것을 비교 1회라고 정합니다. 비교하는 수는 크기가 일정한 기계 수처럼 한 번의 비교 비용이 일정하다고 봅니다.

n≥1에서 맨 앞에 일치가 있으면 1회라 최선입니다. 맨 뒤에서야 일치하거나 끝까지 나타나지 않으면 n회로 최악입니다. 빈 목록에는 비교를 하지 않습니다. 최악이라는 말은 이 길이의 가능한 입력 중 가장 많은 연산을 하는 경우를 뜻합니다. 평균을 알려면 입력이 어떻게 나타나는지 가정해야 합니다.

바깥 반복이 움직일 때 안쪽 범위가 줄어드는 경우

대상 n개로 서로 다른 두 개씩 이루어진 쌍을 만듭니다. 순서를 구분하지 않으면 (0,1)과 (1,0)은 같은 쌍이므로 첫 인덱스 i보다 큰 j만 고릅니다. n=4에서 i=0은 3개, i=1은 2개, i=2는 1개, i=3은 0개입니다. 두 반복문 안에 있다고 언제나 n²번 실행되는 것이 아닙니다.

일반적인 연산 횟수는 (n−1)+(n−2)+⋯+1=n(n−1)/2입니다. 순서까지 따져 i≠j를 모두 만들면 n(n−1)개가 되어 두 배입니다. 비교하는 기준을 한 쌍당 한 번으로 두면, 실제 횟수를 프로그램에서 센 값과 대조할 수 있습니다.

증가 속도와 필요한 저장 공간을 따로 말한다

시간 복잡도는 입력이 커질 때 어떤 연산 비용이 얼마나 자라는지를 표현합니다. O(n)은 일정한 크기 이후 비용이 상수배 n 이하라는 상한입니다. Θ(n)은 그 속도로 자라는 위아래의 한계를 함께 나타냅니다. 첫 일치 찾기의 최악 비교는 정확히 n이라 Θ(n)이고, 쌍의 개수를 전부 세는 절차는 큰 n에서 Θ(n²)입니다. 한 번의 실행 시간이나 실제 상수를 이 표기에서 읽을 수는 없습니다.

공간 복잡도를 말할 때는 무엇을 세는지 정합니다. 이 장에서 보조 공간은 기존 입력과 결과 그 자체를 제외하고 계산 중에 추가로 쓰는 자리입니다. 쌍을 하나씩 확인하고 개수만 세면 인덱스와 누적값 몇 개만 있어 O(1)입니다. 만든 쌍 자체를 모두 목록으로 보관해 반환하면 결과 공간은 Θ(n²)입니다.

비교와 쌍 처리 본문의 실행 횟수를 센다

def record_comparisons(values, threshold):
    count = 0
    for value in values:
        count += 1
        if value >= threshold:
            break
    return count

def count_pairs(n):
    count = 0
    for i in range(n):
        for j in range(i + 1, n):
            count += 1
    return count

for n in (4, 8, 16):
    best = record_comparisons(range(n), 0)
    worst = record_comparisons(range(n), n)
    print(f"n={n}: best {best}, worst {worst}, pairs {count_pairs(n)}")
n=4: best 1, worst 4, pairs 6
n=8: best 1, worst 8, pairs 28
n=16: best 1, worst 16, pairs 120

첫 번째 함수는 값과 기준을 대조한 횟수만 셉니다. 두 번째 함수는 i<j인 쌍을 하나씩 지나며 수를 셉니다. 화면에는 초나 밀리초를 출력하지 않습니다.
