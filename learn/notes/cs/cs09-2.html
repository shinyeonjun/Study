자료구조·알고리즘 · CS09 점화식과 알고리즘 복잡도의 증명

CS09·2

병합의 정확한 비교 상한과 비교 정렬의 결정 트리 하한

정렬을 논할 때 전체 시간과 키 비교 횟수를 구별합니다. 병합 정렬의 최대 비교수를 계산하고, 어떤 비교 정렬에도 필요한 비교의 수를 따로 보입니다.

이 장을 읽고 나면

  • 정렬된 두 배열 병합에서 비교 최대 및 실현 예를 찾는다.
  • 병합 정렬의 정확한 최악 비교 점화식을 유도한다.
  • 결정 트리의 잎 수로 비교 정렬의 최악 하한을 증명한다.

머리끼리 비교는 어느 한쪽이 빌 때 끝납니다

CS06의 병합 정렬은 정렬된 왼쪽·오른쪽 배열의 첫 원소 중 작은 것을 내보냅니다. 양쪽이 비지 않은 동안 비교 하나마다 원소가 하나 빠집니다. 두 배열의 길이가 a와 b로 모두 양수라면, a+b−1개의 원소를 내보냈을 때는 남은 원소가 최대 하나라 양쪽에 나뉘어 있을 수 없습니다. 따라서 비교는 최대 a+b−1번입니다.

왼쪽 [1,3,5,7], 오른쪽 [2,4,6,8]에서는 처음 일곱 비교에서 갈아 가며 원소를 빼고 마지막 8만 남습니다. 상한 7을 실제 달성합니다. 반면 왼쪽의 모든 원소가 오른쪽보다 작으면 왼쪽 원소를 빼는 a번으로 비교가 끝납니다. 남은 복사 비용은 키 비교 횟수와 다른 항목입니다.

모든 내부 호출에서 최대를 달성할 수 있는지 확인합니다

n=2ᵐ에서 병합 정렬의 최대 키 비교수를 C(n)이라 합시다. C(1)=0입니다. 각 병합에서 최대 n−1번이므로 C(n)≤2C(n/2)+(n−1)입니다. 등호도 가능합니다. 정렬된 전체 순위에서 홀수 번째 값들은 왼쪽, 짝수 번째 값들은 오른쪽에 두면 두 정렬된 반쪽이 최상위 병합에서 교대로 나옵니다. 양 반쪽 내부는 각각 다시 자기 순위의 홀수·짝수로 재귀 배열합니다. 이렇게 최상위 병합과 아래 병합의 최대를 동시에 맞출 수 있습니다.

깊이 d의 병합은 2ᵈ개입니다. 각 병합은 크기 n/2ᵈ에서 최대 n/2ᵈ−1번 비교하므로 합은 n−2ᵈ입니다. d=0부터 m−1까지 더하면 n·m−(2ᵐ−1)=n log₂n−n+1입니다. n=8의 최악 비교 횟수는 17입니다. 이미 정렬된 길이 8을 같은 방법으로 병합하면 비교수가 12로 더 작을 수 있지만 여전히 결과를 복사하는 작업은 있습니다.

모든 비교 정렬에 있는 잎 수를 셉니다

서로 다른 키를 비교로만 정렬하는 결정적 방법을 생각합니다. 첫 비교의 작다·크다 두 결과가 결정 트리의 가지입니다. 각 잎은 비교 순서를 모두 마친 뒤 출력할 원소 위치의 순열입니다. 서로 다른 상대 순서를 가진 입력은 서로 다른 출력 위치 순열을 요구하므로, 서로 다른 키의 n!가지 순서에 적어도 n!개의 잎이 필요합니다. 최악 비교 횟수가 h인 이진 트리는 최대 2ʰ개의 잎을 갖습니다. 그러므로 h≥⌈log₂(n!)⌉입니다.

이 값의 차수를 보려면 n!의 큰 쪽 ⌊n/2⌋개 인수가 각각 n/2 이상임을 씁니다. 로그는 적어도 ⌊n/2⌋·log₂(n/2)이며, 동시에 인수 n개가 각각 n 이하라서 n log₂n 이하입니다. 따라서 비교 정렬의 최악 하한은 Ω(n log n)입니다. n=8의 잎 하한은 16이며 병합 정렬의 최악 17과 꼭 같은 정수일 필요는 없습니다. 키 값으로 직접 주소나 계수를 정하는 알고리즘은 이 이진 비교 가정 밖입니다.

4개와 8개의 예로 손계산을 검증합니다

from itertools import permutations
from math import factorial

def sorted_and_comparisons(items):
    if len(items) < 2:
        return list(items), 0
    mid = len(items)//2
    left, a = sorted_and_comparisons(items[:mid])
    right, b = sorted_and_comparisons(items[mid:])
    out = []
    i = j = 0
    used = a+b
    while i < len(left) and j < len(right):
        used += 1
        if left[i] <= right[j]:
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    return out + left[i:] + right[j:], used

for n in (4, 8):
    actual = max(sorted_and_comparisons(seq)[1] for seq in permutations(range(1,n+1)))
    already = sorted_and_comparisons(list(range(1,n+1)))[1]
    lower = (factorial(n)-1).bit_length()
    print(n, "sorted:", already, "worst:", actual, "decision lower:", lower)
print("example:", sorted_and_comparisons((1,5,3,7,2,6,4,8)))
4 sorted: 4 worst: 5 decision lower: 5
8 sorted: 12 worst: 17 decision lower: 16
example: ([1, 2, 3, 4, 5, 6, 7, 8], 17)

열거는 작은 n에서 앞 증명의 값을 확인하기 위한 검산입니다. 팩토리얼만큼 입력을 실행하는 방식 자체로 큰 n의 증명을 대신하지 않습니다.
