결정 문제, 검증기, 증명서의 크기

'답이 있는가'를 묻는 질문과 '이 답이 맞는가'를 묻는 질문을 형식적으로 나눕니다. 정점 덮개를 통해 NP의 증명서와 다항시간 조건이 어디에 쓰이는지 먼저 확인합니다.

이 장을 읽고 나면

  • 결정·탐색·최적화가 어떤 출력으로 구분되는지 설명합니다.
  • 인코딩 길이 기준으로 P와 NP의 차이를 적습니다.
  • NP-hard와 NP-complete에서 요구하는 각각의 조건을 구별합니다.

1. 어떤 입력을 YES로 구분할까요?

결정 문제는 각 입력에 YES 또는 NO를 내놓습니다. 입력을 비트 문자열 x로 표현하면 YES 문자열들의 집합을 언어 L이라고 부를 수 있습니다. 어떤 알고리즘이 모든 입력에 대해 멈추고 x∈L일 때만 YES를 내면 L을 결정합니다. 허용된 형식에 맞지 않는 문자열에는 NO를 반환할 수 있습니다. 그래프를 정점과 간선 목록으로 명시하는 표현을 사용하면 입력 크기는 목록을 적는 데 필요한 비트 수입니다.

정점 덮개에서는 무방향 그래프 G=(V,E)를 받습니다. C⊆V가 모든 간선의 끝점 중 하나 이상을 포함하면 C가 정점 덮개입니다. 최적화 문제는 가장 작은 덮개의 크기 또는 집합을 구합니다. 결정 문제 `Vertex Cover`는 G와 정수 k≥0를 받아 |C|≤k인 덮개가 하나라도 있는지 묻습니다. 탐색 문제는 있다면 그런 정점들의 목록을 돌려줍니다. 같은 그래프라도 세 질문의 출력이 다릅니다.

그림에서 {1,3}은 덮개이고 크기는 2입니다. 그림의 간선 01과 23은 끝점을 공유하지 않습니다. 둘을 덮는 데 정점이 각각 하나 필요하므로 크기 1 이하의 덮개는 없습니다. 따라서 이 그래프의 최소 크기는 2이고, k=1인 결정 입력은 NO입니다.

2. 증명서는 간결하고 검사는 빨라야 합니다

P는 결정 알고리즘이 입출력 포함 다항시간, 즉 입력 비트 길이 n에 대해 O(nc) 같은 상한으로 모든 입력에서 동작하는 언어의 집합입니다. 지수 c는 모든 입력에 고정되어야 합니다. 이진수로 정수 k를 적으면 길이는 약 log₂k 비트입니다. 그러므로 k만큼 반복하는 코드는 이 한 변수의 비트 길이와 비교하면 지수시간이 될 수 있습니다.

NP는 아래 조건을 충족하는 다항시간 검증기 V와 문자열 길이에 대한 다항식 p가 존재하는 언어의 집합입니다. 길이 p(|x|) 이하의 입력 w를 증명서라 부릅니다.

x∈L   ⇔   ∃w: |w|≤p(|x|) 그리고 V(x,w)=수락

YES 입력은 적어도 하나의 받아들여지는 증명서가 필요합니다. NO 입력에는 받아들여지는 증명서가 하나라도 생기면 안 됩니다. 증명서는 미리 주어지는 조건이므로, 검증기가 그 증명서를 스스로 찾는 방법까지 포함할 필요는 없습니다. P에 속한 언어에는 입력만 결정해도 되는 검증기를 쓸 수 있어 P⊆NP입니다. P와 NP가 같은지는 미해결입니다.

정점 목록을 명시하는 그래프에서 정점 덮개 증명서는 |V|칸의 0/1 표시 배열로 쓸 수 있습니다. 표시 수를 세어 k와 견주고, 모든 간선마다 적어도 한 끝점의 표시가 1인지 검사합니다. 배열 첨자와 정수 연산을 한 단계로 세는 모형에서는 O(|V|+|E|)입니다. 비트 연산 모형에서도 끝점 번호의 길이와 비교에 필요한 비용은 다항 범위입니다. 다음 검산은 후보 검사와 크기 한도별 부분집합 열거를 함께 돌립니다.

from itertools import combinations

vertices = set(range(4))
edges = [(0,1), (1,2), (2,3), (3,0), (1,3)]

def accepts(candidate, limit):
    return (candidate <= vertices and len(candidate) <= limit
            and all(u in candidate or v in candidate for u,v in edges))

for limit in (1, 2):
    accepted = [subset for r in range(limit+1)
                for subset in combinations(sorted(vertices), r)
                if accepts(set(subset), limit)]
    print("k", limit, "witnesses", accepted)
print("suggested witnesses", accepts({1,3}, 2), accepts({0,2}, 2))
k 1 witnesses []
k 2 witnesses [(1, 3)]
suggested witnesses True False

3. 쉬운 검증과 정해진 난이도

NP-hard는 NP의 모든 언어를 대상 문제로 효율적으로 변환할 수 있다는 성질입니다. 여기서 효율적 변환은 다음 장의 다항시간 변환이며 결정 답 YES/NO를 보존합니다. 대상이 NP에도 속하면 NP-complete(정확히는 이 환원 기준의 NP-완전)입니다. NP-hard임을 보일 때에는 대상에 다항 검증기가 필요하지 않습니다. NP-complete를 보일 때에는 난이도 조건과 검증 가능 조건을 모두 확인합니다. 예를 들어 다항 검증기를 쓴 위 사실은 정점 덮개가 NP에 속한다는 증명입니다. NP-hard를 보이려면 다른 방향의 증명이 더 필요합니다.

낯선 약어를 실행 시간 이름으로 착각하면 없던 결론을 얻게 됩니다. NP의 N은 비결정적 계산 모형을 가리키며, 이 장에서는 동등한 검증기 정의를 사용합니다. 후보를 빠르게 검증할 수 있다고 해서 후보를 다항시간에 찾는 알고리즘이 자동으로 따라오지는 않습니다.
