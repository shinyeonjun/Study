CS08·1

탐욕 규칙이 맞는지 반례와 교환으로 확인하기

동전에서는 가장 큰 값을 골랐다가 손해를 봅니다. 일정표에서는 가장 일찍 끝나는 선택이 왜 안전한지 따져 봅니다.

이 장을 읽고 나면

  • 탐욕법의 한 번 선택 규칙과 전체 목표를 구분한다.
  • 동전 반례에서 두 해의 크기와 비용을 비교한다.
  • 간격 선택에서 한 선택을 바꿔도 최선이 유지되는 이유를 추적한다.

지금 좋아 보이는 선택과 마지막까지 좋은 선택을 구분한다

1원, 3원, 4원 동전이 얼마든지 있습니다. 거스름돈 6원을 만들면서 동전 수를 최소화하려 합니다. 남은 금액에 들어가는 가장 큰 동전을 고르고 그 선택을 되돌리지 않는다면, 먼저 4원을 고릅니다. 2원이 남아 1원을 두 번 더 골라야 합니다.

탐욕법은 매 단계에서 정해 둔 기준으로 가장 좋은 선택을 하고 그것을 이어가는 전략입니다. 위 선택은 4+1+1=6을 제대로 만들었지만 동전이 세 개입니다. 3+3도 6이며 동전은 두 개입니다. 한 개로는 만들 수 없으므로 실제 최소는 두 개입니다. 이 입력 하나로 ‘항상 가장 큰 동전을 고르면 최소’라는 주장을 반박할 수 있습니다.

목표가 구간의 개수라면 가장 일찍 끝나는 것을 먼저 고른다

하나의 실험실을 쓰는 일정이 있습니다. 작업의 구간은 [시작,끝)으로 두어 이전 작업의 끝과 다음 작업의 시작이 같으면 붙여도 됩니다. 각 작업을 나누지 않고 겹치지 않게 선택해 작업의 개수를 최대화하겠습니다. 먼저 시작하는 A를 고르면 5까지 차지해 아래 다른 구간을 모두 막습니다. 반면 B,C,D,E를 이어 붙일 수 있습니다.

이 문제에서 안전한 탐욕 선택은 가장 일찍 끝나는 구간입니다. 어떤 최선의 일정에서 첫 구간의 끝이 t라면, 가장 빨리 끝나는 구간의 끝 s는 s≤t입니다. 첫 구간을 그것으로 바꾸어도 t 이후에 시작하는 나머지 작업은 여전히 진행 가능합니다. 따라서 가장 빨리 끝나는 구간으로 시작하는 최선도 하나는 있습니다. 남은 시간에서 같은 논리를 반복합니다. 이 설명은 각 작업의 가치가 같고 구간을 겹치게 고르지 않는 문제에 적용합니다.

작은 입력에서 탐욕 결과와 완전 탐색의 결과를 대조한다

동전은 큰 것부터 하나씩 넣습니다. 출력에는 고른 동전 목록과 남은 금액을 함께 표시합니다. 각 일정의 시작 시각이 종료 시각보다 빠르다고 두고, 종료 시각으로 정렬한 뒤, 직전에 고른 작업이 끝났을 때 시작할 수 있는 다음 작업을 고릅니다. 작은 입력에서 가능한 모든 조합을 따로 확인한 결과도 붙입니다. 일정 수가 많아지면 조합을 전부 확인하는 비용이 크게 늘어납니다.

from itertools import combinations

def pick_large(coins, target):
    chosen = []
    for coin in sorted(coins, reverse=True):
        while coin <= target:
            chosen.append(coin)
            target -= coin
    return chosen, target

jobs = [("A", 0, 5), ("B", 1, 2), ("C", 2, 3),
        ("D", 3, 4), ("E", 4, 7)]

def pick_early_finish(jobs):
    chosen = []
    for name, start, end in sorted(jobs, key=lambda job: job[2]):
        if not chosen or start >= chosen[-1][2]:
            chosen.append((name, start, end))
    return chosen

def fits(selection):
    ordered = sorted(selection, key=lambda job: job[1])
    return all(a[2] <= b[1] for a, b in zip(ordered, ordered[1:]))

best_count = max(size for size in range(len(jobs) + 1)
                 if any(fits(s) for s in combinations(jobs, size)))
selected = pick_early_finish(jobs)
print("coins:", *pick_large([1, 3, 4], 6))
print("schedule:", [name for name, _, _ in selected])
print("exhaustive schedule size:", best_count)
assert fits(selected) and len(selected) == best_count
coins: [4, 1, 1] 0
schedule: ['B', 'C', 'D', 'E']
exhaustive schedule size: 4

실제 일정 탐욕법은 종료 시각 정렬 뒤 한 번 훑기 때문에 비교 정렬로 O(n log n)입니다. 전체 조합 검사는 이 작은 예에서 결과를 대조하는 데만 씁니다. 다른 동전 값이나 더 높은 보상이 붙은 일정에서 같은 규칙의 정당성을 쓰려면 문제의 조건부터 다시 확인합니다.
