CS08·3

결정 문제에서 답을 찾기와 검증하기

작은 답안을 받으면 바로 검사할 수 있는 문제를 다룹니다. 입력을 다른 문제로 바꾸는 환원의 방향과 P 대 NP가 묻는 것을 확인합니다.

이 장을 읽고 나면

  • 결정 문제와 ‘예’의 증명으로 쓸 후보를 구분한다.
  • 다항 시간 검증과 다항 시간 풀이의 차이를 설명한다.
  • 작은 환원에서 ‘예/아니오’가 보존되는지 확인한다.

질문은 예 또는 아니오로 끝난다

숫자 [2,4,5]에서 각 항목을 최대 한 번씩 써서 합이 6이 되는 부분집합이 있나요? 이처럼 답이 예 또는 아니오인 질문을 결정 문제라고 합니다. 몇 개를 골라야 하는지를 최소화하는 대신, 주어진 조건을 만족하는 선택이 하나라도 있는지 묻습니다.

이 경우 위치 [0,1]을 후보로 받으면 두 번호가 범위 안이고 서로 다른지 확인하고, 2+4=6을 계산합니다. 이처럼 예를 확인하게 해 주는 후보가 증명서입니다. 후보 [0,2]는 합 7이라 실패하지만, 그 후보 하나가 틀렸다는 사실은 전체 입출력 질문의 답이 ‘아니오’임을 보이지 않습니다. 후보를 새로 찾아야 할 수 있습니다.

판정기의 속도와 검증기의 속도를 따로 잰다

P는 입력의 길이 n에 대해 다항 시간, 예를 들어 O(n³) 안에 답을 직접 구하는 결정 문제의 모임입니다. 여기서 길이는 입력을 나타낸 비트의 수입니다. NP는 ‘예’인 입력마다 길이가 n의 다항식 이내인 올바른 증명서가 있고, 입력과 증명서를 받아 그 타당성을 다항 시간에 확인할 수 있는 결정 문제의 모임입니다. ‘아니오’인 입력에서는 어떤 증명서를 줘도 검증기가 승인하지 않습니다.

P 문제는 증명서 없이 답을 직접 판정할 수 있어 NP에도 속합니다. 반대 방향, 즉 이렇게 검증 가능한 결정 문제가 모두 P에 속하는지는 아직 풀리지 않은 P 대 NP 문제입니다. 부분집합 합은 후보에 적힌 인덱스와 덧셈으로 쉽게 검증할 수 있습니다. 하지만 작은 사례에서 모든 조합을 빠르게 살피는 일이, 임의 크기의 입력에 대한 다항 시간 알고리즘을 증명하지는 않습니다.

문제를 풀 수 있는 도구에 넘기도록 질문을 바꾼다

환원 A→B는 A의 입력을 B의 입력으로 바꾸어 원래 답이 예일 때 그리고 그때에만 새 답도 예가 되게 하는 방식입니다. 변환 자체가 다항 시간이라면, B를 다항 시간에 푸는 풀이기로 A도 다항 시간에 풉니다. 따라서 A의 다항 시간 풀이가 불가능하다는 사실을 안다면 B의 다항 시간 풀이도 불가능하다고 결론을 내릴 수 있습니다. 이 추론에는 A에서 B로 가는 환원이 필요합니다.

예로 각 물건을 한 번 이하로 선택하며 무게 합은 용량 이하, 가치 합은 최소 가치 이상인지를 묻는 배낭 결정 문제가 있다고 합시다. 입력이 양의 정수 목록과 음이 아닌 정수 목표 T인 부분집합 합을 생각합니다. 숫자 a마다 무게 a, 가치 a인 물건을 만들고 용량과 최소 가치를 목표 T로 둡니다. 그러면 같은 합을 동시에 T 이하이자 T 이상으로 만들어야 해서 정확히 T여야 합니다. 숫자 목록을 두 번 적는 정도의 변환입니다.

def valid_indices(items, selection):
    return (all(type(i) is int and 0 <= i < len(items) for i in selection)
            and len(selection) == len(set(selection)))

def subset_certificate(numbers, target, selection):
    return (valid_indices(numbers, selection)
            and sum(numbers[i] for i in selection) == target)

def knapsack_certificate(weights, values, capacity, goal, selection):
    return (valid_indices(weights, selection)
            and sum(weights[i] for i in selection) <= capacity
            and sum(values[i] for i in selection) >= goal)

numbers = [2, 4, 5]
target = 6
weights = values = tuple(numbers)
for selection in ([0, 1], [0, 2], [0, 0, 0]):
    left = subset_certificate(numbers, target, selection)
    right = knapsack_certificate(weights, values, target, target, selection)
    print(selection, left, right)
    assert left == right
[0, 1] True True
[0, 2] False False
[0, 0, 0] False False

코드는 세 후보를 같은 방식으로 검증합니다. 환원이 이 범위의 모든 입력에서 성립하는 이유는 한쪽의 합이 T일 때, 그리고 그때에만 다른 쪽의 두 조건을 동시에 만족한다는 계산입니다. NP-완전은 NP에 속하면서 NP의 모든 문제가 자신으로 다항 시간 환원되는 문제를 뜻합니다. 예를 들어 논리식에 참이 되게 하는 참·거짓 배정이 있는지 묻는 SAT가 여기에 속합니다. NP에 속하는지는 따지지 않고 두 번째 조건만 만족하는 문제는 NP-난해라고 합니다. NP-완전 문제 하나를 다항 시간에 풀 수 있다면 P=NP가 됩니다.

부분집합 합은 NP-완전으로 알려져 있습니다. 그러므로 위의 환원(부분집합 합 → 배낭 결정 문제)은 배낭 결정 문제도 NP-난해임을 보이고, 배낭 결정 문제는 증명서(선택한 인덱스)로 다항 시간에 검증되므로 NP-완전입니다. 앞 장의 동전 DP처럼 목표값 T에 비례하는 표를 쓰는 O(nT) 풀이가 있어도, T는 입력 비트 수에 대해 지수적으로 클 수 있으므로 이것이 P=NP를 뜻하지는 않습니다.

계산이 오래 걸리는 문제와, 모든 입력에서 종료하면서 옳은 답을 내는 알고리즘 자체가 없는 문제도 구분합니다. 유한 목록의 부분집합 합은 모든 선택을 차례대로 검사하면 결국 결정할 수 있습니다. 반면 임의의 프로그램과 입력이 주어졌을 때 실행이 끝날지 항상 판정하는 일반적인 정지 문제는 결정 불가능합니다.
