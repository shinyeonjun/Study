CS03·1

배열의 위치를 계산하고 연결 리스트를 따라가기

나란히 놓인 배열의 자리를 계산해 보고, 연결 리스트에서는 어떤 노드로 이동하는지 확인합니다. 같은 값을 삽입할 때 왜 움직이는 것이 다른지 봅니다.

이 장을 읽고 나면

  • 배열의 위치 번호에서 저장 자리를 계산한다.
  • 연결 리스트의 노드에서 값을 읽고 다음 노드로 이동한다.
  • 위치를 찾는 비용과 그 위치에 삽입하는 비용을 구분한다.

위치 번호로 바로 찾아갈 수 있는 배열

같은 크기의 자리들이 연달아 있다고 합시다. 시작 주소가 1000, 한 자리가 8바이트라면, 0부터 센 자리 i의 주소는 1000+8i입니다. 위치 2는 1016입니다. 이 장에서 정한 기계 모형에서는 i가 범위 안일 때 자리로 직접 가는 임의 접근이 Θ(1)입니다.

고정 크기의 배열에서는 확보한 자리 수를 넘겨 쓰면 안 됩니다. Python의 일반적인 리스트는 끝에 원소를 이어 붙일 수 있습니다. CPython은 원소를 가리키는 참조들의 크기 변경 가능한 배열로 리스트를 구현합니다. 자리가 부족할 때 더 넓은 배열로 옮기는 비용이 생길 수 있습니다. 여러 번의 끝 추가를 함께 셀 때에는 그런 드문 비용을 나누어 보는 분할상환 관점으로 보통 O(1)이라고 설명합니다. 한 번의 추가가 늘 같은 비용이라는 뜻은 아닙니다.

중간에 끼우면 뒤쪽 자리를 이동한다

[A,B,C]의 B 앞에 X를 넣으려고 하며, 맨 뒤에 빈자리가 하나 있다고 합시다. 순서를 보존하려면 C를 위치 2에서 3으로, B를 위치 1에서 2로 옮기고 X를 위치 1에 씁니다. 오른쪽부터 옮겨야 기존 B나 C를 덮어쓰지 않습니다.

배열의 중간 삽입에는 위치를 찾은 뒤에도 이동이 필요합니다. n개에서 i 앞에 추가하고 기존 순서를 유지하면, 자리가 충분한 경우 뒤에 있는 n−i개를 한 칸씩 옮깁니다. 반면 원래 원소 하나를 새 값으로 바꾸기만 하면 나머지 자리를 옮길 필요가 없습니다.

다음으로 가는 곳을 각 노드에 기록한다

단일 연결 리스트에서 각 노드에는 현재 값과 다음 노드를 가리키는 참조가 있습니다. 맨 처음 노드를 머리라고 합니다. 다음 노드가 없으면 끝입니다. 배열처럼 주소를 식으로 계산하지 않고, 앞에서부터 연결을 따라 위치에 갑니다. 머리에서 인덱스 2의 노드를 보려면 연결을 두 번 건넙니다. 임의의 위치를 찾는 데 가장 오래 걸리면 Θ(n)입니다.

A 뒤에 넣으려면 먼저 X가 가리킬 다음을 기존 A의 다음인 B로 둡니다. 그 뒤 A의 다음을 X로 바꿉니다. 이미 A를 찾았으면 이 연결 변경 자체는 Θ(1)입니다. 어느 값 뒤에 넣을지 찾아야 한다면 앞에서 찾아가는 시간이 더해집니다. 노드를 여러 곳에서 가리킬 수 있으니 입력을 변경할 때 어떤 참조를 바꾸는지도 확인합니다.

두 삽입에 들어가는 동작을 실행한다

slots = ["A", "B", "C", None]
moves = 0
for i in range(2, 0, -1):
    slots[i + 1] = slots[i]
    moves += 1
slots[1] = "X"
print("array:", slots, "moves:", moves)

# A node is stored as [value, next_node].
head = ["A", ["B", ["C", None]]]
node = head
for _ in range(2):
    node = node[1]
print("position 2 before insertion:", node[0])

head[1] = ["X", head[1]]
values = []
node = head
while node is not None:
    values.append(node[0])
    node = node[1]
assert slots == values
print("linked:", values)
array: ['A', 'X', 'B', 'C'] moves: 2
position 2 before insertion: C
linked: ['A', 'X', 'B', 'C']

노드를 [값, 다음 노드]로 간단히 표현했습니다. 연결 리스트가 쓰는 실제 Python 자료구조를 바깥 목록의 인덱스로 바로 찾을 수 있다는 뜻은 아닙니다. 코드는 node[1]을 따라 이동합니다.
