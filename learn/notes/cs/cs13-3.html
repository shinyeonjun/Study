어려운 문제의 작은 예산을 정확히 풀기

NP-완전인 정점 덮개도 입력이 작거나 해의 크기 상한이 작을 때는 효율적으로 풀 수 있습니다. 덮어야 할 간선 한 개로 경우를 제한하는 방법을 증명하고, 독립적인 전수 열거로 재귀 함수의 정답을 검사합니다.

이 장을 읽고 나면

  • 미포함 간선의 양 끝점을 기준으로 분기하는 이유를 증명합니다.
  • 분기 노드 수를 해 크기 상한 k로 계산하고 다항시간과 구별합니다.
  • 간단한 종료 조건과 하한으로 합성 문제를 검산합니다.

1. 각 노드에서 반드시 처리해야 할 간선을 하나 고릅니다

결정 문제는 무방향 그래프에 크기 k 이하의 정점 덮개가 있는지 묻습니다. 실제 코드는 덮개가 있으면 집합을 반환합니다. 모든 정점 부분집합을 생성하면 후보 수가 2|V|개입니다. 상한이 작다면 후보를 덜 생성할 수 있습니다. 핵심은 아무 정점이나 다음 선택으로 시도하는 대신, 아직 덮지 못한 간선 (u,v) 하나를 고르는 것입니다. 어떤 가능한 덮개도 u나 v 중 적어도 하나를 포함합니다.

첫 번째 분기에서는 u를 골라 u와 맞닿은 간선을 모두 제거하고 남은 예산을 k−1로 줄입니다. 두 번째에서는 v로 같은 일을 합니다. 재귀 호출의 결과에 이번 정점을 더하면 원래 간선 중 이번에 지운 간선과 남은 간선을 모두 덮습니다. 반대로 주어진 어떤 해에 u가 있으면 u를 고른 분기에서 그 정점을 제외한 나머지 해가 줄어든 그래프와 예산을 만족합니다. u가 없으면 v에 같은 논증을 적용합니다. 두 방향을 합치면 분기가 정확합니다.

남은 간선이 없으면 선택을 더 하지 않고 성공합니다. 간선이 남았고 예산이 0이면 실패합니다. 이 순서로 검사하면 마지막 선택에 정확히 예산을 소진하고도 성공할 수 있습니다. 예산 k가 입력에서 음수일 수 있는 일반 구현은 처음에 입력을 검증해야 합니다. 아래 예제는 음수가 아닌 정수만 받습니다.

2. 상한 2가 왜 부족한가요?

원본 간선 순서가 01, 12, 23, 34, 04인 오각형에서 먼저 01을 처리합니다. 0을 고르면 01과 04가 사라지고 12가 남은 첫 간선입니다. 1을 고르면 01과 12가 사라지고 23이 남은 첫 간선입니다. 남은 예산 1에서 두 끝점을 나눠 확인한 결과는 그림 2입니다.

상한 3에서는 0, 1을 고른 뒤 23에서 3을 선택하면 23과 34가 모두 사라집니다. 한편 23에서 2를 먼저 고르면 34가 남아 그 가지는 실패합니다. 함수는 실패 시 원본 간선을 되돌리는 대신 각 호출에 새로 걸러진 간선 리스트를 넘깁니다. 근사 풀이가 필요하다면 다른 설계가 필요합니다. 여기서는 찾은 덮개가 실제로 가능한지와 실패가 정확히 불가능을 뜻하는지를 모두 증명합니다.

3. k가 작다는 조건과 독립 검증

분기마다 예산 1을 쓰므로 최대 깊이는 k입니다. 깊이 d의 호출은 최대 2d개라 전체 호출 수는 1+2+…+2k=2k+1−1 이하입니다. 각 호출에서 간선을 다시 거르고 성공한 경로의 정점 목록을 최대 |V|개까지 복사하므로 시간 상한은 O(2k(|V|+|E|))입니다. k를 고정하면 그래프 크기에 대해 다항이고, k가 입력과 함께 늘 수 있으면 이 상한 역시 지수적으로 늘 수 있습니다. 문제의 최악 난이도와 작은 k의 입력을 푸는 비용은 이렇게 함께 설명할 수 있습니다.

또 다른 안전한 가지치기는 끝점을 공유하지 않는 미덮개 간선들을 모아 하한을 얻는 방법입니다. 그런 간선이 b개라면 어떤 한 정점도 그중 두 간선을 동시에 덮지 못합니다. b가 남은 예산보다 크면 그 노드는 실패입니다. 하한이 k 이하인 경우는 아직 더 확인해야 합니다. 오각형에서 서로 끝점이 다른 간선을 둘 고를 수는 있지만 그것만으로 상한 2에 대한 답을 정할 수 없습니다.

from itertools import combinations

def find_cover(edges, budget):
    calls = 0

    def search(remaining, left):
        nonlocal calls
        calls += 1
        if not remaining:
            return []
        if left == 0:
            return None
        for selected in remaining[0]:
            leftover = [edge for edge in remaining if selected not in edge]
            chosen = search(leftover, left - 1)
            if chosen is not None:
                return [selected] + chosen
        return None

    return search(edges, budget), calls

cycle = [(0,1),(1,2),(2,3),(3,4),(0,4)]
for k in (2, 3):
    result, calls = find_cover(cycle, k)
    print("k", k, "answer", result, "calls", calls)

vertices = range(5)
all_edges = list(combinations(vertices, 2))
subsets = [set(c) for r in range(6) for c in combinations(vertices, r)]
checked = 0
for mask in range(1 << len(all_edges)):
    edges = [edge for i, edge in enumerate(all_edges) if mask & (1 << i)]
    optimum = min(len(c) for c in subsets
                  if all(u in c or v in c for u, v in edges))
    for k in range(6):
        witness, _ = find_cover(edges, k)
        assert (witness is not None) == (optimum <= k)
        if witness is not None:
            assert len(witness) <= k
            assert all(u in witness or v in witness for u, v in edges)
        checked += 1
print("checked decisions", checked)
k 2 answer None calls 7
k 3 answer [0, 1, 3] calls 5
checked decisions 6144

정점 다섯 개에서는 가능한 무방향 간선이 10개입니다. 간선마다 있고 없고를 고르는 210개 그래프에 여섯 가지 k를 검사해 6144건을 대조했습니다. 코드는 작은 무방향 단순 그래프에서 증명과 구현이 맞는지 확인합니다. 더 큰 그래프에서는 하한을 쓰거나 여러 분기 구조를 비교할 수 있지만, 이 검산이 실행 시간의 일반적인 성능 보장을 제공하지는 않습니다.
