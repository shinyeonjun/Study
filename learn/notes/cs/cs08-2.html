CS08·2

남은 금액을 상태로 만들고 작은 답을 재사용하기

동전 6원을 만드는 최선의 해를 구합니다. 같은 남은 금액의 답을 한 번만 계산하도록 메모하고, 표를 직접 채우는 방법과 비교합니다.

이 장을 읽고 나면

  • 최적화 문제에서 상태가 담아야 할 정보를 정한다.
  • 마지막 동전의 후보로 점화식과 기저 조건을 만든다.
  • 메모이제이션과 작은 상태부터 채우는 표를 비교한다.

앞에서 무엇을 골랐는지 중 꼭 필요한 정보만 남긴다

1원, 3원, 4원 동전이 얼마든지 있을 때, x원을 정확히 만드는 최소 동전 수를 best[x]로 정합니다. 앞으로 골라도 되는 종류나 동전 재고가 지난 선택에 따라 변하지 않으므로, 앞으로 만들 금액 x만 있으면 같은 문제입니다. 이렇게 아직 풀어야 하는 부분을 숫자나 튜플로 표현한 것이 상태입니다.

금액 0은 동전 0개로 만듭니다. x>0이면 마지막 동전 c를 골랐다고 가정하고, 남은 x−c를 최소 개수로 만든 뒤 1개를 더합니다. 가능한 모든 c≤x의 1 + best[x-c] 중 가장 작은 값이 답입니다. 정확히 만들 수 없는 상태는 ∞로 적습니다. ∞에 동전 한 개를 더해도 만들 수 있는 조합은 생기지 않습니다.

다른 경로에서도 같은 상태를 다시 쓴다

6원을 풀다가 마지막 동전이 1원이면 5원으로 가고, 마지막이 3원이면 3원으로 갑니다. 5원에서도 3원을 빼 2원을 만들 수 있고, 3원에서도 1원을 빼 2원 문제를 부를 수 있습니다. 이때 2원 문제의 답은 두 경로에서 같습니다.

상태별 답을 기록하고 같은 상태를 요청받으면 저장된 답을 쓰는 기술이 메모이제이션입니다. 상태별로 정의한 부분문제의 답을 재사용해 전체를 푸는 방법을 동적 계획법(DP)이라고 합니다. 큰 상태부터 재귀로 필요한 것만 요청해도 되고, 작은 것부터 표를 만들어 놓고 값을 읽어도 됩니다.

점화식은 같고 계산 순서만 다르다

예제는 양의 정수 동전과 0 이상 정수 목표를 받습니다. 재귀 쪽은 같은 금액의 결과를 cache로 저장하고, 표 쪽은 x보다 작은 금액을 먼저 채웁니다. 재귀 호출의 입력은 매번 줄어듭니다. 모든 값을 미리 채우는 구현에서는 목표가 T이고 동전 종류가 k일 때 상태 T+1개마다 최대 k종류를 확인해 O(Tk) 시간, O(T) 표 공간이 듭니다.

from functools import cache
from math import inf

def top_down(coins, target):
    @cache
    def solve(amount):
        if amount == 0:
            return 0
        return min((1 + solve(amount - c) for c in coins if c <= amount),
                   default=inf)
    return solve(target)

def bottom_up(coins, target):
    best = [0] + [inf] * target
    for amount in range(1, target + 1):
        best[amount] = min((1 + best[amount - c] for c in coins if c <= amount),
                           default=inf)
    return best

coins = (1, 3, 4)
best = bottom_up(coins, 6)
print("table:", best)
print("memoized:", top_down(coins, 6))
print("unreachable:", bottom_up((3, 4), 2)[2] == inf)
assert best[-1] == top_down(coins, 6) == 2
table: [0, 1, 2, 1, 1, 2, 2]
memoized: 2
unreachable: True

동전마다 수량이 제한되면 같은 x라도 남은 재고에 따라 후보가 달라집니다. 예로 각 동전 항목을 한 번만 쓸 수 있을 때는 x와 함께 앞으로 검토할 항목의 위치를 상태에 넣을 수 있습니다. 또한 T칸을 만든다는 복잡도는 T의 값에 대한 것입니다. 이진수로 T를 적는 데 필요한 자릿수에 대해 T가 지수적으로 커질 수 있으므로, O(Tk)를 입력 비트 수에 대한 다항 시간이라고 단정하지 않습니다.
