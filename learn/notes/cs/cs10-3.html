CS10·3

서로소 집합의 합치기와 경로 압축을 비용으로 확인하기

키의 순서는 잊고 같은 그룹에 있는지만 빠르게 묻습니다. 부모 포인터와 그룹 크기를 써서 합치고, 찾을 때 먼 포인터를 짧게 고칩니다.

이 장을 읽고 나면

  • union–find가 나타내는 분할과 부모 숲의 불변식을 설명한다.
  • 크기에 따른 합치기와 경로 압축의 효과를 각각 증명한다.
  • 별도의 그래프 탐색으로 무작위 합치기·질의 결과를 대조한다.

동일한 그룹에 있으면 같은 루트로 연결합니다

원소 0~7을 처음에 하나씩 다른 그룹으로 둡니다. 자료구조의 find는 부모 포인터를 따라 자기 자신을 가리키는 루트를 찾습니다. union은 두 루트가 다를 때 하나를 다른 것 아래에 붙입니다. 모든 노드가 루트 하나에 닿고, 같은 집합에서만 같은 대표를 얻는다는 것이 핵심 불변식입니다. 대표에 붙은 숫자는 그룹을 부르는 한 방법이며 가장 작아야 한다는 규칙은 없습니다.

이 장의 예에서는 크기가 같은 두 집합을 합칠 때 첫 번째 인자의 루트를 남깁니다. (0,1),(2,3),(4,5),(6,7) 뒤에 (0,2),(4,6),(0,4)를 합칩니다. 7의 부모는 6, 6의 부모는 4, 4의 부모는 0입니다. find(7)의 결과는 0입니다.

작은 집합을 큰 쪽 아래에 붙이면 깊이가 제한됩니다

크기에 따른 합치기는 작은 집합의 루트를 큰 집합의 루트 아래로 옮깁니다. 깊이가 늘어나는 원소는 붙이는 쪽에 속합니다. 그 원소가 속한 새 집합은 예전 크기의 최소 두 배입니다. 어떤 원소의 깊이가 h번 늘었다면 그 성분은 최소 2ʰ개를 가집니다. 원소가 n개라면 깊이가 ⌊log₂n⌋를 넘지 않습니다.

find로 방문한 경로의 원소들을 루트에 직접 연결하는 경로 압축은 집합을 유지하면서 그다음 찾기를 짧게 할 수 있습니다. find(7) 뒤에 7과 6은 0을 가리킵니다. 경로에 없던 3은 이전과 같이 2를 볼 수 있습니다. 압축으로 연결이 바뀌어도 서로소 집합의 구성은 바뀌지 않습니다.

합치지 않는 구간의 비용을 먼저 제한합니다

부모 숲을 한 번 만든 뒤에는 더 합치지 않고 q번 찾기만 한다고 합시다. 루트까지 길이 k인 찾기는 간선 k개를 읽습니다. 그중 마지막 간선을 빼면, 루트에 직접 연결되어 있지 않던 k−1개의 원소의 부모를 루트로 바꿉니다. 이후 합치지 않으므로 이 원소가 같은 종류의 변경을 다시 겪지 않습니다. 이러한 변경은 전체 n개 원소에서 최대 n−1번입니다. 각 find의 마지막 간선에 최대 1번씩을 더하면 전체 간선 읽기는 q+n−1 이하입니다. 이 보장은 어떤 순서로 찾았는지에 대한 확률을 요구하지 않습니다.

합치기가 계속되면 어떤 원소의 현재 루트도 나중에 다른 루트 아래로 들어가므로 위의 ‘한 번만’ 논리가 그대로 적용되지 않습니다. 경로 압축과 크기·순위에 따른 합치기를 함께 분석하면, 초기화도 포함해 n개 원소와 m번 연산을 보통 O((n+m)α(n))으로 쓸 수 있습니다. α는 아주 느리게 증가하는 역 아커만 함수입니다. 이 강한 상계는 연산열에 대한 별도의 정리이며, 앞의 변경 횟수 계산은 합치기 없는 구간만 증명했습니다.

같은 연결을 작은 그래프의 탐색으로 검산합니다

from random import Random

class Groups:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1]*n

    def find(self, x):
        p = self.parent[x]
        if p != x:
            self.parent[x] = self.find(p)
        return self.parent[x]

    def union(self, x, y):
        a,b = self.find(x),self.find(y)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a,b = b,a
        self.parent[b] = a
        self.size[a] += self.size[b]

example = Groups(8)
for x,y in [(0,1),(2,3),(4,5),(6,7),(0,2),(4,6),(0,4)]:
    example.union(x,y)
print("before:", example.parent)
print("find 7:", example.find(7))
print("after:", example.parent)

def reachable(graph, start):
    pending = [start]
    seen = {start}
    while pending:
        new = graph[pending.pop()] - seen
        pending.extend(new)
        seen.update(new)
    return seen

n = 12
groups = Groups(n)
graph = [set() for _ in range(n)]
rng = Random(108)
for _ in range(40):
    x,y = rng.randrange(n),rng.randrange(n)
    groups.union(x,y)
    graph[x].add(y)
    graph[y].add(x)
    for u in range(n):
        expected = reachable(graph,u)
        assert all((groups.find(u) == groups.find(v)) == (v in expected)
                   for v in range(n))
print("checked snapshots:", 40)
before: [0, 0, 0, 2, 0, 4, 4, 6]
find 7: 0
after: [0, 0, 0, 2, 0, 4, 0, 0]
checked snapshots: 40

두 방식은 표현이 다릅니다. 첫 방식은 숲의 대표, 둘째는 실제로 추가한 연결을 탐색합니다. 각 시점에서 모든 원소 쌍의 결과를 비교했으므로, 작은 예에서 어느 중간 합치기가 틀렸는지 재현할 수 있습니다.
