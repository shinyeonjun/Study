CS03·2

스택과 큐의 꺼내는 순서 비교하기

넣는 순서는 그대로 두고 꺼내는 규칙만 바꿔 봅니다. 괄호를 닫는 일과 대기 작업을 처리하는 일에서 각각 어떤 자료형이 맞는지 고릅니다.

이 장을 읽고 나면

  • 스택과 큐에서 추가와 삭제가 어느 쪽에서 일어나는지 설명한다.
  • 같은 입력이라도 삭제 규칙에 따라 처리 순서가 어떻게 바뀌는지 손으로 확인한다.
  • 자료형의 동작 약속과 Python에서 이를 구현하는 비용을 구분한다.

나중에 넣은 것부터 꺼낼지, 먼저 넣은 것부터 꺼낼지

A를 넣고 나서 B를 넣었습니다. 스택에서는 마지막에 들어온 B를 먼저 꺼냅니다. 후입선출, 또는 LIFO라고 합니다. 추가와 삭제는 같은 끝인 꼭대기에서 일어납니다. 큐에서는 먼저 들어온 A를 먼저 꺼냅니다. 선입선출, 또는 FIFO입니다. 뒤쪽으로 넣고 앞쪽에서 뺍니다.

첫 삭제 후 C를 새로 넣고 다시 두 번 뺍니다. 스택에 남은 A 위로 C가 들어가므로 전체 출력은 B,C,A입니다. 큐에 남은 B 뒤에 C가 들어가므로 A,B,C입니다. 저장 방식과 독립적으로 제공하는 동작과 각각의 동작이 지킬 규칙을 정하면 추상 자료형이 됩니다. 스택과 큐는 모두 추가와 삭제를 제공하고, 그중 삭제할 항목을 고르는 규칙이 다릅니다.

최근에 연 괄호를 기억하는 스택

문자열 ([])의 여는 괄호를 만나면 스택 꼭대기에 넣습니다. 닫는 괄호를 만나면 꼭대기의 여는 괄호와 짝이 맞아야 합니다. ]가 왔을 때 꼭대기는 [여서 제거하고, )가 오면 남은 (를 제거합니다. 끝에서 스택이 비면 모든 괄호의 짝이 맞습니다.

([)]는 )가 왔을 때 [가 꼭대기여서 틀립니다. 닫는 괄호가 오는데 이미 비어 있거나, 끝까지 읽고 여는 괄호가 남아도 실패입니다. 예제는 소괄호와 대괄호를 대상으로 하며, 그 외 문자는 건너뜁니다.

동작을 구현하는 저장 방식에 따라 비용을 판단한다

Python 리스트의 append와 인자 없는 pop을 같은 끝에 쓰면 스택이 됩니다. 큐도 리스트로 append와 pop(0)를 조합할 수 있지만, 맨 앞 원소를 빼면 남은 원소가 앞으로 이동합니다. 원소가 n개일 때 앞 삭제 한 번에서 최대 n−1개의 자리가 옮겨지는 이유입니다.

표준 라이브러리 collections.deque는 양 끝 추가·삭제를 지원합니다. append와 popleft를 조합해 큐를 구현하면 양 끝에서 일반적으로 O(1) 비용으로 접근합니다. 입력이 비었을 때 뺄 수 없는 조건은 코드를 짤 때 따로 확인해야 합니다. Python의 빈 리스트에서 pop()을 호출하거나 빈 덱에서 popleft()를 호출하면 IndexError가 납니다.

삭제 순서와 괄호 세 사례를 검산한다

from collections import deque

stack = []
queue = deque()
for item in ("A", "B"):
    stack.append(item)
    queue.append(item)
stack_out = [stack.pop()]
queue_out = [queue.popleft()]
stack.append("C")
queue.append("C")
while stack:
    stack_out.append(stack.pop())
while queue:
    queue_out.append(queue.popleft())
print("stack:", stack_out)
print("queue:", queue_out)

def balanced_brackets(text):
    opening_for = {")": "(", "]": "["}
    saved = []
    for mark in text:
        if mark in "([":
            saved.append(mark)
        elif mark in opening_for:
            if not saved or saved.pop() != opening_for[mark]:
                return False
    return not saved

for text in ("([])", "([)]", "(()"):
    print(text, balanced_brackets(text))
stack: ['B', 'C', 'A']
queue: ['A', 'B', 'C']
([]) True
([)] False
(() False

큐에는 기다린 순서대로 작업을 처리하는 문제, 스택에는 최근 동작의 취소처럼 마지막부터 돌아가는 문제가 잘 맞습니다. 도착 순서보다 우선순위가 앞서는 경우에는 그 규칙을 별도로 정합니다.
