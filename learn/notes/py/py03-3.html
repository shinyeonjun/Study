경계값과 조건 설계

쇼핑몰 공지에 "3만 원 이상 무료 배송"이라고 적혀 있습니다. 딱 30,000원어치를 산 손님은 배송비를 낼까요? 코드에서 >=를 >로 잘못 쓰면 그 손님만 배송비를 내게 됩니다. 이 장에서는 조건이 바뀌는 바로 그 자리, 경계값에서 프로그램이 맞게 동작하는지 표로 하나씩 확인하는 방법을 익히고, 조건을 중첩해서 쓸지 평평하게 쓸지 고르는 법과 성적 등급 프로그램 하나를 끝까지 검사해 봅니다.

이 장을 읽고 나면

  • "이상·이하·초과·미만"이 섞인 규칙을 >=, <=, >, <로 정확히 옮길 수 있다.
  • 경계마다 "바로 아래·경계·바로 위" 값을 골라 입력→출력 표를 만들고, 실행 결과와 맞춰 볼 수 있다.
  • if 안에 if를 넣은 중첩 조건과 and로 묶은 평평한 조건을 서로 바꿔 쓰고, 둘이 같은지 표로 확인할 수 있다.
  • 성적 등급 프로그램의 모든 경계를 검사하고, 흔한 버그 세 가지(> 실수, 순서 실수, if 나열 실수)를 찾아 고칠 수 있다.

30,000원은 무료일까

"주문 금액 3만 원 이상이면 배송비 무료, 아니면 3,000원"을 코드로 옮깁니다. 두 사람이 각각 이렇게 썼습니다.

# (가) >= 로 쓴 것
total = int(input("주문 금액: "))
if total >= 30000:
    fee = 0
else:
    fee = 3000
print(f"배송비 {fee}원, 낼 돈 {total + fee}원")
# (나) > 로 쓴 것
total = int(input("주문 금액: "))
if total > 30000:
    fee = 0
else:
    fee = 3000
print(f"배송비 {fee}원, 낼 돈 {total + fee}원")

네 가지 금액을 두 프로그램에 똑같이 넣어 실행했습니다. 표의 출력은 모두 실제 실행 결과입니다.

입력 (원)규칙대로라면(가) >= 의 출력(나) > 의 출력
0배송비 3,000배송비 3000원, 낼 돈 3000원배송비 3000원, 낼 돈 3000원
29999배송비 3,000배송비 3000원, 낼 돈 32999원배송비 3000원, 낼 돈 32999원
30000무료배송비 0원, 낼 돈 30000원배송비 3000원, 낼 돈 33000원
30001무료배송비 0원, 낼 돈 30001원배송비 0원, 낼 돈 30001원

(나)는 30,000원 딱 한 값에서만 틀립니다. 29,999원이나 30,001원, 0원으로 시험했다면 두 프로그램이 똑같이 맞게 나와서 실수를 찾지 못했을 것입니다. "3만 원 이상"은 30,000을 포함하므로 >=가 맞습니다.

정의

조건의 결과가 바뀌는 바로 그 자리의 값을 경계값(boundary value)이라고 한다. 경계값이 어느 갈래에 들어가는지는 연산자가 정한다. >=, <=는 경계값을 포함하고, >, <는 포함하지 않는다.

규칙의 말코드경계값 포함?수직선 점
30000 이상x >= 30000포함찬 점 ●
30000 초과x > 30000포함 안 함빈 점 ○
30000 이하x <= 30000포함찬 점 ●
30000 미만x < 30000포함 안 함빈 점 ○

경계값 검사하는 법 이해하기

조건이 들어간 프로그램을 확인할 때 아무 값이나 몇 개 넣어 보는 것으로는 부족합니다. 앞의 예처럼 틀린 곳은 대개 경계에 숨어 있기 때문입니다. 그래서 경계마다 세 값을 골라 넣어 봅니다. 이렇게 경계 근처 값으로 시험하는 방법을 경계값 분석(boundary value analysis)이라고 하고, 정보처리기사의 소프트웨어 테스트에서 본 그 이름입니다.

외우는 법 · 경계마다 세 값

① 바로 아래 (정수면 경계 − 1) ② 경계 그 자체 ③ 바로 위 (정수면 경계 + 1).
여기에 ④ 허용 범위의 양 끝(예: 0점, 100점)과 ⑤ 범위를 살짝 벗어난 값(예: −1, 101)을 더한다.

절차는 이렇습니다.

① 규칙에서 경계를 모두 찾는다 (예: 30,000)
② 경계마다 바로 아래·경계·바로 위 값을 고른다 (29,999 · 30,000 · 30,001)
③ 값마다 규칙대로라면 무엇이 나와야 하는지 실행하기 전에 표에 적는다
④ 하나씩 실행해 실제 출력을 옆 칸에 적는다
⑤ 두 칸이 다른 줄이 있으면 그 경계의 연산자를 의심한다

③을 실행 전에 하는 것이 중요합니다. 출력을 먼저 보면 "그렇게 나오는 게 맞겠지" 하고 넘어가기 쉽기 때문입니다.

더 알아보기 · 실수에서는 "바로 아래"가 없다

정수만 들어온다면 30,000의 바로 아래는 29,999입니다. 그래서 정수에서는 x >= 70과 x > 69가 같은 결과를 냅니다. 하지만 실수가 들어오면 다릅니다. 실행해 보면 69.5 > 69는 True, 69.5 >= 70은 False입니다. 실수 69.5는 두 조건 사이에 끼어 버립니다. 그래서 규칙을 옮길 때는 숫자를 하나 바꿔 > 69로 쓰기보다, 규칙에 적힌 경계 숫자를 그대로 쓰고 연산자로 포함 여부를 나타내는 것(>= 70)이 안전합니다. 실수로 받은 점수 89.9, 89.99는 >= 90에서 모두 False입니다(실행해 확인함).

중첩 조건과 평평한 조건

규칙이 조금 복잡해졌습니다. "회원은 2만 원 이상, 비회원은 3만 원 이상이면 무료 배송, 아니면 3,000원". 두 가지 질문(회원인가, 금액이 얼마인가)이 얽혀 있습니다. 두 가지 모양으로 쓸 수 있습니다.

모양 1: if 안에 if (중첩)

member = input("회원(y/n): ") == "y"
total = int(input("주문 금액: "))
if member:
    if total >= 20000:
        fee = 0
    else:
        fee = 3000
else:
    if total >= 30000:
        fee = 0
    else:
        fee = 3000
print(f"배송비 {fee}원")

블록 안에 또 if를 넣었습니다. 안쪽 if의 블록은 빈칸 8개(4 + 4)만큼 들여씁니다. 이렇게 조건 안에 조건을 넣는 것을 중첩(nesting)이라고 합니다. 첫 질문으로 크게 둘로 나누고, 각 갈래 안에서 다시 둘로 나누는 모양입니다.

모양 2: and로 묶은 평평한 조건

member = input("회원(y/n): ") == "y"
total = int(input("주문 금액: "))
if member and total >= 20000:
    fee = 0
elif not member and total >= 30000:
    fee = 0
else:
    fee = 3000
print(f"배송비 {fee}원")

나무의 "무료" 잎 두 개에 이르는 길을 각각 and로 한 줄에 적었습니다. 왼쪽 잎은 "회원이고 2만 이상", 오른쪽 잎은 "회원이 아니고 3만 이상"입니다. 나머지는 모두 else(3,000원)입니다.

두 모양이 같은지 확인

두 프로그램은 같은 일을 할까요? 경계값 검사를 그대로 씁니다. 경계는 20,000과 30,000 두 곳이고, 회원·비회원 두 경우가 있으므로 각 경계의 바로 아래와 경계를 골라 8가지를 넣었습니다.

회원금액규칙대로라면모양 1 (중첩)모양 2 (평평)
y199993000배송비 3000원배송비 3000원
y200000배송비 0원배송비 0원
y299990배송비 0원배송비 0원
y300000배송비 0원배송비 0원
n199993000배송비 3000원배송비 3000원
n200003000배송비 3000원배송비 3000원
n299993000배송비 3000원배송비 3000원
n300000배송비 0원배송비 0원

여덟 줄 모두 두 프로그램의 실제 출력이 같고, 규칙과도 맞습니다. 특히 비회원 20,000원(회원이면 무료가 되는 금액)이 3,000원으로 나오는지가 두 기준을 섞지 않았는지 보여 주는 줄입니다.

중첩 (if 안에 if)평평 (and로 묶기)
잘 맞는 때첫 질문으로 크게 나뉘고, 갈래마다 할 일이 많을 때결과가 같은 경우를 한 줄로 모을 수 있을 때
좋은 점나무 모양이 코드 모양과 같아 갈래가 잘 보인다들여쓰기가 얕고 줄이 짧다
조심할 점세 겹 이상 깊어지면 읽기 어렵다not member처럼 앞 갈래의 반대를 빠짐없이 적어야 한다

왜 그럴까?

모양 2의 elif not member and total >= 30000:에서 not member and를 지워 elif total >= 30000:만 남겨도 결과가 같습니다. 왜 그럴까요? 그래도 남겨 두는 편이 나은 까닭은?

모범 답 보기

회원이면서 3만 원 이상인 경우는 이미 첫 조건(member and total >= 20000)에서 걸러졌으므로, elif에 도착한 "3만 이상"은 비회원뿐입니다. elif에는 "앞 조건이 거짓"이 숨어 있기 때문입니다(PY03·1). 그래도 not member를 써 두면 줄 하나만 읽어도 "비회원 규칙"임을 알 수 있고, 나중에 누가 첫 줄의 기준을 바꾸더라도 둘째 줄의 뜻이 흔들리지 않습니다. 다만 이것은 읽기와 고치기 편의를 위한 선택이고, 둘 다 맞는 코드입니다.

풀이 예제: 성적 등급 끝까지 검사하기 이해하기

마지막으로 처음부터 끝까지 한 프로그램을 만들고 검사합니다. 규칙은 이렇습니다(흔히 쓰는 10점 단위 등급을 예로 정한 것입니다).

규칙

점수는 0 이상 100 이하의 정수다. 범위 밖이면 "잘못된 점수".
90 이상 A, 80 이상 B, 70 이상 C, 60 이상 D, 그 아래는 F.

1단계: 규칙을 수직선에 그린다

그림에서 경계는 0, 60, 70, 80, 90, 100 여섯 곳입니다. "이상"으로 나누므로 등급은 큰 기준부터 elif로 잇습니다(PY03·1의 외우는 법). 범위 밖은 or로 맨 먼저 걸러 냅니다(PY03·2).

2단계: 코드를 쓴다

score = int(input("점수: "))
if score < 0 or score > 100:
    grade = "잘못된 점수"
elif score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
elif score >= 60:
    grade = "D"
else:
    grade = "F"
print(score, grade)

출력을 각 갈래에서 바로 하지 않고 변수 grade에 담았다가 마지막에 한 번 출력했습니다. 이렇게 하면 출력 모양을 바꿀 때 한 줄만 고치면 되고, 다음 단원에서 이 결과를 다른 계산에 넘기기도 쉽습니다.

3단계: 실행 전에 기대값 표를 만들고, 실행해 맞춘다

경계 여섯 곳마다 세 값을 고르면 겹치는 것을 빼고 열두 값이 나옵니다. "규칙대로라면" 칸을 먼저 채운 뒤, 열두 번 실행해 실제 출력을 옆에 적었습니다.

성적 프로그램의 흔한 버그 세 가지

같은 규칙을 조금씩 다르게 잘못 쓴 코드 세 개를 실제로 실행해, 앞의 검사 표가 버그를 어떻게 잡아내는지 봅니다.

버그 1: >= 대신 >

score = int(input("점수: "))
if score > 90:
    grade = "A"
elif score > 80:
    grade = "B"
elif score > 70:
    grade = "C"
elif score > 60:
    grade = "D"
else:
    grade = "F"
print(score, grade)
입력6061707180819091100
규칙대로라면DDCCBBAAA
실제 출력FDDCCBBAA

경계값 60, 70, 80, 90 네 점수만 한 등급씩 낮게 나옵니다. 61, 71처럼 경계 + 1에서는 맞게 나오므로, 경계 자체를 넣어 보지 않으면 절대 발견할 수 없는 버그입니다. 반대로 경계 + 1이 맞고 경계만 틀리다는 사실은 "연산자에 등호가 빠졌다"는 강한 단서가 됩니다.

버그 2: 범위 검사를 맨 뒤에

score = int(input("점수: "))
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
elif score >= 60:
    grade = "D"
elif score < 0 or score > 100:
    grade = "잘못된 점수"
else:
    grade = "F"
print(score, grade)

-1을 넣으면 "잘못된 점수"가 맞게 나오지만, 101과 150을 넣으면 101 A, 150 A가 나옵니다(실행해 확인함). 101은 첫 조건 score >= 90에서 이미 참이라 A로 결정되고, 범위 검사 줄까지 내려가지 못합니다. PY03·1에서 본 "앞 갈래가 뒤 갈래의 몫을 먼저 가져가는" 문제입니다. 잘못된 입력을 거르는 조건은 맨 앞에 둡니다.

버그 3: elif 대신 if를 나열

score = int(input("점수: "))
if score >= 90:
    grade = "A"
if score >= 80:
    grade = "B"
if score >= 70:
    grade = "C"
if score >= 60:
    grade = "D"
else:
    grade = "F"
print(score, grade)

95를 넣으면 95 D, 85를 넣으면 85 D, 50을 넣으면 50 F가 나옵니다(실행해 확인함). 90 이상이 모두 D가 됩니다. if가 네 개의 따로 된 질문이라서, 95점은 네 질문 모두에 참으로 답하고 그때마다 grade를 덮어씁니다.

마지막 else는 넷째 if에만 딸린 "아니면"이라서(PY03·1 왜 그럴까?), 50점일 때만 F가 나옵니다. 고치는 방법은 둘째 if부터 elif로 바꿔 한 묶음으로 만드는 것입니다.

흔한 실수

정상값 몇 개만 넣어 보고 "된다"고 하는 것. 버그 1은 75, 85, 95 같은 "무난한" 점수로는 모두 맞게 나옵니다. 버그 2는 0~100 안의 점수로는 하나도 틀리지 않습니다. 버그 3은 50점으로만 시험하면 맞습니다. 세 버그 모두 경계값과 범위 밖 값을 넣어야 드러납니다. 조건문을 쓰고 나면 경계값 표부터 만드는 습관을 들이세요.

  • PY04: 반복문을 배우면 경계값 열두 개를 손으로 열두 번 넣지 않고 목록에 담아 한 번에 검사할 수 있습니다.
  • PY05: 등급을 정하는 부분을 함수로 떼어 내면, 같은 검사 표를 그 함수에 그대로 쓸 수 있습니다.
  • PY08: 경계값 검사를 assert로 코드에 적어 두고, 고칠 때마다 자동으로 다시 확인하는 방법을 배웁니다.
  • 데이터 분석: 나이를 "20대·30대"로, 점수를 등급으로 나누는 구간 나누기에서도 경계값이 어느 구간에 들어가는지(왼쪽 포함인지 오른쪽 포함인지)가 결과를 바꿉니다.
