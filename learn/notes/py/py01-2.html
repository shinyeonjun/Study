PY01·2

값의 종류: int, float, str, bool

대화형 실행에 7 + 7을 치면 14가 나오는데, "7" + "7"을 치면 '77'이 나옵니다. 눈으로는 같은 7인데 Python은 둘을 전혀 다른 것으로 다룹니다. 이 장에서는 Python 값의 네 가지 기본 종류(정수, 실수, 문자열, 참·거짓)와 그 종류를 확인하는 type(), 그리고 종류에 따라 계산이 어떻게 달라지는지를 다룹니다.

이 장을 읽고 나면

  • int, float, str, bool이 각각 어떤 값인지 예를 들어 설명할 수 있다.
  • type()을 써서 값의 종류를 확인하고, <class 'int'> 같은 결과를 읽을 수 있다.
  • 같은 +가 숫자끼리는 더하고, 문자열끼리는 이어 붙이고, 둘을 섞으면 오류가 나는 까닭을 설명할 수 있다.
  • 종류는 이름이 아니라 값에 붙어 있다는 것을 예로 보일 수 있다.
  • 실수 계산에 아주 작은 오차가 생길 수 있음을 알고, 결과 0.30000000000000004가 왜 나오는지 설명할 수 있다.

같아 보여도 다른 값

대화형 실행에 다음을 차례로 쳐 본 실제 결과입니다.

대화형 실행

>>> 7 + 7
14
>>> "7" + "7"
'77'
>>> 7 * 3
21
>>> "7" * 3
'777'

따옴표 없는 7은 수이고, 따옴표로 감싼 "7"은 글자입니다. 수끼리 +하면 더하고, 글자끼리 +하면 앞뒤로 이어 붙입니다. 글자에 3을 곱하면 글자를 세 번 되풀이합니다. 사람에게 7은 그냥 7이지만, 컴퓨터는 값마다 "이것은 무슨 종류인가"를 함께 기억하고, 그 종류에 따라 계산 방법을 고릅니다.

용어 자료형은 영어 data type을 옮긴 말로, 줄여서 타입(type)이라고도 합니다. "형(形)"은 모양·종류라는 뜻입니다.

정의 외우기

자료형(type): 값의 종류. 그 값으로 무엇을 할 수 있고, 계산이 어떻게 되는지를 정합니다. Python의 기본 자료형 넷은 다음과 같습니다.

  • int (정수, integer): 소수점이 없는 수. 7, 0, -3
  • float (실수, floating point): 소수점이 있는 수. 7.0, 3.14, -0.5
  • str (문자열, string): 따옴표로 감싼 글자들. "7", "안녕", ""
  • bool (참·거짓, boolean): 딱 두 값 True와 False

type()으로 종류 확인하기

값의 종류가 궁금하면 type(…)에 넣어 봅니다. 대화형 실행의 실제 결과입니다.

대화형 실행

>>> type(7)
<class 'int'>
>>> type(7.0)
<class 'float'>
>>> type("7")
<class 'str'>
>>> type(True)
<class 'bool'>

<class 'int'>는 "이 값은 int라는 종류(class)에 속한다"라고 읽습니다. class는 Python이 종류를 부르는 이름인데, 지금은 "종류"로 읽으면 충분합니다. 꺾쇠 < >와 작은따옴표는 그 모양으로 보여 주는 약속일 뿐 뜻은 없습니다.

변수에 넣고 확인할 수도 있습니다. 파일로 실행할 때는 print로 감쌉니다.

코드 (kinds.py)

age = 29
height = 172.5
name = "김하나"
is_member = True
print(age, type(age))
print(height, type(height))
print(name, type(name))
print(is_member, type(is_member))

실행 결과

29 <class 'int'>
172.5 <class 'float'>
김하나 <class 'str'>
True <class 'bool'>

흔한 실수

파일 이름을 types.py처럼 Python에 이미 있는 이름으로 짓기. 이 책을 쓰면서 위 코드를 처음에 types.py라는 파일로 저장했더니, 그 폴더에서 실행한 다른 파일의 오류 메시지가 이상하게 나왔습니다. Python에는 types라는 이름의 부품이 이미 있는데, 같은 폴더에 같은 이름의 파일이 있으면 Python이 그 파일을 대신 읽어 버리기 때문입니다. 연습 파일에는 kinds.py, my_test.py처럼 겹치지 않을 이름을 쓰세요. 부품(모듈)을 불러오는 원리는 PY09에서 배웁니다.

int: 정수

소수점이 없는 수입니다. 음수(-3)와 0도 정수입니다. Python의 정수는 자릿수 제한이 없어서 아무리 큰 수도 정확하게 계산합니다. 2를 100번 곱한 수도 끝자리까지 정확히 나옵니다.

대화형 실행

>>> 2 ** 100
1267650600228229401496703205376
>>> 1_000_000
1000000

**는 거듭제곱(PY01·3에서 자세히)입니다. 큰 수를 읽기 쉽게 쓰고 싶으면 밑줄로 자리를 나눌 수 있습니다(1_000_000). 밑줄은 읽는 사람을 위한 것이라 값에는 영향이 없습니다.

흔한 실수

쉼표로 자릿수 나누기. 우리는 백만을 1,000,000으로 쓰지만 Python 코드에서 쉼표는 "여러 값을 나눈다"는 뜻입니다. print(1,000,000)을 실행하면 오류 없이 1 0 0이 나옵니다. 1과 000(=0)과 000(=0), 세 값을 빈칸으로 이어 출력한 것입니다. 수에는 쉼표를 쓰지 말고, 나누고 싶으면 밑줄을 씁니다.

float: 실수

소수점이 있는 수입니다. 값이 정수와 같더라도 소수점을 찍으면 float입니다. 7은 int, 7.0은 float입니다. 나누기 /의 결과는 나누어떨어져도 항상 float입니다(10 / 2 → 5.0). 소수 끝의 0은 보여 줄 때 지워집니다(3.50 → 3.5). float라는 이름은 floating point(떠다니는 소수점)를 줄인 것으로, 컴퓨터가 실수를 저장하는 방식에서 왔습니다.

str: 문자열

따옴표로 감싼 글자들입니다. 안에 숫자가 들어 있어도 따옴표가 있으면 str입니다. "7", "True"는 수나 참·거짓이 아니라 글자입니다. 따옴표만 있고 안이 빈 ""도 문자열(빈 문자열)이고, 빈칸 하나 " "도 문자열입니다.

bool: 참·거짓

True(참)와 False(거짓) 두 값뿐입니다. 이름은 이 개념을 정리한 수학자 조지 불(George Boole)에서 왔습니다. 앞 장의 x == 5처럼 "같은가?"를 물은 답이 bool입니다. 첫 글자는 반드시 대문자입니다. 소문자 true는 Python이 모르는 이름이라 실제로 이런 오류가 납니다.

실제 오류의 마지막 줄 (파일에 true 한 줄만 썼을 때)

NameError: name 'true' is not defined. Did you mean: 'True'?
자료형읽는 법예알아보는 법
int정수29, 0, -3, 1_000_000따옴표 없음, 소수점 없음
float실수172.5, 7.0, 10 / 2의 결과따옴표 없음, 소수점 있음
str문자열"김하나", "7", "True", ""따옴표로 감쌈
bool참·거짓True, False따옴표 없음, 대문자로 시작하는 이 두 낱말뿐

종류가 계산을 정한다 이해하기

같은 기호라도 양쪽 값의 종류에 따라 하는 일이 다릅니다. 가장 자주 만나는 +로 봅시다.

셋째 줄을 실제로 실행하면 이렇게 나옵니다(U05·3에서 본 traceback 모양입니다).

실행 결과 (파일에 7 + "7" 한 줄, 경로 줄임)

Traceback (most recent call last):
  File "C:\Users\me\Documents\python-study\one.py", line 1, in <module>
    7 + "7"
    ~~^~~~~
TypeError: unsupported operand type(s) for +: 'int' and 'str'

맨 아래 줄은 "+ 의 양쪽 재료(operand) 종류가 int와 str인 경우는 지원하지 않는다"입니다. Python이 멋대로 14나 "77" 가운데 하나를 고르지 않고 멈추는 데에는 까닭이 있습니다. 둘 중 무엇을 원했는지 알 수 없는데 짐작해서 계산하면, 틀린 결과가 오류 없이 조용히 흘러가 나중에 찾기 훨씬 어려워집니다. 문자열 "7"을 수 7로 바꾸는 법(int("7"))은 PY02에서 배웁니다.

섞어도 되는 경우도 있습니다. int와 float는 둘 다 수이므로 함께 계산할 수 있고, 결과는 float가 됩니다.

대화형 실행

>>> 3 + 2.0
5.0
>>> type(3 + 2.0)
<class 'float'>
>>> "ab" + "cd"
'abcd'
>>> "하" * 3
'하하하'

풀이 예제

다음 네 식의 결과와 자료형을 실행하기 전에 예상해 봅시다. (아래는 실제 결과로 확인한 것입니다.)

① 1200 * 3: int × int → 곱한다 → 3600, int
② 10 / 2: 나누기 /는 결과가 항상 float → 5.0, float
③ "10" + "2": str + str → 이어 붙인다 → '102', str (12가 아니다)
④ "7" * "3": 문자열끼리는 곱할 수 없다 → TypeError (can't multiply sequence by non-int of type 'str')

③이 가장 많이 틀리는 곳입니다. 화면에서 숫자를 입력받으면 처음에는 문자열로 들어오기 때문에, 그대로 더하면 이렇게 이어 붙어 버립니다. PY02의 입력받기에서 다시 만납니다.

종류는 이름이 아니라 값에 붙어 있다

PY01·1에서 변수는 값에 붙인 이름표라고 했습니다. 그러면 종류는 이름표에 붙어 있을까요, 값에 붙어 있을까요? 같은 이름에 다른 종류의 값을 대입해 본 실제 결과입니다.

대화형 실행

>>> price = 1200
>>> type(price)
<class 'int'>
>>> price = "천이백"
>>> type(price)
<class 'str'>

type(price)는 "price라는 이름의 종류"가 아니라 "price가 지금 가리키는 값의 종류"를 알려 줍니다. 그래서 같은 이름이라도 언제 묻느냐에 따라 답이 다릅니다. Python처럼 변수 이름에 종류를 미리 정해 두지 않는 언어가 있고, C나 Java처럼 이름을 만들 때 종류를 정해 두어야 하는 언어도 있습니다.

흔한 실수

"변수 price는 int형이다"라고 못박기. 정확히는 "price가 지금 가리키는 값이 int다"입니다. 프로그램 중간에 같은 이름에 문자열을 대입해도 Python은 막지 않습니다. 그래서 오히려 한 이름에는 한 종류의 값만 넣는 습관이 중요합니다. 가격은 늘 int, 이름은 늘 str처럼 정해 두면 7 + "7" 같은 TypeError를 미리 피할 수 있습니다.

정수와 실수는 왜 따로 있나

수학에서는 7과 7.0이 같은 수입니다. Python도 둘을 비교하면 같다고 답합니다(7 == 7.0 → True). 그런데도 종류를 나누는 까닭은 컴퓨터가 둘을 저장하는 방식이 다르기 때문입니다.

  • int는 정확합니다. 자릿수가 아무리 많아도 끝자리까지 틀리지 않습니다.
  • float는 소수를 0과 1의 조합(2진법)으로 근사해서 저장합니다. 유효숫자가 대략 15~17자리로 정해져 있어서, 그보다 아래 자리에는 아주 작은 오차가 생길 수 있습니다.

대화형 실행 (실제 결과)

>>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False
>>> 1 / 3
0.3333333333333333

0.1과 0.2는 2진법으로 딱 떨어지지 않는 수입니다. 10진법에서 1/3을 0.333…으로 끝없이 써야 하는 것과 같은 사정입니다. 그래서 각각 가장 가까운 값으로 저장되고, 둘을 더하면 0.3에서 아주 조금 벗어난 값이 됩니다. Python에게 소수 20자리까지 보여 달라고 하면 실제로 저장된 값이 드러납니다.

이 오차는 Python만의 문제가 아니라 거의 모든 프로그래밍 언어와 엑셀에도 있는 성질입니다. Python의 float는 IEEE 754 배정밀도(64비트, 유효 비트 53개) 형식이고, 실무에서 지킬 것은 세 가지입니다.

  1. 오차는 계산 오류가 아니라 표현 오차다. 크기는 상대적으로 약 10의 −16제곱 수준이다(위 예에서는 소수 17째 자리).
  2. 실수끼리 ==로 "딱 같은가"를 묻는 것은 피한다. 대신 "충분히 가까운가"를 묻는 법은 PY02와 수치계산(OP) 단원에서 다룹니다.
  3. 돈처럼 정확해야 하는 값은 원 단위 정수(int)로 다룬다. 1,200원은 1200으로 씁니다.

왜 그럴까?

오차가 있는 float를 아예 없애고 모든 수를 정확한 int처럼 다루면 안 될까요?

모범 답 보기

1/3처럼 끝없이 이어지는 소수는 어떤 방식으로도 유한한 칸에 정확히 담을 수 없습니다. 또 과학·통계 계산에는 아주 큰 수와 아주 작은 수가 함께 나오는데, float는 정해진 칸 수로 넓은 범위를 빠르게 다룰 수 있게 설계되었습니다. 정확함을 조금 양보하고 범위와 속도를 얻은 것입니다. 필요하면 분수(fractions)나 정확한 10진 소수(decimal)를 다루는 도구를 따로 쓸 수 있습니다.

다음에 이어지는 곳

  • PY01·3: int와 float의 계산 규칙을 연산자마다 봅니다. /와 //가 결과의 종류를 어떻게 바꾸는지가 핵심입니다.
  • PY02: 문자열을 더 자세히 다루고, int("7")처럼 종류를 바꾸는 법(형 변환), 비교와 bool을 배웁니다.
  • DA02 데이터의 종류: 표의 한 열이 수치형인지 범주형인지 가르는 일도 결국 "이 값으로 어떤 계산을 해도 되는가"라는 같은 질문입니다.

한 줄 정리

Python의 값에는 int·float·str·bool 같은 종류가 붙어 있고, 같은 기호라도 종류에 따라 계산이 달라지므로 헷갈리면 type()으로 확인한다.
