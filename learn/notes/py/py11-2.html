pandas로 묶어 세고 키로 두 표 잇기

East의 주문은 세 건인데 결제액을 아는 주문은 두 건입니다. 매장 이름으로 묶어 두 수를 따로 센 다음, 매장 정보 표를 붙입니다. 결합 뒤 행이 늘어나거나 매장 정보가 빠지는 경우도 같은 다섯 주문으로 살펴봅니다.

이 장을 읽고 나면

  • size와 count의 분모를 문장으로 설명하고 여러 통계를 한 표로 모을 수 있다.
  • 한 행이 뜻하는 단위와 결합 키를 구분할 수 있다.
  • 왼쪽 결합과 내부 결합에서 남는 행을 예상할 수 있다.
  • validate와 indicator로 중복 키와 연결 실패를 확인할 수 있다.

그룹별 집계의 분모부터 정한다

앞 장의 주문 다섯 건을 매장별로 비교합니다. 이번 표는 주문번호를 보통 열로 남깁니다. 행 하나의 뜻은 여전히 주문 한 건입니다. 같은 매장의 여러 행을 묶었을 때 '주문이 몇 건 있었는가'와 '결제액이 확인된 주문이 몇 건인가'는 다르게 셉니다.

101East3200
104West5100
105East2400
108West6100
109East결측

groupby()는 동일한 그룹 키의 행을 묶습니다. 키는 여기서 매장 이름입니다. 각 그룹에서 계산한 값을 결과 표에 모으는 것이 집계입니다. size는 그룹의 행 수, count는 지정한 열의 결측이 아닌 칸 수입니다. agg에 새_열=("기존_열", "계산") 쌍을 주면 결과의 각 열이 무엇을 뜻하는지 드러납니다.

import pandas as pd

orders = pd.DataFrame({
    "order_id": [101, 104, 105, 108, 109],
    "store": ["East", "West", "East", "West", "East"],
    "amount": pd.array([3200, 5100, 2400, 6100, None], dtype="Int64"),
})

summary = orders.groupby("store", as_index=False, sort=True).agg(
    orders=("order_id", "size"),
    with_amount=("amount", "count"),
    total_known=("amount", lambda s: s.sum(min_count=1)),
    mean_known=("amount", "mean"),
)

for row in summary.itertuples(index=False):
    print(row.store, row.orders, row.with_amount,
          int(row.total_known), f"{row.mean_known:.0f}")
assert summary["orders"].sum() == len(orders)
assert summary["with_amount"].sum() == orders["amount"].count()

실행 결과

East 3 2 5600 2800
West 2 2 11200 5600

첫 줄의 3 2 5600 2800은 East의 전체 주문 3건, 금액을 아는 2건, 기록된 금액의 합 5,600원, 기록된 금액의 평균 2,800원 순입니다. as_index=False를 주면 요약 표의 매장 이름은 일반 열로 남습니다. 위 코드는 itertuples(index=False)로 요약 표의 행을 차례로 꺼내 출력합니다. 집계는 이 반복문 이전에 끝났습니다.

손검산

East에서 amount 평균 = (3,200 + 2,400) ÷ 2 = 2,800원입니다. 누락 1건까지 나누면 5,600 ÷ 3 ≈ 1,867원이 됩니다. 이는 누락 금액을 0원으로 가정한 평균이라 질문이 달라집니다. 이 사례의 관측률은 East 2 ÷ 3, West 2 ÷ 2입니다. 관측률이 다른 두 매장에서는 관측된 평균이 매장 전체의 평균을 그대로 설명한다고 볼 수 없습니다.

금액 열 전체가 결측인 그룹에서 합계를 계산할 때 sum()의 기본 규칙 때문에 0이 나올 수 있습니다. 예처럼 min_count=1을 주면 알려진 금액이 적어도 하나 있을 때만 합계가 나옵니다. 집계할 값의 누락과 그룹 키의 누락도 다릅니다. groupby("store")는 기본적으로 매장 키가 누락된 행을 그룹에서 제외합니다. 매장 미상 행까지 집계하려면 dropna=False를 명시하고 그 그룹을 별도로 해석합니다.

매장 정보 표를 주문에 붙인다

주문은 주문 시스템에 있고 매장 주소는 별도 기본 정보 표에 있다고 합시다. 행 순서는 서로 다를 수 있으므로 줄 번호로 맞추면 잘못 붙습니다. 두 표의 store 값이 같을 때 같은 매장으로 보겠다는 결합 키가 필요합니다.

merge()는 이러한 키를 기준으로 표를 결합합니다. how="left"를 주면 왼쪽 주문 행을 살리고, 맞는 오른쪽 정보가 없으면 새 열을 결측으로 둡니다. how="inner"를 주면 양쪽에서 키가 맞는 행만 남습니다. 주문이 몇 건 빠졌는지 조사하는 시점에는 왼쪽 결합이 눈에 잘 들어옵니다.

import pandas as pd

orders = pd.DataFrame({
    "order_id": [101, 104, 105, 108, 109],
    "store": ["East", "West", "East", "West", "East"],
    "amount": pd.array([3200, 5100, 2400, 6100, None], dtype="Int64"),
})

stores = pd.DataFrame({
    "store": ["West", "East"],
    "district": ["South", "North"],
})

assert orders["store"].notna().all() and stores["store"].notna().all()
joined = orders.merge(stores, on="store", how="left",
                      validate="many_to_one", indicator=True)
print("결합 전·후:", len(orders), len(joined))
print("맞은 행:", int(joined["_merge"].eq("both").sum()))
print("예: 주문 101의 구역:", joined.loc[joined["order_id"].eq(101), "district"].iloc[0])
assert joined["order_id"].is_unique

실행 결과

결합 전·후: 5 5
맞은 행: 5
예: 주문 101의 구역: North

validate="many_to_one"은 오른쪽 store가 중복되지 않는지 검사하고, 중복이 있으면 MergeError: Merge keys are not unique in right dataset; not a many-to-one merge로 결합을 멈춥니다. indicator=True는 출처 열 _merge를 만들어 both, left_only, right_only 중 무엇에 해당하는지 나타냅니다. 왼쪽 결합 결과에는 오른쪽에만 있는 행이 나오지 않습니다. 양쪽의 미등록 키를 모두 보고 싶을 때 how="outer"를 사용할 수 있습니다.

결합 전후에 사라지거나 늘어난 행을 찾는다

West가 기본 정보에서 빠졌다면 how="inner"로 주문 두 건을 잃어버립니다. 반대로 East가 우연히 기본 정보에 두 번 있다면, 원래 East 주문 3건 각각이 두 행으로 늘어납니다. 검증을 끈 결과는 총 8행으로, 금액을 다시 더하면 같은 주문을 두 번 셀 수 있습니다.

오른쪽 기본 정보검증 없이 왼쪽 결합위험
East·West 각 1행5행기대하는 정상 결과
West가 없음5행. West 2행은 새 정보가 결측미연결 건수를 세지 않으면 빠진 정보를 모른다
East가 두 번East 3 × 2 + West 2 × 1 = 8행키를 검사하지 않고 더하면 중복 집계
import pandas as pd

orders = pd.DataFrame({
    "order_id": [101, 104, 105, 108, 109],
    "store": ["East", "West", "East", "West", "East"],
    "amount": pd.array([3200, 5100, 2400, 6100, None], dtype="Int64"),
})

missing = pd.DataFrame({"store": ["East"], "district": ["North"]})
audit = orders.merge(missing, on="store", how="left",
                     validate="many_to_one", indicator=True)
print("연결 안 된 주문:", audit.loc[audit["_merge"].eq("left_only"), "order_id"].tolist())
print("내부 결합 행 수:", len(orders.merge(missing, on="store", how="inner")))

duplicate = pd.DataFrame({
    "store": ["East", "East", "West"],
    "district": ["North", "Central", "South"],
})
print("검증 없이 결합한 행 수:", len(orders.merge(duplicate, on="store", how="left")))
try:
    orders.merge(duplicate, on="store", how="left", validate="many_to_one")
except pd.errors.MergeError:
    print("오른쪽 키 중복으로 결합 중단")

연결 안 된 주문: [104, 108]
내부 결합 행 수: 3
검증 없이 결합한 행 수: 8
오른쪽 키 중복으로 결합 중단

결측 키끼리 붙을 수 있다

pandas merge는 두 표의 키가 모두 결측이면 서로 짝지을 수 있습니다. 주소를 모르는 주문과 이름을 모르는 매장이 같은 매장이라는 근거는 없습니다. 결합 전에 키에 결측이 있는 행을 분리해 조사하며, 결측을 공통 문자열로 채워 억지로 결합하지 않습니다.

검산할 항목은 결합 전후의 행 수, 키의 중복 수, 못 붙인 키, 원래 행을 대표하는 식별자의 개수입니다. 오른쪽에 있는 중복 행을 발견하면 어느 행이 공식 기록인지 먼저 정합니다. 사유 없는 drop_duplicates()로 첫 행만 남겨 상충하는 정보를 숨기지 않습니다.

왜 그럴까?

왼쪽 결합 앞뒤의 행 수가 같으면 언제나 모든 주문에 구역 이름이 붙었다고 말할 수 있을까요?

모범 답 보기

왼쪽 결합은 짝이 없는 주문도 살립니다. West가 없을 때 행 수는 여전히 5지만 104와 108에는 구역 정보가 없습니다. 그래서 행 수와 따로 _merge가 left_only인 행을 확인합니다.
