PY02·3

참·거짓과 비교, 흔한 오류

"이 손님은 20살 이상인가?", "주문 금액이 3만 원을 넘었나?" 프로그램은 이런 질문에 예·아니오로 답한 뒤 그에 따라 다른 일을 합니다. 이 장에서는 그 예·아니오를 담는 값인 참·거짓과, 그것을 만들어 내는 비교를 익힙니다. 끝으로 처음 코드를 쓸 때 가장 자주 만나는 세 가지 오류를 실제 오류 메시지로 읽어 봅니다.

이 장을 읽고 나면

  • 비교 연산자 6개(== != < > <= >=)로 식을 쓰고 결과가 True인지 False인지 미리 적을 수 있다.
  • =와 ==, ==와 is의 차이를 설명할 수 있다.
  • 1 < x < 10 같은 이어 쓴 비교와, 문자열·실수 비교의 함정을 설명할 수 있다.
  • SyntaxError, NameError, TypeError의 오류 메시지를 맨 아래 줄부터 읽고 고칠 곳을 찾을 수 있다.

예·아니오를 담는 값

PY01·2에서 값의 종류 넷(int, float, str, bool)을 봤습니다. 그 가운데 bool은 이름과 두 값 True, False만 보고 지나갔는데, 이 장에서 그 값이 어디서 나오고 어디에 쓰이는지 자세히 봅니다. 다음을 실행해 봅니다.

print(3 > 2)
print(3 < 2)
print(type(True))
ok = 10 >= 7
print(ok)

실행 결과

True
False
<class 'bool'>
True

3 > 2는 "3은 2보다 큰가?"라는 질문이고, Python은 True(참)로 답했습니다. 3 < 2는 False(거짓)입니다. 이 답 자체가 하나의 값이라서, 넷째 줄처럼 변수에 담아 둘 수도 있습니다.

정의

불(bool, Boolean) 자료형은 True와 False 두 값만 가진다. 첫 글자를 대문자로 쓰고 따옴표를 붙이지 않는다. 비교식처럼 참·거짓으로 답이 나오는 식을 계산하면 불 값이 나온다.

용어 불(Boolean)은 참·거짓으로 계산하는 방법(논리 대수)을 정리한 19세기 수학자 조지 불(George Boole)의 이름에서 왔습니다. 연산자(operator)는 +, >처럼 값에 어떤 계산을 하라는 기호입니다. 표현식(expression, 식)은 3 > 2, price * count처럼 계산하면 값 하나가 되는 코드 조각입니다. 이 단원의 이름 "값과 표현식"이 바로 이것입니다.

흔한 실수

true(소문자)나 "True"(따옴표)는 불 값이 아닙니다. 소문자 true는 PY01·2에서 본 것처럼 그런 이름의 변수를 찾다가 NameError가 나고, "True"는 글자 네 개짜리 문자열입니다. 실제로 True == "True"를 실행하면 False가 나옵니다.

a = 5, b = 7일 때 여섯 가지 비교를 모두 해 봅니다.

a = 5
b = 7

print(a != b)

두 글자짜리 연산자에는 규칙이 있습니다. 등호 =는 항상 뒤에 씁니다(<=, >=, !=). =<나 =!로 쓰면 문법 오류입니다. 키보드에 ≤, ≥, ≠ 기호가 없어서 두 글자로 나타낸 것이라고 기억하면 됩니다. 부등호를 읽는 법은 U04 "기호와 단위 읽기"에서 다룹니다. a <= 5에서 a가 정확히 5여도 True라는 점(경계를 포함)이 PY03에서 아주 중요해집니다.

= 는 넣기, == 는 묻기

수학에서는 = 하나로 "같다"를 나타냈지만, Python에서 =는 PY01에서 본 대로 오른쪽 값을 왼쪽 변수에 넣으라는 명령(대입)입니다. "같은가?"라고 물을 때는 == 두 개를 씁니다.

헷갈려서 질문할 자리에 =를 하나만 쓰면 대부분 문법 오류가 납니다. 이 장 끝의 오류 절에서 실제 메시지를 봅니다.

비교 연산자는 숫자뿐 아니라 문자열에도 쓸 수 있습니다. 결과를 먼저 예상해 보고 실행 결과와 맞춰 봅시다.

print("apple" == "apple")
print("apple" == "Apple")
print("10" == 10)
print(int("10") == 10)
print("10" < "9")
print(10 < 9)
print("가" < "나")

  • "apple" == "Apple"이 False입니다. 대문자와 소문자는 다른 글자입니다.
  • "10" == 10이 False입니다. 문자열과 정수는 자료형이 다르면 같지 않다고 답합니다. 오류는 나지 않습니다. PY02·2에서 input()으로 받은 값을 바꾸지 않고 숫자와 비교하면, 이렇게 조용히 False가 나옵니다.
  • "10" < "9"가 True입니다. 이것이 가장 놀라운 결과입니다. 아래에서 자세히 봅니다.

문자열은 사전 순서로 비교한다

문자열의 크기 비교는 국어사전에서 낱말을 찾는 순서와 같은 방식입니다. 첫 글자부터 하나씩 비교해서, 처음으로 다른 글자가 나오는 자리에서 결정합니다. 이것을 사전식 비교라고 합니다.

"가" < "나"가 True인 것도 같은 원리입니다. 글자마다 컴퓨터 안에서 정해진 번호가 있고, 그 번호가 작은 쪽이 앞 순서입니다. 숫자 글자는 0~9 순서, 영어 대문자는 A~Z 순서, 소문자는 a~z 순서로 번호가 매겨져 있습니다. 대문자 전체가 소문자 전체보다 앞이라서 "B" < "a"도 True입니다. 글자 번호의 정체(유니코드)는 SY01에서 다룹니다.

시험 함정

숫자를 문자열인 채로 비교하면 틀린 순서가 나옵니다. 점수 "9"와 "10"을 문자열로 비교하면 "10점이 9점보다 작다"는 엉터리 결론이 나옵니다. 오류가 나지 않으므로 더 위험합니다. 숫자로 비교하려면 반드시 int()나 float()로 바꾼 뒤 비교합니다.

이어 쓴 비교: 1 < x < 10

수학에서는 "x가 1보다 크고 10보다 작다"를 1 < x < 10으로 씁니다. Python에서도 똑같이 쓸 수 있습니다.

x = 5
print(1 < x < 10)
print(1 < x and x < 10)
print(10 < x < 20)
print(3 > 2 > 1)
print(1 < 3 > 2)

정의

비교를 이어 쓴 a < b < c는 a < b and b < c와 같다. 곧 이웃한 두 개씩 비교해서 모두 참일 때만 True이다. (and는 "그리고"라는 뜻의 논리 연산자로, PY03·2에서 자세히 배운다.)

마지막 줄 1 < 3 > 2도 True입니다. 1 < 3도 참이고 3 > 2도 참이기 때문입니다. 문법으로는 맞지만 사람이 읽기에 헷갈리므로, 이어 쓴 비교는 0 <= score <= 100처럼 작은 수 → 변수 → 큰 수 순서로 범위를 나타낼 때만 쓰는 것이 좋습니다.

흔한 실수

3 > 2 > 1을 "앞에서부터 계산"한다고 생각하면 (3 > 2) > 1 → True > 1이 되어 헷갈립니다. Python은 그렇게 계산하지 않습니다. 이어 쓴 비교는 언제나 3 > 2 and 2 > 1로 풀어 읽습니다. (다른 많은 언어에서는 이렇게 이어 쓰는 문법이 없거나 다르게 동작하니, Python만의 편의 기능이라고 기억하세요.)

실수는 == 로 비교하지 않는다

print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
print(round(0.1 + 0.2, 10) == 0.3)

실행 결과

0.30000000000000004
False
True

0.1 + 0.2가 정확히 0.3이 되지 않습니다. Python의 float는 IEEE 754 배정밀도(64비트) 이진 부동소수점입니다. 0.1은 이진수로 순환소수(0.0001100110011…₂)라서 가장 가까운 표현 가능한 값으로 반올림되어 저장되고, 0.2도 마찬가지입니다. 두 반올림 오차가 더해진 결과가 0.3의 저장값과 마지막 비트에서 달라 ==가 False를 냅니다.

그래서 실수끼리 같은지 볼 때는 셋째 줄처럼 round()로 적당한 자리에서 반올림한 뒤 비교하거나, "차이가 아주 작으면 같다고 본다"는 방법을 씁니다. 이 문제의 원리는 OP01 "컴퓨터 계산의 오차"에서 자세히 다룹니다. 지금은 실수끼리 ==로 비교하면 믿을 수 없다는 것만 기억합니다. 크기 비교(<, >=)는 이런 아주 작은 차이가 경계에 걸리지 않는 한 문제없이 씁니다.

== 와 is

Python에는 is라는 비교도 있습니다. ==와 비슷해 보이지만 묻는 것이 다릅니다. 아래 예의 [1, 2]는 값 여러 개를 담는 목록(list)인데, PY04에서 배우니 지금은 "값 두 개가 든 상자"로만 봅니다.

a = [1, 2]
b = [1, 2]
print(a == b)
print(a is b)
c = a
print(c is a)
x = None
print(x is None)

정의

==는 두 값의 내용이 같은지 묻는다. is는 두 이름이 똑같은 하나의 대상을 가리키는지 묻는다. 입문 단계에서 is는 x is None(x에 "값 없음"이 들어 있나)을 확인할 때만 쓰고, 숫자·문자열 비교에는 언제나 ==를 쓴다.

None은 "아직 값이 없음"을 나타내는 특별한 값입니다. 숫자 0이나 빈 문자열 ""과도 다른, "비어 있다"는 표시입니다. 이름이 가리키는 대상과 복사의 관계는 PY06에서 자세히 다룹니다.

더 알아보기 · True는 1, False는 0

Python에서 불 값은 정수의 한 종류로 취급됩니다. 그래서 True + True는 2, True == 1과 False == 0은 모두 True가 나옵니다(실행해 확인함). 이 성질 덕분에 참인 것의 개수를 더해서 셀 수 있고, 데이터 분석에서 "조건에 맞는 행이 몇 개인가"를 셀 때 자주 씁니다(PY11).

처음 만나는 세 가지 오류 이해하기

U05에서 오류 메시지가 나오는 자리를 봤으니, 여기서는 그 내용을 읽는 법을 정리합니다. 먼저 오류 메시지(traceback) 하나를 부위별로 뜯어봅니다.

외우는 법

오류 메시지는 아래에서 위로. 맨 아래 줄 "종류: 설명"으로 무엇이 문제인지 보고, 위로 올라가 line 번호로 어디인지 찾는다.

SyntaxError: 문법이 틀렸다

SyntaxError(문법 오류)는 Python이 코드를 읽을 수조차 없을 때 납니다. 따옴표·괄호를 닫지 않았거나, 기호를 잘못 쓴 경우입니다. 실제 예 세 개입니다.

① 따옴표를 닫지 않음: print("안녕)

  File "C:\Users\...\e1.py", line 1
    print("안녕)
          ^
SyntaxError: unterminated string literal (detected at line 1)

② 괄호를 닫지 않음: 1번 줄 print("안녕", 2번 줄 print("잘 가")

  File "C:\Users\...\e2.py", line 1
    print("안녕"
         ^
SyntaxError: '(' was never closed

③ 비교 자리에 = 하나: 1번 줄 x = 5, 2번 줄 if x = 5:

  File "C:\Users\...\e3.py", line 2
    if x = 5:
       ^^^^^
SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?

①은 "끝나지 않은 문자열", ②는 "괄호 (가 닫히지 않았다"는 뜻이고 ^가 여는 괄호를 가리킵니다. ③은 "잘못된 문법. '=' 대신 '=='를 쓰려던 것 아닌가요?"라고 고칠 방법까지 알려 줍니다(:=는 입문 범위 밖의 다른 문법입니다). if는 다음 단원 PY03에서 배울 조건문입니다.

SyntaxError 메시지에는 첫 줄 Traceback이 없습니다. 실행하기 전에 코드를 읽는 단계에서 걸렸기 때문입니다. 그래서 오류 줄보다 앞에 있는 코드도 하나도 실행되지 않습니다(아래 그림 (가)).

NameError: 그런 이름이 없다

NameError(이름 오류)는 만든 적 없는 변수나 함수 이름을 썼을 때 납니다. 대개 오타이거나 따옴표를 빼먹은 경우입니다.

① 오타: 1번 줄 name = "민지", 2번 줄 print(nmae)

Traceback (most recent call last):
  File "C:\Users\...\e4.py", line 2, in <module>
    print(nmae)
          ^^^^
NameError: name 'nmae' is not defined

② 대문자: Print("안녕")

Traceback (most recent call last):
  File "C:\Users\...\e8.py", line 1, in <module>
    Print("안녕")
    ^^^^^
NameError: name 'Print' is not defined. Did you mean: 'print'?

③ 따옴표를 빼먹음: print(hello)

Traceback (most recent call last):
  File "C:\Users\...\e5.py", line 1, in <module>
    print(hello)
          ^^^^^
NameError: name 'hello' is not defined. Did you mean: 'help'?

is not defined는 "정의되지 않았다(만든 적 없다)"는 뜻입니다. Python은 대소문자를 구분하므로 Print와 print는 다른 이름입니다. 비슷한 이름이 있으면 Did you mean("~를 말한 건가요?")으로 짐작해 알려 주지만, ③처럼 엉뚱한 이름(help)을 권할 때도 있습니다. 원래 하려던 것은 문자열 "hello"였으므로, 권하는 말을 그대로 따르지 말고 내가 뜻한 것이 무엇인지 생각해야 합니다.

TypeError: 자료형이 맞지 않는다

TypeError(자료형 오류)는 PY02·2에서 이미 만났습니다. 연산이나 함수가 받을 수 없는 자료형의 값을 넣었을 때 납니다.

① 정수 + 문자열: 1번 줄 price = 1200, 2번 줄 count = "2", 3번 줄 print(price + count)

Traceback (most recent call last):
  File "C:\Users\...\e10.py", line 3, in <module>
    print(price + count)
          ~~~~~~^~~~~~~
TypeError: unsupported operand type(s) for +: 'int' and 'str'

② 정수의 길이: print(len(5))

Traceback (most recent call last):
  File "C:\Users\...\e6.py", line 1, in <module>
    print(len(5))
          ~~~^^^
TypeError: object of type 'int' has no len()

①은 "+ 연산에 int와 str 조합은 지원하지 않는다", ②는 "int 자료형에는 길이가 없다"는 뜻입니다. 같은 TypeError라도 PY02·2의 "나이: " + 20(문자열이 앞)과 여기의 1200 + "2"(정수가 앞)는 설명 문장이 다릅니다. 설명은 다르지만 원인은 같습니다. 자료형이 섞였습니다.

흔한 실수

오류가 없다고 맞는 것은 아닙니다. 앞의 ①에서 +를 *로 바꿔 print(price * count)를 실행하면 오류 없이 2가 1,200번 이어진 아주 긴 글자가 출력됩니다. 문자열 반복이 되었기 때문입니다. TypeError가 나는 쪽이 오히려 친절한 것입니다. 오류가 나지 않는 실수는 결과를 눈으로 확인하는 수밖에 없습니다.

오류가 나는 시점

세 오류는 언제 나는지가 다릅니다. 두 파일을 실행해 비교해 봅니다.

# (가) syntax.py
print("시작")
print("안녕)
print("끝")
# (나) name.py
print("시작")
x = 10
print(x + y)
print("끝")

(맨 앞의 #으로 시작하는 줄은 주석(comment)입니다. Python은 # 뒤를 읽지 않으므로 사람에게 남기는 메모로 씁니다.)

(가)의 실행 결과

  File "C:\Users\...\syntax.py", line 3
    print("안녕)
          ^
SyntaxError: unterminated string literal (detected at line 3)

(나)의 실행 결과

시작
Traceback (most recent call last):
  File "C:\Users\...\name.py", line 4, in <module>
    print(x + y)
              ^
NameError: name 'y' is not defined
오류언제 나나흔한 원인먼저 볼 곳
SyntaxError실행 전, 코드를 읽을 때따옴표·괄호 안 닫음, = 와 == 혼동, 쌍점 빠짐^가 가리키는 자리와 그 바로 앞
NameError실행 중, 그 줄에 왔을 때오타, 대소문자, 따옴표 빠짐, 만들기 전에 씀따옴표 안의 이름
TypeError실행 중, 그 줄에 왔을 때문자열과 숫자 섞기, 길이가 없는 값에 len()설명에 나온 두 자료형
ValueError실행 중 (입력값에 따라)숫자로 바꿀 수 없는 글자를 int()에작은따옴표 안의 값 (PY02·2)

왜 그럴까?

(나)에서는 "시작"이 출력된 뒤 멈췄는데, (가)에서는 "시작"조차 출력되지 않았습니다. 둘 다 3~4번째 줄에 문제가 있는데 왜 다를까요?

모범 답 보기

Python은 파일을 실행하기 전에 먼저 전체를 읽어 문법을 검사합니다. (가)의 따옴표 문제는 이 검사에서 걸리므로 실행 자체가 시작되지 않습니다. (나)의 코드는 문법이 맞아서 실행이 시작되고, 위에서부터 한 줄씩 실행하다가 4번 줄에서 y를 찾지 못하는 순간 멈춥니다. "y가 있는지"는 실제로 그 줄을 실행해 봐야 알 수 있기 때문입니다.

이 내용이 다시 나오는 곳

  • PY03: 비교식의 True/False가 if의 갈림길을 정합니다. >=와 >의 차이(경계값 포함 여부)가 결과를 바꾸는 장면을 직접 봅니다. and, or, not도 PY03·2에서 배웁니다.
  • PY08: 오류 메시지(traceback)를 읽고, 오류를 일부러 다시 일으켜 원인을 좁히는 디버깅을 본격적으로 다룹니다.
  • 데이터 분석: "점수가 80 이상인 행만 고르기"는 비교식을 표의 모든 행에 적용해 True인 행만 남기는 일입니다(PY11).

한눈에 정리

개념요점예
불(bool)True, False 두 값뿐. 대문자로 시작, 따옴표 없음3 > 2 → True
비교 연산자== != < > <= >=. 등호는 뒤에5 <= 5 → True
= 와 ===는 넣기(대입), ==는 같은지 묻기if x = 5: → SyntaxError
문자열 비교첫 글자부터 하나씩, 사전식 비교. 자료형이 다르면 == 는 False"10" < "9" → True
이어 쓴 비교a < b < c = a < b and b < c1 < 5 < 10 → True
실수 비교0.1 + 0.2 == 0.3 은 False. 실수는 == 로 비교하지 않는다round(…, 10) == 0.3
is같은 대상인지. 입문에서는 x is None에만a, b에 각각 [1, 2]를 넣으면 a is b → False
오류 읽기맨 아래 줄 "종류: 설명"부터. SyntaxError는 실행 전, NameError·TypeError는 실행 중Print → NameError

한 줄 정리

비교식은 True나 False라는 값을 만들고, 오류 메시지는 맨 아래 줄의 종류와 설명부터 읽어 위로 올라가며 고칠 곳을 찾는다.
