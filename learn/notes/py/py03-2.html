PY03·2

and·or·not으로 조건 묶기

"20살 이상이고 표가 있으면 입장", "65세 이상이거나 회원이면 할인". 실제 규칙은 비교 하나로 끝나지 않고 "그리고", "또는", "아니다"로 여러 조건을 묶습니다. 이 장에서는 조건을 묶는 세 낱말 and·or·not을 진리표로 정확히 익히고, Python이 이 식을 계산하는 순서와 중간에 멈추는 규칙(단락 평가), 그리고 가장 흔한 함정을 실행해 보며 확인합니다.

이 장을 읽고 나면

  • and·or·not의 진리표를 쓰고, 묶인 조건식의 결과를 한 단계씩 계산할 수 있다.
  • not → and → or 의 계산 순서를 알고, 괄호로 뜻을 분명히 할 수 있다.
  • 단락 평가 때문에 조건의 순서가 오류 여부를 바꾸는 예를 설명할 수 있다.
  • x == 1 or 2가 늘 참이 되는 까닭을 설명하고 바르게 고칠 수 있다.
  • "범위 안"과 "범위 밖" 조건을 수직선에 그리고 and·or로 쓸 수 있다.

세 낱말: and, or, not

놀이기구 앞에 "20살 이상이고 표가 있는 사람만 탑승"이라고 적혀 있다고 해 봅시다. 25살이고 표가 있는 사람으로 확인합니다.

age = 25
has_ticket = True
print(age >= 20 and has_ticket)
print(age >= 30 and has_ticket)
print(age >= 30 or has_ticket)
print(not has_ticket)

실행 결과

True
False
True
False
용어 논리 연산자(logical operator)는 True/False 값을 받아 새 True/False를 만드는 연산자입니다(and·or가 실제로 돌려주는 값의 정확한 규칙은 이 장 뒤의 "더 알아보기"). Python의 논리 연산자는 영어 낱말 그대로 and(그리고), or(또는), not(아니다) 세 개입니다. 다른 언어의 &&, ||, !에 해당합니다.
  • 둘째 줄 age >= 30 and has_ticket: 표는 있지만 30 이상이 아니라서 False입니다. and는 양쪽이 모두 참이어야 참입니다.
  • 셋째 줄 age >= 30 or has_ticket: 30 이상은 아니지만 표가 있어서 True입니다. or는 한쪽만 참이어도 참입니다.
  • 넷째 줄 not has_ticket: True를 뒤집어 False입니다. not은 하나를 받아 반대로 바꿉니다.

진리표 외우기

참·거짓 두 값만 다루므로, 가능한 경우를 모두 늘어놓은 표 하나로 연산자를 완전히 정의할 수 있습니다. 이 표를 진리표(truth table)라고 합니다. 아래 표의 모든 칸은 print(True and False)처럼 한 줄씩 실행해 확인했습니다.

정의

A and B는 A와 B가 모두 True일 때만 True다.
A or B는 A와 B 중 적어도 하나가 True이면 True다. 둘 다 True여도 True다.
not A는 A가 True면 False, False면 True다.

흔한 실수

일상 말의 "또는"은 "둘 중 하나만"일 때가 많습니다. "커피 또는 차를 드립니다"는 둘 다 주지는 않는다는 뜻이지요. 하지만 Python의 or는 둘 다 참이어도 참입니다(진리표 (나)의 첫 줄). "둘 중 정확히 하나만"(배타적 논리합, XOR)이 필요하면 a, b가 불 값일 때 따로 a != b처럼 써야 합니다. 이 뜻은 DM01 "집합과 논리"에서 배우는 합집합과 같습니다.

범위 안, 범위 밖 이해하기

and와 or는 수직선 위에서 보면 뜻이 또렷해집니다. "x가 10 이상 20 미만"(범위 안)과 "x가 10 미만이거나 20 이상"(범위 밖)을 실행해 봅니다.

x = int(input("x: "))
print(x >= 10 and x < 20)
print(x < 10 or x >= 20)
xx >= 10 and x < 20x < 10 or x >= 20
9FalseTrue
10TrueFalse
19TrueFalse
20FalseTrue

(네 값을 넣어 실제로 실행한 결과입니다.) 두 식의 결과가 언제나 정반대입니다. 하나는 범위 안, 다른 하나는 정확히 그 나머지인 범위 밖을 나타내기 때문입니다.

(가)는 PY02·3에서 본 이어 쓴 비교로 10 <= x < 20이라고 써도 같습니다. 반면 (나)처럼 범위 밖은 이어 쓴 비교 하나로 쓸 수 없고 or가 필요합니다. 점수 검사에 자주 쓰는 모양입니다.

score = int(input("점수: "))
if 0 <= score <= 100:
    print("올바른 점수")
else:
    print("0~100 밖의 점수")

-1, 0, 55, 100, 101을 넣어 실행하면 차례로 "0~100 밖의 점수", "올바른 점수", "올바른 점수", "올바른 점수", "0~100 밖의 점수"가 나옵니다. 범위 밖을 먼저 걸러 내고 싶으면 if score < 0 or score > 100:으로 쓰면 됩니다. PY03·3의 성적 예제가 이 방법을 씁니다.

시험 함정

범위 밖을 and로 쓰는 실수. score < 0 and score > 100은 "0보다 작으면서 동시에 100보다 큰 수"라서 그런 수는 없습니다. 이 식은 어떤 점수를 넣어도 언제나 False입니다. 수직선에서 두 조건이 겹치는 곳이 없기 때문입니다. "범위 밖"은 or, "범위 안"은 and로 기억하세요.

계산 순서: not → and → or

and와 or를 한 식에 섞으면 어느 쪽을 먼저 계산할까요? 같은 값으로 괄호 위치만 바꿔 봅니다.

print(True or False and False)
print((True or False) and False)
print(not True and False)
print(not (True and False))

실행 결과

True
False
False
True

정의

논리 연산자는 not → and → or 순서로 계산한다. 곱셈이 덧셈보다 먼저인 것처럼 and가 or보다 먼저다. 비교 연산자(>= 등)는 이 셋보다도 먼저 계산된다. 괄호가 있으면 괄호 안이 가장 먼저다.

첫째 줄을 한 단계씩 계산하면 이렇습니다.

① and가 먼저: False and False → False
② 식이 True or False가 된다
③ or: → True

둘째 줄은 괄호 때문에 or가 먼저입니다.

① 괄호 안: True or False → True
② True and False → False

셋째·넷째 줄도 같은 원리입니다. not True and False는 not이 먼저라 False and False → False이고, not (True and False)는 괄호 안이 먼저라 not False → True입니다.

외우는 법

헷갈리면 괄호를 친다. 계산 순서를 외워도, and와 or가 섞인 식은 사람이 읽다가 틀리기 쉽습니다. a or (b and c)처럼 괄호를 넣으면 Python이 하는 계산은 그대로이고 읽는 사람만 편해집니다.

중간에 멈추는 계산: 단락 평가

and의 왼쪽이 False라면 오른쪽이 무엇이든 결과는 False입니다(진리표 (가)의 아래 두 줄). 그래서 Python은 오른쪽을 아예 계산하지 않습니다. 이것이 실제로 어떤 차이를 만드는지, 0으로 나누기를 이용해 확인합니다.

x = 0
print(x != 0 and 10 / x > 1)
print(10 / x > 1 and x != 0)

실행 결과

False
Traceback (most recent call last):
  File "C:\Users\...\short.py", line 3, in <module>
    print(10 / x > 1 and x != 0)
          ~~~^~~
ZeroDivisionError: division by zero

두 줄은 순서만 다를 뿐 같은 두 조건을 and로 묶었습니다. 그런데 둘째 줄은 False, 셋째 줄은 오류입니다.

  • 둘째 줄: 왼쪽 x != 0이 False → 결과는 이미 False로 정해짐 → 오른쪽 10 / x는 계산하지 않음 → 0으로 나누는 일이 일어나지 않음.
  • 셋째 줄: 왼쪽 10 / x부터 계산 → 0으로 나눌 수 없어 ZeroDivisionError("0으로 나누기")로 멈춤.

정의

단락 평가(short-circuit evaluation): and와 or는 왼쪽부터 계산해서, 결과가 정해지면 오른쪽을 계산하지 않는다.
· A and B: A가 False이면 B를 보지 않고 False.
· A or B: A가 True이면 B를 보지 않고 True.

or도 마찬가지입니다. print(True or 1 / 0)은 오류 없이 True가 나오고, print(False and 1 / 0)은 오류 없이 False가 나옵니다(실행해 확인함). 1 / 0은 계산되었다면 반드시 오류가 났을 식인데, 계산되지 않았으므로 오류도 없습니다.

"단락"은 전기 회로의 지름길(short circuit)에서 온 말로, 끝까지 가지 않고 중간에서 빠져나간다는 뜻입니다. 이 성질 덕분에 안전 검사를 왼쪽에, 위험한 계산을 오른쪽에 두면 위험한 계산이 필요할 때만 실행되게 할 수 있습니다. 둘째 줄이 바로 그 모양입니다.

가장 흔한 함정: x == 1 or 2

"x가 1 또는 2이면"을 말 그대로 옮겨 쓰면 이렇게 됩니다. x에 5를 넣어 봅니다.

x = 5
if x == 1 or 2:
    print("1 또는 2입니다")
print(x == 1 or 2)
print(x == 1 or x == 2)

실행 결과

1 또는 2입니다
2
False

x는 5인데 "1 또는 2입니다"가 출력되었습니다. 둘째 출력에서 까닭이 보입니다. Python은 이 식을 사람의 뜻처럼 x == (1 or 2)나 "x가 1이거나 x가 2"로 읽지 않고, 계산 순서대로 (x == 1) or 2로 읽습니다.

① 비교가 먼저: x == 1 → 5 == 1 → False
② False or 2 → 왼쪽이 거짓이니 오른쪽 값 2를 결과로 낸다
③ if는 2를 참으로 친다(PY02·3: 0이 아닌 수는 True) → 블록 실행

바르게 쓰려면 마지막 줄처럼 양쪽에 비교를 하나씩 완전하게 써야 합니다. x == 1 or x == 2는 x가 2일 때 True, 5일 때 False가 나옵니다(실행해 확인함). 목록을 배우고 나면(PY04) x in [1, 2]처럼 더 짧게 쓰는 방법도 있습니다.

더 알아보기 · and·or는 True/False가 아닌 값을 낼 수도 있다

②에서 False or 2의 결과가 True가 아니라 2였습니다. Python의 and·or는 정확히는 "결과를 정한 쪽의 값"을 그대로 돌려줍니다. 실행해 보면 0 or "기본값"은 기본값, "민지" or "기본값"은 민지, 3 and 5는 5, 0 and 5는 0입니다. if 조건 안에서는 이 값을 다시 참·거짓으로 치므로 결과가 같지만, print로 찍으면 차이가 드러납니다. "입력이 비어 있으면 기본값을 쓴다" 같은 짧은 코드에 쓰이지만, 입문 단계에서는 조건에는 진짜 True/False가 나오는 비교식을 쓰는 것이 안전합니다.

not을 괄호 안으로: 드모르간 법칙

"20살 이상이고 표가 있다"의 반대는 무엇일까요? "20살 미만이고 표가 없다"가 아닙니다. 둘 중 하나라도 어긋나면 탈 수 없으므로 "20살 미만이거나 표가 없다"입니다. 이 규칙을 드모르간 법칙(De Morgan's laws)이라고 합니다.

정의

not (A and B) 는 (not A) or (not B) 와 같다.
not (A or B) 는 (not A) and (not B) 와 같다.
not을 괄호 안으로 들여보내면 and와 or가 서로 바뀐다.

a = True
b = False
print(not (a and b), (not a) or (not b))
print(not (a or b), (not a) and (not b))

실행 결과

True True
False False

한 쌍의 값만 넣어 봤지만, a·b의 네 가지 조합을 모두 따져 보면 언제나 양쪽이 같습니다. 아래 표를 직접 채워 확인해 보세요.

FalseTrueFalseTrueTrueFalseTrue

넷째 열과 마지막 열이 네 줄 모두 같습니다. 앞 절의 수직선 그림에서 "범위 안(and)"을 뒤집은 것이 "범위 밖(or)"이었던 것도 이 법칙입니다. not (x >= 10 and x < 20)은 x < 10 or x >= 20과 같습니다. 비교를 뒤집을 때 >=는 <로, <는 >=로 바뀐다는 점(경계값이 반대쪽으로 넘어감)도 함께 보세요.

풀이 예제: 할인 대상

풀이 예제

"65세 이상이거나 회원이면 할인"을 코드로 쓰고, 네 가지 경우를 손으로 먼저 계산한 뒤 실행해 맞춰 봅니다.

age = int(input("나이: "))
member = input("회원(y/n): ") == "y"
if age >= 65 or member:
    print("할인 적용")
else:
    print("정상 요금")

둘째 줄은 처음 보는 모양입니다. input(…) == "y"는 입력이 "y"인지 비교한 결과, 곧 True나 False를 member에 담습니다. 비교식의 결과가 값이라는 PY02·3의 내용을 그대로 쓴 것입니다.

① 70, n: age >= 65 → True. or의 왼쪽이 True이므로 member는 보지 않고 True → 할인 적용
② 30, y: age >= 65 → False. member → True. False or True → True → 할인 적용
③ 30, n: False or False → False → 정상 요금
④ 65, y: 65 >= 65 → True (경계값 65 포함) → 할인 적용

실행 결과 (네 번 실행, 안내문 뒤는 키보드로 친 것)

나이: 70
회원(y/n): n
할인 적용

나이: 30
회원(y/n): y
할인 적용

나이: 30
회원(y/n): n
정상 요금

나이: 65
회원(y/n): y
할인 적용

손으로 계산한 것과 같습니다. 회원 입력에 대문자 "Y"를 넣으면 "Y" == "y"가 False라서 회원으로 치지 않는다는 점도 짚어 둡니다(PY02·3: 대소문자는 다른 글자).

왜 그럴까?

①에서 나이가 70이면 회원 여부를 묻는 input()은 실행될까요, 안 될까요? 단락 평가와 헷갈리기 쉬운 부분입니다.

모범 답 보기

실행됩니다. 회원을 묻는 input()은 둘째 줄에서 이미 실행되어 member에 값이 담긴 뒤입니다. 단락 평가가 건너뛰는 것은 if 줄의 or 오른쪽인 member라는 값을 읽는 일뿐입니다. 만약 if 줄에 age >= 65 or input("회원(y/n): ") == "y"라고 직접 썼다면, 70세일 때는 회원을 묻는 안내문 자체가 나오지 않았을 것입니다.

이 내용이 다시 나오는 곳

  • PY03·3: and로 묶은 평평한 조건과 if 안의 if(중첩)를 비교하고, 경계값마다 결과를 확인합니다.
  • PY08: 입력 검증에서 "비어 있지 않고 숫자 모양이며 범위 안"처럼 여러 조건을 and로 묶고, 단락 평가로 위험한 검사를 뒤로 미룹니다.
  • 집합과 확률: and는 교집합, or는 합집합, not은 여집합과 같은 구조입니다. 드모르간 법칙은 집합에서도 똑같이 성립합니다(DM01, PR01).
  • 데이터 분석: 표에서 "서울이고 30대인 행"을 고르는 필터가 바로 and입니다(PY11).

and는 모두 참일 때, or는 하나라도 참일 때 참이고, Python은 not → and → or 순서로 왼쪽부터 계산하다가 결과가 정해지면 멈춘다.
