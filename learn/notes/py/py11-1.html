pandas로 표 읽고 필요한 행 고르기

주문 표에서 둘째 행과 주문번호 104번은 지금은 같은 행입니다. 표를 결제액순으로 정렬하면 둘째 행은 달라집니다. 주문번호를 보존한 표를 만든 뒤, 이름과 위치를 각각 기준으로 값을 찾아보고 조건에 맞는 행을 골라 냅니다.

이 장을 읽고 나면

  • Series와 DataFrame을 구분하고 행 하나의 뜻을 적을 수 있다.
  • CSV 읽기에 자료형을 명시하고 0과 결측을 구분할 수 있다.
  • loc, iloc, 불리언 마스크로 행과 열을 선택할 수 있다.
  • 원본을 유지하면서 추린 표를 복사해 작업할 수 있다.

한 행의 뜻과 자료형을 정한다

카페의 작은 주문 표입니다. 한 행은 주문 한 건이고 행 번호표에 주문번호가 있습니다. 주문번호가 비어 있거나 중복되지 않는다는 가정입니다. 다섯 번째 주문은 수량을 알지만 결제액이 기록되지 않았습니다.

주문번호매장수량(개)결제액(원)
101East23,200
104West35,100
105East12,400
108West46,100
109East2<NA>

정의

Series는 값과 행 라벨로 이루어진 1차원 자료입니다. 이 표에서는 amount 열 하나가 Series입니다. DataFrame은 행 라벨과 열 이름이 있는 2차원 표입니다. NumPy 배열과 달리 열마다 자료형이 다를 수 있습니다. 행 라벨의 모음을 인덱스(index)라고 부릅니다.

매장은 문자열 string으로 정하고, 수량과 결제액은 정수 Int64로 정합니다. 대문자 I로 시작하는 pandas Int64는 결측값 pd.NA도 허용합니다. 일반 NumPy int64는 결측값을 담지 못합니다. 자료형을 명시하면 문자열 연산과 수치 계산 중 어느 쪽을 의도했는지 코드에서 드러납니다.

import pandas as pd

orders = pd.DataFrame(
    {
        "store": pd.array(["East", "West", "East", "West", "East"], dtype="string"),
        "qty": pd.array([2, 3, 1, 4, 2], dtype="Int64"),
        "amount": pd.array([3200, 5100, 2400, 6100, None], dtype="Int64"),
    },
    index=pd.Index([101, 104, 105, 108, 109], name="order_id"),
)

assert orders.index.is_unique
print("shape:", orders.shape)
print("열:", orders.columns.tolist())
print("수량의 자료형:", orders["qty"].dtype)
print("결제액 결측:", int(orders["amount"].isna().sum()))
print("한 열:", type(orders["amount"]).__name__)
print("한 열을 담은 표:", type(orders[["amount"]]).__name__)

실행 결과

shape: (5, 3)
열: ['store', 'qty', 'amount']
수량의 자료형: Int64
결제액 결측: 1
한 열: Series
한 열을 담은 표: DataFrame

orders["amount"]에서 대괄호 안에 열 이름 하나를 줍니다. orders[["amount"]]에서는 열 이름들의 리스트를 주므로 한 열만 있어도 표로 남습니다. 둘의 행 라벨은 같습니다. 결제액 Series에 isna()를 쓰면 결측인 위치만 참인 Series가 생깁니다. sum()은 여기서 참을 1, 거짓을 0으로 더해 결측을 셉니다.

CSV에서 읽을 때도 열의 뜻을 먼저 정하기

주문번호의 001이 세 자리 식별자라면 앞의 0도 데이터입니다. 수량은 계산할 정수입니다. 같은 숫자 모양이라도 열의 뜻에 따라 읽는 방법을 달리합니다. 다음 예에서 StringIO는 짧은 문자열을 파일 대신 읽게 합니다. 실제 파일에서는 pd.read_csv("orders.csv", ...)처럼 파일 경로를 넣습니다.

import pandas as pd
from io import StringIO

csv_text = "order_id,qty\n001,2\n002,\n"
df = pd.read_csv(
    StringIO(csv_text), dtype={"order_id": "string", "qty": "Int64"}
)
print(df["order_id"].tolist())
print(df["qty"].isna().tolist())

실행 결과

['001', '002']
[False, True]

CSV의 빈 칸을 결측으로 읽었습니다. 실제 자료의 NA 같은 표기가 지역 코드인지 결측 코드인지는 출처에서 확인한 뒤 필요에 따라 na_values와 keep_default_na를 지정합니다.

행 라벨과 위치로 각각 고르기

둘째 행에 적힌 주문번호는 104입니다. 컴퓨터가 세는 위치는 1입니다. 행 선택 명령을 읽을 때 104라는 라벨을 찾는지, 위치 1을 찾는지 먼저 확인합니다.

선택하는 기준이 표에서 쓰는 표현돌아오는 값
.loc는 라벨orders.loc[104, 'amount']주문 104의 결제액 5,100원
.iloc는 위치orders.iloc[1, 2]둘째 행의 셋째 열, 5,100원
라벨로 구간orders.loc[104:108]104, 105, 108. 이 예에서는 양 끝 라벨 포함
위치로 구간orders.iloc[1:3]위치 1, 2의 행. 끝 위치 3 제외

라벨 범위는 번호가 연속으로 늘어나는 정수 범위와 다릅니다. 오늘 표처럼 라벨이 고유하고 정렬되어 있고 양 끝이 존재하면 위처럼 읽으면 됩니다. 라벨 범위의 의미가 불분명한 표에서는 원하는 라벨들을 리스트로 주거나 먼저 정렬합니다.

흔한 함정

orders.loc[1]은 행 라벨 1을 찾습니다. 이 표에는 없어 KeyError: 1이 납니다. orders.iloc[104]는 105번째 자리의 행을 찾으므로 IndexError: single positional indexer is out-of-bounds가 납니다. 우연히 0·1·2 라벨을 쓴 표에서는 두 결과가 같아 보여도, 정렬이나 필터가 들어가면 쉽게 달라집니다.

조건으로 고르고 안전하게 수정한다

이번에는 '결제액이 5,000원 이상이고 수량이 3개 이상'인 주문만 남깁니다. 열과 수를 비교하면 행마다 참·거짓을 담은 Series가 나옵니다. 이것이 불리언 마스크입니다. pandas의 Int64 열에서 pd.NA를 수와 비교하면 그 결과도 참·거짓이 아닌 <NA>입니다. 그래서 orders["amount"] >= 5000은 [False, True, False, True, <NA>]를 담은 boolean 자료형 Series가 됩니다. fillna(False)를 조건에 적용하면 결제액을 모르는 주문을 조건 결과에서 제외하겠다는 결정이 명시됩니다. 원본 결제액은 바꾸지 않습니다.

import pandas as pd

orders = pd.DataFrame(
    {
        "store": pd.array(["East", "West", "East", "West", "East"], dtype="string"),
        "qty": pd.array([2, 3, 1, 4, 2], dtype="Int64"),
        "amount": pd.array([3200, 5100, 2400, 6100, None], dtype="Int64"),
    },
    index=pd.Index([101, 104, 105, 108, 109], name="order_id"),
)

high = (orders["amount"] >= 5000).fillna(False)
many = orders["qty"] >= 3
picked = orders.loc[high & many, ["store", "amount"]].copy()
picked.loc[104, "amount"] = 5200
print("선택한 행:", picked.index.tolist())
print("복사본:", int(picked.loc[104, "amount"]))
print("원본:", int(orders.loc[104, "amount"]))

실행 결과

선택한 행: [104, 108]
복사본: 5200
원본: 5100

조건을 각각 괄호로 감싼 뒤 &는 둘 다, |는 둘 중 하나, ~는 반대를 뜻합니다. Python의 and와 or는 Series 각각의 원소를 묶지 못합니다. 기본적으로 같은 표에서 마스크를 만들면 행 라벨이 맞습니다. 다른 표의 마스크를 가져올 때에는 행의 순서와 라벨을 확인합니다.

복사와 원본 수정의 차이

이 예제의 목적은 원본 기록을 유지한 채 복사본을 시험하는 것입니다. .copy()로 떼어낸 뒤 picked.loc[104, "amount"] = 5200을 한 번에 지정합니다. 반대로 정정 내역에 따라 원본 표를 수정하려면 orders.loc[104, "amount"] = 5200처럼 어느 표를 바꿀지 코드에 명시합니다. orders[high]["amount"] = ...처럼 연달아 선택해서 대입(연쇄 대입)하면, pandas 3.0부터 기본이 된 쓰기 시 복사(Copy-on-Write) 규칙 때문에 중간 결과가 항상 사본처럼 동작합니다. 그래서 원본은 절대 바뀌지 않고 ChainedAssignmentError 경고만 나옵니다. 한 번의 .loc[행, 열] = 값으로 대입합니다.

왜 그럴까?

결제액을 모르는 주문을 찾는 필터와, 0원 주문을 찾는 필터를 왜 분리해야 할까요?

모범 답 보기

0원은 확인한 수치이며 결측은 값의 부재입니다. amount.isna()로 누락된 기록을 찾고, (amount == 0).fillna(False)로 확인된 0원만 찾습니다. 둘을 섞으면 품질 확인과 결제액 계산이 달라집니다.
