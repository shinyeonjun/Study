Python과 프로그래밍 사고 · PY05 함수와 분해

PY05·2

지역변수와 문제 분해

세 반의 점수를 받아 반마다 평균과 등급(A·B·C)을 보고하는 프로그램을 만든다고 합시다. 한 덩어리로 쓰면 같은 반복이 세 번 복사되고, 어디가 틀렸는지 찾기도 어렵습니다. 이 장에서는 먼저 함수 안의 변수가 함수 밖과 어떻게 분리되는지(지역변수와 범위)를 보고, 그다음 이 문제를 평균 구하기, 등급 매기기, 보고하기라는 작은 함수 셋으로 나누어 풉니다.

이 장을 읽고 나면

  • 지역변수가 언제 생기고 언제 사라지는지 설명하고, 함수 밖에서 쓰면 왜 NameError가 나는지 말할 수 있다.
  • 함수 안과 밖에 같은 이름이 있을 때 어느 값이 쓰이는지 예측할 수 있다.
  • 바깥 변수를 함수 안에서 바꾸려다 나는 UnboundLocalError를 매개변수와 return으로 고칠 수 있다.
  • 복사해 붙인 반복 코드를 함수 하나로 묶을 수 있다.
  • 문제를 말로 나눈 뒤 작은 함수로 옮기고, 함수를 하나씩 시험할 수 있다.

함수 안의 변수는 함수 안에서만 외우기

앞 장(PY05·1)에서 매개변수 x는 "상자 안에서만 쓰는 이름"이라고 했습니다. 함수 몸통에서 새로 만든 변수도 마찬가지입니다. 확인해 봅시다.

def double(x):
    result = x * 2
    return result

print(double(5))
print(result)

실행 결과

10
Traceback (most recent call last):
  File "C:\Users\...\practice.py", line 6, in <module>
    print(result)
          ^^^^^^
NameError: name 'result' is not defined

double(5)는 10을 잘 돌려줬습니다. 그런데 함수 밖에서 result를 부르니 "그런 이름은 없다"고 합니다. 분명 함수 안에서 result = x * 2를 실행했는데도요.

정의 · 지역변수와 범위

지역변수(local variable): 함수 안에서 만든 변수와 매개변수. 함수가 호출될 때 생기고, 함수가 끝나면(return) 사라집니다. 그 함수 안에서만 쓸 수 있습니다.
전역변수(global variable): 함수 밖, 파일의 맨 바깥에서 만든 변수. 파일 어디서나 읽을 수 있습니다.
범위(scope, 스코프): 어떤 이름을 쓸 수 있는 코드의 영역. 지역변수의 범위는 그 함수의 몸통입니다.
함수 안에서 이름을 찾는 순서는 지역 → 전역 → 내장입니다. 내장(built-in)은 print, len처럼 Python에 처음부터 들어 있는 이름입니다. (함수 안에 함수를 또 정의하면 그 사이에 한 단계가 더 생기는데, 이 교재에서는 아직 쓰지 않습니다.)

함수를 호출할 때마다 Python은 그 호출만을 위한 작업 공간을 새로 만들고, 매개변수와 몸통의 변수를 그 안에 둡니다. return을 하면 반환값만 들고 나오고 작업 공간은 통째로 치웁니다. 시험장에서 받은 연습지를 시험이 끝나면 걷어 가는 것과 비슷합니다. 답안(반환값)만 제출되고 연습지(지역변수)는 남지 않습니다.

그래서 함수 안의 결과를 밖에서 쓰고 싶으면 지역변수 이름을 부를 것이 아니라 반환값을 받아야 합니다. r = double(5)처럼 받으면 바깥의 r에 10이 들어갑니다.

같은 이름, 다른 변수

함수 안과 밖에서 같은 이름을 쓰면 어떻게 될까요?

x = 100

def show():
    x = 1
    print("함수 안 x =", x)

show()
print("함수 밖 x =", x)

실행 결과

함수 안 x = 1
함수 밖 x = 100

함수 안의 x = 1은 바깥 x를 1로 바꾼 것이 아니라, show의 작업 공간에 x라는 새 지역변수를 만든 것입니다. 이름은 같지만 서로 다른 변수입니다. 함수가 끝나면 지역 x는 사라지고, 바깥 x는 처음 그대로 100입니다.

바깥 변수 읽기는 되고, 바꾸기는 안 된다

함수 안에 그 이름의 지역변수가 없으면 Python은 바깥(전역)에서 찾습니다. 그래서 읽기는 됩니다.

rate = 10

def tax(price):
    return price * rate / 100

print(tax(5000))

실행 결과

500.0

하지만 바깥 변수를 함수 안에서 바꾸려고 하면 문제가 생깁니다.

count = 0

def add_one():
    count += 1

add_one()

실행 결과

Traceback (most recent call last):
  File "C:\Users\...\practice.py", line 6, in <module>
    add_one()
    ~~~~~~~^^
  File "C:\Users\...\practice.py", line 4, in add_one
    count += 1
    ^^^^^
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value

traceback이 두 단계입니다. 아래에서 위로 읽으면, 4번 줄(add_one 함수 안)에서 오류가 났고, 그 함수는 6번 줄에서 호출되었습니다. 메시지는 "지역변수 count에 아직 값이 연결되지 않아 읽을 수 없다"입니다.

왜 그럴까요? Python은 함수 안에 count = …(여기서는 count += 1)처럼 대입하는 줄이 있으면 그 이름을 지역변수로 정합니다. 그런데 count += 1은 count = count + 1이라 오른쪽에서 지역 count를 먼저 읽어야 하는데, 지역 count에는 아직 아무 값도 없습니다. 바깥의 count = 0은 다른 변수라 쓰이지 않습니다.

고치는 방법은 바깥 값을 인자로 넣고, 새 값을 반환받는 것입니다.

def add_one(n):
    return n + 1

count = 0
count = add_one(count)
count = add_one(count)
print(count)

실행 결과

2

이렇게 하면 함수는 매개변수로 받은 값만 쓰고, 결과는 return으로만 내보냅니다. 함수가 하는 일이 괄호 안(들어가는 것)과 return(나오는 것)만 보면 다 드러나므로 읽기도 시험하기도 쉽습니다.

더 알아보기 · global

함수 안에 global count라고 적으면 "이 함수 안의 count는 전역 count다"라고 선언되어 바깥 변수를 직접 바꿀 수 있습니다. 하지만 여러 함수가 같은 전역변수를 바꾸면 어느 함수가 언제 값을 바꿨는지 추적하기 어려워집니다. 이 교재에서는 매개변수와 return으로 값을 주고받는 방식을 기본으로 씁니다.

매개변수에 새 값을 넣어도 바깥은 그대로

def plus_one(n):
    n = n + 1
    return n

a = 5
b = plus_one(a)
print("a =", a, "b =", b)

실행 결과

a = 5 b = 6

호출 때 n = a처럼 a의 값 5가 지역변수 n에 들어갈 뿐, n과 a는 다른 변수입니다. n을 6으로 바꿔도 a는 5 그대로입니다. (리스트처럼 내용을 바꿀 수 있는 값을 넘기면 이야기가 조금 달라지는데, 그것은 PY06 "참조와 복사"에서 다룹니다.)

반복 작업을 함수로 묶기 이해하기

이제 처음 문제로 돌아갑니다. 함수를 모르면 반마다 평균 구하는 코드를 복사해 붙이게 됩니다.

class1 = [80, 90, 70]
total = 0
for s in class1:
    total += s
print("1반 평균:", total / len(class1))

class2 = [95, 90, 91]
total = 0
for s in class2:
    total += s
print("2반 평균:", total / len(class2))

실행 결과

1반 평균: 80.0
2반 평균: 92.0

두 덩어리는 리스트 이름만 다르고 똑같습니다. 바뀌는 부분(리스트)을 매개변수로, 결과(평균)를 반환값으로 하면 함수 하나가 됩니다.

def average(scores):
    total = 0
    for s in scores:
        total += s
    return total / len(scores)

print("1반 평균:", average([80, 90, 70]))
print("2반 평균:", average([95, 90, 91]))

실행 결과

1반 평균: 80.0
2반 평균: 92.0

얻는 것은 세 가지입니다.

  • 고칠 곳이 하나: 평균 계산을 바꿔야 하면 정의 한 곳만 고치면 됩니다. (가)라면 반이 30개일 때 30곳을 고쳐야 하고, 한 곳을 빠뜨리기 쉽습니다.
  • 이름이 뜻을 말함: average([80, 90, 70])은 읽기만 해도 무엇을 하는지 압니다. 네 줄짜리 반복을 볼 때마다 해석할 필요가 없습니다.
  • 따로 시험할 수 있음: 답을 아는 작은 입력을 넣어 함수만 확인할 수 있습니다(아래에서 해 봅니다).

그리고 지역변수 덕분에, average 안의 total과 s는 바깥의 다른 변수와 부딪치지 않습니다. 바깥에 total이라는 변수가 있어도 average를 부를 때 망가지지 않습니다.

작은 함수로 문제 나누기 이해하기

이제 전체 문제를 풉니다. 바로 코드를 쓰지 않고, 먼저 말로 나눕니다. 이렇게 큰 문제를 스스로 풀 수 있을 만큼 작은 문제로 쪼개는 것을 문제 분해(decomposition)라고 합니다.

문제

반 이름과 점수 목록을 받아 "1반 평균 80.0 등급 B"처럼 한 줄로 보고한다. 등급은 평균 90 이상이면 A, 80 이상이면 B, 그 밖에는 C.

① 보고하려면 무엇이 필요한가? → 평균, 등급
② 평균은 무엇으로 구하나? → 점수 목록만 있으면 된다 → average(scores): 목록을 받아 평균을 돌려준다
③ 등급은 무엇으로 정하나? → 평균 하나만 있으면 된다 → grade(avg): 평균을 받아 "A"/"B"/"C"를 돌려준다
④ 둘을 이어 출력한다 → report(name, scores): average와 grade를 불러 결과를 한 줄로 출력한다

나눈 대로 코드로 옮깁니다. 각 함수는 짧고, 하는 일이 하나입니다.

def average(scores):
    total = 0
    for s in scores:
        total += s
    return total / len(scores)

def grade(avg):
    if avg >= 90:
        return "A"
    elif avg >= 80:
        return "B"
    else:
        return "C"

def report(name, scores):
    avg = average(scores)
    g = grade(avg)
    print(name, "평균", avg, "등급", g)

report("1반", [80, 90, 70])
report("2반", [95, 90, 91])
report("3반", [60, 75, 72])

실행 결과

1반 평균 80.0 등급 B
2반 평균 92.0 등급 A
3반 평균 69.0 등급 C

report("1반", [80, 90, 70]) 한 번이 실행되는 과정을 따라가 봅시다. 함수 안에서 또 함수를 부르므로, 실행 흐름이 report → average → report → grade → report로 건너갔다 돌아옵니다.

여기서도 지역변수가 일합니다. average 안의 scores와 report 안의 scores는 서로 다른 지역변수이고(값만 같습니다), grade의 매개변수 avg와 report의 avg도 다른 변수입니다. 함수마다 자기 작업 공간이 있으니 이름이 겹쳐도 괜찮습니다.

함수를 하나씩 시험하기

작게 나눈 함수는 따로따로 확인할 수 있습니다. 손으로 답을 아는 입력, 특히 경계값(PY03에서 본 것처럼 조건의 결과가 바뀌는 바로 그 값, 여기서는 90과 80)을 넣어 봅니다.

print(average([80, 90, 70]))
print(average([100]))
print(grade(90))
print(grade(89.9))
print(grade(80))
print(grade(79))

실행 결과

80.0
100.0
A
B
B
C

average([80, 90, 70]): 240 ÷ 3 = 80 → 80.0 ✔
average([100]): 원소 하나 → 100 ÷ 1 = 100.0 ✔
grade(90): 경계값. 90 이상이면 A ✔ · grade(89.9): 바로 아래라 B ✔
grade(80): 경계값 B ✔ · grade(79): C ✔

(이 여섯 줄을 실행하려면 위의 average·grade 정의가 같은 파일 위쪽에 있어야 합니다.) 이렇게 부품이 맞는 것을 확인한 뒤 report를 보면, report가 틀렸을 때 의심할 곳은 report의 세 줄뿐입니다. 한 덩어리 코드였다면 처음부터 끝까지 다 의심해야 했을 것입니다.

아직 막지 못한 경우

점수가 하나도 없는 반이면 어떻게 될까요?

print(average([]))

실행 결과

Traceback (most recent call last):
  File "C:\Users\...\practice.py", line 7, in <module>
    print(average([]))
          ~~~~~~~^^^^
  File "C:\Users\...\practice.py", line 5, in average
    return total / len(scores)
           ~~~~~~^~~~~~~~~~~~~
ZeroDivisionError: division by zero

빈 리스트의 길이는 0이라 0 ÷ 0을 계산하려다 "0으로 나누기" 오류가 났습니다. (이 traceback은 average 정의 다섯 줄과 빈 줄 하나 아래에 이 한 줄을 둔 파일로 실행한 것이라 줄 번호가 7입니다.) 이런 입력을 미리 검사하고 오류를 다루는 법은 PY08 "디버깅과 검증"에서 배웁니다. 지금은 "이 함수는 점수가 하나 이상 있을 때만 쓴다"는 전제를 기억해 두면 됩니다.

흔한 실수 · return을 반복 안에 넣기

def average(scores):
    total = 0
    for s in scores:
        total += s
        return total / len(scores)

print(average([80, 90, 70]))

실행 결과

26.666666666666668

return을 for의 몸통 안으로 들여쓰면, 첫 회차에서 total = 80이 되자마자 80 ÷ 3을 돌려주고 함수가 끝납니다(return은 함수를 즉시 끝내므로 반복도 함께 끝납니다). 26.666…은 80 ÷ 3입니다. 누적을 다 끝낸 뒤 돌려주려면 return은 for와 같은 깊이로, 반복 뒤에 둡니다. PY04·2의 "print의 위치" 실수와 같은 종류입니다.

좋은 작은 함수의 기준

기준이 장의 예에서
한 가지 일만 한다. 이름 하나로 설명된다average는 평균만, grade는 등급만
필요한 것은 매개변수로 받는다grade는 바깥 변수를 쓰지 않고 avg만 받는다
결과는 return으로 내보낸다 (출력은 맨 바깥에서)average·grade는 return, 출력은 report만
이름은 하는 일을 말하는 동사·명사로f1, do 대신 average, grade

grade가 출력하지 않고 등급을 돌려주기 때문에, 나중에 "등급이 C인 반의 수 세기" 같은 새 일이 생겨도 grade를 그대로 다시 쓸 수 있습니다. 출력까지 해 버리는 함수였다면 다시 쓰기 어렵습니다(PY05·1의 return과 print).

왜 그럴까?

지역변수가 함수가 끝나면 사라지는 것은 불편해 보입니다. 함수 안에서 만든 변수가 모두 바깥에 남는다면 어떤 문제가 생길지 이 장의 report 예로 생각해 보세요.

모범 답 보기

average 안의 total, report 안의 avg, grade 안의 avg가 모두 한 공간에 남는다면, 이름이 같은 변수끼리 서로 값을 덮어씁니다. 예를 들어 바깥에서 total이라는 변수를 쓰고 있었는데 average를 한 번 부르는 순간 그 값이 240으로 바뀌어 버립니다. 함수를 쓸 때마다 "이 함수가 안에서 어떤 이름을 쓰는지"를 다 알아야 하니, 함수를 이름만 보고 가져다 쓰는 장점이 사라집니다. 지역변수는 함수를 서로 부딪치지 않는 독립된 부품으로 만들어 줍니다.

한눈에 정리

개념뜻기억할 점
지역변수함수 안에서 만든 변수와 매개변수호출 때 생기고 return 때 사라진다. 밖에서 부르면 NameError
전역변수파일 맨 바깥에서 만든 변수함수 안에서 읽기는 되지만, 대입하면 지역변수가 된다(UnboundLocalError)
범위(scope)이름을 쓸 수 있는 영역이름은 지역 → 전역 → 내장 순서로 찾는다. 같은 이름이어도 다른 변수
반복 작업 묶기바뀌는 부분 → 매개변수, 결과 → return고칠 곳 하나, 이름이 뜻을 말함, 따로 시험
문제 분해큰 문제를 작은 함수로 나누기말로 먼저 나눈다. 함수 하나에 일 하나
함수 시험답을 아는 작은 입력·경계값으로 하나씩빈 목록 같은 입력은 PY08에서

한 줄 정리

함수 안의 변수는 호출 동안만 있는 지역변수라서 함수끼리 부딪치지 않고, 이 덕분에 큰 문제를 매개변수로 받고 return으로 돌려주는 작은 함수 여러 개로 나누어 하나씩 시험하며 풀 수 있다.
