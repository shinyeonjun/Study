PY09·1

import와 가상환경: 어떤 Python을 쓰고 있나

어제까지 실행되던 코드에 ModuleNotFoundError가 뜨면 먼저 설치한 위치를 확인합니다. 같은 컴퓨터에도 여러 Python과 가상환경이 있을 수 있습니다. 이 장에서는 코드를 불러오는 일과 그 코드를 사용할 수 있게 설치하는 일을 연결합니다.

이 장을 읽고 나면

  • 모듈, 패키지, 표준 라이브러리의 역할을 구분한다.
  • 가상환경을 만들고 그 환경의 Python으로 실행한다.
  • 설치가 안 된 경우와 다른 Python을 쓴 경우를 구분한다.

이미 작성된 코드를 불러오기

숫자 세 개의 평균을 구할 때 직접 sum(values) / len(values)를 써도 됩니다. Python에 포함된 statistics 모듈에서 평균 함수를 가져오면 다른 코드에도 같은 이름으로 쓸 수 있습니다.

import statistics as stats
values = [60, 80, 100]
print(stats.mean(values))
print(stats.median(values))

실행 결과

80
80

용어

모듈은 가져와 쓸 수 있는 코드 단위입니다. 패키지는 모듈이나 하위 패키지를 묶어 이름으로 접근할 수 있게 합니다. 표준 라이브러리에는 이미 Python에 함께 제공되는 모듈이 들어 있습니다. NumPy처럼 따로 설치하는 것은 외부 라이브러리입니다.

as stats는 현재 파일에서 부를 이름을 정합니다. import numpy as np에서도 np는 짧게 부르는 이름이고, 실제로 가져오는 이름은 numpy입니다. 설치용 이름은 배포 패키지의 이름이라 import할 이름과 다른 경우도 있습니다.

같은 파일을 두 환경에서 실행하면

분석 A에 NumPy를 설치한 다음 분석 B의 Python으로 같은 코드를 실행한다고 가정합시다. B에는 아직 NumPy가 없으므로 첫 줄에서 멈춥니다. 터미널 창을 바꿨다거나 편집기가 다른 인터프리터를 가리킬 때 흔히 만나는 상황입니다.

정의

가상환경은 프로젝트별로 패키지 설치 위치를 나누는 Python 실행 환경입니다. C 드라이브 전체를 복제하지 않습니다. .venv를 새로 만들어도 다른 프로젝트에 설치된 패키지가 자동으로 들어오지 않습니다. 일반적인 venv 기본 설정을 기준으로 설명합니다.

Windows에서 만들고 실행하기

연습 폴더를 만든 뒤 그 안에서 PowerShell을 엽니다. -m venv는 현재 명령의 Python으로 venv 모듈을 실행하고, 마지막 인수 .venv는 환경을 만들 폴더입니다. 생성 후에는 이 폴더의 실행 파일을 명시합니다.

python -m venv .venv
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip --version

첫 명령은 보통 메시지 없이 끝납니다. 버전은 설치한 Python에 따라 달라집니다. macOS·Linux의 일반적인 venv에서는 ./.venv/bin/python을 씁니다. 활성화는 명령을 짧게 쓰도록 현재 셸의 검색 경로를 바꾸는 편의 기능입니다. 여기서는 실행 파일을 직접 가리켜 PowerShell 활성화 정책에 의존하지 않습니다.

이 과정을 직접 연습할 때만 다음 설치 명령을 실행합니다. 인터넷이 필요하며 -m pip는 명령 앞에 지정한 Python이 사용하는 pip를 실행합니다.

.\.venv\Scripts\python.exe -m pip install numpy pandas matplotlib
.\.venv\Scripts\python.exe -c "import numpy, pandas, matplotlib; print(numpy.__version__, pandas.__version__, matplotlib.__version__)"

실행한 Python과 모듈의 출처를 확인하기

sys.executable은 지금 실행한 Python의 경로입니다. 아래 예제의 첫 줄은 Windows에서 보이는 실행 파일 이름입니다. 운영체제에 따라 이름이 달라질 수 있으니 실제 문제를 찾을 때는 print(sys.executable)로 전체 경로를 비교하세요. sys.prefix와 sys.base_prefix가 다르면 표준 venv에서 실행 중인지 확인하는 단서입니다.

from pathlib import Path
import sys

print(f"실행 파일: {Path(sys.executable).name.lower()}")
print(f"가상환경: {sys.prefix != sys.base_prefix}")

실행 결과

실행 파일: python.exe
가상환경: True

이 출력은 가상환경의 Python으로 실행했을 때입니다. 기본 Python에서 실행하면 둘째 줄은 False가 나올 수 있습니다.

예를 들어 연습 폴더에 numpy.py를 만들면 그 파일이 외부 NumPy보다 먼저 발견될 수 있습니다. import numpy가 성공했는데 numpy.array가 없다는 오류가 나면 print(numpy.__file__)로 불러온 파일의 위치를 확인합니다. 이 경우 연습 파일의 이름을 array_practice.py처럼 바꾸고, 같은 세션에서 다시 불러오던 중이었다면 Python을 다시 시작합니다.

증상먼저 확인할 것
import부터 실패실행 경로와 설치한 환경, 이름 철자
import는 되는데 필요한 이름이 없음내 파일과 이름이 겹치는지, 패키지 버전
편집기와 터미널의 결과가 다름두 곳에서 sys.executable 비교
패키지 넣었는데 다른 환경에서 안 보임해당 환경의 python -m pip show로 설치 위치 확인

짧은 실습

같은 폴더에서 터미널의 Python과 편집기가 선택한 Python을 각각 실행해 경로를 적습니다. 둘이 다르면 어느 쪽을 프로젝트 환경으로 쓸지 결정한 뒤, 그 Python에서 NumPy를 불러오는지 확인합니다. 다음 장에서는 이 실습을 다른 날에도 다시 실행할 수 있도록 기록합니다.
