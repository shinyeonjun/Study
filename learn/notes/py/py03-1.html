PY03·1

if·elif·else와 들여쓰기

지금까지의 프로그램은 위에서 아래로 모든 줄을 한 번씩 실행했습니다. 그런데 "기온이 30도 이상이면 물을 마시라고 알려 줘"처럼, 어떤 줄은 조건이 맞을 때만 실행해야 할 때가 있습니다. 이 장에서는 PY02·3에서 만든 True/False로 실행할 줄을 고르는 if·elif·else 문과, 어디까지가 조건에 딸린 줄인지 정하는 들여쓰기를 흐름도와 함께 익힙니다.

이 장을 읽고 나면

  • if, if/else, if/elif/else 코드를 흐름도로 그리고, 입력값에 따라 어느 줄이 실행되는지 짚을 수 있다.
  • 쌍점과 들여쓰기로 "조건에 딸린 줄(블록)"이 어디까지인지 가려낼 수 있다.
  • elif 조건의 순서가 결과를 바꾸는 까닭을 설명하고, 잘못된 순서를 고칠 수 있다.
  • if를 여러 개 쓴 것과 if/elif로 이은 것의 차이를 실행 결과로 설명할 수 있다.
  • IndentationError와 쌍점이 빠진 SyntaxError를 읽고 고칠 수 있다.

조건이 맞을 때만: if

여름날 기온을 넣으면, 30도 이상일 때만 주의 문구를 보여 주는 프로그램입니다.

temp = int(input("오늘 최고 기온: "))
if temp >= 30:
    print("더운 날입니다.")
    print("물을 자주 마시세요.")
print("기온 확인 끝")

30과 29를 넣어 두 번 실행합니다.

실행 결과 ① (30은 키보드로 친 것)

오늘 최고 기온: 30
더운 날입니다.
물을 자주 마시세요.
기온 확인 끝

실행 결과 ② (29는 키보드로 친 것)

오늘 최고 기온: 29
기온 확인 끝

같은 코드인데 ②에서는 두 줄이 통째로 빠졌습니다. 둘째 줄의 temp >= 30이 ①에서는 True, ②에서는 False였기 때문입니다. 30을 넣은 ①도 True였다는 점을 눈여겨보세요. >=는 "30 이상"이라 30 자신을 포함합니다(PY02·3).

정의

if 문은 if 조건: 다음 줄부터 들여쓴 줄들을, 조건이 True일 때만 실행한다. 조건이 False이면 그 줄들을 건너뛰고 들여쓰기가 끝난 다음 줄로 간다. 이렇게 조건에 따라 실행할 줄을 고르는 것을 분기(branch, 갈래)라고 한다.

용어 아래 흐름도는 정보처리기사의 순서도와 같은 약속입니다(네모 = 처리, 마름모 = 조건, 마름모에서 True/False 두 갈래).

if에는 꼭 지켜야 할 문법이 두 가지 있습니다.

  1. 조건 뒤의 쌍점 :. "여기서부터 조건에 딸린 줄이 시작된다"는 표시입니다.
  2. 딸린 줄들의 들여쓰기. 줄 앞에 빈칸을 넣어 오른쪽으로 밀어 씁니다. 관례는 빈칸 4개입니다.

들여쓰기가 범위를 정한다 이해하기

다른 많은 언어는 중괄호 { }로 "여기부터 여기까지"를 묶지만, Python은 들여쓰기 자체로 묶습니다. 같은 깊이로 들여쓴 줄들이 한 덩어리가 되고, 이 덩어리를 블록(block)이라고 합니다.

들여쓰기는 모양을 예쁘게 하려는 것이 아니라 뜻을 바꿉니다. 앞 프로그램에서 넷째 줄의 들여쓰기만 지워 봅니다.

temp = int(input("오늘 최고 기온: "))
if temp >= 30:
    print("더운 날입니다.")
print("물을 자주 마시세요.")
print("기온 확인 끝")

실행 결과 (20은 키보드로 친 것)

오늘 최고 기온: 20
물을 자주 마시세요.
기온 확인 끝

20도인데도 "물을 자주 마시세요."가 나왔습니다. 넷째 줄이 왼쪽 끝으로 나오면서 if 블록 밖이 되어, 조건과 상관없이 늘 실행되는 줄이 된 것입니다. 오류가 나지 않으므로 들여쓰기 실수는 결과를 보고서야 알 수 있습니다.

흔한 실수

빈칸과 탭(Tab 키)을 섞어 쓰는 것. 화면에서는 똑같이 밀려 보여도 Python에게는 다른 글자입니다. 섞으면 들여쓰기 깊이를 다르게 읽어 오류가 납니다. VS Code 같은 편집기는 Tab 키를 누르면 빈칸 4개를 넣도록 기본 설정되어 있는 경우가 많으니(U05), 들여쓰기는 Tab 키를 누르되 실제로는 빈칸 4개가 들어가게 쓰는 것이 가장 안전합니다. 설정이 다를 수 있으니 편집기 오른쪽 아래의 "Spaces: 4" 같은 표시를 한 번 확인하세요.

둘 중 하나: if·else

조건이 False일 때 할 일도 따로 있다면 else(그렇지 않으면)를 붙입니다. 정수가 짝수인지 홀수인지 알려 주는 프로그램입니다.

용어 %는 나머지 연산자입니다. Python의 a % b는 결과의 부호가 b를 따르므로 -3 % 2는 1입니다(실행해 확인함, C·Java에서는 -1). 그래서 음수에서도 n % 2 == 0으로 짝수를 판정할 수 있습니다.
n = int(input("정수: "))
if n % 2 == 0:
    print("짝수")
else:
    print("홀수")
print("끝")

(네 값을 하나씩 넣어 실제로 실행한 결과입니다. 0도 2로 나눈 나머지가 0이므로 짝수입니다.)

정의

else:는 바로 위 if(와 elif)의 조건이 모두 False일 때 실행할 블록을 연다. else에는 조건을 쓰지 않는다. "앞의 것이 다 아니면"이 곧 else의 조건이다. else도 줄 끝에 쌍점을 찍고, 그 블록을 들여쓴다. else는 혼자 쓸 수 없고 반드시 if 뒤에 같은 깊이로 붙는다.

흔한 실수

else x <= 5:처럼 else 뒤에 조건을 쓰면 SyntaxError: expected ':'가 납니다(실행해 확인함). Python은 else 바로 뒤에 쌍점이 와야 한다고 알려 줍니다. 조건을 붙이고 싶다면 그것은 else가 아니라 다음 절의 elif입니다.

여러 갈래: if·elif·else

갈래가 셋 이상이면 elif(else if를 줄인 말, "그렇지 않고 만약")를 씁니다. 나이에 따라 입장료를 정하는 프로그램입니다(요금은 예로 지어낸 값입니다).

age = int(input("나이: "))
if age < 8:
    print("무료")
elif age < 20:
    print("청소년 5,000원")
else:
    print("성인 10,000원")
입력age < 8age < 20출력

7True(검사 안 함)무료
8FalseTrue청소년 5,000원
19FalseTrue청소년 5,000원
20FalseFalse성인 10,000원
45FalseFalse성인 10,000원

정의

if → elif → … → else로 이은 묶음은 위에서부터 조건을 차례로 검사해서, 처음으로 True가 나온 블록 하나만 실행하고 묶음 전체를 빠져나간다. 아래 조건은 더 검사하지 않는다. 모두 False이면 else 블록을 실행하고, else가 없으면 아무 블록도 실행하지 않는다. elif는 몇 개든 쓸 수 있다.

표에서 5를 넣었을 때 age < 20을 "(검사 안 함)"이라고 적은 까닭이 이것입니다. 5는 age < 20도 참이지만, 이미 첫 조건에서 "무료"로 결정되었으므로 둘째 조건까지 가지 않습니다. 그 덕분에 elif에 8 <= age < 20처럼 아래 끝을 다시 쓸 필요가 없습니다. elif의 조건에는 "앞 조건들이 모두 거짓"이라는 말이 숨어 있습니다.

순서를 바꾸면 결과가 바뀐다

그렇다면 elif의 순서가 중요해집니다. 90 이상은 A, 60 이상은 D, 나머지는 F를 주려고 이렇게 썼다고 해 봅시다.

score = int(input("점수: "))
if score >= 60:
    print("D")
elif score >= 90:
    print("A")
else:
    print("F")

실행 결과 (95, 70, 50을 넣어 세 번 실행)

점수: 95
D
점수: 70
D
점수: 50
F

95점이 A가 아니라 D를 받았습니다. 95는 첫 조건 score >= 60에서 이미 True라 D로 결정되고, score >= 90은 검사조차 되지 않습니다. 사실 이 코드에서 A는 어떤 점수를 넣어도 절대 나오지 않습니다. 90 이상인 수는 모두 60 이상이기도 해서 첫 갈래가 다 가져가기 때문입니다. 조건의 순서를 바꾸면 고쳐집니다.

score = int(input("점수: "))
if score >= 90:
    print("A")
elif score >= 60:
    print("D")
else:
    print("F")

이 코드에 95, 90, 70, 60, 59, 50을 넣어 실행하면 차례로 A, A, D, D, F, F가 나옵니다.

외우는 법

"이상(≥)"으로 단계를 나눌 때는 큰 기준부터, "미만(<)"으로 나눌 때는 작은 기준부터. 입장료 예가 < 8 → < 20, 점수 예가 >= 90 → >= 60 순서인 까닭입니다. 어느 쪽이든 "앞 갈래가 뒤 갈래의 몫을 먼저 다 가져가지 않는가"를 확인합니다.

if 여러 개와 if·elif의 차이

모양이 비슷한 두 코드를 95점과 85점으로 실행해 비교합니다.

# (가) if를 세 번
score = int(input("점수: "))
if score >= 90:
    print("90 이상")
if score >= 80:
    print("80 이상")
if score >= 70:
    print("70 이상")
# (나) if·elif로 한 묶음
score = int(input("점수: "))
if score >= 90:
    print("90 이상")
elif score >= 80:
    print("80 이상")
elif score >= 70:
    print("70 이상")

(가)의 if 세 개는 서로 남남인 질문 세 개입니다. 앞의 if가 참이었든 아니든 다음 if를 또 검사하므로, 참인 것은 모두 실행됩니다. (나)는 한 묶음의 질문이라 처음 참인 갈래 하나만 실행됩니다. 50점에서 (나)가 아무것도 출력하지 않은 것은 else가 없기 때문입니다.

왜 그럴까?

(가)의 코드에서 셋째 if 위에 else:를 붙이면 어떻게 될까요? else는 바로 위의 어느 if에 붙는 것일까요?

모범 답 보기

else는 바로 위, 같은 깊이에 있는 if 묶음 하나에만 붙습니다. (가)는 if가 세 개의 따로 된 묶음이므로, 마지막 if 뒤에 else를 붙이면 마지막 if(70 이상)에만 딸린 else가 됩니다. 앞의 두 if와는 상관이 없습니다. 그래서 if를 여러 개 쓴 코드에 else를 붙일 때는 그 else가 어느 질문의 "아니면"인지 꼭 확인해야 합니다. 이 함정은 PY03·3의 성적 예제에서 실제로 봅니다.

들여쓰기와 쌍점 오류 읽기

if를 쓰면 새로운 오류 두 종류를 자주 만납니다. 하나씩 일으켜 봅니다.

① 블록을 들여쓰지 않음: 2번 줄 if temp >= 30:, 3번 줄 print("더운 날입니다.")를 왼쪽 끝에

  File "C:\Users\...\indent1.py", line 3
    print("더운 날입니다.")
    ^^^^^
IndentationError: expected an indented block after 'if' statement on line 2

IndentationError는 들여쓰기 오류입니다. "2번 줄의 if 문 뒤에 들여쓴 블록이 와야 한다"는 뜻입니다. 쌍점을 찍었으면 그 아래에는 들여쓴 줄이 적어도 하나 있어야 합니다.

② 쌍점을 빼먹음: if temp >= 30

  File "C:\Users\...\colon.py", line 2
    if temp >= 30
                 ^
SyntaxError: expected ':'

"쌍점이 와야 한다"는 뜻이고, ^가 쌍점이 있어야 할 줄 끝을 가리킵니다.

③ 블록 안에서 들여쓰기 깊이가 다름: 3번 줄은 빈칸 4개, 4번 줄은 빈칸 6개

  File "C:\Users\...\indent2.py", line 4
    print("물을 자주 마시세요.")
IndentationError: unexpected indent

"예상하지 못한 들여쓰기". 같은 블록의 줄은 깊이가 똑같아야 합니다. 2칸 더 들어간 줄을 Python은 새 블록의 시작으로 읽으려 했지만, 앞에 쌍점이 없으니 새 블록이 올 자리가 아닙니다.

④ 블록을 빠져나오다 어중간한 곳에서 멈춤: 3번 줄은 빈칸 4개, 4번 줄은 빈칸 2개

  File "C:\Users\...\indent3.py", line 4
    print("기온 확인 끝")
                    ^
IndentationError: unindent does not match any outer indentation level

"내어쓰기(들여쓰기를 줄인 것)가 바깥의 어떤 깊이와도 맞지 않는다". 블록을 빠져나올 때는 바깥 줄과 정확히 같은 깊이(여기서는 0칸)로 돌아가야 합니다. 2칸은 0칸도 4칸도 아니라서 어느 블록에 속하는지 정할 수 없습니다.

네 가지 모두 실행 전 검사에서 걸리므로(PY02·3의 SyntaxError와 같은 무리), 파일의 어느 줄도 실행되지 않습니다. 실제로 IndentationError는 SyntaxError의 한 종류입니다.

이 내용이 다시 나오는 곳

  • PY03·2: 조건 자리에 and, or, not으로 여러 비교를 묶어 넣습니다.
  • PY03·3: >=와 > 하나 차이로 경계에 선 값의 결과가 바뀌는 것을 표로 확인하고, if 안에 if를 넣는 중첩을 봅니다.
  • PY04·PY05: 반복문(for, while)과 함수(def)도 똑같이 "쌍점 + 들여쓴 블록" 모양입니다. 이 장의 들여쓰기 규칙이 Python 전체의 규칙입니다.

한 줄 정리

if·elif·else는 위에서부터 조건을 검사해 처음 참인 블록 하나만 실행하고, 그 블록의 범위는 쌍점 뒤의 들여쓰기가 정한다.
