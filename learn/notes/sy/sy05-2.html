파일의 이름과 버퍼의 데이터는 다른 상태다

쓰기 함수가 성공했다고 저장장치에 읽을 값이 모두 도착한 것은 아닐 수 있습니다. 파일을 여는 위치, 쓰기 버퍼, 운영체제의 저장 단계를 구분합니다.

이 장을 읽고 나면

  • 파일시스템, 경로, 열린 파일 객체의 역할을 구분한다.
  • 스트림의 버퍼와 읽는 위치를 작은 바이트열로 추적한다.
  • flush, close, fsync를 각각 언제 사용하는지 설명한다.

경로에서 파일을 찾고 열린 스트림에서 읽는다

파일시스템은 파일의 이름과 디렉터리, 내용, 크기 같은 정보를 보관하고 찾을 수 있게 합니다. 파일을 연 뒤 읽는 값은 경로 문자열만으로 결정되지 않습니다. 현재 어떤 파일을 열었는지와, 그 파일 안에서 다음에 읽을 위치가 중요합니다. 상대경로 results/table.csv는 보통 현재 작업 폴더를 기준으로 해석합니다. 같은 이름의 파일을 다른 폴더에 두어도 서로 다른 경로가 될 수 있습니다.

바이너리 모드의 파일에서는 바이트 단위로 읽거나 움직일 수 있습니다. 예를 들어 원본이 b"ABCDEF"이고 처음부터 두 바이트를 읽으면 b"AB"가 나오고 다음 위치는 2입니다. 이어서 두 바이트를 읽으면 b"CD"가 나옵니다. seek(2)는 시작으로부터 두 바이트 위치를 다시 가리킵니다. 텍스트 모드에서는 문자 인코딩이나 줄바꿈 처리가 들어가므로 문자 수를 바이트 위치로 그대로 바꾸지 않습니다.

쓴 내용은 사용자 공간과 운영체제의 여러 층을 지나갈 수 있다

작게 쓰는 내용을 매번 바로 다음층에 넘기면 작은 요청이 많아집니다. 버퍼는 값을 임시로 모아 두는 공간입니다. 쓰기 스트림에 버퍼가 있는 경우 write()로 받은 데이터가 아직 그 버퍼에만 있을 수 있습니다. flush()는 이 스트림에 쌓인 쓰기를 아래 층으로 내보냅니다. 운영체제는 전달받은 파일 데이터를 메모리에 둔 다음 나중에 저장장치에 기록할 수 있습니다.

close()는 열린 스트림을 정리하고 필요한 경우 버퍼를 비웁니다. with open(...) as f:를 쓰면 그 범위를 나올 때 파일 객체를 닫을 수 있습니다. 장애가 나도 보존하는 것이 중요한 작업에서는 버퍼를 비운 뒤 os.fsync(f.fileno())로 파일의 동기화를 별도로 요청하는 경우가 있습니다. 운영체제·파일시스템·장치가 어느 범위까지 보장하는지 확인해야 하고, 파일을 새로 만들거나 바꿀 때 디렉터리 항목의 지속성은 별도 문제일 수 있습니다.

버퍼에서 쓴 값이 언제 보이는지 실습한다

예제의 첫 부분은 파일 대신 메모리의 BytesIO 위에 8바이트 쓰기 버퍼를 붙입니다. 3바이트인 cat을 버퍼에 넣은 다음, 아래쪽의 원본 스트림을 직접 살펴 언제 보이는지 구분할 수 있습니다. OS의 파일 캐시를 측정하는 실습은 아닙니다. 두 번째는 임시 파일을 열어 바이트 위치와 파일 객체의 수명을 확인합니다.

from io import BufferedWriter, BytesIO
from pathlib import Path
from tempfile import TemporaryDirectory

raw = BytesIO()
with BufferedWriter(raw, buffer_size=8) as stream:
    stream.write(b"cat")
    print("raw before:", raw.getvalue())
    stream.flush()
    print("raw after:", raw.getvalue())
print("underlying closed:", raw.closed)

with TemporaryDirectory() as folder:
    path = Path(folder) / "sample.bin"
    path.write_bytes(b"ABCDEF")
    with path.open("rb") as file:
        print("first:", file.read(2), "offset:", file.tell())
        print("next:", file.read(2))
        file.seek(2)
        print("read again:", file.read(2))
    print("file closed:", file.closed)
raw before: b''
raw after: b'cat'
underlying closed: True
first: b'AB' offset: 2
next: b'CD'
read again: b'CD'
file closed: True

파일을 열어 사용한 기간은 코드 블록에서 관리하고, 그 파일의 내용이 알아서 바뀌어서는 안 되는 경우에는 따로 입력과 출력 경로를 정합니다. 기존 파일을 읽는다면 rb, 새 내용을 쓰는 모드에는 기존 내용을 잘라 버리는 종류도 있으므로 모드를 먼저 확인합니다.
