브랜치와 실행 기록으로 실험의 입력을 다시 찾는다

같은 브랜치 이름에서 지난달 실험을 다시 실행해도 코드가 달라졌을 수 있습니다. 어떤 커밋에 어떤 데이터와 설정을 넣었는지 한 줄에서 찾을 수 있게 기록합니다.

이 장을 읽고 나면

  • 브랜치 이름과 커밋 식별자가 가리키는 범위를 구분한다.
  • 재현에 필요한 코드·설정·자료·환경·실행 결과를 연결한다.
  • 분리한 임시 브랜치에서 비교한 지표와 실행 정보를 함께 남긴다.

브랜치는 움직일 수 있고 커밋은 하나의 기록이다

브랜치는 특정 커밋을 가리키는 이름입니다. 같은 시작점에서 trial 브랜치를 만들어 그쪽에서 커밋하면 새 작업을 main과 구분할 수 있습니다. 현재 브랜치는 HEAD를 통해 알 수 있고, 일반적으로 그 브랜치 위에서 새로 커밋하면 그 브랜치가 가리키는 위치가 이동합니다. 과거 실행의 코드 기준을 정하려면 이동하는 브랜치 이름과 함께 커밋 식별자를 적습니다. 커밋 식별자는 커밋 내용에서 계산한 해시(기본 설정에서 SHA-1, 16진 40자리)이고, 겹치지 않는 범위에서 앞 7자리 정도로 줄여 쓰기도 합니다. 새 브랜치를 만들고 그쪽으로 옮겨 가는 명령은 git switch -c trial이고, git rev-parse HEAD는 지금 HEAD가 가리키는 커밋의 전체 식별자를 출력합니다.

커밋 번호만으로는 실험을 다 되돌릴 수 없다

작업 폴더에서 커밋하지 않은 코드를 바꾼 상태로 실행했다면, 기록한 커밋을 열어도 당시 코드와 다를 수 있습니다. 먼저 git status로 남은 작업을 확인합니다. 비교할 코드가 명확하면 실행한 명령과 설정, 입력을 다시 찾을 수 있는 정보를 남깁니다. README에는 그 실험을 재실행하는 순서와 필요한 파일의 위치를 적습니다.

어떤 정보인가기록의 예
코드실제로 사용한 커밋 식별자와 미커밋 변경 여부
입력·설정자료 버전, 분할 조건, 변경한 매개변수, 결과 지표 정의
환경·난수Python·패키지 버전, 사용 장치, 필요한 난수 시드
실행·결과실행 ID, 실행 명령, 결과 표의 경로, 이상이나 실패

공개하거나 함께 보는 저장소에는 API 키, 암호, 개인 정보가 포함된 원자료를 넣지 않습니다. 실행을 재현하는 데 값 자체가 필요하더라도 공개 기록에는 값을 넣지 않고, 필요한 환경 변수의 이름과 별도로 제공할 위치만 안내합니다. .gitignore는 추적하기 전인 파일을 무시하는 규칙입니다. 이미 한 번 추적된 파일이나 과거 커밋의 내용까지 지워 주지는 않습니다. 큰 입력 파일은 안전한 위치에서 버전과 해시를 관리하고, 결과 표는 어떤 입력 버전에서 나왔는지 이름으로 연결할 수 있습니다.

같은 입력으로 설정 두 개를 비교하고 조건을 기록한다

같은 입력 [2,4,6]에 상수 2 또는 4를 예측하는 작은 모델입니다. MAE는 각 행 오차의 절댓값을 평균 냅니다. 기준의 오차는 [0,2,4], 후보의 오차는 [2,0,2]입니다. 이 배치에서는 기준 MAE 2, 후보 MAE 약 1.333입니다. 모형을 크게 실험하지 않아도 어떤 설정과 입력으로 수치를 얻었는지 적는 방식은 같습니다. 예제에는 Git 2.32 이상이 필요합니다.

from hashlib import sha256
import os
import platform
import subprocess
from pathlib import Path
from tempfile import TemporaryDirectory

environment = {k: v for k, v in os.environ.items() if not k.startswith("GIT_")}
environment.update(GIT_CONFIG_NOSYSTEM="1", GIT_CONFIG_GLOBAL=os.devnull)
data = b"2,4,6"
actual = [int(value) for value in data.split(b",")]

with TemporaryDirectory() as folder:
    root = Path(folder)

    def git(*args):
        return subprocess.run(
            ["git", *args], cwd=root, env=environment,
            capture_output=True, encoding="utf-8", check=True,
        ).stdout.strip()

    def record_constant(constant):
        (root / "prediction.txt").write_text(str(constant), encoding="utf-8")
        git("add", "--", "prediction.txt")
        git("-c", "user.name=Study Example", "-c", "user.email=study@example.invalid",
            "commit", "-qm", f"Predict {constant}")
        return git("rev-parse", "HEAD")

    git("init", "-q", "-b", "main", "--template=")
    first = record_constant(2)
    git("switch", "-qc", "trial")
    second = record_constant(4)

    def evaluate(commit):
        constant = int(git("show", f"{commit}:prediction.txt"))
        return sum(abs(y - constant) for y in actual) / len(actual)

    report = {
        "run": "run-07", "commit": second, "input_sha256": sha256(data).hexdigest(),
        "python": platform.python_version(), "mae": evaluate(second),
    }
    print("different commits:", first != report["commit"])
    print(f"main MAE: {evaluate(first):.3f}")
    print(f"trial MAE: {report['mae']:.3f}")
    print("record fields:", ", ".join(sorted(report)))
different commits: True
main MAE: 2.000
trial MAE: 1.333
record fields: commit, input_sha256, mae, python, run

이 연습의 각 커밋은 설정값을 보관합니다. 계산 코드와 예제 입력은 이 장에서 함께 제공합니다. 실제 실험에서는 실행 코드와 설정의 버전을 모두 식별하고, 입력 해시와 함께 자료를 다시 찾을 위치를 기록합니다. 이 비교는 난수를 쓰지 않아 시드가 필요 없습니다. 환경과 의존성은 패키지와 환경에서, 실험 기록은 재현 가능한 실험과 데이터 파이프라인에서 이어서 봅니다.
