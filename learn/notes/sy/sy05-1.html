주소와 포인터는 값이 놓인 위치를 가리킨다

배열의 인덱스 2는 몇 번째 값인지 알려 줍니다. 프로세스마다 다른 가상 주소 공간을 어떻게 실제 메모리 위치에 연결하는지 작은 표로 따라갑니다.

이 장을 읽고 나면

  • 인덱스, 주소, 주소가 가리키는 값을 구분한다.
  • 가상 주소를 페이지 번호와 위치로 나누어 간단히 변환한다.
  • 복사와 같은 저장 공간을 가리키는 뷰, 자료의 수명을 설명한다.

값을 복사하는 일과 위치를 전달하는 일

바이트 세 개가 [10,20,30]인 배열을 생각합니다. 인덱스 1은 배열에서 두 번째 원소라는 뜻입니다. 주소는 어떤 메모리 위치를 가리키는 번호입니다. 배열 첫 바이트의 주소가 100이고, 바이트가 연속하여 놓이는 교육용 모형이라면 둘째 원소의 주소는 101입니다. 자료형이 원소당 네 바이트인 연속 배열에서는 두 번째 원소의 시작 주소는 첫 주소에서 네 바이트 뒤입니다. 실제 Python list의 원소가 이 방식으로 연속한 정수 바이트에 놓인다고 가정하면 안 됩니다.

C에서 포인터는 메모리의 값을 가리킬 수 있는 자료입니다. 예를 들어 int x = 7; int *p = &x;라고 쓰면 &x는 변수 x의 주소이고, 포인터 p에는 그 주소가 들어갑니다. *p는 p가 가리키는 위치의 값을 읽으므로 7이고, *p = 8;로 쓰면 x 자체가 8로 바뀝니다. 값을 복사해 다른 곳에 보존하는 것과, 같은 곳을 다시 읽는 것은 다릅니다. Python에서는 보통 객체에 대한 참조를 다루며, id()는 살아 있는 객체의 식별값으로 쓸 수 있습니다. Python 언어가 그 숫자의 실제 물리 주소를 약속하지는 않습니다.

가상 주소의 페이지와 오프셋을 나누어 읽는다

앞의 운영체제 장에서 프로세스마다 가상 주소 공간을 사용한다고 했습니다. 가상 메모리는 프로그램에 보이는 주소를 실제 메모리의 위치와 연결해 관리하는 방식입니다. 운영체제가 관리하는 페이지 테이블의 자료와 프로세서의 주소 변환 기능이 이 연결에 쓰입니다. 가상 주소를 고정 크기 블록인 페이지 번호와, 그 안의 위치인 오프셋으로 나눌 수 있습니다. 물리 메모리 쪽의 같은 크기 블록은 프레임이라고 부릅니다.

페이지 크기를 4096바이트, 즉 16진수 0x1000으로 둡니다. 가상 주소 0x2345를 그 크기로 나누면 페이지 0x2와 오프셋 0x345입니다. 4096=2¹²이므로 주소의 낮은 12비트(16진 세 자리)가 오프셋이고, 그 위의 비트가 페이지 번호입니다. 이 예제의 표에서 페이지 2가 물리 프레임 9에 대응하므로 물리 주소는 9×0x1000+0x345=0x9345입니다. 페이지 번호가 바뀌고 오프셋은 그대로 남습니다. 실제 시스템의 페이지 크기와 주소 표현은 환경에 따라 다를 수 있습니다.

원하는 페이지가 현재 메모리에 있지 않으면 페이지 폴트가 발생할 수 있습니다. 필요한 페이지를 준비한 뒤 계속 실행하는 경우도 있고, 허용되지 않은 접근이라 운영체제가 오류로 처리하는 경우도 있습니다. 페이지 폴트가 곧 프로그램 오류라는 뜻은 아닙니다. 아래 Python은 주소 변환의 산술만 시뮬레이션하고 실제 메모리 주소에 접근하지 않습니다.

위치를 쓸 수 있는 기간도 정해져 있다

메모리 수명은 특정 변수나 저장 공간이 정상적으로 유효한 기간입니다. C에서는 지역 변수의 수명이 끝난 뒤 그 변수를 가리키던 포인터를 사용할 수 없습니다. 할당한 메모리를 해제할 책임이 어느 코드에 있는지와, 누가 그 공간을 언제까지 잠시 쓰는지도 구분합니다. Python 객체는 참조가 유지되면 살아 있을 수 있습니다. memoryview는 bytearray 같은 원본의 데이터를 복사하지 않고 접근하고, 독립된 bytes로 만드는 시점은 따로 정할 수 있습니다.

페이지 변환과 복사의 차이를 코드로 확인한다

size = 4096
pages = {2: 9, 3: 1}
for address in (0x2345, 0x3100, 0x4123):
    page, offset = divmod(address, size)
    if page in pages:
        print(f"virtual {address:#x} -> physical {pages[page] * size + offset:#x}")
    else:
        print(f"virtual {address:#x} -> no mapping in this table")

buffer = bytearray([10, 20, 30])
snapshot = bytes(buffer)
with memoryview(buffer) as view:
    view[1] = 99
    print("view:", list(view))
print("from buffer:", list(buffer))
print("from copy:", list(snapshot))
virtual 0x2345 -> physical 0x9345
virtual 0x3100 -> physical 0x1100
virtual 0x4123 -> no mapping in this table
view: [10, 99, 30]
from buffer: [10, 99, 30]
from copy: [10, 20, 30]

with 블록은 뷰의 사용이 끝났음을 표시합니다. 뷰에 사용한 원본 buffer를 별도로 변수에 보관했으므로 블록 밖에서도 원본을 읽을 수 있습니다.
