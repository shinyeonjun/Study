SY04·2

운영체제에 자원을 요청하고 실행 공간을 나눈다

코드가 파일을 열고 싶을 때는 운영체제에 요청합니다. 어디까지가 프로그램 안의 계산이고 언제부터 커널이 처리하는지, 자식이 부모와 어디까지 자료를 나눌 수 있는지 확인합니다.

이 장을 읽고 나면

  • 사용자 코드의 일반 함수 호출과 시스템 호출을 구별한다.
  • 프로세스 주소 공간의 격리와 의도적인 자료 공유를 구별한다.
  • 로컬 자식에 전달한 파일 변화와 부모 내부 변수를 대조한다.

파일과 장치에는 운영체제의 관리가 필요한 순간이 있다

프로그램이 리스트의 길이를 계산하는 일은 보통 자기 메모리에 있는 값으로 처리할 수 있습니다. 반면 운영체제에서 관리하는 파일을 읽거나 프로세스를 시작하려면 운영체제의 기능이 필요합니다. 시스템 호출(system call)은 사용자 프로그램이 커널의 서비스를 요청할 때 쓰는 인터페이스입니다. 커널은 요청의 대상과 권한을 확인한 뒤 결과나 오류를 프로그램에 돌려줄 수 있습니다.

파일 읽기에서 Python의 open()이나 read()는 높은 수준의 함수입니다. 이 함수는 문자열을 해석하거나 한 번 읽은 값을 내부 버퍼에 보관할 수도 있습니다. 그래서 Python 함수 한 번이 시스템 호출 정확히 한 번과 대응한다고 볼 수 없습니다. Linux에는 read처럼 커널에 요청하는 시스템 호출이 있습니다. Windows 프로그램은 보통 ReadFile 같은 문서화된 API를 먼저 사용합니다. 운영체제마다 함수 이름·시스템 호출 입구·파일 규칙이 다를 수 있습니다.

시스템 호출을 들어갈 때 CPU가 사용자 모드에서 커널 모드로 들어갈 수 있습니다. 이는 요청을 처리할 권한과 실행 위치의 변화입니다. 운영체제가 차례를 다른 스레드로 바꾸는 문맥 교환이 그때마다 반드시 일어나는 것은 아닙니다. 어느 쪽을 뜻하는지 구별하면 순서도를 더 정확하게 읽습니다.

프로세스 내부 상태는 기본적으로 서로 분리한다

프로세스마다 고유한 가상 주소 공간이 있다는 것은, 같은 주소 번호가 각 프로세스에서 같은 자료를 가리킨다고 가정할 수 없다는 뜻입니다. 일반 프로그램이 자기 메모리에 쓰는 동작으로 다른 프로세스의 변수를 바꾸지 않습니다. 운영체제와 하드웨어가 메모리 접근을 관리하고, 서로 다른 프로세스의 주소를 분리하는 데 도움을 줍니다. 이는 같은 프로세스 안에서 스레드들이 주소 공간을 함께 쓰는 모습과 다릅니다.

격리가 어떤 정보도 공유할 수 없다는 뜻은 아닙니다. 프로세스는 운영체제가 제공하는 파이프나 메시지 통로, 공유 메모리를 사용하도록 구성할 수 있습니다. 서로 열 권한이 있는 같은 파일도 공유할 수 있습니다. 일반적인 파일 접근에서 경로를 안다는 사실과 계정이 읽거나 쓸 수 있다는 사실은 별개입니다. 여러 프로세스가 동시에 같은 파일을 바꾼다면 쓰는 순서나 충돌을 따로 관리해야 합니다.

파일을 전달하되 프로그램 내부 숫자는 따로 남긴다

아래 예에서는 부모가 임시 디렉터리를 만들고 자기 파일을 열어 ‘ready’를 적습니다. 자식에게 그 파일의 경로를 인자로 주고, 자식은 ‘ready’를 읽어 소문자 ‘done’을 씁니다. 자식이 종료한 다음 같은 파일을 읽으므로 동시에 수정하는 문제는 이 예에서 다루지 않습니다.

import subprocess
import sys
from pathlib import Path
from tempfile import TemporaryDirectory

counter = 3
source = """
from pathlib import Path
from sys import argv

counter = 9
path = Path(argv[1])
print("child read:", path.read_text(encoding="utf-8"))
path.write_text("done", encoding="utf-8")
print("child counter:", counter)
"""
with TemporaryDirectory() as folder:
    path = Path(folder) / "example.txt"
    path.write_text("ready", encoding="utf-8")
    child = subprocess.run(
        [sys.executable, "-c", source, str(path)],
        capture_output=True, text=True, encoding="utf-8", check=True,
    )
    print(child.stdout.strip())
    print("parent counter:", counter)
    print("parent read:", path.read_text(encoding="utf-8"))
child read: ready
child counter: 9
parent counter: 3
parent read: done

부모와 자식의 숫자는 따로 남고, 두 프로그램이 직접 지정한 파일에 쓴 변경만 이후 읽기에 보입니다. 출력 문자열을 받아 오는 데도 별도의 통로를 사용했습니다. 어느 Python 함수가 OS 내부에서 몇 번의 호출을 만들었는지는 이 출력만으로 세지 않았습니다.
