SY07·1

diff에서 바뀐 일을 보고 commit에 넣을 내용을 정한다

파일을 고쳤다고 그 변경이 바로 이력에 들어가지는 않습니다. 마지막으로 기록한 내용, 다음에 기록하려고 골라 둔 내용, 지금 편집기에 있는 내용을 서로 대조합니다.

이 장을 읽고 나면

  • 작업 트리, 인덱스, 최근 커밋의 차이를 설명한다.
  • 일반 diff와 스테이징된 diff가 각각 비교하는 내용을 읽는다.
  • 임시 저장소에서 커밋 뒤에도 편집이 남는 상황을 확인한다.

세 위치에 같은 파일의 서로 다른 내용이 있을 수 있다

파일을 수정한 시간을 기억하는 것만으로는 다른 환경에서 같은 코드를 돌리기 어렵습니다. Git은 파일들의 스냅샷을 저장하고 변경 이력을 따라갈 수 있게 합니다. 작업 트리는 지금 폴더에서 읽고 편집하는 파일입니다. 인덱스(스테이징 영역)는 다음 커밋에 넣을 내용을 준비하는 곳입니다. 커밋은 그 상태를 메시지·이전 기록 정보 등과 함께 저장한 이력 단위입니다.

설정 파일의 값이 처음 커밋에 2라고 합시다. 파일을 4로 고친 뒤 git add -- config.txt를 하면 그때의 4가 인덱스에 들어갑니다. 바로 이어 작업 파일을 6으로 고쳐도 이미 준비해 둔 인덱스가 6으로 자동 갱신되지 않습니다. 이 상태에서 커밋하면 4가 이력에 들어가고 작업 파일의 6은 남습니다.

검토할 범위에 맞는 diff를 읽는다

diff는 무엇이 어떻게 달라졌는지 보여 줍니다. 일반적인 git diff는 인덱스와 작업 트리를 비교합니다. git diff --staged는 최근 커밋과 인덱스를 비교합니다. 새 파일이 아직 추적 대상도 아니라면 일반 diff에 내용이 곧바로 나타나지 않을 수 있으므로 git status로 상태를 함께 읽습니다.

명령먼저 답하는 질문
git status수정되거나 새로 생긴 파일이 어느 상태에 있는가
git diff아직 인덱스에 보내지 않은 추적 파일의 변경은 무엇인가
git diff --staged이대로 커밋하면 최근 커밋에서 무엇이 달라지는가
git commit인덱스에 준비된 상태를 어떤 메시지로 기록할 것인가

줄마다 앞에 붙은 −와 +를 보면 기존 줄과 새 줄을 구분할 수 있습니다. 두 비교를 다 읽으면 어떤 변경이 다음 커밋으로 가고 어떤 변경이 더 필요할지 판단할 수 있습니다. 커밋 메시지에는 예를 들어 '경보 임계값을 4로 설정'처럼 변경의 의도를 적을 수 있습니다.

기존 저장소와 떨어진 실습 폴더에서 상태를 비교한다

아래 예제는 Git 2.32 이상이 설치된 환경에서 실행합니다. Python이 만든 임시 폴더에서 새 저장소를 시작하고, 그 폴더만 모든 Git 명령의 작업 위치로 씁니다. 사용자의 기존 Git 설정 대신 연습용 이름을 커밋 명령에만 전달하고 외부 저장소에 연결하지 않습니다. 각 비교에서 설정 파일에 변경이 보이면 1, 없으면 0을 출력합니다.

import os
import subprocess
from pathlib import Path
from tempfile import TemporaryDirectory

environment = {key: val for key, val in os.environ.items() if not key.startswith("GIT_")}
environment.update(GIT_CONFIG_NOSYSTEM="1", GIT_CONFIG_GLOBAL=os.devnull)

with TemporaryDirectory() as folder:
    root = Path(folder)
    file = root / "config.txt"

    def git(*args):
        return subprocess.run(
            ["git", *args], cwd=root, env=environment,
            capture_output=True, encoding="utf-8", check=True,
        ).stdout.strip()

    def commit(message):
        git("-c", "user.name=Study Example", "-c", "user.email=study@example.invalid",
            "commit", "-qm", message)

    def flags():
        return int(bool(git("diff", "--name-only"))), int(bool(git("diff", "--staged", "--name-only")))

    git("init", "-q", "-b", "main", "--template=")
    file.write_text("threshold=2\n", encoding="utf-8")
    git("add", "--", "config.txt")
    commit("Baseline")

    file.write_text("threshold=4\n", encoding="utf-8")
    print("edited:", *flags())
    git("add", "--", "config.txt")
    file.write_text("threshold=6\n", encoding="utf-8")
    print("staged then edited:", *flags())
    commit("Set threshold to four")
    print("recorded:", git("show", "HEAD:config.txt"))
    print("working file:", file.read_text(encoding="utf-8").strip())
    print("after commit:", *flags())
edited: 1 0
staged then edited: 1 1
recorded: threshold=4
working file: threshold=6
after commit: 1 0

출력의 두 숫자는 일반 diff, staged diff 순서입니다. 마지막에 6을 보여 주는 줄은 파일에 남은 편집이며, 최근 커밋에 든 값은 4입니다.

핵심어기억할 기준
작업 트리현재 편집한 파일의 내용이다.
