페이지 교체 순서와 더 많은 프레임의 효과

프레임이 가득 찼을 때 무엇을 내보낼지에 따라 다음 페이지 접근의 결과가 달라집니다. 같은 참조 순서를 두 정책으로 따라가며 적중과 폴트의 개수, 평균 지연, 프레임 수 증가의 효과를 계산합니다.

이 장을 읽고 나면

  • 상주 페이지의 FIFO와 LRU 상태를 참조 기록에서 갱신합니다.
  • FIFO에서 프레임이 늘어도 폴트가 많아지는 사례를 설명합니다.
  • LRU의 포함 관계를 증명하고 가정한 비용으로 평균 접근 지연을 계산합니다.

상주 페이지가 가득 찼을 때 하나를 내보냅니다

프로그램이 페이지 번호를 하나씩 참조합니다. 모든 주소가 유효하며, 초기에는 상주한 페이지가 없습니다. 요청한 페이지가 상주하면 적중입니다. 상주하지 않으면 폴트로 기록하고 필요한 페이지를 불러옵니다. 빈 프레임이 있을 때는 거기에 넣고, 모두 차면 하나를 내보낸 뒤 넣습니다. 여기에서 추적하는 것은 페이지의 내용이나 TLB 조회가 아니라 어떤 페이지들이 상주하는가입니다.

FIFO는 가장 일찍 들여온 상주 페이지를 제거합니다. 중간에 다시 읽어도 들어온 시각을 바꾸지 않습니다. LRU는 가장 오래 참조하지 않은 상주 페이지를 제거합니다. 적중한 페이지도 방금 다시 참조되었으므로 최근 위치로 옮깁니다. 예를 들어 프레임이 2개에 참조가 1,2,1,3이면 마지막 3 직전 FIFO는 들여온 순서 [1,2]를 유지하고 LRU는 참조가 오래된 순서 [2,1]로 바뀝니다. 둘 모두 3에서 폴트가 나고, FIFO는 1을 LRU는 2를 내보냅니다.

FIFO를 세 칸과 네 칸에서 비교합니다

고전적인 이상 현상의 참조열 1,2,3,4,1,2,5,1,2,3,4,5를 재생합니다. 세 칸은 네 번째 참조에서 페이지 1을 먼저 내보냅니다. 그래서 다섯 번째 접근에서 1을 다시 불러와 새로 들어온 페이지가 됩니다. 네 칸은 다섯 번째와 여섯 번째 접근이 적중이고, 1과 2는 처음 들어온 순서를 그대로 유지합니다. 그 결과 일곱 번째 5를 받을 때 네 칸에서 1이 제거되고 세 칸에서는 1이 남습니다.

FIFO3FFFFFFFHHFFH9
FIFO4FFFFHHFFFFFF10
LRU3FFFFFFFHHFFF10
LRU4FFFFHHFHHFFF8

표의 숫자 열은 페이지 참조 순서입니다. H는 적중, F는 폴트입니다. FIFO에서 네 칸은 세 칸보다 폴트가 한 번 더 많습니다. 프레임 추가가 오히려 폴트를 늘리는 이런 현상을 Bélády의 이상 현상이라고 부릅니다. 각각의 단계에서 한 칸 낫거나 나쁘다고 판단하기보다 동일한 참조열을 처음부터 끝까지 비교해야 합니다.

LRU에서는 작은 프레임 집합이 큰 쪽의 부분집합입니다

참조 기록의 어느 시점에서든 마지막으로 참조된 순서대로 서로 다른 페이지를 나열합니다. LRU의 k칸에는 목록의 처음 k개가 남습니다. 시작할 때 목록은 비어 있습니다. 페이지 p를 한 번 더 참조하면 p를 맨 앞으로 옮깁니다. 이미 처음 k개 안에 있으면 상주 순서만 바뀝니다. 밖에 있으면 p를 들이고, 가득 차 있을 때 기존 처음 k개 중 마지막 페이지, 곧 상주 페이지 가운데 가장 오래 참조되지 않은 페이지를 내보냅니다. 이것이 정확히 LRU가 내보내는 페이지이므로, 참조 횟수에 대한 귀납법으로 "LRU k칸의 상주 집합 = 최근 참조 목록의 처음 k개"가 모든 시점에서 성립합니다. 처음 k개는 처음 k+1개의 부분집합이고, k칸에서 적중한 것은 k+1칸에서도 적중합니다. 같은 참조 순서에서 LRU의 폴트 수는 프레임을 늘려도 증가하지 않습니다.

모든 접근에 기본 1사이클이 들고 폴트에만 고정 추가 100사이클이 드는 교육용 비용으로 비교합니다. 접근이 서로 겹치지 않고 폴트가 일어나면 처리까지 기다린다고 둡니다. FIFO 세 칸은 1+(9/12)×100=76사이클, 네 칸은 1+(10/12)×100≈84.33사이클입니다. 실제 폴트 처리에서는 이미 수정한 페이지를 내보내기 위해 쓰기가 필요할 수 있고 페이지를 가져오는 원천과 응답 시간이 다를 수 있습니다. 운영체제는 정확한 참조 순서를 유지하는 부담을 줄이려고 최근 참조를 근사하는 정책을 사용할 수 있습니다.

from fractions import Fraction

trace = [1,2,3,4,1,2,5,1,2,3,4,5]

def replay(frames, lru):
    queue = []
    events, snapshots = [], []
    for page in trace:
        if page in queue:
            events.append("H")
            if lru:
                queue.remove(page)
                queue.append(page)
        else:
            events.append("F")
            if len(queue) == frames:
                queue.pop(0)
            queue.append(page)
        snapshots.append(set(queue))
    return "".join(events), snapshots

for policy in ("FIFO", "LRU"):
    states = []
    for frames in (3, 4):
        events, snapshots = replay(frames, policy == "LRU")
        faults = events.count("F")
        average = 1 + Fraction(100*faults, len(trace))
        print(policy, frames, events, faults, f"{float(average):.2f}")
        states.append(snapshots)
    contains_all = all(a <= b for a, b in zip(*states))
    print("small subset of large at every step:", contains_all)

FIFO 4 FFFFHHFFFFFF 10 84.33
small subset of large at every step: False
LRU 3 FFFFFFFHHFFF 10 84.33
LRU 4 FFFFHHFHHFFF 8 67.67
small subset of large at every step: True

코드는 프레임 수가 양수인 두 설정을 비교합니다. 매 접근 뒤의 상주 집합을 복사해 보존하므로 나중에 리스트가 바뀌어도 앞 단계 기록은 유지됩니다. 폴트 표와 평균 지연을 재현하려면 정책 외에 시작 상태, 참조 순서, 비용의 정의가 같아야 합니다.
