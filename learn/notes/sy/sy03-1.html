소스는 실행 전에 명령으로 바뀐다

편집기에 쓰는 Python 코드와 CPU가 알아듣는 명령은 서로 다른 층에 있습니다. 코드를 내어 주었을 때 누가 무엇을 번역하고 실행하는지 따라갑니다.

이 장을 읽고 나면

  • 소스, 기계 명령, 바이트코드를 구분한다.
  • 미리 실행 파일을 만드는 경로와 CPython에서 실행하는 경로를 비교한다.
  • compile과 dis로 코드 객체를 관찰하고 버전 차이를 설명한다.

소스 파일의 글자는 아직 CPU 명령이 아니다

소스 코드는 사람이 읽고 바꿀 수 있도록 언어의 문자와 규칙으로 쓴 내용입니다. CPU가 직접 실행할 수 있는 기계 명령은 CPU의 명령 집합에서 정한 비트 패턴입니다. 컴파일은 어느 한쪽 표현을 다른 쪽 표현으로 바꾸는 기술입니다. 컴파일 결과가 꼭 그 CPU의 기계 명령이어야 하는 것은 아닙니다.

예를 들어 네이티브 실행 파일을 만드는 C의 일반적인 경로에서는 컴파일 도구가 한 소스 파일을 목적 파일로 바꿉니다. 목적 파일에는 기계 명령과 함께, 다른 파일에 있는 함수나 값을 연결하는 데 필요한 정보가 들어갈 수 있습니다. 링커가 목적 파일과 필요한 라이브러리 참조를 묶어 운영체제가 받아들일 수 있는 실행 파일을 만듭니다. Windows의 일반적인 네이티브 실행 파일 형식은 PE이고, 실행 파일이 사용할 CPU 계열과 운영체제가 맞아야 합니다.

CPython은 소스를 내부 명령으로 번역해 실행한다

우리가 사용하는 일반적인 CPython에서는 Python 소스를 읽어 실행용 코드 객체로 바꿉니다. 그 안에는 CPython 인터프리터가 읽는 바이트코드와 상수나 이름 등에 관한 정보가 있습니다. 실행 장치가 이해하는 명령이 서로 다릅니다. CPU는 CPython 실행 프로그램의 기계 명령을 실행하고, 그 프로그램은 Python 바이트코드의 의미를 처리합니다. “인터프리터를 사용한다”는 말과 “내부 번역 단계를 거친다”는 말은 동시에 맞을 수 있습니다.

임포트하는 모듈의 경우 CPython은 내부 번역 결과를 __pycache__ 아래 .pyc로 캐시할 수 있습니다. 다음 임포트에서 번역 비용을 줄이기 위한 것입니다. 그 파일을 갖고 있다고 해서 CPU가 직접 실행하는 Windows 실행 파일이 되는 것은 아닙니다. 환경이나 쓰기 설정에 따라 캐시 파일이 생기지 않을 수도 있습니다.

번역 오류와 실행 중 오류를 구별한다

괄호가 닫히지 않았다면 CPython은 소스 문법을 읽는 단계에서 오류를 알릴 수 있습니다. 반면 입력으로 받은 값을 0으로 나누면 오류가 나는 코드는 문법이 맞을 수 있습니다. 그 실행 경로에 들어가 실제 값이 0임을 만나기 전까지는 같은 오류가 나지 않습니다. 표시된 오류 줄과 함께 어느 단계에서 실패했는지를 확인합니다.

CPython의 dis는 코드 객체에 들어 있는 바이트코드 명령을 볼 수 있게 합니다. 같은 Python 소스라도 CPython의 버전이나 내부 최적화 방식에 따라 명령 이름과 순서가 달라질 수 있습니다. 프로그램의 결과가 같더라도 이 내부 목록이 같은지까지 약속하는 것은 아닙니다.

소스 문자열을 코드 객체로 바꾸고 함수의 바이트코드를 읽는다

from dis import get_instructions

source = "def twice(value):\n    return value * 2\n"
module_code = compile(source, "<example>", "exec")
definitions = {}
exec(module_code, definitions)
twice = definitions["twice"]

print("compiled:", type(module_code).__name__)
print("twice(9):", twice(9))
print("bytecode:", " ".join(i.opname for i in get_instructions(twice)))
compiled: code
twice(9): 18
bytecode: RESUME LOAD_FAST_BORROW LOAD_SMALL_INT BINARY_OP RETURN_VALUE

CPython 3.14.6에서 확인했습니다. 목록 마지막의 반환 동작을 읽고, 다른 환경에서는 중간 명령 이름이 달라질 수 있음을 기억합니다. 이 코드에서 실행하는 문자열은 예제에 직접 적어 둔 고정된 코드입니다.
