파일 읽기 호출 수와 실행 시간을 따로 계측하기

같은 파일을 작은 컵으로 여러 번 떠 오거나 큰 컵으로 적게 떠 옵니다. 바이트 수와 읽기 호출 수는 정확히 셀 수 있지만, 시간은 워밍업과 기계의 상태에 따라 달라집니다.

이 장을 읽고 나면

  • 응용 프로그램 읽기 호출, 전송 바이트, 실제 지연을 다른 열로 기록한다.
  • 준비 실행과 순서 교대를 둔 비교를 실행한다.
  • 운영체제의 페이지 캐시와 Python 버퍼를 구분한다.

어떤 층에서 일어난 일을 세는지 먼저 쓴다

Python 파일 API에 읽기를 100번 요청한 것과 저장 장치가 실제로 100번 읽은 것은 다릅니다. 운영체제는 이전에 읽은 파일 데이터가 메모리에 있으면 다시 장치에 가지 않을 수 있습니다. Python의 버퍼도 일부 요청을 여러 번에 나누거나 모을 수 있습니다. 이번 예제는 open(…, buffering=0)으로 이진 파일 객체의 Python 버퍼를 끄고, 우리가 직접 호출한 읽기 횟수와 반환된 바이트를 셉니다.

임시 파일은 16,384바이트입니다. 한 번의 읽기 크기가 64바이트라 모두 채워서 돌아오면 값이 든 호출 256번, 256바이트면 64번입니다. 양쪽에 파일 끝을 확인한 빈 호출이 한 번 더 있습니다. 예제는 0바이트보다 많이 반환한 호출만 셉니다. 다른 입출력에선 끝이 오기 전에 읽기가 요청보다 짧을 수 있어, 실제 반환 길이를 함께 남깁니다.

워밍업 뒤 두 실행 순서를 모두 확인한다

하나를 항상 먼저 두면 먼저 실행한 방법이 환경 준비 비용을 더 부담할 수 있습니다. 이번 코드는 준비 실행 뒤 A→B와 B→A를 반복합니다. 같은 파일을 다시 읽으므로 운영체제 캐시에 이미 올라온 읽기가 섞일 수 있습니다. 코드에서 perf_counter_ns()로 구한 시간은 하드웨어와 현재 부하에 따라 다릅니다. 딱 한 번의 실행이나 환경이 바뀐 두 실행의 빠르기를 일반화하지 않습니다.

우선 확인할 값은 같은 바이트 수를 읽었는지, 비교 중 입력이 변하지 않았는지, 횟수가 계획과 맞는지입니다. 시간은 두 설정의 개별 측정과 중앙값을 비교할 수 있습니다. 읽기와 마찬가지로 쓰기에도 층이 있습니다. write()가 돌아왔다는 것은 보통 운영체제의 페이지 캐시에 들어갔다는 뜻이고, 저장 장치에 영속됐다는 보장은 fsync()(Python의 os.fsync) 같은 별도 호출이 끝나야 얻습니다. 이 차이는 데이터베이스 복구의 로그 영속 조건과 이어집니다.

from pathlib import Path
from tempfile import TemporaryDirectory
from time import perf_counter_ns
from statistics import median

def measure(path,chunk):
    start = perf_counter_ns()
    count = total = 0
    with path.open("rb",buffering=0) as handle:
        while data := handle.read(chunk):
            count+=1
            total+=len(data)
    return count,total,perf_counter_ns()-start

with TemporaryDirectory() as tmp:
    path=Path(tmp)/"example.bin"
    path.write_bytes(bytes(range(256))*64)
    measure(path,256)
    stats={64:[],256:[]}
    for order in ((64,256),(256,64),(64,256),(256,64)):
        for chunk in order:
            stats[chunk].append(measure(path,chunk))
    for chunk,samples in stats.items():
        pairs=sorted({(calls,bytes_read) for calls,bytes_read,_ in samples})
        elapsed=[time for _,_,time in samples]
        print(chunk,pairs,len(samples), median(elapsed)>=0)
        assert pairs==[(16384//chunk,16384)]
        # 실제 시간 표를 보고 싶다면 print(chunk, elapsed)로 확인한다.

짧은 읽기read(n)은 n보다 적게 돌려줄 수 있습니다. 실제 반환 길이를 기록하고, 0바이트가 파일 끝입니다.
워밍업·순서 교대준비 실행을 버리고 A→B, B→A를 번갈아 재야 순서 효과를 가려낼 수 있습니다.
fsyncwrite가 돌아와도 영속은 아닙니다. 영속 보장은 fsync가 끝나야 합니다.
