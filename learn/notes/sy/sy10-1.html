  • 전체 20개 배치를 생성해 잃어버린 갱신을 설명한다.
  • 상호 배제 아래 공유 상태의 불변식을 유지한다.

한 줄 읽기와 한 줄 쓰기 사이에 다른 스레드가 온다

공유 카운터 x는 0입니다. 각 스레드는 x를 자기 레지스터에 읽고, 레지스터에 1을 더하고, 그 값을 x에 씁니다. 세 단계는 해당 스레드의 프로그램 순서를 유지합니다. 아래는 개별 읽기·쓰기는 원자적으로 진행되지만 그 사이에서 다른 스레드가 실행될 수 있다고 정한 모형입니다.

순서A의 지역 값B의 지역 값공유 x
A가 먼저 읽음0—0
B도 읽음000
두 스레드가 자기 값에 1을 더함110
A와 B가 차례로 씀111

공유 x에 대한 두 결과는 이전 읽기값을 사용하므로 나중 쓰기가 앞 갱신을 덮습니다. 필요한 불변식은 각 증가 연산이 완료되는 경계에서 공유 값이 완료된 증가 횟수와 같다는 것입니다. 이 배치의 마지막에서 완료는 두 번인데 x가 1입니다.

각 스레드의 세 자리를 지키는 배치를 센다

총 6자리 중 A가 들어갈 3자리를 고르면 그 자리에서 A의 R→Add→W 순서는 정해지고 나머지 세 자리에는 B의 순서가 정해집니다. C(6,3)=20개입니다. 결과가 2가 되려면 나중 읽기가 앞 쓰기 뒤여야 합니다. 중간 순서가 허용된 전체를 열거하면 연달아 A를 끝내고 B를 하거나, 그 반대인 두 경우만 2를 냅니다.

상호 배제로 하나의 연산처럼 보이게 만든다

뮤텍스는 한 순간에 한 실행만 임계 구역에 들어가도록 제한합니다. 읽기와 쓰기 각각에서만 잠금을 걸었다 풀면 중간에 둘 다 옛 값을 읽는 배치를 막지 못합니다. 셋 전체를 보호하면 두 증가 구역은 순서대로 실행되므로, 임계 구역에 들어갈 때의 값에서 정확히 1을 더하고 끝납니다. 공유 변수에 접근하는 다른 경로도 같은 규칙이 필요합니다.

이 계산은 프로그램 단계의 순서를 지키는 순차 일관 모형입니다. 실제 언어와 기계의 메모리 가시성은 동기화 규약도 필요합니다. Python에서도 특정 연산이 한 번에 끝나는지 전제하지 않고, 여러 연산이 같이 지켜야 할 조건을 스레드 동기화로 보호합니다.

from collections import Counter
from itertools import combinations

def run(slots):
    x=0
    local=[None,None]
    pc=[0,0]
    for i in range(6):
        t=int(i not in slots)
        if pc[t]==0:
            local[t]=x
        elif pc[t]==1:
            local[t]+=1
        else:
            x=local[t]
        pc[t]+=1
    return x

results=Counter(run(slots) for slots in combinations(range(6),3))
print(sorted(results.items()))
print(run((0,1,2)),run((3,4,5)))
assert sum(results.values())==20
