페이지 테이블 조회를 TLB에서 줄이기

같은 페이지를 여러 번 읽을 때 프로그램이 보내는 주소는 달라도 페이지 번호는 반복됩니다. 변환 결과를 기억해 테이블 조회를 건너뛰고, 변환을 못 찾았을 때의 두 가지 경우를 구별합니다.

이 장을 읽고 나면

  • 가상 페이지 번호와 물리 프레임 번호를 오프셋과 구분합니다.
  • TLB 미적중 후 테이블에서 유효한 매핑을 찾는 경우와 페이지 폴트를 분리합니다.
  • 주어진 접근 비용과 적중 비율로 평균 주소 변환 포함 지연을 계산합니다.

1. 바이트 주소를 페이지와 위치로 읽습니다

SY05 주소와 파일에서 주소를 페이지 번호와 그 안의 오프셋으로 나눴습니다. 이제 한 번의 접근이 변환기와 메모리를 어떤 순서로 거치는지 보겠습니다. 바이트 주소 x와 페이지 크기 P가 정해지면 가상 페이지 번호(VPN)는 ⌊x/P⌋이고 오프셋 o는 x를 P로 나눈 나머지입니다. CPU의 주소 변환 장치는 해당 가상 페이지의 매핑 정보를 얻습니다. 물리 프레임 번호 PFN을 얻으면 물리 바이트 주소는 PFN×P+o입니다.

페이지 크기를 64바이트로 둔 모형에서는 64=2⁶이라 아래 6비트가 오프셋입니다. 16진수 한 자리는 4비트이므로 '아래 16진수 두 자리'로 끊으면 8비트가 되어 잘못됩니다. 0x12D는 301이라 64로 나눠 몫 4, 나머지 45입니다. VPN 4가 PFN 9에 매핑될 때 물리 주소는 9×64+45=621=0x26D입니다.

2. TLB에 없다고 페이지까지 없는 것은 아닙니다

페이지 테이블 엔트리(PTE)는 대응하는 프레임 번호 외에도 유효 상태와 접근 속성 등을 표현합니다. 구체적인 비트의 이름과 해석은 아키텍처에 따라 다릅니다. 변환 결과를 빠르게 다시 쓰는 장치가 TLB(변환 색인 버퍼)입니다. TLB는 최근 변환을 저장하는 작은 캐시라 잠재적으로 같은 VPN을 여러 번 빨리 변환합니다. 이는 바이트 값을 보관하는 데이터 캐시와 다른 자료를 저장합니다.

TLB에서 검색하던 주소 공간의 VPN 항목을 찾고 접근 조건을 만족하면 테이블을 다시 읽지 않고 프레임을 이용합니다. TLB가 비어 있거나 찾는 항목이 없으면 페이지 테이블을 따라 내려가 매핑을 확인합니다. 해당 페이지가 메모리에 상주하며 필요한 접근이 유효할 때는 이 조회로 변환을 완료하고 TLB에 항목을 채울 수 있습니다. 이 경우에는 TLB 미적중이 발생했으나 페이지 폴트는 없었습니다.

필요한 페이지가 메모리에 상주하지 않았거나 접근이 허용되지 않는 등 매핑대로 진행할 수 없는 경우에는 OS가 예외를 처리합니다. 이 장의 예제는 상주하지 않는 페이지에 대한 접근을 페이지 폴트로 기록합니다. 그 주소만 건너뛰고 다음 기록이 있으면 계속 처리합니다. 실제 시스템에서 폴트가 복구될 수 있는지는 주소 범위와 접근 사유에 의존합니다. 테이블 검색은 하드웨어 또는 시스템 소프트웨어가 담당할 수 있습니다. 주소 공간이 바뀌면 같은 VPN 숫자가 다른 프레임을 뜻할 수 있으므로, 주소 공간 식별자를 같이 보거나 전환 시 관련 항목을 비울 수 있습니다.

3. 적중률을 비용으로 바꾸는 조건

표의 네 호출은 변환의 종류를 보여 주는 예입니다. 이번 계산은 폴트가 전혀 없는 상주 페이지에 대한 별도 작업 부하입니다. TLB 탐색은 1사이클, 물리 데이터 읽기는 10사이클입니다. 테이블 탐색은 4단계이고 각 단계가 10사이클이라고 둡니다. 모든 단계가 직렬로 실행되어 비용이 더해집니다. 적중 때는 11, 미적중 때는 1+4×10+10=51사이클입니다. 실제 구현에서는 테이블 탐색용 캐시가 있거나 데이터 조회와 변환이 겹칠 수 있습니다. 모형의 측정 범위는 변환부터 상주 데이터 읽기까지입니다.

적중 비율을 h라고 두면 평균은 11h+51(1−h)=11+40(1−h)입니다. 적중률이 90%면 15사이클입니다. 동일한 비용 모형에서 95%라면 13사이클입니다. 이 평균에는 페이지 폴트의 운영체제 처리 비용이 들어 있지 않습니다.

page_size = 64
table = {4: 9, 7: 2}
tlb = {}
trace = (0x12D, 0x130, 0x1C4, 0x240)
for virtual in trace:
    vpn, offset = divmod(virtual, page_size)
    assert (vpn, offset) == (virtual >> 6, virtual & 63)
    if vpn in tlb:
        event = "TLB hit"
    elif vpn in table:
        tlb[vpn] = table[vpn]
        event = "TLB miss, PTE present"
    else:
        print(f"0x{virtual:03X}", vpn, offset, "page fault")
        continue
    physical = tlb[vpn] * page_size + offset
    assert physical % page_size == offset
    print(f"0x{virtual:03X}", vpn, offset, event, f"0x{physical:03X}")

hit, miss = 1 + 10, 1 + 4*10 + 10
for hits in (90, 95):
    mean = (hit*hits + miss*(100-hits))/100
    print(f"{hits}% hit: {mean:g} cycles")

0x130 4 48 TLB hit 0x270
0x1C4 7 4 TLB miss, PTE present 0x084
0x240 9 0 page fault

95% hit: 13 cycles

코드는 공간이 충분해 채운 TLB 항목을 교체하지 않는 모형입니다. 상주 매핑을 초기 표에서 고정했으므로 폴트에서 새 페이지를 할당하지 않습니다. 다음 장에서는 변환된 물리 주소가 데이터 캐시에서 어떻게 자리 잡는지 계산합니다.
