연산 시간과 데이터 이동 비용을 따로 잰다

같은 계산이라도 CPU와 GPU가 맡으면 걸리는 시간이 다릅니다. 연산만 비교하면 놓칠 수 있는 복사 비용을 더하고, 실제 코드의 시간과 메모리를 어떻게 관찰하는지도 확인합니다.

이 장을 읽고 나면

  • CPU와 GPU를 사용할 때 연산과 데이터 이동을 함께 비교한다.
  • 작업의 일부만 빠르게 했을 때 전체 속도를 계산한다.
  • CPU 프로파일러와 Python 메모리 추적기의 범위를 구분한다.

계산에 필요한 값을 옮기는 시간도 포함한다

CPU는 운영체제와 프로그램의 여러 종류 명령을 처리합니다. GPU는 큰 배열의 원소에 같은 계열의 연산을 많이 적용할 때 여러 계산을 병렬로 처리할 수 있습니다. 많은 작은 연산을 묶으면 장점이 나타날 수 있지만, CPU와 별도 메모리를 쓰는 GPU에는 자료를 복사하고 결과를 가져오는 비용이 들어갑니다. 일부 장치에서는 메모리가 통합되기도 하므로 실제 이동 경로는 환경에서 확인합니다.

이 교육용 모형의 CPU 시간은 90ms입니다. GPU는 입력을 옮기는 데 12ms, 계산 30ms, 결과를 되가져오는 데 8ms이고 세 단계가 겹치지 않는다고 합시다. 전체는 50ms이며 CPU와 비교한 속도 향상 배율은 기존 시간/새 시간=90/50=1.8입니다. 계산 부분 30ms만으로 전체가 3배 빨라졌다고 해석하면 이동을 빠뜨리게 됩니다.

처리 시간의 일부만 바꾸면 남은 부분은 그대로다

전체 100ms 중 순차 작업에 20ms, 병렬로 나눌 계산에 80ms가 걸립니다. 계산 80ms 부분만 4배 빨라져 20ms가 되면 총 시간은 40ms입니다. 전체 속도 향상은 100/40=2.5배입니다. 계산 부분을 아무리 줄여도 남은 20ms는 처리해야 합니다. 이 단순 비교는 작업을 나누거나 다시 합치는 추가 비용을 0으로 놓았습니다.

이 관계를 암달의 법칙(Amdahl's law)이라고 합니다. 전체 시간에서 빨라지는 부분의 비율을 p, 그 부분의 속도 배율을 s라 하면 전체 속도 향상은 1 ÷ ((1 − p) + p ÷ s)입니다. 위 예는 p = 0.8, s = 4이므로 1 ÷ (0.2 + 0.2) = 2.5배이고, s를 아무리 키워도 1 ÷ 0.2 = 5배를 넘지 못합니다.

프로파일러의 시간과 메모리 값이 무엇을 세는지 확인한다

프로파일링은 실제 프로그램을 보며 어느 함수나 구간에서 시간이 들고 메모리가 늘어나는지 찾는 일입니다. Python의 cProfile은 함수 호출 수와 시간을 추적합니다. 누적 시간은 그 함수가 부른 다른 함수에서 보낸 시간을 포함할 수 있습니다. 여러 함수의 누적 시간을 단순히 더하면 포함 관계를 두 번 셀 수 있으므로, 느린 구간을 먼저 찾아 작은 실험으로 다시 확인합니다.

tracemalloc은 추적을 시작한 뒤 Python의 메모리 할당을 살펴볼 수 있습니다. 현재 추적량과 그 기간의 최고 추적량은 다릅니다. 운영체제가 보고한 프로세스 전체 메모리, 라이브러리의 모든 외부 할당, GPU에 올라간 메모리를 이 숫자 하나로 다 알 수는 없습니다. GPU 함수가 결과 계산을 미뤄 두는 환경에서 끝까지의 시간을 재려면 작업 완료를 기다린 뒤 시계를 읽습니다. 비교할 때에는 데이터 크기, 반복·준비 실행, 장치, 이동 포함 여부를 기록합니다.

시간 모형, 실제 호출 수, 메모리 크기 확인을 구분한다

import cProfile
import tracemalloc

def squared_sum(n):
    return sum(k * k for k in range(n))

print(f"CPU/GPU model: {90 / (12 + 30 + 8):.1f}x")
print(f"partial speedup model: {100 / (20 + 80 / 4):.1f}x")

profiler = cProfile.Profile()
profiler.enable()
squared_sum(2)
squared_sum(4)
profiler.disable()
calls = sum(
    entry.callcount for entry in profiler.getstats()
    if getattr(entry.code, "co_name", "") == "squared_sum"
)
print("profiled calls:", calls)

tracemalloc.start()
payload = bytearray(50000)
_, peak = tracemalloc.get_traced_memory()
print("tracked peak at least payload:", peak >= len(payload))
tracemalloc.stop()
CPU/GPU model: 1.8x
partial speedup model: 2.5x
profiled calls: 2
tracked peak at least payload: True

속도 배율 두 개는 가정한 시간으로 계산했습니다. 호출 수와 메모리 확인은 실제 Python 실행에서 가져왔습니다. 프로파일링 도구 자체에도 비용이 있으므로 관찰한 시간과 프로파일러 없이 얻은 실제 완료 시간을 목적에 맞게 구분합니다.
