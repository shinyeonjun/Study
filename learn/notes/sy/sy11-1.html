컴퓨터 시스템 · SY11 입출력과 성능 분석 실습

SY11·1

입출력을 기다리는 시간과 전체 처리량을 분리해 계산하기

작업자가 하나에서 둘로 늘어나면 같은 요청의 서비스 시간은 그대로여도 줄이 짧아집니다. 네 요청의 도착, 시작, 완료 시각을 계산해 지연과 처리량을 구분합니다.

이 장을 읽고 나면

  • 블로킹과 비동기 요청, 버퍼가 하는 일을 구별한다.
  • 큐의 대기와 실제 처리 구간을 합해 응답 지연을 구한다.
  • 시작·종료 시점을 고정해 한 작업자와 두 작업자를 비교한다.

요청의 시작과 완료는 다른 시각일 수 있다

블로킹 입출력에서는 요청한 흐름이 필요한 결과가 올 때까지 기다립니다. 다른 스레드나 작업은 실행할 수 있습니다. 비동기 인터페이스에서는 요청이 접수된 뒤 호출 흐름이 다른 일을 진행하고 완료 통지를 나중에 받습니다. 저장 장치나 네트워크의 서비스에 필요한 시간이 사라지는 것은 아닙니다. 요청과 데이터의 성격에 따라, 호출자가 기다리거나 대신 할 수 있는 작업이 달라집니다.

버퍼에는 아직 처리하지 못했거나 전달하기 전에 모아 둔 데이터가 들어갑니다. 느린 소비자 앞에서 버퍼가 가득 차면, 생산자에게 기다리라는 신호를 보내거나 특정 정책에 따라 거부해야 합니다. 버퍼는 잠시 격차를 흡수할 수 있지만, 계속 들어오는 속도가 처리 속도보다 크면 결국 빈 칸이 부족해집니다.

일정한 서비스 시간의 큐를 한 건씩 푼다

도착 시각이 0,1,2,8이고 요청 하나를 서비스하는 데 같은 시간 4가 듭니다. 작업자는 빈 시간이 되면 먼저 들어온 요청부터 맡습니다. 시작 시각은 arrival과 작업자의 사용 가능 시각 중 큰 값, 완료는 시작+4입니다. 응답 지연은 완료−도착으로, 대기와 서비스의 합입니다.

도착한 작업자 시작 → 완료한 작업자 지연두 작업자 시작 → 완료두 작업자 지연
00 → 440 → 44
14 → 871 → 54
28 → 12104 → 86
812 → 1688 → 124

평균 응답 지연은 각각 29/4=7.25, 18/4=4.5입니다. 두 작업자에서 가장 오래 걸린 세 번째 요청은 대기 2와 서비스 4를 더해 6입니다. 실제 시간에는 작업을 나누는 비용도 있을 수 있지만 여기서는 0으로 둔 모형입니다.

각 관측 구간에 완료된 개수를 비교한다

이번 비교는 각 실험에서 첫 도착부터 끝 완료까지를 관측 창으로 지정했습니다. 그 안에서 완료한 건을 나누면 처리량은 4/16과 4/12입니다. 실제 서비스는 한 작업자당 시간 단위에 1/4건이므로 작업자 두 명의 계속 바쁜 최대 용량은 1/2입니다. 큐가 비는 시간이 있는 이번 관측값과 다릅니다. 시작 구간을 버렸는지와, 아직 완료되지 않은 요청을 분모 또는 지연 계산에서 어떻게 다뤘는지도 함께 기록합니다.

정의 · 리틀의 법칙

시스템 안에 머무는 요청의 시간 평균 개수를 L, 도착률(단위 시간당 도착 수)을 λ, 요청 하나가 시스템에 머무는 평균 시간(응답 지연)을 W라 하면 L=λW입니다. 장기 평균이 존재하는 안정 상태에서 성립하며, 도착 순서나 서비스 분포와 무관합니다. 관측 창 안에서 모든 요청이 도착하고 완료됐다면 창에 대해 정확히 성립합니다. 한 작업자: λ=4/16, W=29/4이므로 L=29/16이고, 이는 지연의 합 29를 창 길이 16으로 나눈 값과 같습니다. 두 작업자: λ=4/12, W=9/2이므로 L=18/12=1.5입니다. 처리량과 지연 중 둘을 재면 나머지 하나(평균 대기 개수)를 검산할 수 있습니다.

from fractions import Fraction as F
from heapq import heapify, heappop, heappush

arrivals = [0,1,2,8]
def measure(workers):
    free = [0]*workers
    heapify(free)
    complete = []
    for a in arrivals:
        end = max(a,heappop(free))+4
        complete.append(end)
        heappush(free,end)
    delays = [b-a for a,b in zip(arrivals,complete)]
    elapsed = max(complete)-arrivals[0]
    return complete,F(sum(delays),len(delays)),F(len(complete),elapsed)

for workers in (1,2):
    print(*measure(workers))
assert measure(1)[1] > measure(2)[1]

[4, 8, 12, 16] 29/4 1/4
[4, 5, 8, 12] 9/2 1/3

한눈에 정리

핵심어기억할 기준
블로킹·비동기호출한 흐름이 결과까지 기다리는지의 차이입니다. 장치의 서비스 시간은 그대로입니다.
응답 지연완료−도착 = 대기 + 서비스. 예제 평균은 7.25와 4.5입니다.
처리량관측 창에서 완료한 건수 ÷ 창 길이. 최대 용량(작업자 수 ÷ 서비스 시간)과 구별합니다.
리틀의 법칙L=λW. 평균 개수, 도착률, 평균 지연 중 둘로 나머지를 검산합니다.

한 줄 정리

지연은 요청 하나의 경험, 처리량은 관측 창 전체의 완료율이며, 둘은 리틀의 법칙으로 이어집니다.
