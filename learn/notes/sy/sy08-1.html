같은 값을 동시에 고칠 때 락으로 순서를 정한다

두 사람이 같은 총계 0을 읽고 각각 1을 더해 적었습니다. 두 번 처리했는데 총계가 1인 이유를 확인하고, 여러 단계에 걸친 한 작업을 어디까지 묶어야 하는지 살핍니다.

이 장을 읽고 나면

  • 읽기·계산·쓰기 사이에 순서가 섞이면 결과가 달라짐을 설명한다.
  • 잠금이 보호해야 하는 범위를 고른다.
  • 같은 총계를 두 스레드에서 바꾸는 예제의 결과를 예상한다.

계산 횟수와 마지막 기록이 같지 않을 수 있다

서버에서 처리한 주문 수를 기록한다고 합시다. 각 실행 흐름은 현재 수를 읽고, 1을 더한 값을 계산한 뒤, 그 결과를 다시 적습니다. 값을 바꾸는 세 단계가 정말 한꺼번에 처리된다는 보장이 없다면, 실행 순서에 따라 마지막 값이 달라질 수 있습니다. 실행 순서를 바꿨을 때 올바르게 돌아가는지 여부가 달라지는 상황을 경쟁 상태(race condition)라고 합니다.

시작값이 0입니다. A가 0을 읽고 B도 A가 쓰기 전에 0을 읽습니다. A와 B는 각각 1을 계산합니다. A가 1을 쓰고 B가 같은 1을 써도 마지막 값은 1입니다. 두 번째 저장이 앞의 변경을 반영하지 않아 증가 하나가 사라졌습니다. 한 코어에서 두 실행이 번갈아 진행되는 경우에도 이런 순서가 가능합니다.

읽는 순간부터 쓰는 순간까지 함께 보호한다

락(lock)은 약속된 코드 구간에 동시에 여러 흐름이 들어가지 못하게 하는 도구입니다. 공유 값을 읽고 바꾼 결과를 다시 쓰는 임계 구역 전체에서 동일한 락을 사용해야 합니다. 쓰기 줄만 따로 잠그면, 그 전에 두 흐름이 여전히 0을 읽고 각자 1을 계산할 수 있습니다.

락을 쓰면 동시에 처리할 수 있는 범위가 좁아집니다. 공유 값과 무관한 작업까지 오래 묶으면 기다림 때문에 프로그램이 느려질 수 있습니다. 여러 락을 다른 순서로 얻으려는 흐름들이 서로가 가진 락을 기다리면 둘 다 더 이상 진행하지 못합니다. 이를 교착 상태(deadlock)라고 하며, 모든 흐름이 락을 같은 순서로 얻게 하면 피할 수 있습니다. 이 장에서는 공유 카운터 하나에 락 하나만 사용합니다.

표준 CPython 빌드에는 한 번에 한 스레드만 Python 바이트코드를 실행하게 하는 GIL(전역 인터프리터 락)이 있습니다. 그래도 바이트코드 명령 사이에서 실행 스레드가 바뀔 수 있으므로, GIL이 읽기·계산·쓰기 전체가 한 번에 끝난다는 보장을 대신하지 않습니다. counter += 1 한 줄도 여러 바이트코드로 나뉘어 원자적이라는 보장이 없습니다. CPython 3.13부터는 GIL 없이 여러 스레드가 Python 코드를 실제로 동시에 실행하는 free-threaded 빌드(실행 파일 이름 예: python3.14t)가 따로 있고, 3.14에서 공식 지원 단계가 되었지만 기본 설치는 여전히 GIL이 있는 빌드입니다. 어느 빌드에서든 공유 값을 바꾸는 구간은 락으로 보호합니다.

두 흐름 모두 값을 읽은 뒤에만 쓰도록 순서를 재현한다

실제 경쟁 상태는 운에 따라 매번 드러나지는 않습니다. 예제에서는 Barrier(2)로 두 흐름 모두 읽을 때까지 다음 쓰기를 기다리게 해 한 가지 가능한 순서를 일정하게 재현합니다. 락을 쓴 경우에는 대기 장벽을 사용하지 않습니다. 두 코드의 계산은 각각 값 하나를 읽고 1을 더합니다.

from threading import Barrier, Lock, Thread

def count_orders(protect):
    counter = 0
    both_read = Barrier(2, timeout=5)
    lock = Lock()

    def update():
        nonlocal counter
        if protect:
            with lock:
                before = counter
                counter = before + 1
        else:
            before = counter
            both_read.wait()
            counter = before + 1

    workers = [Thread(target=update) for _ in range(2)]
    for worker in workers:
        worker.start()
    for worker in workers:
        worker.join()
    return counter

print("same initial read:", count_orders(False))
print("protected interval:", count_orders(True))
same initial read: 1
protected interval: 2

join()은 주 실행 흐름이 각 스레드가 끝날 때까지 기다리게 해, 모두 처리한 뒤 결과를 읽게 합니다. 업데이트 구간의 겹침을 막는 락과 역할이 다릅니다.

한눈에 정리

핵심어기억할 기준
경쟁 상태공유 데이터를 바꾸는 단계가 섞여 실행 순서에 따라 결과가 달라질 수 있다.
임계 구역하나의 결과로 처리되어야 할 읽기부터 쓰기까지의 범위다.
락과 join락은 구간에 함께 들어가는 것을 막고 join은 종료를 기다린다.
