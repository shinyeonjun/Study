입출력을 기다리는 동안 다른 태스크를 진행한다

한 작업이 파일이나 네트워크의 답을 기다릴 때 다른 준비된 일은 진행할 수 있습니다. 기다림을 겹치는 일과, 두 계산을 서로 다른 코어에서 동시에 실행하는 일을 구분합니다.

이 장을 읽고 나면

  • 순차 실행, 동시성, 병렬성의 관계를 설명한다.
  • asyncio의 코루틴·태스크·await가 이 예에서 어떤 역할을 하는지 읽는다.
  • 대기가 많은 프로그램과 계산이 많은 프로그램에서 비교할 방식을 고른다.

두 일이 겹쳐 진행되어도 명령을 같은 순간에 실행할 필요는 없다

작업 A에 실행 1초, 결과 대기 3초, 이어서 실행 1초가 필요하다고 합시다. 작업 B에는 실행 2초가 필요합니다. 기다리는 동안 아무 다른 일을 하지 않는다면 A와 B를 차례로 끝내는 데 7초가 걸립니다. A가 기다리는 3초 안에 B의 2초를 진행하면 끝나는 시점을 5초로 당길 수 있습니다. 여기서는 준비된 계산을 한 번에 하나만 실행하는 교육용 예입니다.

앞에서 보았듯 동시성은 여러 일이 전체 시간에 걸쳐 함께 진행되는 모습입니다. 병렬성은 여러 계산이 정말 같은 순간에 진행되는 모습입니다. 여러 CPU 코어 또는 GPU가 서로 독립된 계산을 나눠 맡을 수 있습니다. 한 실행 흐름이 기다리며 다른 일을 진행하도록 하는 비동기 패턴은 그 자체로 CPU 코어를 더 늘리지는 않습니다.

asyncio에서는 기다리는 곳에서 다른 코루틴에 차례를 줄 수 있다

yield 없이 async def로 만든 코루틴 함수를 호출하면 실행을 시작하기 전의 코루틴 객체를 얻습니다. await하거나 태스크로 만들어 실행 루프에서 진행시킬 수 있습니다. 이벤트 루프는 실행할 준비가 된 태스크를 진행합니다. 한 태스크가 아직 준비되지 않은 결과를 await하면 그 지점에서 멈추고, 다른 준비된 태스크를 실행할 수 있습니다. 이미 준비된 값을 기다리는 표현이라고 해서 매번 반드시 실행이 바뀌는 것은 아닙니다.

입출력 대기가 많다면 기다리는 동안 다른 일을 진행할 수 있는지가 중요합니다. 반면 큰 계산을 async def 안에 넣기만 하면 그 계산이 빨라지지 않습니다. 그 함수가 긴 계산을 하며 다른 태스크에 차례를 주지 않으면 같은 루프가 멈춰 보일 수도 있습니다. CPU 연산이 많은 작업은 여러 프로세스나 병렬로 실행되는 수치 라이브러리를 고려하고, 자료를 나누는 비용과 사용 환경을 함께 봅니다.

코루틴이 멈추고 재개되는 순서를 직접 따라간다

아래 예제는 실제 asyncio 이벤트 루프에서 두 코루틴을 실행합니다. request는 A가 응답을 기다리기 시작했다는 신호이고, answer는 B의 응답이 준비됐다는 신호입니다. 시간이나 컴퓨터 속도에 의존하지 않게 두 이벤트로 순서를 정합니다.

import asyncio

async def first(request, answer):
    print("A: waiting")
    request.set()
    await answer.wait()
    print("A: received")

async def second(request, answer):
    await request.wait()
    print("B: answered")
    answer.set()

async def main():
    request = asyncio.Event()
    answer = asyncio.Event()
    await asyncio.gather(first(request, answer), second(request, answer))

asyncio.run(main())
A: waiting
B: answered
A: received

A는 요청 신호를 보낸 뒤 응답 이벤트를 기다립니다. B는 요청이 들어온 뒤 응답 이벤트를 설정합니다. 이벤트 루프가 멈춰 있던 A를 다시 실행하면 마지막 줄이 출력됩니다.
