운영체제는 실행할 스레드에 CPU 시간을 나눈다

한 CPU 코어에서 세 계산이 차례를 기다립니다. 작업을 만들고 관리하는 단위와 실제 실행 흐름을 구분하면, 왜 어떤 작업이 먼저 반응하고 다른 작업이 나중에 끝나는지 이해할 수 있습니다.

이 장을 읽고 나면

  • 운영체제의 자원 관리와 프로세스·스레드의 관계를 설명한다.
  • 먼저 온 순서와 라운드 로빈의 작은 실행표를 읽는다.
  • 완료, 대기, 첫 응답 시점을 서로 구분한다.

하나의 실행 공간에 여러 실행 흐름이 존재할 수 있다

프로그램은 CPU 시간, 메모리, 파일, 화면과 같은 자원을 사용합니다. 운영체제는 여러 프로그램이 같은 기계에서 실행되도록 자원을 관리하고, 프로그램에 그 자원을 요청할 수 있는 방법을 제공합니다. 핵심 부분인 커널은 메모리와 CPU 사용을 조정하고 장치의 입출력을 관리합니다.

프로세스는 실행과 자원을 관리하는 단위입니다. 스레드는 그 프로세스 안에서 명령을 이어서 실행하는 흐름입니다. 한 프로세스의 스레드들은 코드·데이터가 놓인 가상 주소 공간과 열린 파일 같은 프로세스 자원을 보통 공유합니다. 각 스레드는 다음에 실행할 명령 위치와 레지스터 상태, 함수 호출을 보관할 자기 스택을 가집니다. 스택은 스레드마다 쓰는 공간이지만 같은 프로세스의 주소 공간에 있으므로, 스레드 사이의 보안 격리를 뜻하지 않습니다.

하나의 흐름이 입출력 결과를 기다리면 CPU는 다른 준비된 흐름을 실행할 수 있습니다. 한 코어에서 실행을 빠르게 번갈아 진행해도 두 작업이 여러 시점에 걸쳐 함께 진행되는 동시성은 생깁니다. 여러 실행 단위에서 실제로 같은 순간에 명령이 실행되면 병렬 실행입니다. 이 장의 계산은 실행 단위 하나만 두므로 어느 순간에 하나만 실행합니다.

처음 실행할 차례와 완료할 시각은 다르다

스케줄링은 지금 실행할 수 있는 흐름에 CPU 차례를 주는 일입니다. 준비 상태인 스레드는 기다리는 줄에 들어갈 수 있습니다. 실행 중 입출력을 기다리면 준비 상태와 달리 그 일이 끝날 때까지 바로 실행할 수 없습니다. 실행 흐름을 바꿀 때는 현재 레지스터 같은 상태를 남기고 다음 흐름의 상태를 복구합니다. 이 과정을 문맥 교환이라고 합니다.

작업 A, B, C가 시각 0에 A→B→C 순서로 준비 상태에 들어갔다고 합시다. 필요한 CPU 시간은 5, 2, 3입니다. 중간에 입출력 대기가 없고 흐름을 교체하는 비용도 0인 가상 모형입니다. 선입선출에서는 차례를 받은 일을 끝까지 진행합니다. 라운드 로빈은 각 차례에 최대 시간 조각만큼 실행한 뒤, 아직 남았다면 준비 줄 뒤로 보냅니다. 시간 조각이 2라도 남은 일이 1만큼이면 그 자리에서 끝납니다.

시각 0에 준비됐으므로 첫 실행 시각 이름 그대로가 첫 응답 시간입니다. 작업 B의 경우 먼저 온 순서에서 첫 응답 5에 완료 7, 라운드 로빈에서 첫 응답 2에 완료 4입니다. 이 모형에서는 입출력 대기와 교체 비용이 없어, 완료 시각에서 일한 CPU 시간을 빼면 준비 줄에서 기다린 시간이 됩니다. A의 대기는 선입선출에서 5−5=0, 라운드 로빈에서 10−5=5입니다.

라운드 로빈에서는 B가 더 빨리 응답하지만 A는 더 늦게 끝납니다. 이 예에서 평균 대기는 선입선출 4, 라운드 로빈 13/3으로 오히려 더 큽니다. 어떤 방식이 더 낫다는 판단은 첫 응답, 평균 대기, 처리량 중 무엇을 중요하게 두는가에 따라 달라집니다. Windows는 준비된 스레드를 우선순위 등의 규칙에 따라 선택합니다. 이 예는 실제 Windows 스케줄러의 전체 동작을 재현하지 않습니다.

대기열에서 하나씩 꺼내 시간을 기록한다

from collections import deque

needed = {"A": 5, "B": 2, "C": 3}

def schedule(quantum):
    remaining = needed.copy()
    ready = deque(needed)
    finish = {}
    spans = []
    clock = 0
    while ready:
        name = ready.popleft()
        duration = remaining[name] if quantum is None else min(remaining[name], quantum)
        spans.append(f"{name}:{clock}-{clock + duration}")
        clock += duration
        remaining[name] -= duration
        if remaining[name]:
            ready.append(name)
        else:
            finish[name] = clock
    waiting = [finish[name] - needed[name] for name in needed]
    return spans, waiting

for name, quantum in (("FIFO", None), ("RR", 2)):
    spans, waits = schedule(quantum)
    print(name, " ".join(spans))
    print("wait A, B, C:", waits)
FIFO A:0-5 B:5-7 C:7-10
wait A, B, C: [0, 5, 7]
RR A:0-2 B:2-4 C:4-6 A:6-8 C:8-9 A:9-10
wait A, B, C: [5, 2, 6]

현재 시각은 실제 시계가 아니라 모형의 수치입니다. 시간이 2인 B는 한 번으로 끝나고, 시간이 5인 A는 시간 조각 2를 두 번 받은 뒤 마지막 1을 더 받아 끝납니다.
