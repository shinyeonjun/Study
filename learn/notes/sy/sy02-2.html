캐시는 가까운 주소와 최근 읽은 주소를 활용한다

복도 끝 창고에 가서 상자 하나를 열 때마다 시간이 걸립니다. 같은 상자 안에 다음 재료도 있으면 한 번 가져와 여러 번 쓸 수 있습니다. 캐시도 주소를 묶어 가져옵니다.

이 장을 읽고 나면

  • 캐시의 블록과 적중·실패의 뜻을 설명한다.
  • 두 칸짜리 직접 매핑 캐시의 저장 상태를 추적한다.
  • 연속 접근과 충돌 접근의 비용을 주어진 규칙으로 비교한다.

한 주소만 바뀌어도 같은 블록을 다시 사용할 수 있다

CPU가 메인 메모리에 접근할 때, 이미 가져온 일부 값을 더 가까운 작은 저장 공간에 두는 것을 캐시라고 합니다. 이 장은 CPU와 메인 메모리 사이의 읽기 캐시만 생각합니다. 원하는 데이터 블록이 있으면 적중(hit), 없으면 실패(miss)입니다. 실패일 때는 더 먼 곳에서 필요한 블록을 가져옵니다. 캐시 실패 자체는 프로그램 오류를 뜻하지 않습니다.

실제 하드웨어에서는 메모리 주소 여러 개가 한 캐시 라인에 묶입니다. 교육용 모형에서는 메모리 주소 하나가 1바이트이고 주소 네 개를 한 블록으로 둡니다. 블록 0은 주소 0~3, 블록 1은 4~7, 블록 2는 8~11입니다. 이 모형의 블록 번호는 주소 // 4입니다. 바로 앞에서 읽은 주소 0과 다음 주소 1은 서로 다른 값이지만 같은 블록의 일부입니다.

곧 다시 같은 자료를 참조하는 경향을 시간 지역성이라고 합니다. 방금 읽은 주소 근처를 바로 읽는 경향은 공간 지역성입니다. 캐시는 두 경향 덕분에 작아도 자주 쓰는 값이나 이어서 읽을 값을 가까이 둘 수 있습니다.

같은 캐시 칸을 차지하는 두 블록은 서로를 밀어낸다

이 예의 캐시는 비어 있는 칸이 둘이고, 각 칸은 블록 하나를 담습니다. 블록 번호를 2로 나눈 나머지가 쓸 칸입니다. 이처럼 각 블록이 들어갈 위치를 하나로 고정하는 방식이 직접 매핑입니다. 블록 0과 2는 둘 다 칸 0을 사용하고, 블록 1은 칸 1을 사용합니다. 칸 0에 무언가 있다는 사실만으로 적중이 되지 않습니다. 캐시는 찾는 블록과 같은 블록인지도 확인합니다. 실제 캐시는 칸마다 지금 어느 블록이 들어 있는지 알려 주는 번호(태그)를 함께 저장하고, 요청한 주소의 태그와 비교합니다.

주소를 [0,1,2,8,0,4,5,8] 순서로 읽습니다. 처음 0은 블록을 가져와야 하므로 실패입니다. 1과 2는 같은 블록 0이 남아 있어 적중합니다. 8은 블록 2라 실패한 뒤 칸 0의 블록 0을 밀어냅니다. 그래서 그 다음 0도 다시 실패합니다.

복잡한 기계를 측정하는 값과 모형 비용을 구별한다

가상으로 적중 한 번의 전체 비용을 1, 실패 한 번의 전체 비용을 20이라 둡니다. 위 접근의 비용은 적중 3회와 실패 5회로 3×1+5×20=103입니다. 연속 주소 0~7은 블록 0과 1을 한 번씩 가져온 뒤 각 블록 안에서 세 번 적중합니다. 적중 6회와 실패 2회이므로 6+40=46입니다. 이 숫자는 실제 기계의 시간 측정값이 아닙니다.

실제 CPU에는 여러 캐시 층과 다양한 매핑이 있습니다. 미리 데이터를 가져오거나 한 번에 여러 요청을 처리할 수도 있습니다. 배열의 순서대로 접근하는 코드가 더 유리할 수 있는 이유는 보이지만, 정확한 속도 비교는 실제 환경에서 실행해 확인해야 합니다.

주소를 블록·칸으로 바꿔서 적중을 센다

def run(addresses):
    cache = [None, None]
    flags = []
    for address in addresses:
        block = address // 4
        slot = block % len(cache)
        hit = cache[slot] == block
        flags.append("H" if hit else "M")
        cache[slot] = block
    hits = flags.count("H")
    misses = flags.count("M")
    return " ".join(flags), hits, misses, hits + 20 * misses

for name, addresses in (
    ("mixed", [0, 1, 2, 8, 0, 4, 5, 8]),
    ("ordered", range(8)),
):
    print(name, *run(addresses))
mixed M H H M M M H M 3 5 103
ordered M H H H M H H H 6 2 46

각 비교의 처음에는 캐시가 비어 있습니다. 두 번째 비교에 첫 기록의 캐시가 남아 있으면 첫 접근의 결과가 달라질 수 있습니다.
