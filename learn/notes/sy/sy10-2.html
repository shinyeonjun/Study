조건변수의 대기 조건과 잠금 순서로 교착을 막기

한 칸짜리 상자에 새 물건을 넣으려면 먼저 비어야 합니다. 신호를 받은 사람이 상자를 열기 전에 다른 사람이 물건을 가져갈 수도 있습니다. 기다리는 조건과 상태의 변경을 같은 잠금 안에서 확인합니다.

이 장을 읽고 나면

  • 조건변수의 대기가 잠금을 푸는 이유를 설명한다.
  • 한 칸 버퍼의 크기와 생산·소비 차이를 불변식으로 검증한다.
  • 잠금 획득 순서가 교착 순환을 막는다는 논증을 제시한다.

알림과 조건이 참인 상태를 구분한다

한 칸 버퍼의 상태는 비었거나 하나가 들어 있습니다. 소비자는 비어 있으면 기다리고, 생산자는 한 칸이 차 있으면 기다립니다. 두 작업 모두 버퍼 상태와 기다리는 조건을 같은 잠금으로 보호합니다. 조건변수의 wait는 새 작업이 조건을 바꿀 수 있도록 잠금을 풀고 기다린 뒤, 돌아올 때 다시 잠금을 획득합니다.

소비자 A가 알림을 받고 대기에서 풀려도 그 시점에 이미 버퍼를 가지고 있는 것은 아닙니다. A가 잠금을 다시 잡기 전 소비자 B가 먼저 가져갈 수 있습니다. 알림은 조건을 다시 검사하라는 뜻입니다. 따라서 while not buffer …: wait()처럼 루프로 검사합니다. 알림을 보낸 쪽이 잠금을 계속 쥐고 깨어난 쪽은 나중에 다시 경쟁하는 이 방식을 Mesa 의미론이라 하며, POSIX·Java·Python의 조건변수가 모두 이 방식입니다. (알림과 동시에 잠금을 넘겨 조건이 보장되는 Hoare 의미론도 있지만 실제 라이브러리에서는 드뭅니다.) POSIX는 알림 없이 깨어나는 가짜 깨어남도 허용하므로 if 한 번의 검사로는 안전하지 않습니다. 버퍼와 조건 확인이 따로 보호되면 검사와 상태 갱신 사이에 빈틈이 생깁니다.

기록된 수와 큐 길이를 맞춘다

처음 produced=consumed=0이고 버퍼는 비었습니다. 생산자는 빈 상태에서 한 개를 넣고 produced를 1 올립니다. 소비자는 값이 있을 때만 한 개를 꺼내고 consumed를 1 올립니다. 임계 구역을 마친 시점마다 produced−consumed=len(buffer)∈{0,1}이 유지됩니다. 상태를 바꾼 뒤에 알림을 보내고, 생산을 끝냈다는 상태도 같은 잠금에서 바꿉니다.

잠금이 둘이면 서로 기다리는 방향을 그린다

스레드 A가 L1을 든 채 L2를 기다리고, B가 L2를 든 채 L1을 기다리면 둘은 계속 멈춥니다. 상호 배제, 자원을 가진 채 기다림, 강제로 뺏기 어려움, 순환 대기의 조건이 이 예에 모였습니다. 모든 스레드에서 L1,L2의 전역 순서를 정하고 작은 번호에서 큰 번호로만 획득하면, 기다리는 방향은 항상 증가합니다. 유한 순환을 만들려면 번호가 계속 증가해 처음으로 돌아와야 하므로 불가능합니다.

교착이 없는 것과 모든 작업이 정해진 시간 안에 차례를 얻는 것은 다릅니다. 어떤 스레드가 잠금을 여러 번 다시 얻는 정책에서는 다른 스레드가 계속 뒤로 밀릴 수 있습니다. 실제 조건변수와 잠금 API가 깨어나는 공정한 순서를 보장하는지도 따로 확인합니다.

from collections import deque
from threading import Condition, Thread

condition = Condition()
buffer = deque()
out = []
produced = 0
closed = False

def invariant():
    return produced-len(out)==len(buffer) and len(buffer)<=1

def produce():
    global produced,closed
    for value in (10,20,30):
        with condition:
            while buffer:
                condition.wait()
            buffer.append(value)
            produced+=1
            assert invariant()
            condition.notify_all()
    with condition:
        closed=True
        condition.notify_all()

def consume():
    while True:
        with condition:
            while not buffer and not closed:
                condition.wait()
            if not buffer:
                return
            out.append(buffer.popleft())
            assert invariant()
            condition.notify_all()

reader=Thread(target=consume)
writer=Thread(target=produce)
reader.start()
writer.start()
writer.join()
reader.join()
print(out, produced, len(buffer))
assert invariant() and out==[10,20,30]

실행 결과

[10, 20, 30] 3 0

한눈에 정리

핵심어기억할 기준
조건변수 wait잠금을 풀고 잠든 뒤, 돌아올 때 잠금을 다시 잡습니다. 알림은 "다시 검사하라"는 뜻일 뿐입니다.
while 검사Mesa 의미론과 가짜 깨어남 때문에 조건은 반복문으로 다시 확인합니다.
생산자/소비자 불변식임계 구역 경계마다 produced−consumed=len(buffer)∈{0,1}입니다.
교착의 네 조건상호 배제, 점유하며 대기, 비선점, 순환 대기. 전역 잠금 순서는 순환 대기를 없앱니다.
기아교착이 없어도 특정 스레드가 계속 밀릴 수 있습니다. 공정성은 따로 보장해야 합니다.

한 줄 정리

조건은 잠금 안에서 반복해 검사하고, 잠금은 모두가 같은 전역 순서로 잡습니다.
