SY01·2

문자·픽셀·소리를 바이트로 기록한다

문장에 있는 ‘한’과 사진 속 빨강, 녹음의 한 순간은 모두 바이트로 저장됩니다. 무엇을 한 단위로 세는지 알면 화면의 글자 수와 파일 크기를 같은 값으로 착각하지 않습니다.

이 장을 읽고 나면

  • 유니코드 코드 포인트와 UTF-8 바이트 수를 구분한다.
  • 행과 열, 채널 수와 비트 폭으로 원시 이미지 크기를 구한다.
  • PCM의 샘플링률과 프레임, 원시 오디오 크기를 계산한다.

문자를 알려 주는 번호와 파일에 적는 바이트는 다르다

같은 문장을 저장하고 되살리기 위해 문자와 번호를 대응시킵니다. 유니코드에서 부여한 번호를 코드 포인트라고 합니다. A는 U+0041, 한은 U+D55C, 🙂는 U+1F642입니다. UTF-8은 이 번호들을 바이트열로 바꾸는 인코딩입니다. UTF-16에 예약된 대리 코드 포인트를 제외한 번호를 1~4바이트로 표현하며, ASCII에 해당하는 처음 128개 값은 각 한 바이트입니다.

Python의 str은 문자 데이터를 다루고 bytes는 0~255 바이트의 열을 다룹니다. encode("utf-8")로 문장을 바이트로 바꾸고 같은 인코딩으로 decode하면 되살릴 수 있습니다. 문자열 길이 len(str)는 코드 포인트 수입니다. 눈에 보이는 글자 수와도 항상 같지는 않습니다. 한 코드 포인트 é와, e 다음에 결합 악센트를 붙인 두 코드 포인트는 화면에서 한 글자처럼 보일 수 있습니다. UTF-8 바이트 길이는 각각 2와 3입니다.

파일을 읽을 때 인코딩이 맞지 않으면 다른 글자가 나오거나 해석 오류가 납니다. 자료 제공자가 정한 인코딩을 확인하고, CSV에서 화면 글자 수와 파일 크기를 따로 확인합니다. 문자열을 바이트로 만들 때 문자의 개수만 보고 저장 크기를 계산하면 한글이나 이모지에서 빗나갈 수 있습니다.

이미지는 격자와 색 채널, 소리는 시간과 샘플로 읽는다

가로 2, 세로 2인 RGB 원시 이미지는 픽셀 네 개입니다. 각 픽셀의 빨강(R), 초록(G), 파랑(B)에 8비트씩을 쓰면 픽셀당 3바이트입니다. 채널을 그 순서로 행마다 이어 적고 여분의 행 간격을 두지 않으면 전체는 2×2×3=12바이트입니다. 빨강 한 픽셀은 [255,0,0]으로 표현할 수 있습니다. RGBA라면 픽셀당 투명도 채널 A도 한 바이트 추가될 수 있습니다. PNG 파일은 헤더나 부가 정보와 압축을 사용하므로 실제 파일 크기는 이 곱셈과 다를 수 있습니다.

PCM 오디오는 일정한 시점마다 파형의 크기를 측정하고 제한된 숫자 수준으로 기록합니다. 초당 8,000개의 시간 위치를 기록한다면 샘플링률은 8,000Hz입니다. 한 시간 위치에서 모든 채널에 기록하는 값을 한 프레임으로 셉니다. 모노라면 프레임당 샘플 하나, 스테레오면 왼쪽·오른쪽 두 개입니다. 8,000Hz, 16비트, 2초 모노의 원시 데이터 크기는 8,000×2×1×2=32,000바이트입니다. 이 계산은 헤더나 압축을 빼고 오디오 데이터만 셉니다.

이미지에서 픽셀을 늘리는 일과 채널당 구분 가능한 밝기 수준을 늘리는 일은 다릅니다. 소리의 샘플링률은 시간 간격을, 비트 폭은 한 시점의 값을 얼마나 촘촘한 단계로 나눌지 정합니다. 같은 데이터 양을 만드는 방법이라도 어떤 정보가 더 자세하게 기록되는지 달라집니다.

문자와 작은 미디어 데이터의 바이트 수를 확인한다

text = "A한🙂"
encoded = text.encode("utf-8")
print("text:", len(text), len(encoded), encoded.hex(" "))
print("round trip:", encoded.decode("utf-8") == text)
print("two accents:", len("é".encode("utf-8")), len("e\u0301".encode("utf-8")))

pixels = [(255, 0, 0), (0, 255, 0), (0, 0, 255), (255, 255, 255)]
rgb = bytes(channel for pixel in pixels for channel in pixel)
print("RGB bytes:", len(rgb), rgb[:3].hex(" "))
frames = 8_000 * 2
print("PCM frames:", frames)
print("mono / stereo bytes:", frames * 2, frames * 2 * 2)
text: 3 8 41 ed 95 9c f0 9f 99 82
round trip: True
two accents: 2 3
RGB bytes: 12 ff 00 00
PCM frames: 16000
mono / stereo bytes: 32000 64000

출력은 문자 인코딩, 픽셀 채널 데이터, 소리의 원시 PCM 길이를 비교합니다. RGB와 PCM의 계산은 파일 헤더를 만들지 않습니다.

한눈에 정리

핵심어기억할 기준
UTF-8유효한 코드 포인트 하나를 해당 번호에 따라 1~4바이트로 표현한다.
픽셀과 채널원시 RGB의 저장량은 픽셀 수와 채널별 바이트 폭의 곱이다.
PCM 프레임한 시점의 모든 채널을 묶어 세며 채널 수만큼 샘플이 있다.
