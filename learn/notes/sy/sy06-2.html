환경 변수와 표준 입출력이 명령을 연결한다

두 프로그램을 연결할 때 각 프로그램은 서로의 내부 변수를 몰라도 됩니다. 필요한 설정은 환경으로 건네고, 데이터는 입출력 통로로 전달합니다.

이 장을 읽고 나면

  • 셸 변수와 자식 프로그램에 전달되는 환경의 관계를 설명한다.
  • 표준 입력·출력·오류와 파이프·리다이렉션의 연결을 읽는다.
  • Python에서 로컬 프로세스의 환경과 실제 파이프로 작은 데이터를 전달한다.

현재 셸의 변수를 새 프로그램에도 전할까

Bash에서 WORD_LIMIT=2라고 적으면 현재 셸의 변수를 정합니다. 자식 프로세스에 이 설정이 필요하다면 export WORD_LIMIT로 환경에 포함할 수 있습니다. 환경 변수는 실행할 프로그램에 넘기는 이름과 문자열 값입니다. 설정을 읽은 프로그램이 2를 정수로 사용하려면 스스로 바꿔야 합니다. WORD_LIMIT=2 command처럼 외부 명령 앞에 넣으면 그 실행의 환경에 값을 줄 수 있습니다.

Python에서는 subprocess.run(..., env=...)으로 자식이 받을 환경 사전을 전달할 수 있습니다. 아래 예에서는 현재 환경을 복사한 뒤 실습에 필요한 설정 한 개만 추가합니다. 부모의 환경을 그 자리에서 변경하지 않습니다. 새 프로세스가 내부의 환경 값을 바꾸어도 부모에게 변경이 자동으로 돌아오는 것은 아닙니다.

표준 출력과 오류를 다른 곳으로 보낼 수 있다

명령줄 프로그램은 흔히 표준 입력(stdin)으로 데이터를 읽고 표준 출력(stdout)으로 결과를 냅니다. 진단 메시지는 표준 오류(stderr)로 보낼 수 있습니다. A | B 형태의 기본 파이프는 A의 표준 출력을 B의 표준 입력으로 연결합니다. A의 표준 오류는 따로 리다이렉션하지 않으면 이 연결에 들어가지 않습니다.

Bash에서 printf '%s\n' ink book ink pen | sort | uniq -c는 단어 네 줄을 만들어, 정렬하고, 이어진 동일한 줄의 수를 셉니다. uniq -c 앞에서 정렬해야 떨어져 있던 두 ink 줄도 같은 묶음에 놓입니다. 셸의 리다이렉션 > file은 표준 출력을 파일로 보내며 기존 파일을 잘라 쓸 수 있습니다. >> file은 끝에 붙입니다. < file은 표준 입력을 파일에서 읽도록 연결하고 2> file은 오류 통로를 보냅니다. 쓰기 대상은 자기 연습용 파일처럼 내용을 바꿔도 되는 경로로 명확하게 정합니다.

Windows에서도 두 Python 프로세스 사이에 실제 파이프를 잇는다

예제에서 A의 출력은 네 단어가 들어 있는 줄입니다. B는 파이프로 들어온 줄의 빈도를 구하고, 전달받은 WORD_LIMIT 값으로 두 개만 골라 표시합니다. 그런 다음 stderr에 'processed 4'를 적습니다. 부모에서 stdout과 stderr를 각각 읽으면 결과와 진행 메시지를 구분할 수 있습니다.

import os
import subprocess
import sys

emit = "print('ink\\nbook\\nink\\npen')"
count = """
import os
import sys
from collections import Counter

words = sys.stdin.read().splitlines()
counts = Counter(words)
limit = int(os.environ["WORD_LIMIT"])
for word in sorted(counts)[:limit]:
    print(word, counts[word])
print("processed", len(words), file=sys.stderr)
"""
environment = dict(os.environ, WORD_LIMIT="2")
with subprocess.Popen([sys.executable, "-c", emit], stdout=subprocess.PIPE) as first:
    result = subprocess.run(
        [sys.executable, "-c", count], stdin=first.stdout, env=environment,
        capture_output=True, encoding="utf-8", check=True,
    )
    first.stdout.close()
    if first.wait() != 0:
        raise RuntimeError("producer failed")

print("stdout:", result.stdout.strip().replace("\n", " / "))
print("stderr:", result.stderr.strip())
stdout: book 1 / ink 2
stderr: processed 4

Python이 셸의 | 문장을 해석한 것은 아닙니다. 프로그램 A의 파이프에 연결된 출력을 B의 입력으로 직접 전달하도록 인자를 명시했습니다. 실제 스크립트에서는 전체 작업이 성공했는지 확인하려면 각 단계의 종료 상태를 살핍니다.
