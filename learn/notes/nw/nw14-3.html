네트워크 · NW14 TCP 스트림 설계와 상태

NW14·3

손실·재정렬·재전송을 앱의 완료 시각까지 이어 보기

손실이 복구돼도 앱이 기다릴 수 있는 시간을 넘겼을 수 있습니다. 가상의 전송 상태와 앱 파서가 각각 어느 시점에 진행하는지 잇습니다.

이 장을 읽고 나면

  • 바이트 구간의 순서와 프레임 경계를 구분한다.
  • 새 ACK와 같은 ACK가 타이머에 미치는 영향을 추적한다.
  • 같은 전송 완료를 앱의 서로 다른 마감으로 판정한다.

같은 프레임을 다른 구간에서 나눠 보냅니다

2바이트 길이와 본체의 규약으로 ‘CAT’(길이 3), ‘OK’(길이 2)를 순서대로 만듭니다. 총 길이는 9이며 전송 구간은 A=[0,3), B=[3,6), C=[6,9)입니다. A에는 첫 길이와 문자 C가 들어 있고, B에는 문자 A,T와 다음 길이의 첫 바이트가 들어 있습니다. C에는 다음 길이의 나머지와 OK가 들어 있습니다. 수신 TCP는 연속으로 받은 접두부만 앱에 내보내고, 앱은 길이와 바이트열로 프레임을 완성합니다.

처음 A,B,C를 모두 보낼 수 있는 창이 있다고 가정합니다. A는 10 ms에, C는 15 ms에 오지만 B는 사라집니다. 수신자는 C를 순서 밖 버퍼에 보관합니다. A로 연속 접두부가 3이 되지만 첫 본체는 한 바이트뿐이므로 앱의 완료 프레임은 0개입니다. C만 도착한 뒤에도 접두부는 3이라 앱에 더 전달하지 않습니다.

확인이 실제로 전진하는지 확인하고 타이머를 갱신합니다

초기 송신 시각은 0, 예제의 RTO는 30 ms입니다. 첫 만료 예정은 30입니다. 이 모형에서는 새 바이트를 확인했고 남은 미확인이 있으면 타이머를 다시 시작합니다. t=10의 ACK 3으로 기록이 전진했으므로 새 만료 예정은 10+30=40입니다. t=15의 ACK 3은 같은 번호라 이 예의 타이머를 바꾸지 않습니다. t=40에 가장 앞 미확인 구간 B를 재시도하고 RTO를 두 배로 해 다음 만료를 40+60=100으로 둡니다. t=45에 받은 B는 버퍼의 C와 이어져 ACK를 9로 바꿉니다. 모든 자료가 확인되어 만료 예정도 사라집니다.

이 모형은 ACK가 수신 시각에 즉시 도달하고, 같은 ACK 한 번으로 빠른 재전송하지 않으며, 두 번째 만료 이전에 복구된다고 둡니다. 실제 TCP의 RTO와 만료 뒤 배가는 NW11의 타이머 편에서 계산했습니다. 여기서는 송신·수신 상태와 연결된 앱의 완료 기준을 보는 것이 목적입니다.

전송의 성공과 사용자의 마감을 각각 판정합니다

수신 TCP가 t=45에 새 연속 부분 여섯 바이트를 제공하면 앱은 CAT과 OK 두 프레임을 처리할 수 있습니다. 요청이 첫 프레임을 44ms까지 요구했다면 채널의 최종 복구에도 불구하고 앱은 마감을 지키지 못합니다. 마감 46ms면 도착을 기다릴 수 있습니다. 실패로 재시도하는 앱은 원래 상태 변경 요청이 상대에게 이미 도착했을 가능성도 고려해야 합니다. 이 장은 응답 조각만 모의하고 앱이 요청을 처리했는지는 별도 정보로 남깁니다.

wire = bytes.fromhex("00 03 43 41 54 00 02 4f 4b")
pieces = {"A": (0, wire[:3]), "B": (3, wire[3:6]), "C": (6, wire[6:])}
pending = {}
stream = bytearray()
rto = 30
expiry = rto

def frames(data):
    results = []
    start = 0
    while start + 2 <= len(data):
        length = int.from_bytes(data[start:start+2], "big")
        end = start + 2 + length
        if end > len(data):
            break
        results.append(bytes(data[start+2:end]))
        start = end
    return results

for at, name in [(10, "A"), (15, "C"), (40, "retry"), (45, "B")]:
    if name == "retry":
        assert at == expiry
        rto *= 2
        expiry = at + rto
        print(at, "retransmit", "B", "timer", expiry)
        continue
    begin, piece = pieces[name]
    previous = len(stream)
    pending.update({begin+i: v for i, v in enumerate(piece)})
    while len(stream) in pending:
        stream.append(pending.pop(len(stream)))
    ack = len(stream)
    if ack > previous:
        expiry = None if ack == len(wire) else at + rto
    print(at, name, "ACK", ack, "timer", expiry, "frames", frames(stream))

for deadline in (44, 46):
    print("application deadline", deadline, "completed:", 45 <= deadline)

15 C ACK 3 timer 40 frames []
40 retransmit B timer 100
45 B ACK 9 timer None frames [b'CAT', b'OK']
application deadline 44 completed: False
application deadline 46 completed: True

코드의 프레임 함수는 정해 둔 9바이트 접두부가 어디까지 완성됐는지를 확인합니다. 프레임을 중복 전달하지 않는 실제 증분 동작과 저장 상한은 앞 장의 파서를 사용합니다. 이 결정적 실행에서는 시각을 직접 적어 모든 사건을 표의 순서와 대조할 수 있습니다.
