스위치 루프를 지우는 루트와 포트 역할 계산

스위치 세 대를 삼각형으로 잇더라도 사용자 프레임을 세 링크 모두로 보내야 하는 것은 아닙니다. 루트를 정하고 각 포트의 역할을 계산합니다.

이 장을 읽고 나면

  • 프레임을 넓게 보내는 동작이 순환 경로에서 어떤 문제를 만드는지 설명한다.
  • 루트 포트·지정 포트·대체 포트를 작은 망에서 선택한다.
  • 루트로의 최단 경로 트리와 가중치 전체가 최소인 트리를 구분한다.

경로가 여러 곳에서 다시 들어오는 문제를 줄입니다

NW07의 주소 학습에서 스위치는 들어온 프레임의 출발 MAC에 따라 출구를 배웁니다. 목적지 정보를 모를 때 같은 브리지 영역의 허용 포트로 프레임을 복제해 보낼 수 있습니다. 여분의 물리 링크가 순환을 만들고 모두 활성이라면 복제된 프레임이 다른 쪽에서 다시 들어옵니다. Ethernet의 일반 프레임에 IP처럼 라우터마다 하나씩 줄이는 홉 제한이 있는 것으로 가정할 수 없습니다. 이 순환은 같은 출발 주소가 서로 다른 포트에서 연달아 다시 학습되는 문제도 만들 수 있습니다.

스패닝 트리 계열은 교환한 제어 정보(BPDU)로 하나의 루트 쪽에 관계를 정하며, 논리적으로 순환 없는 전달 경로를 만들도록 여분 포트를 조정합니다. 여기서는 브리지 ID 순으로 A가 가장 작고, B, C가 뒤따르는 연결된 점대점 토폴로지입니다. 선출이 끝나 동일한 루트와 링크 비용을 모두 반영했다고 가정합니다.

루트 방향과 각 링크의 대표 방향을 구분합니다

루트가 아닌 브리지는 루트까지의 총비용이 가장 좋은 포트를 루트 포트로 고릅니다. B의 후보는 A로 직접 4, C를 거치는 경로는 1+5로 6이므로 A 쪽입니다. C는 B 쪽입니다. 각 점대점 링크에서는 더 좋은 루트 정보를 대표로 보내는 쪽이 지정 포트가 됩니다. 이 숫자에는 동률이 없습니다. A–C의 A 쪽은 루트 비용 0, C 쪽은 5입니다. A가 지정 포트가 되고 C는 이미 B 쪽을 루트 포트로 택했으므로 A 쪽의 대체 포트는 사용자 프레임 전달에서 차단됩니다. 현대 대표 규약에서 쓰는 상태 명칭은 discarding입니다.

동점인 실제 규약에서는 브리지 ID, 포트 식별자 등을 포함한 우선 벡터를 비교합니다. 아래 장난감 식은 비용 동점이 없는 경우만 추적합니다. 루트 포트를 따라 한 단계 움직일 때 양의 링크 비용만큼 루트까지의 남은 비용이 작아집니다. 한 바퀴를 돌아 원래 점으로 돌아오려면 그동안의 감소가 0이어야 하므로, 이런 방향의 선택에는 순환이 없습니다. 모든 비루트에 루트 포트 하나가 있다면 어떤 곳에서 시작해도 루트로 이어집니다.

트리가 만드는 목적은 루트까지의 길입니다. A–B와 A–C의 비용을 각각 3, B–C를 1이라고 바꾸면 루트 A까지 직접 가는 비용이 3, 우회하면 4입니다. 두 직접 링크를 살리는 루트 경로 트리의 간선 비용 합은 6입니다. 그래프 전체 간선 합만 최소화하는 트리의 값은 3+1=4가 될 수 있습니다. 둘의 최적화 기준이 다릅니다.

비용으로 결정되는 루트 포트와 남는 간선을 계산합니다

distance_to_root = {"A": 0, "B": 4, "C": 5}
links = [("A", "B", 4), ("A", "C", 6), ("B", "C", 1)]
port = {}
for node in "BC":
    candidates = []
    for u, v, cost in links:
        if node in (u, v):
            neighbor = v if node == u else u
            candidates.append((cost+distance_to_root[neighbor], neighbor))
    cost, parent = min(candidates)
    assert cost == distance_to_root[node] and distance_to_root[parent] < cost
    port[node] = parent
    print(node, "root via", parent, "cost", cost)

for u, v, _ in links:
    designated = min((u,v), key=lambda p: (distance_to_root[p], p))
    carrying = port.get(u) == v or port.get(v) == u
    print(u+v, "designated", designated, "data path", carrying)
B root via A cost 4
C root via B cost 5
AB designated A data path True
AC designated A data path False
BC designated B data path True

코드의 거리표는 그림에서 구해 넣었습니다. 실제 BPDU 교환을 구현한 것이 아니라 일치한 상태에서 포트 역할이 수식과 맞는지 확인합니다. 링크가 끊긴 직후의 전환 시간과 임시 상태는 이 정상 상태의 결과와 따로 측정합니다.
