IP 목적지와 가까운 링크의 MAC 주소 구분하기

내 컴퓨터가 보낸 인터넷 요청에는 목적지 IP와 첫 번째 링크의 MAC 주소가 함께 들어갈 수 있습니다. 가까운 서버와 먼 서버로 보내 보면서 두 주소가 왜 다른지 확인합니다.

이 장을 읽고 나면

  • 이더넷 프레임과 안에 실은 IP 패킷을 구분한다.
  • 같은 링크에 있는 목적지와 다음 라우터를 결정한다.
  • IPv4 ARP가 어느 주소를 찾는지 설명한다.

링크 안에서 전달하는 단위

이더넷에서 프레임 하나는 링크에서 보낼 데이터 단위입니다. 헤더에는 출발지와 목적지 MAC 주소가 들어가고 그 안에 IP 패킷을 실을 수 있습니다. IP 패킷의 목적지 주소는 통신하려는 끝 장치를 나타냅니다. 이더넷 프레임의 목적지 MAC은 지금 링크에서 먼저 받아야 할 장치를 나타냅니다. 라우터가 다음 링크로 보낼 때 그 링크의 주소와 규칙으로 다시 감쌉니다.

MAC 주소는 네트워크 인터페이스(랜카드, Wi-Fi 칩)에 붙은 48비트 링크 계층 주소로, 02:00:00:00:00:25처럼 16진수 두 자리씩 여섯 묶음으로 씁니다. 제조사가 넣는 주소는 앞 24비트가 IEEE가 제조사에 배정한 번호(OUI)입니다. 첫 바이트의 가장 낮은 비트가 1이면 여러 장치가 받는 그룹 주소이고, 모든 비트가 1인 ff:ff:ff:ff:ff:ff는 같은 링크의 모든 장치가 받는 브로드캐스트 주소입니다. 첫 바이트의 둘째 비트가 1이면 제조사 번호가 아니라 소프트웨어가 정한 주소(로컬 관리)이며, 요즘 휴대폰이 Wi-Fi마다 무작위로 바꿔 쓰는 MAC이 이런 주소입니다. 이 장의 02:… 주소도 이 표시가 붙은 예입니다. IP 주소가 망을 옮기면 바뀌는 것과 달리, MAC은 같은 링크 안에서 장치를 구별하는 데만 씁니다.

이더넷 프레임(Ethernet II)의 칸은 다음과 같습니다. 외우기

데이터 칸의 최대 1500바이트가 이더넷의 MTU(한 프레임에 실을 수 있는 최대 IP 패킷 크기)입니다. 실제 선 위에서는 프레임 앞에 동기를 맞추는 8바이트(프리앰블과 시작 표시)가 더 나가고, 프레임 사이에 12바이트 길이의 쉬는 간격을 둡니다.

연습에는 IPv4 하나와 이더넷 인터페이스 하나를 씁니다. 내 주소는 10.0.0.2/24, 기본 라우터는 10.0.0.1입니다. /24에서 10.0.0.37은 같은 연결 네트워크에 있습니다. 203.0.113.10은 문서 예시에 쓰는 주소이고 이 연결 네트워크에는 없습니다.

최종 IPv4 목적지다음으로 보낼 IPv4첫 링크에서 확인할 MAC
10.0.0.3710.0.0.37가까운 서버의 MAC
203.0.113.1010.0.0.1기본 라우터의 MAC

다음 IPv4를 알지만 MAC을 모를 때

ARP는 IPv4 주소와 링크의 하드웨어 주소를 연결합니다. 이더넷 예에서는 다음으로 받을 IPv4 주소를 넣은 ARP 요청을 같은 링크에 브로드캐스트합니다. 그 주소에 대응하는 장치가 자신의 MAC을 응답하면, 보낸 장치는 결과를 일정 시간 보관할 수 있습니다. 라우터를 넘어서 먼 서버의 MAC을 알아오는 과정은 이 예의 직접 전달 단계에 필요하지 않습니다. IPv6에서는 같은 일을 ICMPv6의 이웃 탐색(NDP)이 브로드캐스트 대신 멀티캐스트로 합니다.

ARP 응답은 요청한 장치에게만 보냅니다(유니캐스트). 보관한 대응표를 ARP 캐시라 하며, 항목은 일정 시간이 지나면 지워져 다시 묻게 됩니다. ARP에는 인증이 없어서 다른 장치가 거짓 응답을 보내 라우터 행세를 하는 공격(ARP 스푸핑)이 가능하다는 점도 알아 둡니다.

스위치는 MAC 주소를 배워 프레임을 골라 보낸다

오늘날 유선 이더넷은 장치들을 스위치에 한 선씩 연결합니다. 스위치는 프레임이 들어온 포트와 그 프레임의 출발지 MAC을 표(MAC 주소 테이블)에 적어 둡니다. 이것을 자기 학습이라 합니다. 프레임을 내보낼 때는 목적지 MAC을 표에서 찾아 그 포트로만 보내고, 표에 없거나 브로드캐스트 주소면 들어온 포트를 뺀 모든 포트로 내보냅니다(플러딩). 스위치는 IP 주소를 보지 않는 링크 계층 장치이고, 같은 스위치들로 이어진 장치 전체가 하나의 브로드캐스트 범위를 이룹니다. 라우터는 이 범위를 넘기지 않으므로, ARP 요청은 라우터 너머로 가지 않습니다.

from ipaddress import ip_address, ip_network

local = ip_network("10.0.0.0/24")
gateway = ip_address("10.0.0.1")
neighbors = {
    ip_address("10.0.0.1"): "02:00:00:00:00:01",
    ip_address("10.0.0.37"): "02:00:00:00:00:25",
}
for text in ("10.0.0.37", "203.0.113.10"):
    destination = ip_address(text)
    next_hop = destination if destination in local else gateway
    print(destination, "다음 IPv4", next_hop, "목적지 MAC", neighbors[next_hop])

실행 결과

10.0.0.37 다음 IPv4 10.0.0.37 목적지 MAC 02:00:00:00:00:25
203.0.113.10 다음 IPv4 10.0.0.1 목적지 MAC 02:00:00:00:00:01

코드는 인터페이스가 하나이고 기본 경로만 있는 설명용 표입니다. 실제 패킷이나 ARP 요청을 보내지 않습니다. 실제 시스템은 먼저 라우팅 테이블에서 가장 적절한 경로를 골라 어느 인터페이스와 다음 주소를 쓸지 정합니다. 경로가 없으면 위 코드처럼 언제나 기본 라우터를 찾을 수 있는 것은 아닙니다.

한 줄 정리

목적지 IP로 경로를 고르고, 지금 링크에서 받을 다음 장치의 MAC 주소로 프레임을 구성합니다.
