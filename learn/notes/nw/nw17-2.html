네트워크 · NW17 네트워크 성능 측정과 해석

NW17·2

같은 입력에 큐 한도만 바꾸고 차이를 보고하기

큰 큐가 손실을 줄인다는 가설과 지연을 늘릴 수 있다는 가설을 한 실험에서 따로 기록합니다. 조건을 고정한 네 합성 시나리오를 실행합니다.

이 장을 읽고 나면

  • 실험 단위와 통제 변수, 보고할 지표를 먼저 정한다.
  • 같은 입력의 대응 결과로 큐 한도의 차이를 계산한다.
  • 확정된 실행 결과와 다른 네트워크에 대한 결론의 범위를 구분한다.

무엇을 바꾸고 무엇을 그대로 비교할지 정합니다

실험 질문은 ‘같은 도착 패턴에서 큐 한도를 2개에서 4개로 바꾸면 고정된 관찰 구간의 전달과 응답 지연이 어떻게 달라지는가’입니다. 가상 출력 링크는 슬롯 하나(10 ms)에 100 B짜리 항목 하나를 처리합니다. 도착은 슬롯 처음, 수용 판정은 그 직후, 한 건의 처리 완료는 슬롯 끝입니다. 용량은 아직 처리하지 않은 항목을 센 값이며 그 슬롯에 곧 서비스할 항목도 포함합니다. 다른 전파 지연과 재전송은 이 모형에 없습니다.

항목마다 나중에 도착하는 것으로 시작 시간을 따로 두며, 바로 도착한 때부터 완료까지 비교합니다. 사용할 지표를 미리 정합니다. 80ms 동안 새로 완료한 100바이트로 유효 처리량을 계산하고, 완료 지연만으로 가까운 순위 p95를 구합니다. 각 항목이 큐에 온 뒤 30ms 이내에 완료하면 마감 내 성공입니다. 초기에 버린 항목도 마감 지표의 전체 분모에 남깁니다.

각 시나리오를 빈 큐부터 실행하고, 어느 한 큐가 앞 시나리오의 대기를 다음으로 가져가지 않게 합니다. 같은 시나리오를 두 다른 큐 한도에 사용하면 이 차이는 한 쌍의 결과입니다. 한 큐에 들어온 항목은 서로 대기를 늘릴 수 있어 여러 패킷을 여러 독립 실험으로 세지 않습니다. 이 네 입력은 정해 둔 대비적 사례이며 무작위로 모집단을 대표하게 뽑은 표본이 아닙니다.

빈자리와 대기 시간이 서로 반대로 움직일 수 있습니다

세 번째 입력 [3,2,0,1]의 시작에 세 항목이 한꺼번에 옵니다. 작은 큐는 첫 시점에 2개만 받고 1개를 버립니다. 다음 시점 기존 대기 1개에 새로 2개가 들어오므로 또 하나를 버립니다. 80ms까지 4개 완료이며 확인한 가장 느린 완료는 20ms입니다. 큰 큐는 같은 도착 6개를 전부 받아 처리하며, 완료 시각의 지연 표본은 [10,20,30,30,40,30]ms입니다. 30ms 이내 성공은 5이며 p95는 최댓값 40입니다.

기간 0.08초 동안 100바이트짜리 항목 4개를 완료하면 유효율은 4×100×8/0.08=40,000 bit/s입니다. 이 경우 큐 4가 더 많은 항목을 완료했지만 완료 항목 중 꼬리 지연도 커졌습니다. 이 결과는 ‘제시간에 성공하는 핵심 항목이 많은가’와 ‘완료한 항목의 가장 느린 쪽은 얼마인가’를 함께 보고해야 해석할 수 있습니다.

시나리오 장부와 한 쌍씩의 변화량을 출력합니다

from collections import deque
from statistics import mean
from math import ceil

scenarios = [(1,1,1,1), (4,0,0,0), (3,2,0,1), (2,0,4,0)]

def run(arrivals, capacity):
    queue = deque()
    delays = []
    drops = 0
    for tick in range(8):
        incoming = arrivals[tick] if tick < len(arrivals) else 0
        admitted = min(incoming, capacity-len(queue))
        queue.extend([tick] * admitted)
        drops += incoming-admitted
        if queue:
            delays.append((tick+1-queue.popleft()) * 10)
    assert len(delays)+drops+len(queue) == sum(arrivals)
    p95 = sorted(delays)[ceil(.95*len(delays))-1] if delays else None
    return len(delays), drops, p95, sum(d <= 30 for d in delays), 10_000*len(delays)

deltas = []
for number, trace in enumerate(scenarios, 1):
    small, large = run(trace, 2), run(trace, 4)
    print(number, small, large)
    deltas.append(large[-1]-small[-1])
print("mean paired change bps:", mean(deltas))
1 (4, 0, 10, 4, 40000) (4, 0, 10, 4, 40000)
2 (2, 2, 20, 2, 20000) (4, 0, 40, 3, 40000)
3 (4, 2, 20, 4, 40000) (6, 0, 40, 5, 60000)
4 (4, 2, 20, 4, 40000) (6, 0, 40, 5, 60000)
mean paired change bps: 15000

출력 튜플의 순서는 완료, 손실, p95(ms), 마감 내 성공, 유효율(bit/s)입니다. 대응 차이는 [0,20,000,20,000,20,000]이라 네 장부 평균은 15,000 bit/s입니다. 새 네트워크를 일반화하려면 다른 도착 패턴, 서비스 속도, 큐 관리, 경로와 시작 시점에서 결과를 반복해 봅니다. 이 결과표로 원인을 비교할 수 있는 범위는 위에서 고정한 모형입니다.
