HTTP/2에서 섞어 보내고 TCP에서 함께 기다리는 경우

HTTP/2도 요청들을 한 연결에 섞어 보낼 수 있습니다. 앞 바이트의 손실이 같은 TCP 연결 위의 다른 요청에도 미치는 영향을 두 스트림의 완료 시간으로 봅니다.

이 장을 읽고 나면

  • HTTP/2 프레임의 다중화와 TCP 전달 순서를 구분한다.
  • 연결의 바이트 순서와 스트림별 바이트 순서에서 완료 시각을 계산한다.
  • 한 요청의 개선과 모든 요청 완료의 차이를 비교한다.

한 연결의 프레임을 여러 요청으로 나눕니다

HTTP/2는 요청·응답의 데이터를 이진 프레임으로 쪼개 스트림 식별자를 붙입니다. 한 연결에서 스트림 A와 B의 프레임을 섞어 보낼 수 있습니다. 수신 HTTP 계층은 프레임의 식별자를 읽어 각 스트림으로 보냅니다. 이러한 멀티플렉싱 덕분에 한 요청의 데이터 전체를 보내고야 다음을 시작할 필요는 없습니다.

한편 HTTP/2가 사용하는 TCP는 연속해서 받은 바이트 접두부를 위에 건넵니다. TCP 수준에서 앞쪽 번호에 빈칸이 생기면, 빈칸 뒤쪽의 바이트가 수신기에 들어와 있어도 HTTP 계층이 아직 읽지 못할 수 있습니다. 앞 데이터가 뒤 데이터의 전달을 가로막는 현상을 순서 제약 때문에 생기는 줄 앞막힘(head-of-line blocking)이라고 합니다.

A만 빠졌는데 B도 늦어지는 상황을 계산합니다

A에는 4바이트, B에도 4바이트가 있습니다. 그림의 TCP 모형에서 A 앞부분 [0,2)가 10 ms에 들어오고, A 뒤 [2,4)는 빠집니다. B 전체 [4,8)는 20 ms에 도착합니다. A의 빠진 바이트가 70 ms에 복구되기 전까지 TCP에서 위로 읽을 수 있는 접두 길이는 2입니다. A와 B를 모두 70 ms에 완성합니다. B의 자료 자체는 20 ms에 수신된 것과, 응답의 완료가 70 ms인 것을 구분합니다.

HTTP/3은 QUIC의 스트림을 사용합니다. QUIC은 같은 연결에 여러 순서 있는 스트림을 제공하지만 스트림마다 자체 바이트 오프셋을 씁니다. 같은 두 스트림과 도착 시각을 적용하면 A의 오프셋 2에서 빈칸이 생겨 A는 70 ms까지 기다립니다. B는 자기 오프셋 [0,4)가 20 ms에 모두 있으므로 B만 20 ms에 줄 수 있습니다. 이 예에서는 QPACK을 포함한 다른 의존성과 연결 설정 시간, 경로·송신 일정의 차이를 빼고 순서 제약만 비교합니다.

모두 끝난 시각 max(A,B)는 두 사례 모두 70 ms입니다. 두 응답의 평균 완료 시각은 TCP 모형 70 ms, QUIC 모형 (70+20)/2=45 ms입니다. 중요한 응답이 B라면 이용자에게 보이는 차는 50 ms입니다. 같은 사고 실험이어도 무엇이 빨라졌다고 말할지는 결과 지표에 달려 있습니다.

같은 사건으로 두 순서 제약을 적용합니다

events = [(10, "A", 0, 0, 2), (20, "B", 0, 4, 4), (70, "A", 2, 2, 2)]
tcp_bytes = set()
per_stream = {"A": set(), "B": set()}
tcp_done, quic_done = {}, {}
for at, stream, offset, global_offset, count in events:
    tcp_bytes.update(range(global_offset, global_offset + count))
    per_stream[stream].update(range(offset, offset + count))
    for label, required in (("A", 4), ("B", 8)):
        if set(range(required)) <= tcp_bytes:
            tcp_done.setdefault(label, at)
        if set(range(4)) <= per_stream[label]:
            quic_done.setdefault(label, at)

for name, result in (("TCP", tcp_done), ("QUIC", quic_done)):
    times = [result[key] for key in ("A", "B")]
    print(name, times, "mean/max:", sum(times)/len(times), max(times))
TCP [70, 70] mean/max: 70.0 70
QUIC [70, 20] mean/max: 45.0 70

코드는 스트림당 본체 한 개와 미리 아는 각 경계만 모델링합니다. 실제 QUIC에서 패킷 하나가 여러 스트림의 자료를 담으면 그 패킷의 손실로 둘이 동시에 기다릴 수 있습니다. 다음 장에서 연결 전체가 공유하는 제약과 헤더 복호화 의존성을 살펴봅니다.
