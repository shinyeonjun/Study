해시·암호화·서명과 인증·인가의 역할 비교하기

전송 내용을 감출지, 바뀌었는지 확인할지, 누가 보냈는지 확인할지는 다른 질문입니다. 작은 메시지와 공유 비밀의 예로 구별합니다.

이 장을 읽고 나면

  • 해시·암호화·메시지 인증·디지털 서명을 구분한다.
  • 확인하려는 각 속성에 필요한 정보를 설명한다.
  • 인증과 인가를 작은 웹 업무에 적용한다.

일반 해시는 메시지와 함께 새로 계산해 바꿀 수 있으므로, 메시지에 붙은 해시만으로 누가 보냈는지 알 수 없습니다. 원본 파일의 해시를 믿을 수 있는 별도 경로에서 받았다면 내려받은 파일의 해시와 비교할 수 있습니다. 서로 다른 데이터가 같은 해시를 낼 수 있다는 한계도 있어서, 용도에 맞는 검증된 해시 알고리즘을 씁니다.

공유 비밀이 있는 두 장치

두 장치가 같은 비밀을 사전에 가진 경우, HMAC은 그 비밀과 메시지를 결합해 인증 값을 계산합니다. 수신자는 받은 메시지로 같은 계산을 한 뒤 비교합니다. 두 장치는 모두 같은 비밀을 쓰므로 어느 장치가 값을 생성했는지 제삼자에게 구분해 증명하는 디지털 서명과는 용도가 다릅니다. HMAC 자체가 내용을 숨기거나 같은 메시지의 반복 전송을 자동으로 제한하는 것도 아닙니다.

import hashlib
import hmac

example_key = b"example-key"
original = b"order:16"
changed = b"order:17"

digest = hashlib.sha256(original).hexdigest()
original_tag = hmac.digest(example_key, original, "sha256")

def verifies(message, tag):
    expected = hmac.digest(example_key, message, "sha256")
    return hmac.compare_digest(expected, tag)

print("SHA-256 바이트 수:", len(bytes.fromhex(digest)))
print("원본 메시지:", verifies(original, original_tag))
print("바뀐 메시지:", verifies(changed, original_tag))

실행 결과

SHA-256 바이트 수: 32
원본 메시지: True
바뀐 메시지: False

누구인지와 무엇을 할 수 있는지를 차례로 확인한다

학습 사이트에 로그인할 때의 인증은 요청한 사용자가 어떤 계정인지 확인하는 일입니다. 계정이 문서를 읽거나 편집할 수 있는지 결정하는 것은 인가입니다. 읽기 전용 계정의 신원을 확인했어도 편집 권한을 주지 않을 수 있습니다. 서버는 보호해야 하는 자원에 대한 요청에서 권한 규칙을 적용합니다.

TLS에서 서버를 인증하는 일과 학습 사이트의 사용자가 로그인하는 일도 구별합니다. 서버 인증서는 서버와의 연결을 확인하고, 응용에서 계정 세션과 권한은 별도의 규칙을 따릅니다.
