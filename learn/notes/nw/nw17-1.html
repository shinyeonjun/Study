NW17·1

RTT·손실·유효 처리량의 분모와 끝 시각 맞추기

같은 자료에서 패킷 손실률, 제시간에 끝나지 않은 비율, 성공한 응답의 지연을 얻습니다. 분모가 무엇인지 먼저 정하면 숫자가 맞물립니다.

이 장을 읽고 나면

  • 측정 계층·대상·시간창을 먼저 정의한다.
  • 패킷 손실률과 앱의 마감 미완료율을 따로 구한다.
  • 성공 표본의 백분위수와 유효 처리량을 계산하고 제한을 설명한다.

시작점과 끝점을 먼저 정합니다

RTT는 요청을 보내고 그에 대응하는 반응이 돌아오기까지 걸린 왕복 시간입니다. 시계 하나에서 두 시각을 기록하고, 반응이 어느 요청에 속하는지 연결해야 합니다. 앱이 응답을 만들기 위해 기다리는 시간이 포함된 경우에는 링크 전파 지연만의 측정이 아닙니다. 다른 두 시계의 시각을 그냥 빼는 한 방향 지연과도 조건이 다릅니다.

이번 합성 실험의 항목 A~E는 각 1,000 유용 바이트이며 공통 시작점은 t=0입니다. 전송 기록에는 첫 시도 다섯 개와 B의 재시도 한 개가 있습니다. 모델은 B의 첫 시도와 E의 시도가 전달되지 않았다고 표시합니다. 앱에서는 A가 20 ms, 재시도한 B가 50 ms, C가 80 ms에 완료됩니다. D는 105 ms에 완료되고 E는 이 실행에서는 끝나지 않습니다. 이 완료 지연은 별도로 실행한 RTT 측정과 구분합니다.

패킷의 실패, 업무의 실패, 성공한 항목의 지연을 구분합니다

송신 시도 여섯 개 중 두 개에서 패킷이 손실됐으므로 시도 손실률은 2/6입니다. 앱의 100 ms 마감까지는 총 다섯 항목 중 두 개가 미완료라 미완료율은 2/5입니다. D처럼 마감 이후에 도착한 항목을 ‘패킷이 물리적으로 사라졌다’고 분류하지 않습니다. 이 예에서 시도 손실 여부는 시뮬레이터가 알고 있는 값입니다. 실제 송신 쪽에서 응답을 관측하지 못했다면 결과에는 늦은 응답, 응답 경로 손실, 측정 종료 등도 섞였을 수 있습니다.

마감 내 성공한 표본만 놓고 초기 순위를 1로 세는 가까운 순위(nearest rank) 백분위수를 구합니다. 값이 n개면 p에 대해 ⌈pn⌉ 위치를 읽습니다. 세 값 [20,50,80]에서 p50은 2위인 50 ms, p95는 3위인 80 ms입니다. ‘완료자 중 p95=80’은 미완료 둘을 포함한 전체 응답의 p95를 뜻하지 않습니다. 표본 수가 작을수록 높은 분위수는 표본의 가장 큰 값과 같아지기 쉽습니다.

유효 처리량은 정한 구간에 도착한 새 앱 바이트를 구간의 길이로 나눈 값입니다. 0~100 ms 동안 새로 완료한 앱 바이트는 A,B,C의 3,000입니다. 이미 완료한 바이트의 복사본, 헤더, 늦게 도착한 D는 이 구간의 분자에 넣지 않습니다. 3,000×8/0.1=240,000 bit/s입니다. 같은 기간의 링크 부하를 구할 때는 재전송 시도나 헤더 등 목적에 맞는 다른 바이트들을 셉니다.

같은 기록에서 분모를 바꾸어 세 값을 계산합니다

from fractions import Fraction as F
from math import ceil

outcomes = {"A": 20, "B": 50, "C": 80, "D": 105, "E": None}
attempt_delivered = [True, False, True, True, True, False]
limit_ms = 100
timely = sorted(t for t in outcomes.values() if t is not None and t <= limit_ms)
def quantile(values, p):
    return values[ceil(p * len(values)) - 1] if values else None

print("attempt loss:", F(attempt_delivered.count(False), len(attempt_delivered)))
print("deadline misses:", F(len(outcomes)-len(timely), len(outcomes)))
print("complete sample p50/p95:", quantile(timely, .5), quantile(timely, .95))
print("goodput bps:", F(len(timely)*1000*8*1000, limit_ms))
echo = [(0,16), (12,31), (25,None), (60,94)]
print("observed RTT:", [arrival-start for start,arrival in echo if arrival is not None])
attempt loss: 1/3
deadline misses: 2/5
complete sample p50/p95: 50 80
goodput bps: 240000
observed RTT: [16, 19, 34]

RTT의 세 값은 별도 모의 반향 요청 묶음입니다. 네 요청 중 하나는 시각을 얻지 못했다는 상태를 함께 남깁니다. 다음 장에서는 여러 시나리오마다 이 같은 분모와 시각을 고정해 큐 설정만 비교합니다.
