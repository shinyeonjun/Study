브라우저로 웹 요청을 관찰하고 API 값 읽기

한 주소를 열었어도 브라우저는 문서와 꾸밈 파일, 코드 등 여러 자료를 읽어 옵니다. 네트워크 기록에서 어느 요청의 결과를 보고 있는지 찾고, 내가 만든 작은 서버에서 JSON 응답을 받아 봅니다.

이 장을 읽고 나면

  • 브라우저에서 문서와 추가 파일 요청을 찾는다.
  • 한 요청의 주소·메서드·상태·헤더·본문을 확인한다.
  • 로컬 API에 요청을 보내 JSON 데이터로 해석한다.

문서 한 장과 요청 한 개를 구별한다

이 교재 페이지를 열면 맨 먼저 HTML 문서를 받습니다. HTML에는 꾸밈을 담당하는 CSS와 목차를 계산하는 JavaScript를 읽으라는 내용이 들어 있습니다. 따라서 주소창에서 한 번 이동했더라도 아래처럼 여러 항목이 남을 수 있습니다.

브라우저의 개발자 도구에서 Network(네트워크) 탭을 열고, 열린 상태에서 이 교재를 새로고침합니다. 요청을 이름이나 주소로 찾아봅니다. 먼저 현재 문서의 항목을 열어 메서드와 상태를 읽고, 그 뒤 notes.js를 골라 자료가 별도로 불리는지 확인합니다. 브라우저가 파일을 미리 받아 놓았다면 캐시에서 제공됐다고 표시될 수 있습니다.

화면에서 찾는 것관찰할 질문
이름·URL지금 보고 있는 항목은 문서인가, 스크립트인가?
Method·StatusGET으로 요청했는가? 어떤 상태가 찍혔는가?
Headers서버와 브라우저가 알아들을 자료 형식은 무엇인가?
Response실제로 받은 데이터는 HTML, JavaScript, JSON 중 무엇인가?
Timing보내기와 기다리기, 내려받기 등 어느 단계에서 시간이 들었는가?

관찰 단계마다 항목을 지정합니다. 예를 들어 문서는 200이어도 뒤이어 읽는 파일 하나가 404일 수 있습니다. 목록이 이상할 때 페이지 한 줄의 상태뿐 아니라 기능에 필요한 요청 항목을 확인합니다.

프로그램끼리 쓰는 약속을 지정한다

API는 프로그램에서 다른 코드나 서비스에 일을 요청하는 방식과 결과를 사용하는 방법을 정한 접점입니다. 웹 API에서는 요청 경로·메서드·입력과 응답의 상태·데이터 형식 등을 약속합니다. 이 장의 API에서 GET /api/summary는 노트 수를 조회하며, 성공하면 JSON의 count 항목에 정수를 담습니다.

JSON은 프로그램이 구조를 알아보기 쉬운 텍스트 자료 형식입니다. 웹 API가 항상 JSON을 쓰는 것은 아닙니다. 응답의 Content-Type을 확인한 뒤 본문을 해석합니다. 상태 200만 보고 count가 반드시 있다고 가정하면, 다른 형식이나 변경된 응답이 왔을 때 확인할 근거가 없습니다.

같은 컴퓨터에서 실제 요청을 만들어 본다

아래 코드는 Python 표준 라이브러리만 씁니다. 127.0.0.1은 지금 프로그램이 실행된 컴퓨터만 가리킵니다. 포트 자리에 0을 넣어 운영체제가 사용하지 않는 포트를 정합니다. 같은 컴퓨터에서 접속할 뿐이며 외부 사이트의 상태나 인터넷 연결에 따라 결과가 바뀌지 않습니다.

from http.client import HTTPConnection
from http.server import BaseHTTPRequestHandler, HTTPServer
from threading import Thread
import json

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path != "/api/summary":
            self.send_response(404)
            self.end_headers()
            return

        body = json.dumps({"count": 2}).encode("utf-8")
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, format, *args):
        pass

with HTTPServer(("127.0.0.1", 0), Handler) as server:
    worker = Thread(target=server.serve_forever)
    worker.start()
    client = HTTPConnection("127.0.0.1", server.server_port, timeout=3)
    try:
        for path in ("/api/summary", "/absent"):
            client.request("GET", path)
            response = client.getresponse()
            body = response.read()
            print(path, response.status)
            if response.status != 200:
                continue
            media_type = response.headers.get_content_type()
            if media_type != "application/json":
                raise ValueError("JSON 응답을 기대했습니다.")
            data = json.loads(body)
            if not isinstance(data, dict) or type(data.get("count")) is not int:
                raise ValueError("count가 정수여야 합니다.")
            print(media_type)
            print("노트 수", data["count"])
    finally:
        client.close()
        server.shutdown()
        worker.join()

실행 결과

/api/summary 200
application/json
노트 수 2
/absent 404

먼저 서버의 do_GET이 요청 대상을 읽습니다. self.path에는 쿼리가 있을 때 그 부분도 함께 들어옵니다. 이 예제에서는 예약한 문자열 /api/summary와 같으면 응답을 만들고, 다른 요청 대상에는 404를 돌려줍니다. 클라이언트는 200 응답의 자료 형식이 JSON인지 확인한 뒤 본문을 읽습니다. 읽은 JSON은 객체여야 하고 count는 정수여야 값을 사용합니다. 마지막에는 연결과 서버를 닫습니다.

이 작은 예제에서는 실행할 때 서버와 요청 기능을 한 파일에 두었습니다. 역할은 여전히 각각 서버와 클라이언트입니다. 나중에 소켓 프로그래밍에서는 프로그램이 서로 데이터를 보내는 연결 자체를 다룹니다.

한눈에 정리

  • Network 화면에서 요청 하나를 골라 주소·메서드·상태·헤더·본문을 함께 읽는다.
  • 웹 API는 요청 방법과 응답 형태를 프로그램 사이에 함께 정하는 약속이다.
  • 작은 로컬 서버에 요청을 보내도 HTTP의 메서드, 상태, 자료 형식을 확인할 수 있다.
