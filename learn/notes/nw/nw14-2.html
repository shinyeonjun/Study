NW14·2

반쪽 종료·정상 EOF·응답 전체 마감을 상태에 기록하기

쓰기 방향의 종료와 읽기 방향의 종료는 함께 일어날 필요가 없습니다. 타임아웃도 바이트열의 끝과 구별해야 합니다.

이 장을 읽고 나면

  • 읽기 방향과 쓰기 방향에서 끝을 나타내는 사건을 구분한다.
  • 프레임 중간의 EOF와 프레임 사이의 EOF를 구별한다.
  • 읽기 한 번의 대기 한도와 전체 응답 마감이 다른 결과를 계산한다.

쓰기 방향을 끝내고도 반대 방향에서 응답을 읽을 수 있습니다

TCP는 두 방향의 순서 있는 바이트열을 제공합니다. 예를 들어 요청 쪽이 몇 프레임을 쓰고 더 보낼 것이 없음을 정상적으로 알리는 일을 반쪽 종료(half-close)라고 합니다. 이 방향에서 데이터가 끝나도 반대 쪽은 응답을 보낼 수 있습니다. Python 소켓에서 shutdown(SHUT_WR)은 쓰기 방향을 닫는 동작입니다. 일반적으로 이미 보낸 요청이 끝나면 그 방향의 FIN이 오고, 상대는 FIN보다 작은 순서 번호에 해당하는 바이트를 모두 읽은 뒤에 EOF를 읽습니다.

두 방향을 따로 보면 상태를 (쓰기 가능, 읽기 EOF 수신)처럼 적을 수 있습니다. 요청 쪽이 쓰기를 끝낸 직후에는 (아니오, 아니오)입니다. 응답 쪽에서 오는 마지막 바이트와 EOF를 읽고 나면 (아니오, 예)입니다. EOF 전에 응답 쪽이 프레임 전체를 보냈는지는 앱 규약으로 확인합니다. recv(n)에서 n이 양수이고 정상 끝에서 반환된 빈 바이트 b''는 읽을 스트림의 끝을 뜻합니다. 예외로 보고된 타임아웃이나 연결 오류는 그 신호와 구분합니다.

프레임의 진행 상태에서 EOF를 판정합니다

길이 헤더가 본체 3을 설명하고 이미 A,B 두 바이트를 받았는데 읽기 EOF가 오면 기록은 잘렸습니다. ABC를 모두 반환하고 다음 헤더가 비어 있는 상태에서 EOF가 오면 정상 끝입니다. 여기서 EOF가 정상이라는 것은 프레이밍 관점입니다. 앱 규약이 응답 프레임을 반드시 한 개 요구했다면 빈 상태의 EOF라도 ‘응답 누락’을 앱에서 별도로 판정합니다. 프레임 파서의 불변식과 앱에서 필요한 응답의 종류를 각각 확인합니다.

조금씩 도착해도 총 시간은 늘어날 수 있습니다

길이 3인 프레임의 조각이 요청 시작 t=0 뒤 12,31,51 ms에 도착한다고 합시다. 읽을 때마다 25ms만 기다린다면 각각의 대기는 12,19,20ms로 모두 통과합니다. 그래도 마지막 바이트는 시작 51ms 뒤에 도착합니다. 앱의 전체 마감이 45ms라면 프레임을 다 받지 못한 채 시간이 끝납니다. 같은 문제에서 ‘지금부터 몇 초 기다릴지’와 ‘처음부터 정한 시각까지 얼마 남았는지’는 서로 다릅니다.

진행을 유지하면서 다음 읽기의 최대 시간을 정하려면 현재까지 흐른 시간을 마감 시각에서 뺍니다. 31ms에 일부를 받은 다음에는 마감까지 14ms입니다. 새로 25ms를 전부 주면 원래 마감을 넘길 수 있습니다. 이 장에서는 마감과 같은 시각의 도착은 허용한다고 정합니다. 타임아웃에서 기존 수신 자료를 버릴지, 상태를 보존한 채 더 늦게 재시도할지는 앱 규약과 실패 처리에서 정합니다.

가상 시각으로 두 규약을 비교합니다

events = [(12, bytes([0])), (31, bytes([3]) + b"A"), (51, b"BC")]

def outcome(deadline):
    clock = 0
    accumulated = b""
    for at, fragment in events:
        stop = clock + 25
        if deadline is not None:
            stop = min(stop, deadline)
        if at > stop:
            return "timeout", stop, len(accumulated)
        accumulated += fragment
        clock = at
    size = int.from_bytes(accumulated[:2], "big")
    assert len(accumulated[2:]) == size
    return "complete", clock, accumulated[2:]

print("per read only:", outcome(None))
print("with deadline:", outcome(45))
for body in (b"ABC", b"AB"):
    print(body, "clean EOF" if len(body) == 3 else "truncated at EOF")
per read only: ('complete', 51, b'ABC')
with deadline: ('timeout', 45, 3)
b'ABC' clean EOF
b'AB' truncated at EOF

마감에서 출력한 3은 이미 읽은 전체 바이트 수이며 헤더 2와 본체 1을 포함합니다. 정상 EOF와 잘린 프레임은 길이를 알고 있는 본체의 별도 예입니다. 실제 소켓 관찰은 NW09의 종료·타임아웃에서 기본 반환을 다룹니다.
