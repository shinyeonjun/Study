네트워크 · NW11 신뢰 전송의 상태 기계

NW11·1

확인이 사라져도 한 번만 전달하는 번갈이 비트

송신자는 확인을 못 받으면 다시 보냅니다. 수신자는 같은 자료가 다시 도착했는지 상태로 판단하고, 이미 전달한 자료의 확인을 다시 보냅니다.

이 장을 읽고 나면

  • 정지 후 대기 방식의 송신 상태와 수신 상태를 분리한다.
  • 데이터 손실과 확인 응답 손실을 각각 추적한다.
  • 전달의 안전성과 결국 진행하는 조건을 구분한다.

두 장치가 같은 사실을 알고 있는지 구분합니다

연결 위에서 A와 B라는 기록 두 개를 순서대로 넘기는 합성 프로토콜을 만듭니다. 정지 후 대기(stop-and-wait)는 기록 하나를 보내고 그 기록의 확인이 올 때까지 새 기록을 보내지 않습니다. 첫 기록을 보낸 뒤 아무 응답이 없으면 두 상황이 가능합니다. 기록 자체가 사라졌거나, 기록은 전달됐지만 확인만 사라졌을 수 있습니다. 송신 타이머가 끝났다는 사실만으로 어느 상황인지 판정할 수 없습니다.

각 기록에 순번 비트 0 또는 1을 붙이고, 아직 확인을 못 받은 기록을 다시 보낼 때는 같은 비트를 붙입니다. 이 장의 ACK(b)는 ‘비트 b의 기록을 수락했다’는 확인입니다. TCP의 누적 ACK는 다음에 기대하는 번호이므로 뜻이 다릅니다. 송신자는 기다리는 비트와 맞는 확인을 받은 뒤 다음 기록의 비트를 바꿉니다. 수신자는 기대한 비트가 오면 앱에 기록을 전달하고 기대 비트를 바꿉니다.

중복은 전달을 건너뛰고 확인만 되풀이합니다

A(0)가 도착하고 ACK(0)만 사라졌다고 합시다. 수신자는 이미 A를 전달하여 1을 기대하고 있습니다. 송신자는 아직 A(0)를 기다리므로 타이머 만료에 같은 A(0)를 보냅니다. 수신자의 기대와 맞지 않아서 앱에 다시 전달하지 않고, ACK(0)만 다시 보냅니다. 이 ACK가 도착하면 송신자는 B(1)로 넘어갑니다. 이번에는 B(1) 자체가 사라지므로 수신 상태가 변하지 않습니다. 같은 비트로 재전송했을 때 수신자가 처음으로 B를 전달합니다.

사건송신자의 대기 비트수신자의 다음 기대앱에 누적 전달
A(0) 도착 · 첫 ACK 손실01A
A(0) 재도착 · ACK(0) 전달1로 진행1A
B(1) 첫 전송 손실11A
B(1) 재도착 · ACK(1) 전달0으로 진행0A, B

안전성을 살필 때는 불변식을 씁니다. 앱에 전달한 기록은 항상 원래 기록열의 접두부입니다. 한 세대에서 기대 비트와 맞는 자료를 처음 수락하면 접두부가 한 칸 늘고 기대 비트가 뒤집힙니다. 이 세대의 재전송은 그 뒤에 수락되지 않습니다. 송신자는 현재 기록이 수락됐다는 확인을 받아야 다음 기록을 내므로 전달 순서도 유지됩니다. 이 논증은 같은 비트를 다시 쓸 때 예전 세대의 데이터나 ACK가 뒤늦게 넘어오지 않는 채널을 전제합니다. 한 바퀴 전의 패킷이 임의로 오래 남을 수 있으면 비트 하나만으로 세대를 구분할 수 없습니다.

정해진 네 시도만 실행해 확인합니다

이 모형의 진행성은 기다리는 동안 재전송 기회가 계속 오고, 어느 시도에서는 기록과 맞는 ACK가 결국 도착하는 조건에 의존합니다. 채널이 계속 사라지는 메시지만 만들면 안전하게 멈춘 상태일 수 있습니다. 예제는 실제 시간을 기다리거나 통신을 열지 않고 네 사건을 순서대로 적용합니다.

expected = 0
waiting = 0
delivered = []
events = [
    ("A", 0, True, False),
    ("A", 0, True, True),
    ("B", 1, False, False),
    ("B", 1, True, True),
]
for name, bit, data_arrives, ack_arrives in events:
    assert bit == waiting
    if not data_arrives:
        result = "data lost"
    elif bit == expected:
        delivered.append(name)
        expected ^= 1
        result = "accepted"
    else:
        result = "duplicate"
    if data_arrives and ack_arrives:
        waiting ^= 1
    print(name, bit, result, "|", waiting, expected, "".join(delivered))
assert delivered == ["A", "B"]
A 0 accepted | 0 1 A
A 0 duplicate | 1 1 A
B 1 data lost | 1 1 A
B 1 accepted | 0 0 AB

waiting과 expected의 숫자가 첫 시도 뒤 서로 다릅니다. 데이터 수락과 확인 도착이 다른 사건이라 두 상태를 하나로 합치면 이 상황을 표현할 수 없습니다.
