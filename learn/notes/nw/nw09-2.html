소켓의 타임아웃과 수신 종료 구분하기

서버가 아무 바이트도 보내지 않을 때에는 기다림의 한도를 정해야 합니다. 수신 방향이 끝났을 때 그 신호와 대기 오류가 어떻게 다른지 실행해 봅니다.

이 장을 읽고 나면

  • 소켓의 수신 종료, 타임아웃, 길이 0 메시지를 구분한다.
  • 한쪽 쓰기를 끝낸 뒤 반대 방향으로 응답하는 과정을 설명한다.
  • 응용에서 시간 제한과 작업 결과를 기록하는 방법을 정한다.

recv가 비어 돌아온 것과 기다리다 실패한 것은 다르다

양의 길이로 요청한 TCP recv에서 결과가 b""이면, 정상적인 수신 스트림의 끝을 뜻합니다. 이미 받은 바이트가 있으면 먼저 돌려주고 그 뒤에 끝을 알려 줄 수 있습니다. 이와 달리 정해 둔 시간 안에 데이터를 읽지 못하면 예외가 납니다. 연결이 끝난 것인지, 잠시 응답이 늦은 것인지는 타임아웃 하나만으로 알기 어렵습니다.

받은 결과뜻예제의 행동
비어 있지 않은 bytes읽은 데이터의 일부필요한 길이까지 다시 읽음
b''더 받을 데이터가 없음정상 종료인지 중간에 잘렸는지 메시지 규칙으로 판정
TimeoutError설정한 대기 시간 초과정보를 기록하고 호출자의 조건에 따라 중단
ConnectionResetError상대가 RST로 연결을 비정상적으로 끊음(상대 프로그램이 읽지 않은 데이터를 남기고 죽거나 강제 종료)정상 종료(b'')가 아니므로 오류로 기록
ConnectionRefusedError (connect에서)그 주소·포트에서 기다리는 프로그램이 없어 상대 커널이 SYN에 RST로 답함서버가 떠 있는지, 포트가 맞는지 확인. Windows는 거부를 몇 번 다시 시도한 뒤(로컬에서 약 2초) 이 오류를 내므로, 그보다 짧은 시간 제한이면 TimeoutError로 보일 수 있다

나는 보냈고, 답은 계속 받을 수 있다

연결은 양방향입니다. 보내는 쪽의 shutdown(socket.SHUT_WR)는 그 방향으로 더 보낼 바이트가 없다고 알립니다. 다른 방향은 여전히 열려 있어 상대가 응답할 수 있습니다. 아래에서는 socketpair()로 만든 두 로컬 스트림을 씁니다. 운영체제에 따라 소켓의 주소 계열이 다를 수 있습니다. 이 장은 한 번의 요청에서 스트림의 끝으로 본문 끝을 표시하는 예입니다. 길이가 필요한 여러 메시지를 같은 연결에서 보내려면 앞 장처럼 별도 경계를 사용합니다.

import socket

def receive_to_end(connection):
    chunks = []
    while True:
        chunk = connection.recv(8)
        if chunk == b"":
            return b"".join(chunks)
        chunks.append(chunk)

client, server = socket.socketpair()
with client, server:
    client.settimeout(2)
    server.settimeout(2)
    client.sendall(b"AB")
    client.shutdown(socket.SHUT_WR)
    print("서버가 받은 요청:", receive_to_end(server))
    server.sendall(b"OK")
    server.shutdown(socket.SHUT_WR)
    print("클라이언트가 받은 응답:", receive_to_end(client))

reader, writer = socket.socketpair()
with reader, writer:
    reader.settimeout(0.05)
    try:
        reader.recv(1)
    except TimeoutError:
        print("열려 있지만 아직 받은 값 없음: 시간초과")

실행 결과

서버가 받은 요청: b'AB'
클라이언트가 받은 응답: b'OK'
열려 있지만 아직 받은 값 없음: 시간초과

시간 제한은 어떤 작업을 겨냥하는가

소켓 동작 하나에 적용한 시간 제한 때문에 메시지 전체가 꼭 같은 시간 안에 도착한다는 보장은 없습니다. 여러 번 읽는 동안 각각의 읽기가 조금씩 완료될 수 있기 때문입니다. 응용 전체의 마감이 필요하면 연결 시점과 제출 기한을 정해 그 안에 시도와 읽기를 끝냅니다. 응답을 못 받았어도 상대가 이미 요청을 처리했을 수 있으므로 같은 작업을 다시 요청할 때는 중복 처리 여부도 고려합니다. 여러 번 처리돼도 결과가 같은(멱등) 요청이면 다시 보내도 안전하고, 그렇지 않으면 요청마다 고유 번호를 붙여 상대가 중복을 걸러 내게 합니다.

한 줄 정리

빈 바이트 반환은 스트림에서 온 끝 표시이고, 시간초과는 설정한 시간 안에 해당 읽기를 완료하지 못했다는 뜻입니다.
