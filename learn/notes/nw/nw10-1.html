DNS·연결·TLS·HTTP 중 어느 단계에서 실패했는지 찾기

브라우저에 ‘열리지 않는다’고만 보이면 다음에 확인할 곳을 정하기 어렵습니다. 이름 조회 실패, 연결 실패, HTTPS 확인 오류와 404 응답을 나누어 봅니다.

이 장을 읽고 나면

  • 이름 조회와 연결 및 HTTP 상태를 구분한다.
  • 로컬에서 200과 404를 재현하고 응답을 본다.
  • 실패를 재현할 최소 기록을 정한다.

웹 요청을 확인할 순서

도메인 이름을 쓸 때는 주소를 알아내고 해당 주소·포트의 서비스에 연결합니다. HTTPS면 서버 인증과 보호된 연결 설정을 거친 뒤 HTTP 요청을 보냅니다. 주소가 이미 확인되어 있거나 연결을 다시 쓰는 경우에는 단계 일부를 재사용할 수 있습니다.

관찰한 결과먼저 확인할 곳단계만 따로 확인하는 도구 예
DNS가 이름 존재하지 않음을 알림주소 철자와 응답을 낸 해석기nslookup 이름, dig 이름(Windows PowerShell은 Resolve-DnsName)
연결 거부 또는 연결 시간초과지정 주소·포트의 서비스 상태와 연결 경로Test-NetConnection 주소 -Port 443, nc -vz 주소 443
TLS에서 서버 이름을 확인하지 못함URL의 이름, 인증서, 접속한 환경openssl s_client -connect 주소:443 -servername 이름, curl -v
HTTP 404 응답을 받음입력한 HTTP 경로, 메서드, 응답한 서버나 중간 서비스curl -i URL(상태 줄과 헤더 표시), 브라우저 Network 탭

DNS의 NXDOMAIN은 DNS 응답이 그 이름의 존재를 부정한 경우입니다. 질의가 아예 응답 없이 시간초과된 상황과 구분합니다. HTTP 404는 HTTP 응답을 받았음을 보여 줍니다. 서버가 해당 자원에 접근하지 않게 일부러 404를 반환할 수도 있으므로 상태 코드만으로 운영 원인을 전부 확정하기 어렵습니다.

연결 단계의 두 실패도 뜻이 다릅니다. 연결 거부는 패킷이 그 호스트까지 갔지만 그 포트에서 기다리는 프로그램이 없어 상대 운영체제가 RST로 즉시 답한 경우입니다. 연결 시간초과는 SYN에 아무 답도 오지 않은 경우로, 호스트가 꺼졌거나 경로가 끊겼거나 방화벽이 패킷을 조용히 버렸을 때 생깁니다. 거부는 “거기까지는 닿는다”는 정보를 주고, 시간초과는 어디서 막혔는지 더 찾아야 합니다.

같은 로컬 서비스에서 경로 둘을 비교한다

같은 컴퓨터에서 시험용 HTTP 서버를 만들고, 한 경로에 200, 나머지 경로에 404를 보냅니다. IPv4 루프백 주소를 직접 사용하므로 외부 DNS나 사이트에 요청하지 않습니다. 응답 상태와 본문을 함께 보면 존재하는 주소에서도 특정 경로는 실패할 수 있음을 확인합니다.

from http.server import BaseHTTPRequestHandler, HTTPServer
from threading import Thread
from urllib.error import HTTPError
from urllib.request import ProxyHandler, build_opener

class ExampleHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        status, body = (200, b"ready") if self.path == "/health" else (404, b"missing")
        self.send_response(status)
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, *args):
        pass

opener = build_opener(ProxyHandler({}))
with HTTPServer(("127.0.0.1", 0), ExampleHandler) as server:
    worker = Thread(target=server.serve_forever, kwargs={"poll_interval": 0.05})
    worker.start()
    try:
        for path in ("/health", "/report"):
            url = f"http://127.0.0.1:{server.server_port}{path}"
            try:
                with opener.open(url, timeout=2) as response:
                    print(path, response.status, response.read().decode())
            except HTTPError as response:
                with response:
                    print(path, response.code, response.read().decode())
    finally:
        server.shutdown()
        worker.join()

실행 결과

/health 200 ready
/report 404 missing

나중에 같은 상황을 찾아갈 기록을 남긴다

브라우저의 네트워크 탭으로 요청 경로, 메서드, 상태, 시각, 전체 시간을 확인할 수 있습니다. 토큰이나 개인 정보가 포함될 수 있는 헤더와 본문은 공유 전에 가립니다. 주소, 요청 시점, 실패 단계와 영향을 받은 요청만 적어도 같은 증상을 비교할 수 있습니다.
