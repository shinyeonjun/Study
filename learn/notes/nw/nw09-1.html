로컬 TCP 소켓에서 길이를 붙여 메시지 주고받기

서버와 클라이언트를 같은 컴퓨터에서 실행합니다. 문자열 하나를 보내고 돌려받으면서, TCP가 보장하는 바이트 순서와 프로그램이 직접 정할 메시지 경계를 구분합니다.

이 장을 읽고 나면

  • 서버의 대기 소켓과 연결 소켓을 구분한다.
  • TCP에서 recv의 한 번 반환과 메시지가 다른 이유를 설명한다.
  • 길이 머리말을 읽는 로컬 에코를 실행한다.

주소와 포트를 정해 연결한다

서버는 들어오는 연결을 받을 주소와 포트에 bind하고 listen합니다. 이 장은 자신의 컴퓨터에만 연결되는 IPv4 루프백 127.0.0.1을 씁니다. 포트에 0을 주면 운영체제가 사용 가능한 포트를 정합니다. 서버는 실제 포트를 getsockname()으로 읽고, 클라이언트는 그 주소와 포트로 연결합니다.

대기 중인 소켓에서 accept하면 이 클라이언트와 대화할 새 소켓을 얻습니다. 대기 소켓은 연결을 받는 데, 연결 소켓은 그 연결의 데이터를 주고받는 데 사용합니다. 소켓은 운영체제가 프로그램에 내주는 통신 끝점의 손잡이(파일 기술자와 비슷한 번호)이고, 실제 TCP 동작은 운영체제 커널이 합니다(SY04와 이어집니다).

socket()socket()TCP용(SOCK_STREAM) 또는 UDP용(SOCK_DGRAM) 소켓을 만든다

바이트 흐름에 메시지 경계를 넣는다

TCP는 순서가 있는 바이트 스트림을 전달합니다. 송신자가 한 번에 10바이트를 넣어도 수신자의 recv(10)은 한 번에 10을 넘겨준다는 약속이 없습니다. 반대로 송신 쪽에서 논리적으로 두 번 보낸 바이트가 한 읽기에서 같이 들어올 수 있습니다.

보내는 쪽도 마찬가지로, send는 넘긴 바이트 중 일부만 커널 버퍼에 넣고 그 개수를 돌려줄 수 있습니다. 남은 바이트를 다시 보내야 하는데, sendall은 이 반복을 대신 해 줍니다.

이 예에서는 처음 4바이트에 본문의 길이를 큰 자리 바이트부터 적은 정수(빅엔디언)로 적고 이어서 그 수만큼 읽습니다. 인터넷 프로토콜 헤더의 숫자도 모두 빅엔디언으로 적으므로 이 순서를 네트워크 바이트 순서라고 부릅니다. 예를 들어 길이 6은 00 00 00 06 네 바이트입니다. 한 글자가 여러 바이트일 수 있으므로 문자열을 UTF-8로 바꾼 뒤 바이트 수를 셉니다. ‘공부’의 UTF-8 본문은 6바이트이므로 보내는 단위는 4+6=10바이트입니다.

import socket
from concurrent.futures import ThreadPoolExecutor

MAX_MESSAGE = 64

def read_exact(connection, count):
    data = bytearray()
    while len(data) < count:
        chunk = connection.recv(min(count - len(data), 3))
        if not chunk:
            raise EOFError("메시지가 끝나기 전에 연결이 종료됐습니다.")
        data.extend(chunk)
    return bytes(data)

def send_message(connection, message):
    if len(message) > MAX_MESSAGE:
        raise ValueError("본문이 너무 깁니다.")
    connection.sendall(len(message).to_bytes(4, "big") + message)

def read_message(connection):
    length = int.from_bytes(read_exact(connection, 4), "big")
    if length > MAX_MESSAGE:
        raise ValueError("본문이 너무 깁니다.")
    return read_exact(connection, length)

def serve_once(listener):
    connection, _ = listener.accept()
    with connection:
        connection.settimeout(5)
        send_message(connection, read_message(connection))

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as listener:
    listener.bind(("127.0.0.1", 0))
    listener.listen(1)
    listener.settimeout(5)
    with ThreadPoolExecutor(max_workers=1) as executor:
        worker = executor.submit(serve_once, listener)
        with socket.create_connection(listener.getsockname(), timeout=5) as client:
            message = "공부".encode("utf-8")
            send_message(client, message)
            reply = read_message(client)
            assert reply == message
            print("본문 바이트:", len(message))
            print("되돌아온 문자열:", reply.decode("utf-8"))
        worker.result(timeout=7)

읽기 크기와 올바른 범위를 함께 정한다

이 실습은 한 번의 recv에서 최대 3바이트만 요청해 4바이트 머리말부터 계속 읽는 연습을 합니다. 받은 데이터에 적힌 길이를 그대로 신뢰하지 않고 최대 64바이트로 제한했습니다. 실제 응용에서도 메시지 규칙과 지원하는 크기를 함께 정합니다. 필요한 바이트 수를 다 받기 전에 연결이 끝나면 온전한 메시지가 아니라는 오류를 내보냅니다.

한 줄 정리

TCP는 바이트의 순서를 보존합니다. 응용은 길이 또는 별도 규칙을 정하고 그만큼 받을 때까지 읽습니다.
