NW12·1

링크 상태에서 최단 경로 트리와 다음 홉 만들기

모두에게 같은 지도가 도착하더라도 각 라우터가 시작하는 곳은 다릅니다. A가 자기 시작점에서 거리와 앞 노드를 계산해 전달 표를 만드는 과정을 추적합니다.

이 장을 읽고 나면

  • 링크 상태가 전파되는 과정과 로컬 최단 경로 계산을 구분한다.
  • 다익스트라의 후보 거리·확정 집합·앞 노드를 표로 갱신한다.
  • 경로 트리에서 다음 홉을 읽고 비용 변화 뒤 다시 계산한다.

각 링크의 상태를 공유하고 자기 위치에서 계산합니다

NW05에서 라우팅과 포워딩을 구분했습니다. 이제 라우팅 과정에서 전달 표의 근거가 만들어지는 방법을 계산합니다. 링크 상태 방식에서는 상대에게 ‘E까지 내가 아는 비용은 8이다’라고만 알리는 대신 자신이 연결된 링크와 비용을 광고합니다. 그 정보가 범위 안에 전파되면 각 라우터는 링크 상태 데이터베이스에서 그래프를 구성합니다. 서로 같은 그래프를 보더라도 각자 자기 위치를 시작점으로 최단 경로 트리를 계산합니다.

OSPFv2는 링크 상태 광고(LSA)를 사용하며, 광고 유형에 따라 전파 범위가 다릅니다. 여기서는 하나의 영역 안에서 다섯 라우터가 비용이 고정된 같은 양방향 지도를 받았다고 가정합니다. 비용은 합성 양의 정수이며, 실제 물리 지연을 직접 뜻하는 단위는 아닙니다. OSPF의 실제 그래프에는 라우터 외에 네트워크 정점도 있을 수 있고, 아래 다섯 정점 모형은 SPF 계산만 담습니다.

가장 작은 후보를 확정하고 그 이웃만 다시 비교합니다

후보 거리 d(v)는 지금까지 발견한 A→v 경로의 최소 비용입니다. 시작에서 d(A)=0이고 나머지는 아직 경로를 모른다는 뜻의 ∞입니다. 미확정 중 d가 가장 작은 u를 고른 뒤, 각 이웃 v에 대해 d(u)+c(u,v)<d(v)이면 d(v)와 그 앞 노드를 고치는 완화를 합니다. 먼저 A에서 B를 6, C를 2로 잡습니다. C 뒤에는 B가 2+1=3으로 좋아지고 D는 2+7=9입니다. B를 처리하면 D가 3+3=6으로 바뀌고 E가 3+9=12로 처음 나타납니다. D를 처리하면 E는 6+2=8로 내려갑니다.

확정 단계의 불변식은 ‘확정한 점의 거리가 실제 최단 비용’이라는 것입니다. 가장 작은 후보 u에 더 짧은 경로가 있다고 가정합니다. 그 경로가 확정 집합에서 처음 나갈 때의 정점 v를 잡습니다. v로 들어오는 링크는 이미 확정한 정점의 이웃이라 완화했습니다. 따라서 v의 후보는 더 짧다는 그 경로의 v까지 비용 이하입니다. 이후 링크의 비용이 모두 0 이상이므로, 그 접두 비용은 경로 전체 비용보다 커지지 않습니다. 그러면 v의 후보가 u 후보보다 작아져 u를 먼저 뽑았다는 가정과 충돌합니다.

앞 노드를 거슬러 시작점 바로 옆을 찾습니다

E의 앞 노드는 D, D의 앞 노드는 B, B의 앞 노드는 C, C의 앞 노드는 A입니다. A에서 E까지 경로는 A→C→B→D→E이고 A의 다음 홉은 바로 옆 C입니다. 중간 노드는 자기 위치에서 계산한 전달 표를 사용합니다. 해당 네트워크 접두사를 어떤 라우터가 제공하는지 붙인 뒤에야 IP 주소를 기준으로 한 전달 항목이 됩니다.

링크 한 개를 제거해 최단 경로 표를 다시 비교합니다

links = [("A", "B", 6), ("A", "C", 2), ("B", "C", 1),
         ("B", "D", 3), ("C", "D", 7), ("B", "E", 9), ("D", "E", 2)]

def shortest(edges):
    d = {v: float("inf") for v in "ABCDE"}
    prev = {}
    d["A"] = 0
    unseen = set(d)
    while unseen:
        u = min(unseen, key=lambda v: (d[v], v))
        if d[u] == float("inf"):
            break
        unseen.remove(u)
        for a, b, cost in edges:
            if u not in (a, b):
                continue
            v = b if u == a else a
            if v in unseen and d[u] + cost < d[v]:
                d[v], prev[v] = d[u] + cost, u
    if d["E"] == float("inf"):
        return list(d.values()), "unreachable"
    route = ["E"]
    while route[-1] in prev:
        route.append(prev[route[-1]])
    return list(d.values()), " ".join(reversed(route))

print("before:", *shortest(links))
print("after:", *shortest([e for e in links if e[:2] != ("B", "D")]))
before: [0, 3, 2, 6, 8] A C B D E
after: [0, 3, 2, 9, 11] A C D E

링크가 달라진 직후에는 모든 라우터가 새 지도를 같은 시간에 적용하지 않습니다. 여기서 앞과 뒤를 각각 계산한 값은 각 상태의 지도가 일치했을 때의 결과입니다. 아직 서로 다른 정보를 보고 있으면 잠깐 다른 다음 홉 결정을 내릴 수 있습니다.
