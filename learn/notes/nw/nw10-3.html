공부 교재

네트워크

NW10·3

한 연결의 패킷 시각과 웹 요청 시각 맞춰 읽기

한 연결의 일부를 시간순으로 관찰하면 연결 설정과 응답 기다림을 구분할 수 있습니다. 합성 기록으로 어느 수치까지 설명할 수 있는지 확인합니다.

이 장을 읽고 나면

  • 정상적인 TCP 연결 설정을 방향과 함께 읽는다.
  • 패킷 기록에서 연결과 첫 응답의 시간 간격을 계산한다.
  • 관측 위치와 필요한 헤더만 기록하는 이유를 설명한다.

어디에서 무엇을 관측한 기록인가

이 장의 표는 평문 HTTP를 쓰는 연습용 TCP 연결에서 클라이언트 한 곳이 관측한 합성 기록입니다. 실제 사람이나 외부 서버의 트래픽은 없습니다. 표는 상대 주소와 포트, 메시지 방향, 시각을 알면 평범한 요청 하나에서도 연결 설정과 요청 처리 구간을 나눠 읽을 수 있음을 보여 줍니다.

클라이언트에서의 시각(ms)방향관찰
0클라이언트 → 서버SYN
12서버 → 클라이언트SYN + ACK
13클라이언트 → 서버ACK
15클라이언트 → 서버HTTP 요청
31서버 → 클라이언트HTTP 응답의 첫 바이트

SYN은 새 연결의 동기화 요청이고 ACK는 받은 정보를 확인하는 표시입니다. 이 예에서는 클라이언트 SYN으로 연결을 시작한 뒤 서버가 SYN과 ACK를 함께 보내고, 클라이언트가 ACK를 돌려줍니다. 실제 관측에서는 마지막 ACK에 이어 데이터가 아주 가까운 시각에 나갈 수도 있습니다. 그림의 행 간격은 설명을 위한 배치입니다.

연결 설정과 요청 이후의 대기 시간을 구한다

첫 SYN을 보낸 때부터 SYN+ACK가 돌아올 때까지 12ms입니다. 같은 관찰점에서 HTTP 요청을 보낸 15ms부터 첫 응답이 도착한 31ms까지는 16ms입니다. 이 16ms에는 응답을 만드는 시간과 왕복 과정이 함께 포함될 수 있습니다. 한쪽 기록만으로 서버의 내부 작업 시간은 구분할 수 없습니다.

events = {
    "syn_out": 0,
    "syn_ack_in": 12,
    "ack_out": 13,
    "request_out": 15,
    "first_response_in": 31,
}
assert list(events.values()) == sorted(events.values())
handshake_reply = events["syn_ack_in"] - events["syn_out"]
request_reply = events["first_response_in"] - events["request_out"]
print("SYN의 응답:", handshake_reply, "ms")
print("요청부터 첫 응답:", request_reply, "ms")

실행 결과

SYN의 응답: 12 ms
요청부터 첫 응답: 16 ms

기록의 누락과 개인정보를 함께 생각한다

캡처가 연결 이후에 시작했다면 SYN이 기록에 없는 것이 정상입니다. 연결을 재사용하는 요청에서도 새 핸드셰이크가 없습니다. HTTPS가 TCP로 전송되는 연결이라면 TCP 헤더와 시각은 볼 수 있지만, 동일한 방식으로 보호된 HTTP 본문까지 읽을 수는 없습니다. 진단에 필요한 시간·방향·상태 등 최소 항목만 보고하면 토큰과 개인 정보를 공유하지 않고도 여러 기록을 비교할 수 있습니다.

한 줄 정리

한 관측 위치에서 같은 연결의 방향과 시각을 맞추고, 기록만으로 계산 가능한 시간 간격을 보고합니다.
