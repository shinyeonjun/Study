네트워크 · NW11 신뢰 전송의 상태 기계

NW11·2

슬라이딩 윈도와 누적 ACK를 바이트 구간으로 읽기

동시에 여러 구간을 보낼 때는 아직 확인되지 않은 바이트, 새로 보낼 수 있는 공간, 받았지만 순서를 기다리는 바이트를 나눕니다.

이 장을 읽고 나면

  • 반열린 순번 구간으로 송신 한도와 미확인 바이트 수를 계산한다.
  • 순서가 바뀐 수신과 재전송으로 누적 ACK가 어떻게 이동하는지 추적한다.
  • 선택적 확인과 누적 확인이 알리는 정보의 차이를 설명한다.

송신의 왼쪽과 오른쪽 경계를 따로 기록합니다

연결을 준비한 뒤 자료만 보내는 한 방향의 합성 모형입니다. 순번은 감기지 않는 정수이고 모든 길이는 바이트입니다. [100,104)는 100부터 103까지 네 바이트입니다. 송신자가 아직 확인받지 못한 첫 번호를 una, 지금까지 새 데이터에 배정한 구간의 바로 다음 번호를 nxt라 적습니다. 현재 윈도 크기 W=12를 고정합니다. 실제 TCP의 수신·혼잡 윈도는 NW06에서 다룬 별도 장치입니다.

처음 두 숫자 모두 100입니다. 송신 가능 구간 [una,una+12)는 [100,112)이고, 그 안에 기존 미확인 구간 [una,nxt)와 새 데이터에 쓸 구간 [nxt,una+12)가 있습니다. 따라서 새로 보낼 수 있는 바이트 수는 12−(nxt−una)입니다. 첫 세 구간 [100,104), [104,108), [108,112)를 차례로 보내면 nxt=112이고 그때 추가 여유는 0입니다.

수신자가 알려주는 것은 이어진 접두부입니다

수신자의 rcv_nxt는 아직 오지 않은 첫 번호입니다. [100,104)가 와서 rcv_nxt=104가 되고 ACK 104를 돌려줍니다. [104,108)는 네트워크에서 사라졌고 [108,112)가 먼저 도착합니다. 이 모형은 순서가 늦은 경우를 위해 받은 바이트를 보관할 공간을 둡니다. 빠진 104는 그대로라 ACK는 104입니다. 송신자는 첫 4바이트를 이미 확인받아 [112,116)을 이어 보냅니다. 이 구간이 먼저 수신되어도 같은 ACK 104입니다.

수신자가 [104,108)을 재전송으로 받으면 보관 중인 [108,116)까지 연달아 이어집니다. rcv_nxt가 116으로 건너뛰고 누적 ACK도 116입니다. 보관할 공간이 부족해 뒤 구간을 버리는 수신자는 뒤 바이트를 다시 받을 때까지 이 값으로 이동할 수 없습니다. SACK 옵션을 쓰기로 합의한 TCP는 뒤에 연속으로 받은 블록 [108,116) 같은 정보를 함께 알릴 수 있습니다. 그 경우에도 누적 ACK 104의 뜻은 그대로이며, 수신 버퍼에 있는 정보와 순서대로 전달한 정보도 구분합니다.

경계를 보존하는 조건을 코드로 확인합니다

정상적으로 수신한 확인 번호 a가 una<a≤nxt일 때만 이 장의 송신 창 왼쪽이 이동합니다. 같은 번호 또는 더 오래된 확인은 이동시키지 않습니다. nxt를 넘는 번호는 이 모형에서 새 데이터 확인으로 인정할 수 없습니다. 재전송은 이미 배정한 순번이므로 nxt를 더하지 않습니다. 이 규칙을 위 단계에 반복 적용하면 una≤nxt≤una+W가 유지됩니다. 실제 TCP의 순번은 32비트 순환 공간이며, 연결 제어 플래그의 순번과 송수신 허용 범위도 함께 처리합니다.

una = nxt = rcv_nxt = 100
window = 12
buffered = set()
delivered = []

def send(length):
    global nxt
    assert nxt + length <= una + window
    nxt += length

def receive(begin, end):
    global una, rcv_nxt
    buffered.update(range(max(begin, rcv_nxt), end))
    while rcv_nxt in buffered:
        buffered.remove(rcv_nxt)
        delivered.append(rcv_nxt)
        rcv_nxt += 1
    if una < rcv_nxt <= nxt:
        una = rcv_nxt
    assert una <= nxt <= una + window

def show(label):
    print(label, "una/nxt:", una, nxt, "ack:", rcv_nxt,
          "buffered:", len(buffered), "room:", una + window - nxt)

for _ in range(3):
    send(4)
show("after sends")
receive(100, 104)
show("first")
receive(108, 112)
show("third")
send(4)
receive(112, 116)
show("fourth")
receive(104, 108)
show("retry")
assert delivered == list(range(100, 116))
after sends una/nxt: 100 112 ack: 100 buffered: 0 room: 0
first una/nxt: 104 112 ack: 104 buffered: 0 room: 4
third una/nxt: 104 112 ack: 104 buffered: 4 room: 4
fourth una/nxt: 104 116 ack: 104 buffered: 8 room: 0
retry una/nxt: 116 116 ack: 116 buffered: 0 room: 12

코드에서는 발생한 ACK를 즉시 송신 쪽 상태에 반영합니다. ACK 지연이나 손실 자체를 추적하려면 수신과 ACK 도착을 서로 다른 사건으로 분리합니다. 앞 장의 예제가 그 차이를 보여 줍니다.
