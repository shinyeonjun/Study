BGP가 도달 경로의 길이보다 조직의 정책을 먼저 보는 경우

같은 접두사로 가는 경로가 둘이어도 어느 이웃에게 무엇을 배웠는지에 따라 선택과 전파가 달라집니다.

이 장을 읽고 나면

  • 접두사, AS_PATH, 로컬 선호의 역할을 구분한다.
  • 고객·제공자·피어를 포함한 예시 경로를 선택하고 전파 범위를 계산한다.
  • 라우팅 정책의 수렴과 전역 최단거리 문제를 구분한다.

경로는 목적지 접두사와 그쪽으로 가는 AS 열입니다

하나의 관리 정책을 공유하는 네트워크 묶음을 자율 시스템(AS)이라고 합니다. BGP는 어떤 목적지 접두사에 어느 경로로 도달할 수 있다고 알리고, 더 이상 사용할 수 없으면 철회합니다. 같은 접두사에 대해서도 여러 이웃이 다른 AS_PATH를 전달할 수 있습니다. 이 예의 AS 열은 내 이웃부터 목적지 접두사의 출발 AS까지 읽습니다. 실제 경로에는 추가 속성과 내부 전달 조건도 있지만, 여기서는 모든 후보가 사용 가능한 다음 홉을 가졌다고 둡니다.

합성 AS S는 고객 C로부터 [C,X,O]를, 제공자 P로부터 [P,O]를 배웁니다. O가 접두사 d를 시작해 두 쪽에서 알려 왔습니다. 이 예에서 C와 O 사이의 X와 O는 각각 앞 AS의 고객이고, P 쪽에서 O도 P의 고객입니다. 두 후보 길이는 3과 2입니다. S의 로컬 정책은 고객 경로 200, 제공자 경로 100의 선호를 부여하고 값이 높은 경로를 택합니다. 고객 경로가 더 길어도 S는 [C,X,O]를 고릅니다. 다른 AS가 같은 선호 수치를 쓸 이유는 없습니다.

받은 경로의 AS_PATH 안에 내 AS S가 이미 있으면 이 단순 모형은 그 후보를 버립니다. S가 자체를 포함한 경로를 다시 채택하면 광고 경로가 돌아온 방향의 순환이 생길 수 있기 때문입니다. AS_PATH 검사로 모든 일시적 전달 루프나 정책 진동까지 사라진다고 결론낼 수는 없습니다. 네트워크 전체가 하나의 비용 합을 최소화하도록 BGP를 설정한다고 가정하지 않습니다.

선택한 경로를 누구에게 알릴지는 또 다른 결정입니다

제공자–고객 관계에서는 고객이 제공자를 통해 더 넓은 네트워크에 도달하는 경우가 많습니다. 피어끼리는 서로 합의한 범위의 자료를 주고받습니다. 예제 S는 고객 T와 피어 Q에게 어떤 경로를 전파할지도 규칙으로 둡니다. S가 고객 C에게 배운 경로는 T와 Q에게 둘 다 알립니다. S가 제공자 P에게 배운 경로는 자기 고객 T에게는 알리지만 피어 Q에게는 알리지 않습니다. 피어끼리 서로의 다른 제공자까지 대신 이어 주지 않으려는 흔한 범위 규칙의 예입니다. 피어에게 배운 길도 이 단순 정책에서는 고객에게만 보냅니다.

S가 고른 [C,X,O]를 외부 AS에 알릴 때는 앞에 S를 붙여 [S,C,X,O]로 전달합니다. C가 경로를 철회하면 남은 [P,O]를 고릅니다. 이때 T는 [S,P,O]를 받을 수 있고, Q에게는 직전에 알린 고객 경로를 더 이상 알릴 수 없어 해당 광고를 철회합니다. Q가 다른 이웃에서 목적지 경로를 배웠을 수도 있으므로, S가 Q에 철회했다고 Q 전체의 도달 불가를 단정하지 않습니다.

받기, 고르기, 전파하기를 분리해 봅니다

routes = [
    ("customer", 200, ("C", "X", "O")),
    ("provider", 100, ("P", "O")),
]

def best(options):
    valid = [row for row in options if "S" not in row[2]]
    return min(valid, key=lambda row: (-row[1], len(row[2])), default=None)

def export(route, neighbor_role):
    learned, _, path = route
    if learned == "customer" or neighbor_role == "customer":
        return " ".join(("S",) + path)
    return "none"

assert best([("customer", 999, ("C", "S", "O"))]) is None
for options in (routes, routes[1:]):
    learned, preference, path = route = best(options)
    print("selected:", learned, preference, " ".join(path))
    print("T:", export(route, "customer"), "| Q:", export(route, "peer"))
selected: customer 200 C X O
T: S C X O | Q: S C X O
selected: provider 100 P O
T: S P O | Q: none

이 코드는 주어진 두 후보의 정책 결과만 비교합니다. 선호가 같은 경우를 위해 길이를 두 번째 키에 두었고, 실제 BGP의 전체 선택 규칙을 표현한 것은 아닙니다. 새 광고가 순서대로 도착해도 서로 의존하는 정책 때문에 통신망 전체의 경로가 항상 안정된다고 일반화할 수 없습니다. 고객과 제공자의 관계 및 내보내기 정책을 제약할 때 안정성이 나오는 조건은 별도의 연구 주제입니다. 거리 벡터의 수렴에서 본 메트릭 갱신과, 여러 조직이 서로 다른 선호를 쓰는 상황을 구분합니다.
