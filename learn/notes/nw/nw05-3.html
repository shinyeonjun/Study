네트워크 · NW05 IP와 길 찾기

NW05·3

최장 접두사로 전달하고 최단 비용으로 길을 구하기

주소를 보고 다음 홉을 찾는 조회와, 그래프에서 경로를 정하는 계산을 나눠 봅니다. 겹치는 접두사 표와 네 라우터의 가중치 예제를 각각 계산합니다.

이 장을 읽고 나면

  • 라우팅으로 경로 정보를 만드는 일과 포워딩으로 패킷을 다음 홉에 내보내는 일을 설명한다.
  • 목적지와 일치하는 접두사들 가운데 길이가 가장 긴 것을 찾는다.
  • 가중치 그래프의 최단 비용을 계산하고, OSPF와 BGP가 쓰이는 범위를 설명한다.

경로를 알아내는 일과 패킷을 내보내는 일

라우터가 로컬 링크에서 패킷을 받았습니다. 다음 연결로 내보낼 순간에는 목적지 IP를 보고 전달 표에서 다음 홉이나 출력 인터페이스를 찾습니다. 이 동작을 포워딩이라고 합니다. 전달 표에 어떤 경로를 둘지 연결된 망, 관리자가 지정한 정보, 다른 라우터에서 배운 정보로 정하는 과정은 라우팅입니다.

목적지 접두사이 예의 IPv4 다음 홉
0.0.0.0/0R0
198.51.100.0/24R1
198.51.100.128/25R2
198.51.100.144/28R3

비트를 0개 고정하는 /0은 IPv4 주소 전체와 일치합니다. 다른 일치 줄이 없을 때 위 예에서는 이 기본 경로를 씁니다. 실제 표에 맞는 경로가 없다면 전달할 방법이 없을 수 있습니다. 이 장에서는 단순화를 위해 각 접두사에 이미 선택된 다음 홉이 하나씩 있습니다.

목적지 비트와 더 많이 일치하는 접두사를 고른다

198.51.100.150은 /24 전체, .128에서 .255까지인 /25, .144에서 .159까지인 /28에 모두 들어갑니다. 최장 접두사 일치에서는 더 구체적인 /28의 R3을 고릅니다. 198.51.100.200은 /28에 들지 않아 /25의 R2를 고릅니다.

경로를 만드는 단계의 비용이 다른 기준이 될 수 있지만, 설치된 접두사들이 겹치는 이 조회에서는 접두사 길이를 비교합니다. IPv6도 앞쪽 비트가 일치하는 접두사를 사용합니다.

연결 비용을 그래프로 계산한다

라우터를 정점으로 두고 일방향 링크의 비용을 붙였습니다. S→A→T는 2+7=9, S→B→T는 5+2=7, S→A→B→T는 2+1+2=5입니다. S에서 T로 가는 최저 비용 경로의 첫 홉은 A입니다. 간선 수만 비교하면 오히려 첫 두 경로가 짧습니다.

음이 아닌 비용에서는 현재까지 값이 가장 작은 후보로부터 이웃까지의 더 싼 길을 적는 방식으로 최단 경로를 구할 수 있습니다. 이를 다익스트라 알고리즘이라고 합니다. S에서 시작하면 A의 임시 비용은 2, B는 5입니다. A를 처리하면 B가 3으로 줄고 T는 9가 됩니다. B에서 T로 2를 더한 5가 기존 9보다 작습니다. 아래 코드는 작은 후보부터 꺼내는 우선순위 큐를 씁니다.

OSPF는 하나의 자율 시스템 내부 라우팅에 쓰이는 링크 상태 프로토콜입니다. 자율 시스템(AS)은 공통 관리와 라우팅 정책 아래 운영되는 네트워크의 묶음입니다. OSPF는 내부를 영역으로 나눌 수 있고, 라우터는 공유한 링크 상태와 비용으로 최단 경로를 계산합니다. 이 그림은 비용 계산만 남긴 모형입니다. BGP는 자율 시스템 사이의 목적지 접두사 도달 정보를 교환하는 데 쓰입니다. 경로를 선택할 때 조직의 정책과 AS 경로 등 여러 정보를 사용합니다.

AS 안에서 쓰는 라우팅 프로토콜을 IGP(내부 게이트웨이 프로토콜), AS 사이에서 쓰는 것을 EGP라 부르고, 오늘날 EGP는 사실상 BGP 하나입니다. IGP의 계산 방식은 두 갈래입니다. OSPF 같은 링크 상태 방식은 모든 라우터가 망 전체의 연결과 비용을 알고 각자 다익스트라로 계산합니다. RIP 같은 거리 벡터 방식은 이웃끼리 “목적지까지 내가 아는 비용”만 주고받으며 벨만-포드 식으로 값을 고쳐 갑니다(RIP의 비용은 지나는 라우터 수, 즉 홉 수).

주소 조회와 가중치 탐색을 각각 실행한다

from heapq import heappop, heappush
from ipaddress import ip_address, ip_network

entries = [
    ("0.0.0.0/0", "R0"),
    ("198.51.100.0/24", "R1"),
    ("198.51.100.128/25", "R2"),
    ("198.51.100.144/28", "R3"),
]
routes = [(ip_network(prefix), hop) for prefix, hop in entries]

for raw in ("198.51.100.150", "198.51.100.200", "198.51.100.30", "203.0.113.7"):
    target = ip_address(raw)
    match = max((pair for pair in routes if target in pair[0]),
                key=lambda pair: pair[0].prefixlen)
    print(target, match[0], match[1])

graph = {"S": [("A", 2), ("B", 5)], "A": [("B", 1), ("T", 7)],
         "B": [("T", 2)], "T": []}

def shortest(graph, start, end):
    best = {start: 0}
    queue = [(0, start, (start,))]
    while queue:
        cost, u, path = heappop(queue)
        if cost != best[u]:
            continue
        if u == end:
            return cost, path
        for v, weight in graph[u]:
            candidate = cost + weight
            if v not in best or candidate < best[v]:
                best[v] = candidate
                heappush(queue, (candidate, v, path + (v,)))
    return None

cost, path = shortest(graph, "S", "T")
print("->".join(path), cost)

198.51.100.200 198.51.100.128/25 R2
198.51.100.30 198.51.100.0/24 R1
203.0.113.7 0.0.0.0/0 R0
S->A->B->T 5

앞 네 줄은 접두사가 이미 적힌 전달 표의 조회입니다. 마지막 줄은 가상의 링크 비용으로 계산한 경로입니다. 네트워크에 접속하거나 설정을 바꾸는 코드는 없습니다.
