TCP 바이트 스트림과 UDP 데이터그램

TCP가 빠진 바이트를 확인하고 순서대로 건네는 과정을 읽습니다. 같은 앱 자료를 TCP와 UDP의 관점으로 나눠 놓으면 어디에서 메시지의 경계를 찾는지 보입니다.

이 장을 읽고 나면

  • TCP 연결이 어떻게 준비되는지와 수신 확인·재전송을 설명한다.
  • TCP가 애플리케이션에게 건네는 바이트 순서와 메시지 경계를 구별한다.
  • UDP 데이터그램 경계와 도착 보장의 범위를 말한다.

TCP는 먼저 연결 상태를 맞춘다

IP는 목적지 방향으로 패킷을 전달합니다. TCP는 그 위에서 두 끝점이 양방향으로 나눠 보낼 바이트 스트림을 제공합니다. 보통 연결을 시작할 때 첫 끝점이 SYN을 보내고, 상대가 SYN과 ACK를 함께 보낸 뒤, 첫 끝점이 ACK로 확인합니다. 이 세 단계로 양쪽은 연결을 열고 각 방향의 시작 순서 번호를 맞춥니다.

TCP는 데이터에 대응하는 바이트 순서 번호를 써서 빠진 부분이나 중복을 구별합니다. 다음 그림에서는 데이터 시작을 상대 오프셋 0으로 두고, 첫 3바이트가 빠진 동안 뒤의 4바이트가 도착했다고 가정합니다. 수신쪽이 먼저 온 뒤쪽 바이트를 저장해 둘 공간이 있습니다.

ACK는 수신 TCP가 확인하는 번호입니다. 3~6이 와도 먼저 필요한 0이 빠져 있으면 누적 확인 번호는 0에 남습니다. 송신 TCP가 재전송 타이머와 확인 응답 등의 신호로 손실을 판단해 0~2를 다시 보낼 수 있습니다. 빠진 0~2가 도착하면 0~6이 이어져 수신 TCP는 애플리케이션에 순서대로 바이트를 내줄 수 있습니다.

TCP의 신뢰성은 연결이 작동할 때 바이트를 순서대로 전달하고 손실과 중복을 복구하는 전송의 성질입니다. 오래 끊겨 연결이 실패하면 끝까지 성공할 수 없습니다. 수신 TCP가 ACK를 보냈다는 사실로 상대 앱이 읽기나 저장을 끝냈다고 판단할 수도 없습니다. 그런 확인이 필요하면 애플리케이션의 규칙으로 따로 만듭니다.

TCP 스트림에는 앱이 쓴 경계가 없다

앱이 줄바꿈을 붙인 hi와 cat을 각각 쓴다면 전체 데이터는 줄바꿈까지 7바이트입니다. 받는 쪽의 한 번 읽기에 같은 크기의 덩어리가 오리라는 보장은 없습니다. 예를 들어 받는 프로그램이 처음 1바이트, 다음 4바이트, 끝의 2바이트를 따로 얻을 수 있습니다.

한 메시지가 여러 읽기에 걸치거나, 한 읽기에 메시지의 끝과 다음 메시지의 앞이 함께 올 수 있습니다. 줄바꿈이나 길이 머리말처럼 사용할 프레이밍 규칙을 정하고, 아직 완성되지 않은 부분을 보관합니다. 프레임이라는 말은 여기서는 앱의 메시지 구분 방식이라는 뜻입니다.

UDP는 순서를 다시 맞추지 않고 데이터그램을 전달한다

UDP에서는 앱이 보낸 데이터그램의 경계가 있습니다. 온전히 도착해서 충분한 버퍼로 읽을 수 있는 데이터그램은 다른 데이터그램과 합쳐진 바이트 스트림으로 들어오지 않습니다. UDP 자체가 TCP처럼 연결을 열어 양쪽 순서 번호를 맞추지는 않습니다. 손실을 자동 재전송하거나 보낸 순서를 복구하는 기능도 UDP 자체에는 없습니다.

늦은 자료보다 최신 자료를 먼저 쓰는 앱이나 자기 규칙으로 재시도할 앱은 이 특성을 고려해 UDP를 사용할 수 있습니다. 어떤 전송 규칙이 필요한지는 업무에 따라 달라집니다. 예를 들어 UDP 위에 애플리케이션 프로토콜이 별도의 손실 복구와 혼잡 제어를 둘 수 있습니다.

합성한 바이트 조각과 데이터그램을 읽는다

writes = [b"hi\n", b"cat\n"]
stream = b"".join(writes)
reads = [stream[:1], stream[1:5], stream[5:]]
print("TCP read lengths:", [len(part) for part in reads])

buffer = b""
for part in reads:
    buffer += part
    while b"\n" in buffer:
        message, buffer = buffer.split(b"\n", 1)
        print("app message:", message.decode("ascii"))
assert not buffer

arrived_datagrams = [writes[1], writes[0]]
for datagram in arrived_datagrams:
    print("UDP datagram:", repr(datagram))
TCP read lengths: [1, 4, 2]
app message: hi
app message: cat
UDP datagram: b'cat\n'
UDP datagram: b'hi\n'

줄바꿈까지 읽어야 메시지 하나가 완성됩니다. 뒤의 두 줄은 순서가 뒤바뀌었지만 데이터그램 각각은 경계를 유지하는 가상의 UDP 사례입니다. 여기서는 파일이나 네트워크 소켓에 연결하지 않습니다.
