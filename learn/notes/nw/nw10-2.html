왕복 시간과 응답 누락을 함께 보고하기

여덟 번의 확인 요청 중 두 번이 돌아오지 않았습니다. 응답한 기록의 속도와 실패한 시도를 따로 세고, 경로 도구가 보여 주는 범위를 확인합니다.

이 장을 읽고 나면

  • RTT의 뜻과 제한 시간 내 응답률을 설명한다.
  • 응답한 값의 중앙값과 백분위수를 계산한다.
  • 경로 중간의 빈 응답만으로 장애를 단정하기 어려운 이유를 설명한다.

가서 돌아온 시간을 잰다

네트워크 확인에서 RTT는 요청이 나간 시각부터 응답이 돌아온 시각까지의 왕복 시간입니다. 오고 가는 경로와 서비스가 응답을 만드는 시간이 다를 수 있어 RTT를 절반으로 나눠 항상 정확한 편도 시간을 얻지는 못합니다. ping은 흔히 ICMP 에코 요청과 응답을 이용합니다. HTTP 서비스의 경로나 응답 형식을 검사하는 작업과는 다릅니다.

미응답을 빠른 기록처럼 더하지 않는다

설명용 데이터는 시도 8개입니다. 제한 시간 내에 응답이 돌아오면 경과 시간을 기록했고, 두 번은 응답이 없어 빈 값으로 남겼습니다.

시도12345678
RTT(ms)2024미응답2234미응답2028

미응답은 2/8=25%입니다. 응답한 RTT만 정렬하면 20, 20, 22, 24, 28, 34ms입니다. 가운데 두 수의 평균은 23ms입니다. 이 예에서 95번째 백분위수를 가까운 순위법으로 구하면 순위는 올림(0.95×6)=6이고 값은 34ms입니다. 백분위수 계산법과 표본 수가 다르면 값이 달라질 수 있습니다.

from math import ceil
from statistics import median

measurements = [20, 24, None, 22, 34, None, 20, 28]
observed = sorted(value for value in measurements if value is not None)
missing = len(measurements) - len(observed)
rank = ceil(0.95*len(observed))
print("응답:", len(observed), "/", len(measurements))
print("미응답률:", f"{100*missing/len(measurements):.1f}%")
print("중앙값:", f"{median(observed):.1f}", "ms")
print("가까운 순위 p95:", observed[rank - 1], "ms")

실행 결과

응답: 6 / 8
미응답률: 25.0%
중앙값: 23.0 ms
가까운 순위 p95: 34 ms

중간 장치의 응답과 서비스 장애를 나눈다

경로를 관찰하는 traceroute 계열 도구는 먼저 도달할 수 있는 홉 수를 제한한 요청을 보내고, 그 범위를 단계별로 늘립니다. 중간 라우터가 제한이 끝났음을 알려 주면 어느 홉에서 답이 돌아왔는지 표시할 수 있습니다. 한 홉이 답을 내지 않아도 그 뒤의 홉은 답할 수 있습니다. 중간 장치가 이런 확인 응답을 제한하거나, 서로 다른 시도가 다른 경로를 지날 수 있기 때문입니다.

확인 응답이 정해 둔 시간 내 돌아오지 않았다고 해서 어느 쪽 패킷이 사라졌는지 바로 정할 수는 없습니다. 측정 대상, 시각, 시도 수, 시간 제한, 응답한 시간의 중앙값이나 상위 백분위수를 함께 적습니다. 웹 요청에 문제가 있다면 마지막 단계의 HTTP 응답도 따로 확인합니다.
