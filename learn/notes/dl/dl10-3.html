모델 크기와 추론 지연·처리량을 따로 재기

모델이 작으면 어떤 자원을 덜 쓰는지, 묶음으로 처리하면 누가 더 오래 기다리는지 계산합니다. 자료 수와 평가 분할까지 맞춰 실제 비교를 준비합니다.

이 장을 읽고 나면

  • 가중치의 저장 바이트를 근사한다.
  • 한 요청 지연과 초당 처리량을 계산하고 구분한다.
  • 표현·예산·정확도를 함께 비교할 조건을 적는다.

가중치 수와 저장 형식을 함께 봐야 한다

매개변수가 200만 개인 모형을 가정합니다. 각 가중치를 32비트, 즉 4바이트로 저장하면 가중치 배열은 800만 바이트(8MB)입니다. 8비트 값만 저장한다면 200만 바이트(2MB)입니다. 여기서 MB는 100만 바이트입니다. 실제 모델 파일에는 배열을 해석할 스케일 등 추가 정보가 있을 수 있고, 실행 중 임시 배열이나 토큰의 이전 계산을 보관하는 캐시도 메모리를 더 씁니다.

한 번에 몇 건을 처리하는지 기록한다

가상 측정에서 한 건만 처리하면 6ms, 여덟 건을 한 묶음으로 처리하면 40ms라고 합시다. 묶음 가운데 각 요청이 완성 결과를 받는 시점은 40ms입니다. 초당 처리량은 8/0.040=200건입니다. 한 건씩에서는 1/0.006≈166.67건/초입니다. 이 계산은 연속으로 가득 처리할 때의 수치이며, 요청이 충분히 모이기까지 기다리는 시간은 따로 잽니다.

지연(latency)은 요청 하나가 들어와 결과가 나올 때까지의 시간, 처리량(throughput)은 단위 시간에 끝내는 건수입니다. 지연은 요청마다 다르므로 평균 하나보다 분포로 보고합니다. 흔히 중앙값(p50)과 느린 쪽 꼬리인 95·99 백분위수(p95, p99)를 함께 적습니다. 예를 들어 p95=50ms는 요청의 95%가 50ms 안에 끝났다는 뜻입니다.

from fractions import Fraction as F

parameters = 2_000_000
for width in (32, 8):
    mb = F(parameters*width, 8*1_000_000)
    print(width, "비트 가중치 배열:", mb, "MB")
for batch, milliseconds in ((1, 6), (8, 40)):
    rate = F(batch*1000, milliseconds)
    print(batch, "건 묶음:", f"{float(rate):.2f}", "건/초")

속도 표의 바깥 조건을 맞춘다

생성 모형을 비교할 때는 입력을 읽고 첫 토큰이 나오기까지의 시간과, 그 이후 남은 토큰들을 생성하는 시간을 나눌 수 있습니다. 같은 모델도 입력과 출력 길이에 따라 속도가 달라집니다. 첫 실행과 충분히 실행한 뒤 결과가 다른지도 봅니다. 첫 몇 번은 메모리 할당·커널 준비 때문에 느리므로 버리고(워밍업) 잽니다. GPU 연산은 비동기로 실행되어 Python 쪽 시계가 계산이 끝나기 전에 멈출 수 있으므로, 시간을 읽기 전에 torch.cuda.synchronize()를 부르거나 torch.utils.benchmark를 씁니다.

훈련 자료 규모를 바꿀 때는 고유한 자료 수와 중복, 학습 횟수 및 모델 크기도 기록합니다. 자료의 개수가 많았다는 사실만으로 평가 향상의 원인을 알 수 없습니다. 다른 정밀도나 작은 모델을 검토할 때에는 실제로 줄인 자원과 같은 평가에서의 품질을 같이 보고합니다.
