DA06·1

중복·결측·단위·범주 검사

매장 주문표를 두 파일에서 모았더니 같은 주문이 두 번 나오고, 결제 금액이 ‘4천원’인 행과 빈칸인 행도 있습니다. 평균을 내기 전에 어떤 값을 고쳐도 되고 어떤 행을 확인해야 하는지, 원본 아홉 행을 따라가며 판단합니다.

이 장을 읽고 나면

  • 행 단위와 키를 정한 뒤 동일 사본과 충돌 기록을 구분한다.
  • 단위 환산과 범주 검사로 비교 가능한 값을 만든다.
  • 분석에 사용한 행과 확인 대기 행을 나누고 건수를 대조한다.

행을 고치기 전에 무엇을 한 건으로 세는지 정한다

가상의 주문 분석을 해 봅니다. 질문은 ‘온라인과 매장에서, 금액이 확인된 주문 한 건당 얼마인가?’입니다. 이 예의 행 단위는 상품 한 개나 주문 상태 변경 한 번이 아니라 결제가 확정된 주문 한 건입니다. 주문번호가 그 한 건을 구별하는 키(key)입니다. 주문 항목표라면 주문번호가 같아도 품목마다 행이 여럿일 수 있습니다. 그 표를 분석하면 판단 기준도 달라집니다.

아래 원본에는 주문번호와 기록된 금액, 단위, 채널이 있습니다. ‘공백’은 표에서 설명하기 위한 표시입니다.

101번의 두 행은 같은 내보내기를 합치면서 생긴 사본이라고 확인했습니다. 한 행만 유지해도 원본 주문은 빠지지 않습니다. 107번은 금액이 충돌합니다. 파일의 마지막 값이 언제나 최신이라는 보장이 없으므로 두 행을 모두 따로 보관하고, 주문 원장이나 확인 시각으로 해결한 뒤 집계합니다.

거래의 0원, 비어 있는 금액, 단위가 섞인 값

결측(missing)은 값이 기록되지 않았거나 알 수 없는 상태입니다. 103번은 금액 필드가 비어 있어 주문 건수에는 나타나지만, 확인된 금액의 평균을 계산할 때 사용할 수 없습니다. 104번은 지급액이 0원으로 확인된 주문입니다. 이 교재의 질문은 ‘확인된 결제 금액’이므로 0도 분모에 넣습니다.

풀이 예제

온라인의 101, 103, 105번에서 금액을 아는 주문은 3,000원과 9,000원의 두 건입니다. 확인된 금액만의 평균은 (3,000 + 9,000) ÷ 2 = 6,000원입니다. 결측을 0으로 덮으면 12,000 ÷ 3 = 4,000원으로 바뀝니다. 없는 값을 추측하는 순간 분모와 결과도 바뀝니다.

102번의 4는 4원이 아니라 4천원입니다. 단위 열을 본 뒤 1,000을 곱해 4,000원으로 환산합니다. 단위가 적혀 있지 않다면 값이 작다는 이유로 ‘천원’이라고 추측하지 않습니다. 같은 원칙이 초와 밀리초, m와 cm에도 적용됩니다.

105번은 끝 공백을 없애면 허용 범주인 ‘온라인’과 같습니다. 106번 ‘전화?’는 이 예에서 허용 범주가 아닙니다. 전화 주문이 어떤 채널인지 정의가 없는 상태라 원본은 남기고 확인 대기에 둡니다. 실제 보고서에서 채널 미확인을 별도 범주로 집계할 수도 있습니다. 어떤 기준을 썼는지 명시합니다.

원본과 확인 대기 목록을 분리해 정리한다

먼저 원본을 보존합니다. 확인된 사본을 제외하고, 같은 키의 값이 서로 다른 기록을 찾습니다. 그 밖의 행에서 단위, 범주, 타입, 필수값을 검사해 분석 자료와 확인 대기를 나눕니다. 결제 금액이 음수인 환불은 이 결제 자료의 허용 범위 밖이지만, 환불을 연구하는 별도 표에서는 정상 값일 수 있습니다. 범위 규칙은 분석 목적과 데이터 설명에 근거합니다.

아래 코드는 이 표에서 확정한 규칙을 적용합니다. dict.fromkeys는 같은 튜플에 한 번만 키를 넣어 완전히 동일한 행을 모읍니다. 이 예에서는 동일 행이 사본이라는 사실이 이미 확인되었습니다. Counter는 같은 주문번호가 사본을 제거한 뒤에도 남는지 셉니다.

from collections import Counter
from statistics import mean

raw = [
    ("101", "3000", "원", "온라인"),
    ("101", "3000", "원", "온라인"),
    ("102", "4", "천원", "매장"),
    ("103", "", "원", "온라인"),
    ("104", "0", "원", "매장"),
    ("105", "9000", "원", "온라인 "),
    ("106", "6000", "원", "전화? "),
    ("107", "12000", "원", "매장"),
    ("107", "15000", "원", "매장"),
]
units = {"원": 1, "천원": 1000}
channels = {"온라인", "매장"}

unique = list(dict.fromkeys(raw))
key_count = Counter(row[0] for row in unique)
clean = []
pending = []
for order, amount, unit, channel in unique:
    channel = channel.strip()
    if key_count[order] > 1:
        pending.append((order, "키 충돌"))
    elif amount == "":
        pending.append((order, "금액 결측"))
    elif unit not in units or channel not in channels:
        pending.append((order, "단위·채널 확인"))
    else:
        try:
            won = int(amount) * units[unit]
        except ValueError:
            pending.append((order, "금액 형식 확인"))
        else:
            if won < 0:
                pending.append((order, "음수 금액 확인"))
            else:
                clean.append((order, won, channel))

copies = len(raw) - len(unique)
assert len(clean) + len(pending) + copies == len(raw)
print("원본 / 사본 / 사용 / 대기:", len(raw), copies, len(clean), len(pending))
print("대기:", pending)
for channel in sorted(channels):
    amounts = [won for _, won, c in clean if c == channel]
    print(channel, "n =", len(amounts), "평균 =", mean(amounts))
원본 / 사본 / 사용 / 대기: 9 1 4 4
대기: [('103', '금액 결측'), ('106', '단위·채널 확인'), ('107', '키 충돌'), ('107', '키 충돌')]
매장 n = 2 평균 = 2000
온라인 n = 2 평균 = 6000

여기서 대기는 4행이지만 주문번호로는 103, 106, 107의 3건입니다. 최종 보고에는 채널당 사용 건수와 제외 사유를 같이 적습니다. 네 행으로 확인된 평균이 이 기간의 전체 주문을 대표한다고 단정하지 않습니다. 정리 작업 자체가 어느 주문이 비교에 남는지를 바꿀 수 있습니다.
