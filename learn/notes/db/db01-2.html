DB01·2

기본 키, 외래 키와 복합 키

고객 이름이 같아도 두 사람을 구분해야 합니다. 주문에서 고객을 가리키고, 항목에서 주문을 가리키는 식별자가 이를 가능하게 합니다.

이 장을 읽고 나면

  • 후보 키와 기본 키, 단일 키와 복합 키를 구별한다.
  • 외래 키가 가리키는 방향과 일대다 관계의 뜻을 설명한다.
  • 업무에서 허용하는 중복과 잘못된 중복을 구별한다.

한 행을 다시 찾을 이름표

누락 없이 표의 서로 다른 행을 항상 구분하고, 열을 하나라도 빼면 그 성질이 사라지는 열의 집합을 후보 키라고 합니다. 고객 번호와 기관이 보증한 별도 식별 코드가 모두 그 조건을 만족하면 두 후보가 생깁니다. 설계자는 그중 하나를 기본 키로 선택합니다. 두 사람의 이름이 오늘 우연히 달랐다는 관측만으로 이름을 후보 키로 삼을 수 없습니다. 앞으로 올바른 자료에서 이름이 같을 수 있기 때문입니다.

주문 번호처럼 업무에서 이미 쓰는 식별자를 자연 키로 삼을 수 있고, 원래 속성 대신 시스템이 배정한 정수처럼 식별 전용 값을 쓸 수도 있습니다. 시스템 번호를 추가해도 '고객 계정 코드가 겹치면 안 된다' 같은 별도 업무 규칙은 제약으로 남겨야 합니다.

행을 다른 표의 규칙과 연결하기

주문 customer_id는 customers.customer_id를 참조하는 외래 키입니다. 이 열은 한 고객의 여러 주문에서 반복될 수 있습니다. 이 예에서는 외래 키가 필수라서 주문은 정확히 한 고객을 가리킵니다. 고객에게 주문은 0개, 1개 또는 여러 건일 수 있습니다. 이와 같이 한쪽의 행 하나가 다른 쪽 여러 행과 연결될 수 있는 관계를 일대다라고 합니다.

외래 키는 있지 않은 고객 번호가 실수로 기록되는 것을 막습니다. SQLite에서는 연결을 열고 트랜잭션이 시작되기 전에 PRAGMA foreign_keys = ON을 실행합니다. 주문을 하지 않은 고객도 허용되는 관계이므로, 번호 3이 주문 표에 없어도 오류가 아닙니다.

항목 순번은 주문 안에서만 유일하다

항목 1번이라는 값은 주문마다 다시 시작하며, 주문 101에도 항목 1과 2가 있습니다. order_id 하나로는 상품 항목 두 줄을 구별할 수 없습니다. (order_id, line_no)의 조합으로 구별하는 키가 복합 키입니다. 같은 상품을 주문에서 여러 줄로 입력하게 할지 여부는 업무 규칙에 달려 있으므로 product_id를 항목 식별자로 단정하지 않습니다.

왜 그럴까?

상품 명칭이 바뀌면 주문 내역을 연결하는 번호도 바꿔야 할까?

모범 답 보기

상품 번호를 같은 상품의 안정적인 식별자로 정했다면 이름이 바뀌어도 번호는 같습니다. 주문 당시 가격처럼 이력에 필요한 속성은 별도로 보존할 수 있습니다.

하나의 열과 두 열로 구분해 보기

항목 두 줄에서 이미 line_no에 중복이 생깁니다. 한 행을 찾을 때 두 열의 값을 함께 제시합니다. 아래 값은 파이썬의 튜플로 바인딩되며 SQL 값 바인딩은 다음 단원에서 자세히 다룹니다.

실행 예제

import sqlite3

with sqlite3.connect(":memory:") as db:
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript("""
    CREATE TABLE customers (
        customer_id INTEGER PRIMARY KEY,
        name TEXT NOT NULL
    );
    CREATE TABLE orders (
        order_id INTEGER PRIMARY KEY,
        customer_id INTEGER NOT NULL REFERENCES customers(customer_id),
        order_date TEXT NOT NULL,
        status TEXT NOT NULL CHECK (status IN ('paid', 'pending')),
        total_won INTEGER NOT NULL CHECK (total_won >= 0),
        coupon_won INTEGER CHECK (coupon_won >= 0)
    );
    CREATE TABLE products (
        product_id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        list_price_won INTEGER NOT NULL CHECK (list_price_won >= 0)
    );
    CREATE TABLE order_items (
        order_id INTEGER NOT NULL REFERENCES orders(order_id),
        line_no INTEGER NOT NULL,
        product_id INTEGER NOT NULL REFERENCES products(product_id),
        qty INTEGER NOT NULL CHECK (qty > 0),
        unit_price_won INTEGER NOT NULL CHECK (unit_price_won >= 0),
        PRIMARY KEY (order_id, line_no)
    );
    """)
    db.executemany("INSERT INTO customers VALUES (?, ?)", [
        (1, 'Mina'),
        (2, 'Jun'),
        (3, 'Sol'),
    ])
    db.executemany("INSERT INTO orders VALUES (?, ?, ?, ?, ?, ?)", [
        (101, 1, '2025-01-02', 'paid', 10000, None),
        (102, 1, '2025-01-03', 'paid', 15000, 1000),
        (103, 2, '2025-01-04', 'pending', 12000, None),
        (104, 2, '2025-01-05', 'paid', 15000, 0),
    ])
    db.executemany("INSERT INTO products VALUES (?, ?, ?)", [
        (11, 'notebook', 6000),
        (12, 'pen', 2000),
        (13, 'pouch', 3000),
    ])
    db.executemany("INSERT INTO order_items VALUES (?, ?, ?, ?, ?)", [
        (101, 1, 11, 1, 6000),
        (101, 2, 12, 2, 2000),
        (102, 1, 11, 2, 6000),
        (102, 2, 13, 1, 3000),
        (103, 1, 11, 2, 6000),
        (104, 1, 13, 5, 3000),
    ])

    ones = db.execute(
        "SELECT order_id FROM order_items WHERE line_no = ? ORDER BY order_id",
        (1,),
    ).fetchall()
    item = db.execute(
        "SELECT product_id, qty FROM order_items WHERE order_id = ? AND line_no = ?",
        (102, 2),
    ).fetchone()
    print("orders with line 1:", [row[0] for row in ones])
    print("order 102, line 2:", item)
db.close()

실행 결과

orders with line 1: [101, 102, 103, 104]
order 102, line 2: (13, 1)
