DB07·3

배치와 스트리밍, 스키마 변경과 자료 계보

어떤 주문이 오전에 발생하고 오후에 도착했다면 오전 합계는 언제 완성될까요? 이벤트 시각과 도착 시각을 나누고, 변경된 열을 이전 값과 같은 단위로 읽는 규칙을 세웁니다.

이 장을 읽고 나면

  • 배치 처리와 스트리밍 처리를 비교한다.
  • 이벤트 시각 윈도, 지연 도착과 워터마크를 해석한다.
  • 스키마 변경에 대응하는 규칙과 자료 계보를 기록한다.

정해진 구간을 모아서 계산하거나 도착 즉시 계산

배치 처리는 정해진 시간이나 기간에 수집한 유한한 자료를 모아 처리합니다. 모든 입력을 기다려 매일 마감 주문을 계산하는 것이 예입니다. 스트리밍은 기록이 계속 도착한다고 보고 새 기록을 받아 요약을 갱신합니다. 작은 묶음을 짧은 간격으로 이어서 처리하는 방식도 가능합니다. 결과가 언제 필요하고 어느 정도 지연을 허용할지 정합니다.

주문이 발생한 이벤트 시각과 수집기가 받은 도착 시각은 다를 수 있습니다. 집계 구간을 [0,10)으로 잡으면 0 이상 10 미만 발생 주문을 같은 묶음으로 계산합니다. 기준을 도착 시각으로 바꾸면 질문이 바뀝니다.

늦은 자료와 윈도의 마감

도착 시각 12까지는 101, 102, 103이 도착했습니다. 이벤트 구간 [0,10)의 합은 10,000+15,000=25,000원입니다. 주문 103은 시각 11에 발생해 그 윈도에서 제외됩니다. 뒤늦게 도착한 주문 104는 이벤트 시각이 8이므로 원래 같은 윈도 소속입니다. 이를 포함하면 40,000원입니다.

워터마크는 처리기가 어떤 이벤트 시각까지 자료가 들어왔을 것으로 보는 진행 경계입니다. 학습 모형은 그때까지 관측한 가장 큰 이벤트 시각에서 1을 빼서 경계를 둡니다. 시각 12에 이벤트 시각 11을 보았으므로 경계는 10입니다. 그 경계는 뒤늦은 기록이 없다는 증명이 아닙니다. 아래 정책은 경계를 넘긴 윈도라도 늦게 도착한 기록의 정정을 허용합니다. 운영에서는 허용할 지연과 정정을 알리는 방법을 정합니다.

열의 모양뿐 아니라 단위도 바뀔 수 있다

제공자가 선택적인 쿠폰 필드를 추가하면 이전 소비자가 그 필드를 모르더라도 기존 주문 조회는 유지될 수 있습니다. 필수 열을 지우거나, 원 단위 값을 100원 단위로 바꾸면 의미가 바뀝니다. 버전별 형식과 단위를 명시하고, 아는 버전만 변환합니다. 모르는 버전에서 비슷한 값을 발견해 같은 단위로 단정하지 않습니다.

자료 계보는 결과가 어떤 입력에서 어떤 변환 단계를 거쳐 나왔는지 따라가는 정보입니다. 파일과 스키마 버전, 변환 코드의 버전, 구간과 필터, 검증과 출력 요약을 남깁니다. 코드를 기록하는 방법은 SY07 Git와 재현 가능한 작업에서 이어서 봅니다.

실행 예제

events = [
    # order_id, event_time, arrival_time, amount_won
    (101, 1, 2, 10000),
    (102, 4, 5, 15000),
    (103, 11, 12, 12000),
    (104, 8, 15, 15000),
]
received = [row for row in events if row[2] <= 12]
watermark = max(row[1] for row in received) - 1

def window_total(rows):
    return sum(amount for _, t, _, amount in rows if 0 <= t < 10)

initial = window_total(received)
corrected = window_total(events)
print("watermark:", watermark)
print("initial:", initial, "correction:", corrected - initial, "final:", corrected)

def to_won(row):
    if row["schema"] == 1:
        return row["total_won"]
    if row["schema"] == 2:
        return 100 * row["total_hundred_won"]
    raise ValueError("unknown schema")

print("same amount:", to_won({"schema": 1, "total_won": 15000}),
      to_won({"schema": 2, "total_hundred_won": 150}))

실행 결과

watermark: 10
initial: 25000 correction: 15000 final: 40000
same amount: 15000 15000

마지막 줄은 각 버전이 실제로 단위를 그렇게 문서화한 경우입니다. 버전이 알려졌어도 열이 필수로 존재하는지, 정수인지, 금액 범위를 만족하는지는 앞 장의 검증 단계에서 확인합니다.
