서브쿼리, 윈도 함수와 누적 합

전체 평균보다 큰 주문을 고르고, 주문 하나마다 그날까지 고객이 주문한 누적액을 붙입니다. 두 계산에 필요한 결과의 입도를 구분합니다.

이 장을 읽고 나면

  • 서브쿼리가 돌려줄 한 값과 EXISTS의 행 존재 조건을 구별한다.
  • 윈도 함수의 PARTITION BY, ORDER BY, ROWS의 역할을 설명한다.
  • 같은 그룹을 다룰 때 집계와 윈도 함수의 출력 행 수를 예측한다.

다른 질의의 결과를 조건으로 읽기

서브쿼리는 다른 SQL 문 안에 들어가는 질의입니다. 예로 모든 주문의 평균을 구하는 (SELECT AVG(total_won) FROM orders)를 외부의 WHERE total_won > (...) 비교값으로 사용합니다. 비교에 넣을 값 하나를 만들기 위해 GROUP BY 없이 AVG를 씁니다. 비어 있는 입력이면 AVG 결과가 NULL이므로 일반 크기 비교가 참인 행은 없습니다.

비교하려는 값이 하나이면 서브쿼리가 한 값만 내도록 명시합니다. 스칼라 서브쿼리가 여러 행을 돌려주면 SQLite는 오류 없이 첫 행의 값만 쓰지만, PostgreSQL과 MySQL은 오류를 냅니다. SQLite의 방식에 기대면 어느 행이 쓰였는지 알 수 없고 다른 DB에서 실패합니다. 여러 행을 확인할 때는 목적에 맞게 존재 여부(EXISTS)나 집합에 속하는지(IN)를 묻습니다. customer_id IN (SELECT customer_id FROM orders)는 서브쿼리가 돌려준 값 목록 중 하나와 같으면 참입니다.

행이 하나라도 있는지 묻기

WHERE EXISTS (SELECT 1 FROM orders AS o WHERE o.customer_id=c.customer_id AND o.status='paid')는 외부에서 현재 보는 고객 c에 대해 결제 완료 주문이 한 건이라도 있는지를 묻습니다. 바깥 행의 값을 쓰므로 상관 서브쿼리입니다. 여기서 SELECT 1은 한 주문의 값에 관심 없음을 드러냅니다. 존재 조건만 검사하므로 한 고객의 주문이 여러 건이어도 고객 결과 행은 하나입니다. 반대로 NOT EXISTS는 조건에 맞는 행이 하나도 없을 때 참이며, 주문이 없는 고객 3을 찾을 때 씁니다.

시험 함정 · NOT IN과 NULL

주문 없는 고객을 WHERE customer_id NOT IN (SELECT customer_id FROM orders)로 찾으면 이 자료에서는 고객 3이 나옵니다. 그런데 서브쿼리 결과에 NULL이 하나라도 섞이면 결과가 0행이 됩니다. 3 NOT IN (1, 2, NULL)은 3 <> 1 AND 3 <> 2 AND 3 <> NULL과 같고, 마지막 비교가 UNKNOWN이라 전체가 TRUE가 될 수 없기 때문입니다(3값 논리). 이 교재의 orders.customer_id는 NOT NULL이라 안전하지만, NULL이 들어올 수 있는 열에는 NOT EXISTS나 LEFT JOIN 뒤 IS NULL로 찾는 안티 조인을 씁니다.

주문 행을 유지하며 묶음으로 계산하기

GROUP BY customer_id는 고객 1의 두 주문을 결과 한 줄로 합칩니다. 고객별로 주문을 나열하면서 각 주문에 누적액을 붙이려면 윈도 함수를 사용합니다. SUM(total_won) OVER (...)처럼 OVER 안에 계산에 포함할 다른 행을 지정하면 같은 SELECT 결과에서 주문마다 계산된 열이 하나 추가됩니다.

PARTITION BY customer_id는 고객이 바뀔 때 계산을 나눕니다. ORDER BY order_date, order_id는 묶음 안의 순서를 정합니다. 예제의 주문 날짜는 고정 폭의 YYYY-MM-DD 문자열이라 날짜순으로 정렬됩니다. 같은 날짜의 주문은 주문 번호로 순서를 결정합니다. ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW는 묶음의 첫 행에서 현재까지를 프레임으로 정합니다. 누적 합계에만 넣을 행을 고르는 규칙입니다. ROW_NUMBER()는 같은 묶음 내의 정렬 순번을 부여합니다.

윈도 안의 정렬은 계산 순서에 적용합니다. 결과 출력 순서를 보장하려면 SELECT의 마지막에 별도로 ORDER BY를 씁니다. 윈도에 ORDER BY만 쓰고 프레임을 생략하면 표준 SQL의 기본 프레임 RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW가 적용됩니다(SQLite·PostgreSQL 모두 같음). RANGE는 정렬 값이 같은 행(동점)을 한꺼번에 현재 행으로 취급하므로, 날짜만으로 정렬하면 같은 날짜의 행들이 함께 포함됩니다. 첫날 금액 10과 5, 다음 날 7이라면 날짜별 계산 결과는 15, 15, 22입니다. 주문 번호까지 순서를 정하고 ROWS로 처음부터 현재 행까지 포함하면 10, 15, 22로 한 행씩 늘어납니다.

세 조회를 같은 데이터에서 실행

실행 예제

import sqlite3

with sqlite3.connect(":memory:") as db:
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript("""
    CREATE TABLE customers (
        customer_id INTEGER PRIMARY KEY,
        name TEXT NOT NULL
    );
    CREATE TABLE orders (
        order_id INTEGER PRIMARY KEY,
        customer_id INTEGER NOT NULL REFERENCES customers(customer_id),
        order_date TEXT NOT NULL,
        status TEXT NOT NULL CHECK (status IN ('paid', 'pending')),
        total_won INTEGER NOT NULL CHECK (total_won >= 0),
        coupon_won INTEGER CHECK (coupon_won >= 0)
    );
    """)
    db.executemany("INSERT INTO customers VALUES (?, ?)", [
        (1, 'Mina'),
        (2, 'Jun'),
        (3, 'Sol'),
    ])
    db.executemany("INSERT INTO orders VALUES (?, ?, ?, ?, ?, ?)", [
        (101, 1, '2025-01-02', 'paid', 10000, None),
        (102, 1, '2025-01-03', 'paid', 15000, 1000),
        (103, 2, '2025-01-04', 'pending', 12000, None),
        (104, 2, '2025-01-05', 'paid', 15000, 0),
    ])

    large = db.execute("""
        SELECT order_id FROM orders
        WHERE total_won > (SELECT AVG(total_won) FROM orders)
        ORDER BY order_id
    """).fetchall()
    paid = db.execute("""
        SELECT c.customer_id FROM customers AS c
        WHERE EXISTS (
            SELECT 1 FROM orders AS o
            WHERE o.customer_id = c.customer_id AND o.status = ?
        )
        ORDER BY c.customer_id
    """, ("paid",)).fetchall()
    running = db.execute("""
        SELECT customer_id, order_id,
               ROW_NUMBER() OVER (
                   PARTITION BY customer_id ORDER BY order_date, order_id
               ) AS position,
               SUM(total_won) OVER (
                   PARTITION BY customer_id ORDER BY order_date, order_id
                   ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
               ) AS running_won
        FROM orders
        ORDER BY customer_id, order_date, order_id
    """).fetchall()
    print("above average:", [row[0] for row in large])
    print("paid customers:", [row[0] for row in paid])
    print("running:", running)
db.close()

실행 결과

above average: [102, 104]
paid customers: [1, 2]
running: [(1, 101, 1, 10000), (1, 102, 2, 25000), (2, 103, 1, 12000), (2, 104, 2, 27000)]

결제 완료 여부를 확인한 두 번째 질의에서 고객 1은 완료 주문을 두 건 가졌지만 고객 번호는 한 번만 나옵니다. 마지막 질의는 네 주문 모두를 읽으며 결제 상태로 행을 거르지 않습니다.
