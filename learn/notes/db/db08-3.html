CAP 정리에서 일관성과 가용성이 충돌하는 조건

값이 0인 항목을 노드 두 곳에 복제합니다. 두 노드는 살아 있지만 통신이 끊겼습니다. 한쪽에서 쓰기를 마친 뒤 다른 쪽에서는 언제 무엇을 읽을 수 있을지 따져 봅니다.

이 장을 읽고 나면

  • CAP에서 말하는 일관성·가용성과 네트워크 분할의 뜻을 말한다.
  • 같은 관측으로 서로 다른 정답을 요구하는 두 상황을 비교한다.
  • 장애 중 기다림·거절·오래된 값 반환에 따르는 조건을 설명한다.

전제가 있는 정리

Gilbert와 Lynch의 CAP 정리는 복제한 하나의 읽기·쓰기 데이터 객체를 다룹니다. 비동기 네트워크 모형에서는 메시지가 언제 도착할지 상한을 보장하지 않으며, 두 노드 사이의 메시지가 계속 소실되는 실행도 허용합니다. 다음 세 조건을 동시에 언제나 만족시킬 수 있는지가 질문입니다.

일관성 C은 하나의 데이터 객체에 연산을 한 번에 하나씩 적용한 것처럼 동작하는 선형화 가능성입니다. 한 연산이 끝난 뒤에 다른 연산이 시작됐다면 그 순서를 지켜야 합니다. 실행이 겹친 연산을 무조건 시작한 순서대로 놓지는 않습니다. 예를 들어 쓰기 1이 완료된 다음 읽기가 시작되고 중간에 다른 쓰기가 없으면 읽기는 1을 돌려줘야 합니다. 이는 한 트랜잭션이 제약을 보존하는 ACID의 C와 다른 질문입니다.

가용성 A는 정상 노드가 받은 모든 읽기·쓰기 요청이 결국 해당 연산의 응답으로 완료된다는 뜻입니다. 정상 값을 읽는 계약에서 영원히 기다리거나 요청을 거절하면 이 조건을 충족하지 못합니다. 100ms 안처럼 고정된 응답시간 목표와도 구분합니다. 분할 P의 전제는 활성 노드들이 서로 메시지를 전하지 못하는 실행도 견뎌야 한다는 것입니다.

읽는 노드에서 구별할 수 없는 두 상황

처음 x=0인 사본이 A와 B에 있습니다. 분할 중에 A의 클라이언트와 B의 클라이언트는 자기 노드에 접속할 수 있다고 합시다. 상황 1에서는 쓰기가 없습니다. 상황 2에서는 A가 x=1 쓰기를 받아 완료 응답을 보냅니다. 모든 정상 노드에서 가용성을 보장한다면 그 쓰기도 완료되어야 합니다.

이후 B에 같은 읽기 요청을 보냅니다. B의 시작 값과 받은 요청, 노드 사이에 온 메시지가 두 상황에서 같습니다. 읽기 시작 전에 완료된 쓰기 결과를 반영하려는 일관성은 상황 1에서 0, 상황 2에서 1을 요구합니다. B는 두 상황을 가를 정보를 받지 못했으니 언제나 올바른 값을 고를 수 없습니다.

읽기 동작을 비교하고 영향을 정한다

B가 자기 사본의 0을 돌려주면 응답은 오지만 상황 2에서 오래된 값입니다. 다른 쪽의 최신성을 확인할 때까지 기다리면 모르는 값을 단정하지 않지만, 단절이 계속될 경우 정상 노드에서 요청이 완료된다는 조건을 지킬 수 없습니다. 마찬가지로 A가 쓰기를 확인하지 못해 완료할 수 없는 방식을 택하면 쓰기의 가용성이 제한됩니다.

시스템에서 읽기와 쓰기의 중요도가 다르면 연산별로 허용할 동작을 정할 수 있습니다. 주문 상태의 과거 화면을 잠시 보여도 되는 읽기와 같은 주문의 재고를 확정하는 쓰기는 요구가 다를 수 있습니다. CAP의 전제에서 벗어나 통신이 복구된 평상시의 지연과 오류율은 실측과 시스템의 보장으로 따로 판단합니다. 실험에서 관찰한 응답 하나로 모든 장애의 동작을 단정하기 어렵습니다.

두 상황에서 세 응답을 모두 확인

실행 예제

required = {"no prior write": 0, "write 1 completed": 1}
actions = [
    ("return local 0", 0),
    ("guess 1", 1),
    ("no value while disconnected", None),
]
for action, response in actions:
    completed = response is not None
    wrong = [name for name, value in required.items()
             if completed and response != value]
    print(action, "| completed:", completed, "| wrong in:", wrong)

실행 결과

return local 0 | completed: True | wrong in: ['write 1 completed']
guess 1 | completed: True | wrong in: ['no prior write']
no value while disconnected | completed: False | wrong in: []

마지막 행은 잘못된 값이 출력되지 않아도 읽기가 완료되지 않았음을 보입니다. 예제는 두 상황에서 값을 하나 반환하는 결정을 비교한 것으로, 전체 합의 알고리즘을 구현한 코드가 아닙니다.
