DB11·2

미리 쓴 로그에서 커밋의 효과를 되살리고 미완료 변경 되돌리기

작업이 끊긴 직후 저장된 두 페이지의 합계가 이상합니다. 어떤 변경이 완료됐고 어떤 변경만 먼저 새어 나갔는지 로그를 따라가며 다시 계산합니다.

이 장을 읽고 나면

  • 버퍼 정책이 복구의 redo·undo를 요구하는 이유를 설명한다.
  • 페이지 LSN으로 이미 적용한 변경을 골라낸다.
  • 같은 저장 관측과 로그 복구가 어떤 값을 보장하는지 검산한다.

로그가 먼저 영속되는 순서를 정한다

버퍼의 수정 페이지는 저장소에 즉시 기록되지 않을 수 있습니다. 커밋 때 모든 데이터 페이지 쓰기를 강제하지 않는 정책을 no-force라 합니다. 이미 커밋한 값이 저장소에 없을 때 다시 반영하는 redo가 필요합니다. 미커밋 페이지도 자리를 비우기 위해 먼저 저장할 수 있는 정책을 steal이라 합니다. 이후 미완료로 판단한 거래의 변경을 되돌리는 undo가 필요할 수 있습니다.

미리 쓰는 로그(WAL)에서는 수정 데이터 페이지를 영속 저장소로 내보내기 전에 그 변경을 설명할 로그를 먼저 영속합니다. 거래를 영속 커밋했다고 응답하기 전에 관련 로그와 커밋 기록을 영속합니다. 버퍼 메모리에서 먼저 계산하는 것과 영속 장치에 기록 완료를 선언하는 조건은 구분합니다.

어느 페이지에 이전 변경이 이미 들어 있는지 확인한다

LSN거래로그 기록
1T₁X 10→7
2T₁Y 20→23
3T₁커밋
4T₂X 7→99

처음 값은 X=10, Y=20입니다. 로그 번호 LSN 4까지 영속됐다고 둡니다. T₂의 커밋 기록은 없습니다. 중단 때 디스크 X는 (LSN 4, 값 99), Y는 (LSN 0, 값 20)입니다. 로그를 순서대로 다시 적용하는 redo에서, 페이지 LSN이 이미 해당 기록 이상이면 그 변경이 반영된 페이지로 보고 건너뜁니다. X의 두 변경은 건너뛰고, Y에는 LSN 2의 23을 적용합니다.

이제 커밋이 없는 T₂의 최종 로그에서 변경 전 값 7을 가져와 X를 되돌립니다. 복구 뒤 X+Y는 30입니다. 실제 ARIES는 세 단계로 복구합니다. 분석 단계는 마지막 체크포인트부터 로그를 읽어 중단 때 활동 중이던 거래 표와 수정 페이지 표(dirty page table)를 만들고 redo를 시작할 위치를 정합니다. redo 단계는 미완료 거래의 변경까지 포함해 로그를 순서대로 다시 적용해 중단 직전 상태를 그대로 재현합니다(이력 반복, repeating history). 이때 이 장처럼 pageLSN이 로그 LSN 이상이면 건너뜁니다. undo 단계는 미완료 거래의 변경을 LSN이 큰 것부터 되돌리면서 되돌린 일마다 보상 로그 레코드(CLR)를 남깁니다. CLR은 다시 되돌리지 않는 기록이라, 복구 도중 또 중단돼도 같은 변경을 두 번 되돌리지 않고 이어서 진행할 수 있습니다. 이 실습은 한 번의 복구가 끝까지 실행되고 거래 둘의 변경 순서가 위와 같다고 둔 메모리 모형입니다.

아직 어느 데이터가 영속됐는지에 따라 시작을 바꾸어 본다

세 가지 시작 상태에서 같은 영속 로그를 읽습니다. 데이터 페이지가 아직 하나도 쓰이지 않은 상태, X의 미완료 변경만 쓰인 상태, T₁의 두 변경만 쓰인 상태입니다. redo에서 모두 같은 이력 상태를 얻고, undo 뒤에는 커밋된 값만 남는지 검사합니다. 실제 DB를 중단하지 않고 값과 페이지 LSN으로 만든 표에 대해서만 계산합니다.

log = [(1,1,"X",10,7),(2,1,"Y",20,23),
       (3,1,None,None,None),(4,2,"X",7,99)]

def recover(disk):
    pages = dict(disk)
    committed = {tid for _,tid,key,_,_ in log if key is None}
    for lsn,tid,key,before,after in log:
        if key is not None and pages[key][0]<lsn:
            pages[key]=(lsn,after)
    result={key:value for key,(_,value) in pages.items()}
    for lsn,tid,key,before,after in reversed(log):
        if key is not None and tid not in committed:
            result[key]=before
    return result

for x,y in (((0,10),(0,20)),((4,99),(0,20)),((1,7),(2,23))):
    result=recover({"X":x,"Y":y})
    print(result["X"],result["Y"],sum(result.values()))
    assert result=={"X":7,"Y":23}

한눈에 정리

핵심어기억할 기준
steal / no-forcesteal이면 미커밋 변경이 디스크에 있을 수 있어 undo가, no-force면 커밋 변경이 디스크에 없을 수 있어 redo가 필요합니다.
WAL 규칙데이터 페이지보다 그 로그를 먼저, 커밋 응답보다 커밋 기록까지의 로그를 먼저 영속합니다.
pageLSNpageLSN ≥ 로그 LSN이면 이미 반영된 변경이므로 redo를 건너뜁니다.
ARIES분석 → redo(이력 반복) → undo(CLR 기록). 예제 복구 결과는 X=7, Y=23입니다.

한 줄 정리

어느 페이지가 디스크에 먼저 나갔든, 영속 로그만 있으면 redo로 이력을 재현하고 undo로 미완료 거래를 지워 같은 상태에 도달합니다.
