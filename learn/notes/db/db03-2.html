DB03·2

다대다 관계와 결합 전에 입도 맞추기

주문 하나에 두 항목과 두 태그가 달렸습니다. 상세 기록을 한꺼번에 연결했더니 주문액을 네 번 셌습니다. 결합에서 행이 얼마나 늘어나는지 먼저 예상해 봅니다.

이 장을 읽고 나면

  • 다대다 관계와 중간 표의 역할을 설명한다.
  • 상세 표를 두 개 결합할 때 주문 하나당 행 수를 계산한다.
  • 원본 집계나 사전 집계로 주문 입도를 유지한다.

여러 상품을 담는 주문, 여러 주문에 담기는 상품

한 주문은 여러 상품을 담고, 같은 상품은 여러 주문에 나올 수 있습니다. 이것이 다대다 관계입니다. order_items는 주문 번호와 상품 번호를 함께 담아 이 관계를 표현합니다. 그 자체의 입도는 주문과 상품의 단순 조합이 아니라 주문의 항목 한 줄입니다. 같은 상품을 여러 줄로 둘 수 있게 하려면 상품 번호만으로 항목을 식별하지 않습니다.

연결만 필요하다면 (order_id, tag)를 기본 키로 두어 주문에 태그 하나가 달렸다는 사실을 한 번만 기록할 수 있습니다. order_tags에서 주문 101은 gift와 pickup이고, 주문 102는 pickup입니다. 주문과 태그 모두 반대쪽과 여러 번 이어질 수 있습니다.

같은 주문 아래에 항목과 태그가 여러 줄

서로 다른 두 상세를 order_id만으로 주문에 INNER JOIN합니다. 한 주문에 항목 m줄과 태그 k줄이 있다면, 항목 한 줄이 모든 태그와 짝을 이뤄 결과는 m×k줄입니다. 태그가 없으면 내부 결합에서는 주문의 항목이 있어도 결과 줄이 없습니다.

원래 주문 101의 할인 전 합계는 10,000원입니다. 이 상세 결합에서 SUM(o.total_won)을 계산하면 주문 101의 네 행에서 총 40,000원을 더하게 됩니다. 주문 102와 104의 15,000원까지 포함하여 태그 있는 세 주문의 실제 총액은 40,000원인데 잘못된 상세 결합의 합은 85,000원입니다. SUM(DISTINCT o.total_won)은 값이 같은 서로 다른 주문 102와 104를 하나처럼 취급하여 25,000원을 줍니다. 주문의 식별자를 확인해야 하는 문제입니다.

상세별로 요약한 뒤 주문에 연결

주문 총액만 필요하면 주문 표에서 원하는 주문을 골라 바로 합할 수 있습니다. 항목 합과 태그 개수도 필요하면 항목 표에서 주문별 항목 수와 금액을 구하고, 태그 표에서 주문별 태그 수를 따로 구합니다. GROUP BY order_id로 요약하면 각 결과의 주문 번호는 유일합니다. 요약한 두 표를 주문에 LEFT JOIN하면 태그 없는 주문도 유지됩니다.

SQL의 WITH ... AS (...)는 이어지는 질의 안에서 이름 붙여 쓰는 중간 결과입니다. 아래의 COALESCE(tags.tag_count, 0)은 맨 앞의 NULL이 아닌 값을 택합니다. 태그 원본에 그 주문의 관계가 하나도 없다는 사실을 이 장의 자료 정의에서 알고 있으므로 태그 개수 0으로 해석합니다. 모르는 할인액에 같은 처리 규칙을 넣을 근거는 없습니다.

잘못된 합과 주문별 요약 비교

실행 예제

import sqlite3

with sqlite3.connect(":memory:") as db:
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript("""
    CREATE TABLE customers (
        customer_id INTEGER PRIMARY KEY,
        name TEXT NOT NULL
    );
    CREATE TABLE orders (
        order_id INTEGER PRIMARY KEY,
        customer_id INTEGER NOT NULL REFERENCES customers(customer_id),
        order_date TEXT NOT NULL,
        status TEXT NOT NULL CHECK (status IN ('paid', 'pending')),
        total_won INTEGER NOT NULL CHECK (total_won >= 0),
        coupon_won INTEGER CHECK (coupon_won >= 0)
    );
    CREATE TABLE products (
        product_id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        list_price_won INTEGER NOT NULL CHECK (list_price_won >= 0)
    );
    CREATE TABLE order_items (
        order_id INTEGER NOT NULL REFERENCES orders(order_id),
        line_no INTEGER NOT NULL,
        product_id INTEGER NOT NULL REFERENCES products(product_id),
        qty INTEGER NOT NULL CHECK (qty > 0),
        unit_price_won INTEGER NOT NULL CHECK (unit_price_won >= 0),
        PRIMARY KEY (order_id, line_no)
    );
    CREATE TABLE order_tags (
        order_id INTEGER NOT NULL REFERENCES orders(order_id),
        tag TEXT NOT NULL,
        PRIMARY KEY (order_id, tag)
    );
    """)
    db.executemany("INSERT INTO customers VALUES (?, ?)", [
        (1, 'Mina'),
        (2, 'Jun'),
        (3, 'Sol'),
    ])
    db.executemany("INSERT INTO orders VALUES (?, ?, ?, ?, ?, ?)", [
        (101, 1, '2025-01-02', 'paid', 10000, None),
        (102, 1, '2025-01-03', 'paid', 15000, 1000),
        (103, 2, '2025-01-04', 'pending', 12000, None),
        (104, 2, '2025-01-05', 'paid', 15000, 0),
    ])
    db.executemany("INSERT INTO products VALUES (?, ?, ?)", [
        (11, 'notebook', 6000),
        (12, 'pen', 2000),
        (13, 'pouch', 3000),
    ])
    db.executemany("INSERT INTO order_items VALUES (?, ?, ?, ?, ?)", [
        (101, 1, 11, 1, 6000),
        (101, 2, 12, 2, 2000),
        (102, 1, 11, 2, 6000),
        (102, 2, 13, 1, 3000),
        (103, 1, 11, 2, 6000),
        (104, 1, 13, 5, 3000),
    ])
    db.executemany("INSERT INTO order_tags VALUES (?, ?)", [
        (101, 'gift'),
        (101, 'pickup'),
        (102, 'pickup'),
        (104, 'repeat'),
    ])

    rows, inflated, distinct_amounts = db.execute("""
        SELECT COUNT(*), SUM(o.total_won), SUM(DISTINCT o.total_won)
        FROM orders AS o
        JOIN order_items AS i ON o.order_id = i.order_id
        JOIN order_tags AS t ON o.order_id = t.order_id
    """).fetchone()
    print("detail join:", rows, inflated, distinct_amounts)

    summary = db.execute("""
        WITH items AS (
            SELECT order_id, COUNT(*) AS item_count, SUM(qty * unit_price_won) AS amount
            FROM order_items GROUP BY order_id
        ), tags AS (
            SELECT order_id, COUNT(*) AS tag_count
            FROM order_tags GROUP BY order_id
        )
        SELECT o.order_id, items.item_count, items.amount, COALESCE(tags.tag_count, 0)
        FROM orders AS o
        LEFT JOIN items ON o.order_id = items.order_id
        LEFT JOIN tags ON o.order_id = tags.order_id
        ORDER BY o.order_id
    """).fetchall()
    print("order summaries:", summary)
db.close()

실행 결과

detail join: 7 85000 25000
order summaries: [(101, 2, 10000, 2), (102, 2, 15000, 1), (103, 1, 12000, 0), (104, 1, 15000, 1)]

내부 결합의 7행은 주문 101의 4행, 102의 2행, 104의 1행으로 이루어집니다. 요약 결과는 원본의 모든 주문 번호가 하나씩 나타나 4행입니다.
