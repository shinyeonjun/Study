DB06·1

API의 요청·응답, JSON과 웹 페이지 구조

주문 목록을 받으려면 어디에 무엇을 요청하고 어떤 형식의 답이 돌아오는지 알아야 합니다. 같은 주문 목록도 HTML 화면에는 표시 구조가 있고 JSON에는 데이터 구조가 있습니다.

이 장을 읽고 나면

  • API 요청과 응답에서 메서드, 경로, 상태, 헤더, 본문의 역할을 구별한다.
  • JSON의 객체·배열과 null을 파이썬 값으로 읽는다.
  • HTML 문서의 요소와 JSON 응답의 필드를 구분한다.

프로그램끼리 주고받기로 정한 규칙

API는 프로그램이 다른 시스템에 어떤 동작이나 자료를 요청할 수 있는지 정한 인터페이스입니다. 이 장은 HTTP를 사용하는 주문 API를 가정합니다. GET /orders에서 GET은 읽기를 요청하는 메서드, /orders는 자료의 경로입니다. 응답은 상태 코드, 본문의 설명을 담을 수 있는 헤더, 필요한 자료를 전달하는 본문으로 이루어집니다. 요청도 헤더와 경우에 따라 본문을 가질 수 있습니다. 읽는 GET 외에 새로 만드는 POST, 바꾸는 PUT·PATCH, 지우는 DELETE 같은 메서드가 있습니다.

상태 200은 이 예의 목록 요청이 성공했음을 뜻합니다. Content-Type이 application/json이면 JSON 형식의 본문을 예상할 수 있습니다. 성공 상태에서도 기대한 필드가 있는지는 문서의 응답 구조와 대조합니다.

상태 코드뜻수집 프로그램의 대응
2xx (200, 201)성공본문 형식과 필드를 검증한 뒤 사용한다.
3xx (301, 304)다른 위치로 이동, 변경 없음안내된 위치나 캐시를 사용한다.
4xx (400, 401, 403, 404, 429)요청 쪽 문제같은 요청을 반복해도 대개 다시 실패한다. 429(요청 과다)는 안내된 시간만큼 기다렸다 재시도한다.
5xx (500, 503)서버 쪽 문제간격을 늘려 가며 정해진 횟수만 재시도한다.

실제 헤더는 application/json; charset=utf-8처럼 매개변수가 붙어 올 수 있습니다. 아래 예제는 단순화해 문자열 전체를 비교하지만, 실무 코드는 세미콜론 앞의 미디어 유형만 떼어 비교합니다.

문자열을 구조로 읽고 값의 의미 확인

JSON에서 객체는 문자열 키로 값에 접근합니다. 배열은 값에 순서를 부여합니다. {"orders": [{"order_id": 101}]}는 바깥 객체에서 orders 배열을 찾고 그 안의 첫 주문 객체를 읽을 수 있습니다.

앞서 쿠폰 기록을 모르는 값을 표에 NULL로 쓴 것처럼 JSON에서 null을 줄 수 있습니다. 제공자가 coupon_won을 생략했다면 뜻이 다를 수 있습니다. 예를 들어 API 버전이 해당 필드를 보내지 않는 경우와 필드를 보내지만 특정 주문의 값만 모르는 경우는 구분합니다.

화면을 표현하는 HTML

웹 페이지 문서는 제목, 문단, 링크, 표 같은 요소가 다른 요소 속에 놓인 구조입니다. <a href="/orders">주문</a>에서 href는 링크의 목적지이고 글자는 화면에 보이는 이름입니다. 화면의 글자만 복사하면 요소 관계와 속성을 잃을 수 있습니다.

공식 API가 있고 목적과 이용 권한이 맞으면 문서화된 데이터 필드와 버전을 읽습니다. 웹 화면에서 자료를 사용할 때는 제공자가 허용한 범위 안에서 쓰고, 화면 요소의 구성이 바뀌었는지 점검합니다.

모의 바이트열과 HTML 조각 읽기

실행 예제

import json
from html.parser import HTMLParser

status = 200
media_type = "application/json"
body = b'{"orders":[{"order_id":101,"coupon_won":null},{"order_id":102}]}'

if status != 200 or media_type != "application/json":
    raise ValueError("unexpected response")
payload = json.loads(body)
orders = payload["orders"]
print("ids:", [row["order_id"] for row in orders])
for row in orders:
    has_coupon = "coupon_won" in row
    print(row["order_id"], "has coupon field:", has_coupon,
          "value:", row.get("coupon_won"))

class Links(HTMLParser):
    def __init__(self):
        super().__init__()
        self.links = []

    def handle_starttag(self, tag, attrs):
        if tag == "a":
            attributes = dict(attrs)
            if "href" in attributes:
                self.links.append(attributes["href"])

parser = Links()
parser.feed('<main><h1>목록</h1><a href="/orders">주문</a></main>')
print("HTML link:", parser.links)

실행 결과

ids: [101, 102]
101 has coupon field: True value: None
102 has coupon field: False value: None
HTML link: ['/orders']

get은 필드가 없어도 None을 돌려줘 두 사례가 겉보기에는 같습니다. 존재 검사를 함께 하면 두 상태를 확인할 수 있습니다.
