GROUP BY와 집계의 분모

주문 네 건에서 결제 상태별 건수와 합계를 계산합니다. 같은 그룹에서도 전체 행 수와 값이 기록된 행 수는 다를 수 있습니다.

이 장을 읽고 나면

  • GROUP BY의 입력 행과 출력 그룹의 단위를 구별한다.
  • COUNT(*), COUNT(열), SUM, AVG에서 NULL 처리 방식을 설명한다.
  • WHERE와 HAVING을 조합해 그룹에 조건을 건다.

그룹 하나를 결과 한 줄로

GROUP BY status는 WHERE까지 적용되어 남은 주문을 상태값으로 묶습니다. 그룹마다 COUNT(*)나 SUM(total_won)을 계산하면 결과의 입도는 주문 한 건에서 상태 하나로 바뀝니다. 그룹을 정한 열과 그 그룹에서 계산한 집계를 결과에 적습니다. 그룹 안에 서로 다른 값이 있는 order_date를 아무 규칙 없이 선택하면 그 날짜가 그룹을 어떻게 대표하는지 모호합니다. SQLite는 이런 비집계 열을 허용하고 그룹 안의 한 행 값을 돌려주지만, PostgreSQL은 오류를 내고 MySQL도 기본 설정(ONLY_FULL_GROUP_BY)에서는 거부합니다. 표준 SQL에서 SELECT에 쓸 수 있는 것은 GROUP BY에 쓴 열과 집계 함수입니다. 이 동작에 기대지 않습니다.

NULL이 있어도 주문은 한 건

결제 완료 세 주문의 쿠폰 값은 NULL, 1000, 0입니다. COUNT(*)는 세 행을 모두 셉니다. COUNT(coupon_won)은 값이 NULL이 아닌 두 건을 세므로 쿠폰 할인이 있었던 건수와도 다릅니다. 양수 값을 비교해서 쿠폰액이 0보다 큰 행을 골라야 그 사례를 셉니다.

SUM(coupon_won)은 두 알려진 값의 합 1,000원을, AVG(coupon_won)은 그 두 건 평균 500원을 줍니다. 미결제 그룹에 알려진 쿠폰액이 한 건도 없어서 SUM과 AVG는 NULL입니다. NULL을 모두 0으로 처리하면 평균의 분모와 의미가 달라집니다. 모르는 값을 0으로 간주해도 되는지는 지표 정의가 결정합니다.

MIN과 MAX도 NULL을 건너뜁니다. COUNT(DISTINCT customer_id)는 NULL이 아닌 서로 다른 값의 개수를 셉니다. 네 주문의 COUNT(customer_id)는 4이지만 COUNT(DISTINCT customer_id)는 2이므로, 앞 장의 '주문한 고객 수'는 이 식으로 구합니다.

행 조건과 그룹 조건을 함께 쓰기

WHERE는 합을 계산하기 전 개별 주문부터 골라 냅니다. 가령 total_won >= 12000이면 102, 103, 104가 남습니다. 고객 번호 1은 주문 한 건, 번호 2는 주문 두 건을 갖습니다.

HAVING은 그룹에서 계산한 값에 대해 조건을 묻습니다. HAVING COUNT(*) >= 2를 쓰면 고객 2만 남습니다. '한 주문이 12,000원 이상'과 '그런 주문이 두 건 이상인 고객'은 서로 다른 수준의 질문입니다.

SELECT 문의 논리적 처리 순서

SELECT 문은 적힌 순서와 달리 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY 순서로 처리된다고 생각하면 결과를 정확히 예측할 수 있습니다. 실제 실행 계획은 최적화로 달라질 수 있지만 결과는 이 순서로 계산한 것과 같습니다. 그래서 WHERE 단계에는 아직 그룹이 없어 WHERE COUNT(*) >= 2는 오류입니다(SQLite: misuse of aggregate: COUNT()). SELECT에서 붙인 별칭은 그 뒤인 ORDER BY에서는 쓸 수 있지만 표준 SQL과 PostgreSQL에서는 WHERE에 쓸 수 없습니다. SQLite는 WHERE에서도 별칭을 받아 주지만 다른 DB로 옮기면 오류가 나므로 기대지 않습니다.

왜 그럴까?

결제 완료 주문 중 평균 금액이 1만 원을 넘는 고객을 찾으려면 어디에 조건을 쓸까?

모범 답 보기

결제 완료라는 조건은 WHERE에 쓰고, 고객별로 그룹화한 뒤 HAVING AVG(total_won) > 10000을 사용합니다.

두 집계의 결과를 읽기

실행 예제

import sqlite3

with sqlite3.connect(":memory:") as db:
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript("""
    CREATE TABLE customers (
        customer_id INTEGER PRIMARY KEY,
        name TEXT NOT NULL
    );
    CREATE TABLE orders (
        order_id INTEGER PRIMARY KEY,
        customer_id INTEGER NOT NULL REFERENCES customers(customer_id),
        order_date TEXT NOT NULL,
        status TEXT NOT NULL CHECK (status IN ('paid', 'pending')),
        total_won INTEGER NOT NULL CHECK (total_won >= 0),
        coupon_won INTEGER CHECK (coupon_won >= 0)
    );
    """)
    db.executemany("INSERT INTO customers VALUES (?, ?)", [
        (1, 'Mina'),
        (2, 'Jun'),
        (3, 'Sol'),
    ])
    db.executemany("INSERT INTO orders VALUES (?, ?, ?, ?, ?, ?)", [
        (101, 1, '2025-01-02', 'paid', 10000, None),
        (102, 1, '2025-01-03', 'paid', 15000, 1000),
        (103, 2, '2025-01-04', 'pending', 12000, None),
        (104, 2, '2025-01-05', 'paid', 15000, 0),
    ])

    by_status = db.execute("""
        SELECT status, COUNT(*) AS order_count,
               COUNT(coupon_won) AS known_coupon_count,
               SUM(total_won) AS gross_won, SUM(coupon_won) AS coupon_sum,
               AVG(coupon_won) AS known_coupon_mean
        FROM orders
        GROUP BY status
        ORDER BY status
    """).fetchall()
    for row in by_status:
        print(row)

    frequent = db.execute("""
        SELECT customer_id, COUNT(*) AS order_count, SUM(total_won) AS gross_won
        FROM orders
        WHERE total_won >= ?
        GROUP BY customer_id
        HAVING COUNT(*) >= ?
        ORDER BY customer_id
    """, (12_000, 2)).fetchall()
    print("qualifying customers:", frequent)
db.close()

실행 결과

('paid', 3, 2, 40000, 1000, 500.0)
('pending', 1, 0, 12000, None, None)
qualifying customers: [(2, 2, 27000)]

AS는 결과 열에 이름을 붙입니다. Python에서 보이는 None은 조회 결과의 SQL NULL입니다. 마지막 행은 고객 2에게 조건을 통과한 주문이 2건 있고 합계가 27,000원이라는 뜻입니다.
