DB10·1

같은 조인을 여러 연산으로 실행하고 계획 비용 비교하기

조인 조건은 하나여도 행을 찾는 방법은 여러 가지입니다. 중복 때문에 나오는 행을 세고, 같은 답을 내는 세 계획 중 어느 쪽이 중간 결과를 적게 만드는지 계산합니다.

이 장을 읽고 나면

  • 논리적 내부 조인과 그것을 실행하는 물리 연산자를 구별한다.
  • 중복과 NULL을 고려해 정확한 출력 행 수를 구한다.
  • 비용 단위를 명시하고 세 가지 조인 순서를 대조한다.

부모 연산자가 다음 행을 요청한다

필터가 조인 결과를 읽을 때 모든 중간 행을 한꺼번에 만들 필요는 없습니다. iterator 모델에서 위 연산자가 다음 행을 요청하면 아래에서 필요할 때 데이터를 처리합니다. 다만 예제의 해시 조인이 한쪽 입력으로 해시 구조를 먼저 만든다면 그 입력은 결과를 내기 전에 읽어야 합니다. 정렬이 필요한 병합 조인도 입력 준비에 시간이 듭니다.

SQL에서 두 표의 키가 같을 때 결합하는 내부 조인을 생각합니다. 장난감 입력 L=[1,2,2,3,NULL], S=[2,2,3,4,NULL]에서 키 2는 양쪽 두 행씩이어서 2×2=4개 행 쌍을 냅니다. 키 3에서 1×1=1개를 더합니다. 일반 동등 연산에서 두 NULL은 서로 참으로 비교되지 않아 출력에 포함되지 않습니다.

후보 비교, 해시 조회, 정렬 준비를 따로 센다

물리 연산작은 모형에서 계산한 작업추가로 따질 비용
중첩 반복NULL 제외 4×4=16개의 키 비교같은 행을 몇 번 읽는가
해시S 삽입 4개, L 조회 4개해시 및 충돌 처리, 메모리
정렬·병합이미 모은 키 그룹 3번 비교정렬과 그룹 만들기, 중복 행 출력

정렬한 병합에서는 양쪽 가장 작은 미처리 키를 비교합니다. 1 대 2에서 왼쪽을 전진한 뒤, 2 대 2와 3 대 3에서 각 쌍의 조합을 모두 냅니다. 일반 해시 조인은 같은 키를 가진 모든 행을 보존해야 합니다. 아래 코드처럼 출력이 키뿐이면 해시에 키 빈도만 담아도 같은 키를 필요한 횟수만큼 출력할 수 있습니다. 비교 한 번과 해시 조회 한 번이 같은 시간이라고 미리 결론 내리지 않습니다. 어떤 단위로 셌는지와 출력 5건의 작업을 같이 기록합니다.

세 관계에서 먼저 만들 중간표를 선택한다

T=[3,4]도 같은 키로 조인합니다. 중첩 반복에서 후보 키 비교를 동일 단가로 잡고 NULL은 먼저 제거했다고 둡니다. 각 순서는 같은 최종 키 [3]을 내지만 중간 행 수가 달라 뒤 조인의 후보 수도 바뀝니다.

먼저 결합할 관계중간 행후보 비교 합
L과 S54·4+5·2=26
L과 T14·2+1·4=12
S와 T24·2+2·4=16

행 수 추정이 어긋나면 계획도 달라질 수 있다

정확한 출력 행 수는 NULL을 제외한 키별 빈도의 곱을 합한 값입니다. 키가 두 종류이고 양쪽 100행이어도 빈도가 각각 (99,1)이라면 9,802행입니다. 오른쪽 빈도를 (1,99)로 뒤집으면 198행입니다. 두 경우를 같은 균등 빈도로 근사한 100·100/2=5,000은 서로 다른 실제 값을 구별하지 못합니다. 실제 DB에서 EXPLAIN의 계획 비용과 예상 행, 실행한 분석의 실제 행과 측정 시간을 각각 봅니다.

from collections import Counter
from contextlib import closing
import sqlite3

tables={"L":[1,2,2,3,None],"S":[2,2,3,4,None],"T":[3,4]}

def match(left,right):
    return [x for x in left for y in right if x==y]

def hashed(left,right):
    groups=Counter(right)
    for key in left:
        for _ in range(groups[key]):
            yield key

clean={k:[x for x in seq if x is not None] for k,seq in tables.items()}
print(list(hashed(clean["L"],clean["S"])))
with closing(sqlite3.connect(":memory:")) as connection:
    connection.executescript("CREATE TABLE l(k); CREATE TABLE s(k);")
    connection.executemany("INSERT INTO l VALUES (?)",[(x,) for x in tables["L"]])
    connection.executemany("INSERT INTO s VALUES (?)",[(x,) for x in tables["S"]])
    print(connection.execute(
        "SELECT l.k, COUNT(*) FROM l JOIN s ON l.k=s.k GROUP BY l.k ORDER BY l.k"
    ).fetchall())

for a,b,c in ("LST","LTS","STL"):
    left,right,last = clean[a],clean[b],clean[c]
    mid=match(left,right)
    result=match(mid,last)
    print(a+b,len(mid),len(left)*len(right)+len(mid)*len(last),result)
    assert result==[3]
