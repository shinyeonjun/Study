행을 선택하고 조건값을 바인딩하기

어떤 주문을 볼지, 어떤 열을 표시할지, 어떤 순서로 출력할지를 각각 적습니다. 사용자가 선택하는 조건값은 SQL과 함께 값으로 전달합니다.

이 장을 읽고 나면

  • SELECT, FROM, WHERE, ORDER BY의 역할을 구별한다.
  • NULL과 일반 비교의 차이를 설명하고 IS NULL을 쓴다.
  • sqlite3에서 고정된 SQL의 자리표시자에 값을 전달한다.

필요한 행과 열을 고르기

SELECT order_id, total_won FROM orders에서 FROM은 읽을 표, SELECT는 돌려줄 열을 정합니다. 결과에 WHERE status = 'paid' AND total_won >= 15000을 붙이면 조건을 만족하는 행만 남깁니다. 단일 따옴표 안의 'paid'는 문자열 값입니다. 예제에서는 주문 총액이 할인 전 원 단위이며 status는 결제 여부입니다.

두 행의 총액이 15,000원으로 같습니다. 큰 금액 우선, 금액이 같으면 주문 번호가 작은 순서로 표시하려면 ORDER BY total_won DESC, order_id ASC라고 씁니다. DESC는 내림차순, ASC는 오름차순입니다. 주문 번호가 유일해 두 번째 정렬까지 지정하면 이 예의 순서가 결정됩니다.

값을 모를 때와 0을 확인했을 때

coupon_won의 값이 0이면 쿠폰 할인액이 0으로 확인된 경우이고, NULL은 기록에서 할인액을 알 수 없는 경우입니다. NULL 값에 대해 coupon_won = 0을 평가하면 결과가 미지(UNKNOWN)가 됩니다. SQL의 WHERE에는 참만 남습니다. 따라서 이 조건으로 NULL 기록까지 찾을 수 없습니다.

누락된 쿠폰 기록은 coupon_won IS NULL, 기록이 있는 경우는 coupon_won IS NOT NULL로 확인합니다. 모르는 값과의 = NULL 비교도 참이 되지 않으므로 NULL 여부를 확인할 때에는 IS NULL을 사용합니다.

SQL의 조건식은 참(TRUE)·거짓(FALSE)·미지(UNKNOWN) 세 값 가운데 하나가 되는 3값 논리를 따릅니다. 비교하는 값에 NULL이 있으면 결과가 UNKNOWN이 되고, 그 UNKNOWN이 AND·OR·NOT을 거칠 때의 규칙은 아래 표와 같습니다. 원리는 하나입니다. UNKNOWN 자리에 참과 거짓 중 무엇을 넣어도 결과가 같으면 그 결과로 정해지고, 넣는 값에 따라 달라지면 UNKNOWN입니다.

ABA AND BA OR B
TRUEUNKNOWNUNKNOWNTRUE
FALSEUNKNOWNFALSEUNKNOWN
UNKNOWNUNKNOWNUNKNOWNUNKNOWN

NOT UNKNOWN도 UNKNOWN입니다. WHERE는 TRUE인 행만 남기므로 FALSE와 UNKNOWN은 똑같이 걸러집니다.

흔한 실수

'쿠폰액이 0이 아닌 주문'을 WHERE coupon_won <> 0으로 찾으면 이 자료에서는 102만 남고, 쿠폰액이 NULL인 101과 103도 빠집니다. NULL <> 0 역시 UNKNOWN이기 때문입니다. = 0으로 고른 행과 <> 0으로 고른 행을 합해도 전체가 되지 않습니다. NULL 행까지 원하면 coupon_won <> 0 OR coupon_won IS NULL처럼 따로 적습니다.

질의의 틀을 고정하고 값만 보내기

앱이 최소 주문액을 받아 질의를 한다면 SQL의 비교 위치에 ?를 쓰고 db.execute(질의, 값들의_튜플)로 값을 전달합니다. 이 방식을 매개변수 바인딩이라고 합니다. 자리표시자는 따옴표로 감싸지 않습니다. 매개변수가 두 개면 첫 값이 첫 자리, 다음 값이 두 번째 자리에 채워집니다. 사용자에게 입력받은 값은 정수 범위나 허용되는 상태인지 따로 검사할 수 있습니다.

자리표시자로 채우는 것은 값입니다. 선택할 열이나 정렬 방향을 화면에서 고르게 할 때는 애플리케이션이 미리 마련한 몇 개의 질의 중 하나를 고릅니다. 데이터베이스 드라이버에 따라 값의 자리표시자 문법은 다를 수 있으므로 여기서는 Python의 sqlite3 문법을 씁니다.

흔한 실수 · 문자열로 SQL 조립하기

입력값을 f-string이나 +로 SQL 문장에 끼워 넣으면, 입력 안의 따옴표가 문자열을 닫고 그 뒤가 SQL 구문으로 해석됩니다. 이렇게 입력으로 질의의 구조를 바꾸는 공격을 SQL 주입(SQL injection)이라고 합니다. 아래에서 상태 값으로 x' OR '1'='1을 받으면 조립한 문장의 조건이 status = 'x' OR '1'='1'이 되어 항상 참이고, 주문 네 건이 모두 나옵니다. 바인딩하면 같은 입력이 그 글자 그대로의 값 하나로 비교되어 일치하는 행이 없습니다. 드라이버는 SQL 문장과 값을 따로 전달하므로 값이 구문으로 해석되지 않습니다.

실행 예제

import sqlite3

with sqlite3.connect(":memory:") as db:
    db.execute("CREATE TABLE orders (order_id INTEGER PRIMARY KEY, status TEXT NOT NULL)")
    db.executemany("INSERT INTO orders VALUES (?, ?)",
                   [(101, "paid"), (102, "paid"), (103, "pending"), (104, "paid")])
    user_input = "x' OR '1'='1"

    unsafe = f"SELECT order_id FROM orders WHERE status = '{user_input}' ORDER BY order_id"
    print(unsafe)
    print("concatenated:", db.execute(unsafe).fetchall())
    safe = db.execute(
        "SELECT order_id FROM orders WHERE status = ? ORDER BY order_id", (user_input,)
    ).fetchall()
    print("bound:", safe)
db.close()

실행 결과

SELECT order_id FROM orders WHERE status = 'x' OR '1'='1' ORDER BY order_id
concatenated: [(101,), (102,), (103,), (104,)]
bound: []

조건과 값의 개수를 맞추기

실행 예제

import sqlite3

with sqlite3.connect(":memory:") as db:
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript("""
    CREATE TABLE customers (
        customer_id INTEGER PRIMARY KEY,
        name TEXT NOT NULL
    );
    CREATE TABLE orders (
        order_id INTEGER PRIMARY KEY,
        customer_id INTEGER NOT NULL REFERENCES customers(customer_id),
        order_date TEXT NOT NULL,
        status TEXT NOT NULL CHECK (status IN ('paid', 'pending')),
        total_won INTEGER NOT NULL CHECK (total_won >= 0),
        coupon_won INTEGER CHECK (coupon_won >= 0)
    );
    """)
    db.executemany("INSERT INTO customers VALUES (?, ?)", [
        (1, 'Mina'),
        (2, 'Jun'),
        (3, 'Sol'),
    ])
    db.executemany("INSERT INTO orders VALUES (?, ?, ?, ?, ?, ?)", [
        (101, 1, '2025-01-02', 'paid', 10000, None),
        (102, 1, '2025-01-03', 'paid', 15000, 1000),
        (103, 2, '2025-01-04', 'pending', 12000, None),
        (104, 2, '2025-01-05', 'paid', 15000, 0),
    ])

    query = """
        SELECT order_id, total_won
        FROM orders
        WHERE status = ? AND total_won >= ?
        ORDER BY total_won DESC, order_id ASC
    """
    result = db.execute(query, ("paid", 15_000)).fetchall()
    unknown = db.execute(
        "SELECT order_id FROM orders WHERE coupon_won IS NULL ORDER BY order_id"
    ).fetchall()
    zero = db.execute(
        "SELECT order_id FROM orders WHERE coupon_won = ? ORDER BY order_id",
        (0,),
    ).fetchall()
    print("paid >= 15000:", result)
    print("coupon unknown:", [row[0] for row in unknown])
    print("coupon zero:", [row[0] for row in zero])
db.close()

실행 결과

paid >= 15000: [(102, 15000), (104, 15000)]
coupon unknown: [101, 103]
coupon zero: [104]
