DB09·1

슬롯 페이지의 레코드 주소와 B+트리의 페이지 분할

좁은 서랍에서 종이를 앞으로 당겨 빈 공간을 모아도, 서류 번호는 유지해야 합니다. 한 페이지의 슬롯과 키를 찾는 B+트리의 리프를 따로 만들어 이 관계를 확인합니다.

이 장을 읽고 나면

  • 페이지 번호와 슬롯 번호가 레코드를 가리키는 방식을 설명한다.
  • 가변 길이 레코드에서 연속 빈 공간을 손으로 계산한다.
  • B+트리 리프를 나눈 뒤 경계 키를 통해 올바른 리프로 들어간다.

슬롯 번호를 두고 바이트 위치를 연결한다

페이지는 저장소와 메모리 사이에서 옮기는 고정 길이 블록입니다. 한 페이지에 가변 길이 레코드를 여러 개 넣는다고 합시다. 앞쪽에는 헤더와 슬롯 배열을, 뒤쪽에는 레코드 바이트를 배치합니다. 슬롯에는 레코드의 시작 위치와 길이를 적습니다. 레코드 ID를 (페이지 번호, 슬롯 번호)로 잡으면 레코드 바이트의 위치를 바꿀 때 페이지의 슬롯 내용만 갱신하면 됩니다.

단순한 64바이트 페이지를 사용합니다. 헤더는 16바이트, 슬롯은 각 4바이트입니다. 10, 12, 14바이트 레코드를 뒤에서 차례로 배치하면 시작 위치는 54, 42, 28입니다. 앞쪽 메타데이터 끝은 16+3·4=28이고 마지막 레코드가 28에서 시작합니다. 새 레코드를 넣을 연속 빈 공간이 없습니다.

작업활성 슬롯의 시작 위치슬롯 영역 끝연속 빈 공간
A, B, C를 삽입A=54, B=42, C=28280
B 슬롯을 삭제 표시A=54, C=28280
남은 레코드를 압축A=54, C=402812
8바이트 D, 새 슬롯A=54, C=40, D=32320

B를 지워도 42~53 바이트에 빈 구멍만 생깁니다. 압축하면 C의 시작이 40으로 옮겨지고, C의 슬롯 번호(0부터 세어 A=0, B=1, C=2)는 2 그대로입니다. 유효 레코드 바이트 길이 24에 메타데이터 28을 빼면 64−24−28=12가 나옵니다. 이 공간을 이용해 D에 새 슬롯 4바이트와 데이터 8바이트를 할당할 수 있습니다. 삭제한 슬롯은 사용하지 않는다고 정한 예입니다. 실제 시스템이 슬롯을 재사용한다면 이전 레코드를 가리키던 주소와 새 레코드 주소를 잘못 혼동하지 않도록 관리합니다.

실제 PostgreSQL 페이지도 같은 구조입니다. 기본 8,192바이트 페이지의 앞에 24바이트 페이지 헤더, 이어서 항목마다 4바이트인 항목 식별자(line pointer) 배열이 앞에서부터 자라고, 행(튜플)은 페이지 끝에서부터 채워집니다. 행의 주소 ctid는 (블록 번호, 항목 번호)이며 항목 번호는 1부터 셉니다. 이 장의 16바이트 헤더·64바이트 페이지는 손으로 계산하기 위해 줄인 모형입니다.

인덱스 키의 범위를 페이지마다 나눈다

레코드 주소를 찾아가는 인덱스를 별도로 둡니다. B+트리에서는 검색에 쓰는 경계 키를 내부 노드에 두고, 키에 대응하는 레코드 주소를 리프에 둡니다. 리프를 키 순서대로 연결해 두면 범위 질의에서 처음 리프까지 트리를 내려간 뒤 옆으로 읽을 수 있습니다. 여기서는 각 키가 하나의 주소만 가리킵니다.

새 키 25 때문에 정렬된 리프가 4칸을 요구합니다. 왼쪽에 10,20, 오른쪽에 25,30을 두고 부모에 25를 복사하면 25 미만은 왼쪽으로, 이상은 오른쪽으로 갑니다. 부모 노드도 가득 차면 내부 노드를 나눕니다. 리프 분할은 오른쪽 첫 키를 부모에 복사해 리프에도 남기지만(데이터가 리프에 있어야 하므로), 내부 노드 분할은 가운데 키를 부모로 올려 보내고 두 내부 노드에는 남기지 않습니다. 예를 들어 키 최대 3개인 내부 노드에 [10,20,30,40]이 생기면 [10,20]과 [40]으로 나누고 30을 부모로 올립니다(올릴 키를 고르는 위치는 구현마다 다를 수 있습니다). 루트가 분할되면 새 루트를 만들어 모든 리프 깊이가 함께 한 단계 증가합니다. 이 예는 리프 분할 때 오른쪽 최소 키를 부모로 복사하는 규칙을 씁니다.

슬롯과 리프를 메모리에서 확인한다

size, header, slot_bytes = 64, 16, 4
records = [10, 12, 14]

def pack(lengths):
    cursor = size
    slots = []
    for length in lengths:
        if length:
            cursor -= length
            slots.append(cursor)
        else:
            slots.append(None)
    free = cursor - header - slot_bytes*len(slots)
    if free < 0:
        raise ValueError("page full")
    return slots, free

print(*pack(records))
print(*pack([10, 0, 14]))
print(*pack([10, 0, 14, 8]))

overflow = sorted([10,20,30] + [25])
left, right = overflow[:2], overflow[2:]
border = right[0]
print(border, left, right)
for key in overflow:
    page = left if key < border else right
    assert key in page

실행 결과

[54, 42, 28] 0
[54, None, 40] 12
[54, None, 40, 32] 0
25 [10, 20] [25, 30]

예제의 0은 실제 길이 0인 레코드가 들어왔다는 뜻 대신 삭제 슬롯을 나타냅니다. 쓰는 자료가 0바이트 레코드도 허용한다면 별도의 사용 여부 필드가 필요합니다. 슬롯 번호는 목록 인덱스로 추적하고, 리프의 순서와 키 경계를 따로 검증합니다.

한눈에 정리

핵심어기억할 기준
레코드 ID(페이지 번호, 슬롯 번호). 페이지 안에서 바이트를 옮겨도 슬롯만 고치면 주소가 유지됩니다.
슬롯 페이지헤더·슬롯 배열은 앞에서, 레코드는 뒤에서 자랍니다. 연속 빈 공간 = 레코드 시작 − 슬롯 영역 끝.
압축삭제로 생긴 구멍을 모아 연속 공간으로 만듭니다. 예제에서 0 → 12바이트.
B+트리 분할리프는 오른쪽 첫 키를 부모에 복사, 내부 노드는 가운데 키를 올려 보냅니다. 루트가 나뉠 때만 높이가 1 늘어납니다.

한 줄 정리

슬롯은 레코드의 바이트 위치를 숨기고, B+트리의 경계 키는 키 범위를 리프 페이지로 나눕니다.
