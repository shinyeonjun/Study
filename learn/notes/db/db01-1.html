표, 스키마, 한 행의 의미

주문이 네 줄이라는 말과 상품이 네 개 팔렸다는 말은 서로 다른 정보를 줍니다. 관계형 데이터베이스에서는 행 하나가 세는 대상부터 정합니다.

이 장을 읽고 나면

  • 표와 행·열, 데이터와 스키마를 구별한다.
  • 행 하나가 나타내는 관측 단위를 정의한다.
  • 주문 수, 항목 줄 수, 판매 수량을 각각 계산한다.

행 하나를 무엇으로 세는가?

여러 날에 걸쳐 문구를 주문하는 합성 가게 자료를 사용합니다. 같은 사람이 여러 건 주문할 수 있고, 주문에는 상품이 여러 종류 들어갈 수 있습니다. 관계형 데이터베이스에서는 고객, 주문, 주문항목처럼 단위가 같은 기록을 표로 모읍니다. customers에는 고객 번호 customer_id와 이름 name이 들어 있습니다.

열에는 모든 고객에게 공통인 한 가지 속성이 들어 있고, 행에는 고객 한 명에게 해당하는 값이 들어갑니다. 한 줄이 항목인지 주문인지 고객인지를 나타내는 단위를 입도라고 합니다. '고객 수'를 구할 때 고객 표와 주문 표의 줄 수를 바꾸어 쓸 수 없는 이유입니다.

표의 정의와 그날의 내용

스키마는 표의 이름, 열 이름과 유형, 키, 값의 제약 등 데이터를 기록하는 구조입니다. customer_id INTEGER PRIMARY KEY는 이 표의 정수 고객 식별자를 정합니다. name TEXT NOT NULL은 표시 이름의 데이터 유형과 누락 금지를 정합니다. Mina를 고객으로 추가하는 일은 그 정의에 맞는 값을 입력하는 일입니다. 고객의 이메일을 저장할 열 자체를 새로 만들면 표의 구조가 달라집니다.

결과에 순서가 필요하다면 ORDER BY로 정합니다. 행이 파일에 들어간 순서로 결과가 나온다고 가정할 수 없습니다. 관계 모델을 바탕으로 한 데이터베이스라도 SQL 질의 결과에는 같은 값의 행을 여러 개 담을 수 있습니다. 이름이 같은 두 고객에게서 이름만 조회하면 같은 문자열이 두 번 나옵니다. 두 이름을 하나로 묶는 일과 두 고객을 같은 사람으로 보는 일은 구분합니다.

질문에 맞는 표를 고르기

주문 101에 공책 한 개와 펜 두 개가 있다면 주문은 한 건, 상품 항목은 두 줄, 수량은 세 개입니다. 다음 날 같은 사람이 다시 주문하면 주문 수는 늘고 고객 수는 유지됩니다. 월 주문 건수는 해당 월의 주문을 세고, 펜 판매 수량은 펜에 해당하는 상품 항목들의 수량을 더합니다.

왜 그럴까?

주문 행 수와 실제 주문한 고객 수가 다른 이유는?

모범 답 보기

고객 번호는 주문 표에 여러 번 나타날 수 있습니다. 주문한 고객 수가 필요하면 해당 기간의 주문에서 고객 번호가 몇 종류인지 셉니다.

두 표를 열어 직접 읽기

:memory:는 연결을 유지하는 동안 메모리에 예제용 데이터베이스를 만듭니다. CREATE TABLE로 구조를 정하고 INSERT로 자료를 넣은 뒤 SELECT로 값을 읽습니다. fetchall()이 돌려준 리스트 안에서 튜플 하나가 결과의 행 하나입니다.

실행 예제

import sqlite3

with sqlite3.connect(":memory:") as db:
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript("""
    CREATE TABLE customers (
        customer_id INTEGER PRIMARY KEY,
        name TEXT NOT NULL
    );
    CREATE TABLE orders (
        order_id INTEGER PRIMARY KEY,
        customer_id INTEGER NOT NULL REFERENCES customers(customer_id),
        order_date TEXT NOT NULL,
        status TEXT NOT NULL CHECK (status IN ('paid', 'pending')),
        total_won INTEGER NOT NULL CHECK (total_won >= 0),
        coupon_won INTEGER CHECK (coupon_won >= 0)
    );
    """)
    db.executemany("INSERT INTO customers VALUES (?, ?)", [
        (1, 'Mina'),
        (2, 'Jun'),
        (3, 'Sol'),
    ])
    db.executemany("INSERT INTO orders VALUES (?, ?, ?, ?, ?, ?)", [
        (101, 1, '2025-01-02', 'paid', 10000, None),
        (102, 1, '2025-01-03', 'paid', 15000, 1000),
        (103, 2, '2025-01-04', 'pending', 12000, None),
        (104, 2, '2025-01-05', 'paid', 15000, 0),
    ])

    names = db.execute(
        "SELECT customer_id, name FROM customers ORDER BY customer_id"
    ).fetchall()
    orders = db.execute(
        "SELECT order_id, customer_id FROM orders ORDER BY order_id"
    ).fetchall()
    print("customers:", names)
    print("order -> customer:", orders)
    print("customer rows:", len(names), "order rows:", len(orders))
db.close()

실행 결과

customers: [(1, 'Mina'), (2, 'Jun'), (3, 'Sol')]
order -> customer: [(101, 1), (102, 1), (103, 2), (104, 2)]
customer rows: 3 order rows: 4

고객 번호 3은 고객 표에 있지만 주문 표에는 나오지 않습니다. 이번 예의 규칙에서는 아직 주문한 적이 없어도 고객으로 등록할 수 있습니다.
