RL03·2

에피소드의 종료와 기록의 중단을 가려내기

같은 위치에서 실험이 멈춰도, 과제가 끝난 것과 관측을 외부에서 끊어 버린 것은 다릅니다. 마지막 보상을 기록한 뒤 어디에서 다시 시작할지, 중단된 경우에 무엇을 추정해야 할지 분리합니다.

이 장을 읽고 나면

  • 초기 관측부터 마지막 전이까지 에피소드 기록을 읽는다.
  • 과제의 종료와 외부 중단을 플래그와 환경 정의로 구분한다.
  • 관측된 부분 반환과 이후 반환의 추정값이 결합되는 간단한 예를 계산한다.

한 번의 실행을 어디에서 끊어야 하나

에피소드는 초기화한 뒤 과제의 끝까지 이어지는 한 번의 실행입니다. Sutton·Barto는 에피소드가 끝나는 시각을 T로, 그때 도달한 특별한 상태를 종료 상태(terminal state)라고 부릅니다. 종료 상태 뒤에는 보상이 더 없으므로 그 반환과 가치는 0으로 둡니다(GT=0). 이렇게 에피소드로 나뉘는 과제를 에피소드형 과제, 끝없이 이어지는 과제를 연속형 과제(continuing task)라고 합니다. 환경에서 얻은 경험을 파일에 남길 때에는 과제가 끝났는지, 관측만 끊겼는지 표시합니다. 프로그램에서는 어느 쪽이든 이번 실행 로그를 닫고 다음 실행을 초기화할 수 있기 때문에 두 종류의 플래그가 필요합니다.

한 칸씩 오른쪽으로 갈 수 있는 경로에서 위치 0에 시작하고, 위치 3에 도착하면 과제가 끝난다고 합시다. 중간 이동에는 각각 −1점, 도착하는 마지막 행동에는 +5점이 나옵니다. 확률적인 변화는 없는 모형입니다. 매회 ‘오른쪽’을 고르는 정책으로 끝까지 실행하면 보상열은 [−1,−1,5]입니다.

관측 장비를 한 실행에 최대 두 행동 동안만 쓸 수 있다면, 위치 2의 관측과 두 번째 보상 −1까지 기록하고 중단합니다. 위치 2에서는 원래 환경 규칙대로 계속 오른쪽으로 가서 5점을 얻을 수 있습니다. 5점은 이번 기록에서 보지 못한 값입니다.

시간 제한이 주어졌다면 과제 정의를 읽는다

Gymnasium의 step(action)은 (observation, reward, terminated, truncated, info)를 돌려줍니다. terminated는 성공·실패 또는 과제 자체의 제한 시간처럼 과제 정의가 정한 끝에 도착했음을 뜻합니다. truncated는 과제를 계속할 수 있는지와 별개로, 실험 횟수 제한처럼 외부 규칙에서 기록을 끊었음을 나타냅니다. 일반적인 단일 환경에서는 둘 중 하나라도 참이면 다음 실행 전에 reset()을 호출합니다. 두 신호가 같은 전이에 함께 참일 수도 있습니다.

‘두 번 안에 목표를 달성해야 한다’가 과제 규칙 자체라면 두 번 뒤 실패하는 것은 종료입니다. 그 경우 위치가 같아도 남은 행동 수에 따라 앞으로 가능한 결과가 달라집니다. 완전관측 상태로 모형을 만들려면 남은 횟수도 함께 포함합니다. 반면 ‘과제는 계속되지만 이 실험에서는 두 번까지만 실행한다’는 외부 중단입니다.

상황플래그둘째 이동 뒤의 실제 결과
도착 3을 목표로 하지만 2회만 관측truncated=True위치 2, 보상 −1, 원래 과제는 계속 가능
두 번 안에 도착해야 하는 과제에서 실패terminated=True이 예에서 실제 마지막 보상을 −1로 두면 이후 과제 보상 없음

중단된 보상열의 합과 과제의 가치는 다르다

γ=1/2에서 한 실행의 처음 두 관측 보상만으로 구한 부분 반환은 −1+(1/2)(−1)=−1.5입니다. 끝까지 계속했다면 원래 시작에서 반환은 −1−0.5+0.25×5=−0.25입니다. 중단 로그는 −1.5가 관측된 부분의 반환이라는 정보만 직접 제공하고, 아직 나올 수 있는 +5는 그 로그에 없는 값입니다.

향후 학습에서 다음 상태의 반환을 이미 알고 있거나 추정해 둔 경우에는, 실제 보상에 그 다음 추정값을 할인해 더하는 계산을 합니다. 시각 1에서 실행한 두 번째 이동의 보상은 −1입니다. 위치 2에서 정책을 계속 따르면 한 번 뒤에 5를 얻으므로, 이 모형에서 위치 2의 반환은 5입니다. 따라서 두 번째 행동 바로 전의 반환은 −1+(1/2)×5=1.5입니다.

기존 반환 추정값을 써서 새 갱신 목표를 만드는 방식을 부트스트래핑이라고 부릅니다. 종료됐다면 이미 마지막 보상을 받았으므로 이 다음 상태의 반환은 0으로 취급합니다. 중단만 된 경우에는 원래 과제의 다음 상태 가치가 남아 있고, 이를 사용할 수 있다면 이어서 계산합니다. 두 플래그가 모두 참이면 과제도 끝난 것이므로 다음 상태의 가치를 더하지 않습니다. 중단된 환경을 초기화한 뒤 새로 받은 초기 관측을 이전 전이의 다음 관측으로 쓰면 다른 실행을 잇게 됩니다.

전이를 출력해 두 플래그를 확인한다

아래 코드는 라이브러리 설치 없이 같은 형태의 플래그를 보여 줍니다. 외부 제한은 이동 횟수만 세고, 종료는 위치가 3일 때 따로 확인합니다. 기록 한 줄은 (현재 위치, 행동, 보상, 다음 위치, 종료, 중단)입니다.

def rollout(limit):
    position = 0
    records = []
    for turn in range(1, limit + 1):
        next_position = position + 1
        terminated = next_position == 3
        reward = 5 if terminated else -1
        truncated = turn == limit
        records.append((position, "오른쪽", reward, next_position, terminated, truncated))
        position = next_position
        if terminated or truncated:
            break
    return records

def target(reward, terminated, next_value):
    return reward if terminated else reward + 0.5 * next_value

full = rollout(4)
short = rollout(2)
same_step = rollout(3)
print("완주 마지막:", full[-1])
print("중단 마지막:", short[-1])
print("동시 표시:", same_step[-1][-2:])
print("중단만: 목표값", target(short[-1][2], short[-1][4], 5))
print("과제 종료: 목표값", target(full[-1][2], full[-1][4], 0))
완주 마지막: (2, '오른쪽', 5, 3, True, False)
중단 마지막: (1, '오른쪽', -1, 2, False, True)
동시 표시: (True, True)
중단만: 목표값 1.5
과제 종료: 목표값 5

이 프로그램에서 두 신호를 별개의 조건으로 계산했으므로 제한 걸음에 정확히 도착하면 둘 다 참이 됩니다. target의 next_value는 이 장에서 직접 풀 수 있는 모형의 값입니다. 일반 과제에서 그 값을 어떻게 계산하거나 학습하는지는 다음 단원에서 다룹니다.
