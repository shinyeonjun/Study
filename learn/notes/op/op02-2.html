수치미분으로 도함수와 기울기 검산하기

점 주변의 함숫값만 읽을 수 있어도 기울기를 대략 확인할 수 있습니다. 한쪽을 읽는 차분과 양쪽을 읽는 차분을 비교하고, 간격을 지나치게 줄이면 왜 틀릴 수 있는지 봅니다.

이 장을 읽고 나면

  • 전진 차분과 중앙 차분을 계산한다.
  • 간격이 너무 크거나 작을 때의 오차를 구분한다.
  • 벡터 기울기를 한 좌표씩 검산한다.

가까운 두 값으로 기울기 구하기

f(x)=x²에서 x=2의 정확한 도함수는 4입니다. 함수값을 직접 불러 계산할 때는 h>0을 두고 전진 차분 [f(2+h)−f(2)]/h를 사용합니다. h=0.1에서 f(2.1)=4.41, f(2)=4이므로 약 4.1입니다.

중앙 차분은 [f(2+h)−f(2−h)]/(2h)입니다. f(1.9)=3.61을 쓰면 (4.41−3.61)/0.2=4입니다. 이차식에서는 정확한 산술의 중앙 차분이 도함수와 일치합니다. 일반적인 충분히 매끄러운 함수에서 양옆을 사용하면 양쪽의 낮은 차수 오차가 상쇄돼 2차 정확도를 얻을 수 있지만, 중앙 차분 값과 참값이 항상 같지는 않습니다.

방식사용하는 위치이 예의 h=0.1 값
전진2, 2.14.1
중앙1.9, 2.14.0
분석 미분24.0

간격을 줄여도 한동안만 좋아진다

h가 너무 크면 함수의 휘어짐이 차이를 바꿉니다. 너무 작으면 가까운 함수값을 뺄 때 반올림과 상쇄가 커질 수 있습니다. 예로 이 환경에서 float 2+10⁻¹⁶은 2와 같습니다. 이 두 값을 사용하는 전진 차분은 0을 반환하지만 실제 기울기는 4입니다.

두 오차의 크기 이해하기

테일러 전개 f(x+h)=f(x)+hf′(x)+(h²/2)f″(x)+(h³/6)f‴(x)+…를 차분식에 넣으면 공식 자체의 오차(절단 오차, truncation error)가 나옵니다.

전진: [f(x+h)−f(x)]/h − f′(x) ≈ (h/2)·f″(x)  → h에 비례(1차)
중앙: [f(x+h)−f(x−h)]/(2h) − f′(x) ≈ (h²/6)·f‴(x)  → h²에 비례(2차)

x²에서 전진 차분 오차는 정확히 h(=4.1−4)이고, f‴=0이라 중앙 차분 오차는 0입니다. 반면 함수값을 저장할 때 생기는 상대오차 약 ε(OP01-1의 기계 엡실론)는 분자의 차이에 ε|f| 정도의 오차를 남기고, h로 나누면 반올림 오차가 대략 ε|f|/h로 커집니다. 두 오차의 합은 h가 중간일 때 가장 작습니다. x가 1 정도 크기일 때 경험적으로 전진 차분은 h≈√ε≈10⁻⁸, 중앙 차분은 h≈ε1/3≈6×10⁻⁶ 근처가 좋습니다. |x|가 크면 h도 그 크기에 맞춰 키웁니다.

from math import e, exp

x = 1.0                       # f(x)=eˣ, 참 도함수 f′(1)=e
for k in (1, 2, 4, 6, 8, 10, 12):
    h = 10.0**-k
    forward = (exp(x+h) - exp(x)) / h
    central = (exp(x+h) - exp(x-h)) / (2*h)
    print(f"h=1e-{k:<2} 전진 오차 {abs(forward-e):.1e}  중앙 오차 {abs(central-e):.1e}")

h를 10배 줄이면 처음에는 전진 오차가 10배, 중앙 오차가 100배씩 줄어듭니다(h=0.1에서 (0.1/2)e≈0.14, (0.01/6)e≈0.0045로 위 식과 맞음). 그 아래에서는 반올림 오차가 커져 오히려 나빠집니다.

벡터에서는 한 좌표씩 바꾼다

f(a,b)=a²+2b²에서 (1,2)의 기울기는 (2,8)입니다. a 성분을 검산할 때는 b를 그대로 두고 a만 ±h로 바꿉니다. 다음에는 a를 되돌려 놓고 b만 ±h로 바꿉니다. 두 성분을 동시에 바꾸면 특정 방향의 변화가 되어 개별 미분과 같지 않습니다.

import numpy as np

x, h = 2.0, 0.1
forward = ((x+h)**2 - x*x) / h
central = ((x+h)**2 - (x-h)**2) / (2*h)
print("전진 · 중앙:", f"{forward:.4f}", f"{central:.4f}")
print("두 입력이 같아짐:", x + 1e-16 == x)

def f(point):
    a, b = point
    return a*a + 2*b*b

point = np.array([1., 2.])
h = 0.001
gradient = [(f(point+h*axis) - f(point-h*axis))/(2*h)
            for axis in np.eye(2)]
assert np.allclose(gradient, [2, 8], rtol=1e-9, atol=1e-9)
print("수치 기울기:", *(f"{v:.3f}" for v in gradient))

실행 결과

전진 · 중앙: 4.1000 4.0000
두 입력이 같아짐: True
수치 기울기: 2.000 8.000

자동미분 결과와 크게 다르면 먼저 같은 손실, 같은 입력과 단위를 사용했는지 봅니다. 계단처럼 불연속이 있는 계산이나 꺾이는 점에서는 기울기가 다르게 정의되거나 존재하지 않을 수 있습니다. 잡음이 있는 함수를 평가하면 간격을 줄일 때 분자에 잡음이 남을 수도 있습니다.

기울기 검산(gradient checking)의 절차와 비용

역전파·자동미분으로 얻은 기울기 g를 중앙 차분 기울기 g̃와 비교하는 것을 기울기 검산이라고 합니다. 두 값의 크기가 제각각이므로 상대 차이 ‖g−g̃‖/(‖g‖+‖g̃‖)를 봅니다. 배정밀도와 h≈10⁻⁵~10⁻⁶에서 매끄러운 함수라면 보통 10⁻⁷ 이하로 작게 나오고, 10⁻³ 이상이면 구현을 의심합니다(기준값은 관례이며 문헌마다 다릅니다). 위 f(a,b)에서 h=10⁻⁶이면 이 값은 약 2×10⁻¹¹입니다.

매개변수가 n개이면 중앙 차분 기울기 하나에 함수 평가가 2n번 필요합니다. 역전파는 함수 평가 몇 번 정도의 비용으로 n개 성분을 모두 얻습니다. 그래서 수치미분은 학습에 쓰지 않고, 작은 모형이나 일부 좌표에서 구현을 검산하는 데 씁니다. 검산 중에는 dropout처럼 매번 결과가 바뀌는 요소를 끄고, float32 대신 float64로 계산합니다.

한 줄 정리

정확도와 반올림 사이에서 간격을 고르고, 각 좌표를 하나씩 움직여 기울기를 확인합니다.
