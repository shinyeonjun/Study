수치미분으로 도함수와 기울기 검산하기

점 주변의 함숫값만 읽을 수 있어도 기울기를 대략 확인할 수 있습니다. 한쪽을 읽는 차분과 양쪽을 읽는 차분을 비교하고, 간격을 지나치게 줄이면 왜 틀릴 수 있는지 봅니다.

이 장을 읽고 나면

  • 전진 차분과 중앙 차분을 계산한다.
  • 간격이 너무 크거나 작을 때의 오차를 구분한다.
  • 벡터 기울기를 한 좌표씩 검산한다.

가까운 두 값으로 기울기 구하기

f(x)=x²에서 x=2의 정확한 도함수는 4입니다. 함수값을 직접 불러 계산할 때는 h>0을 두고 전진 차분 [f(2+h)−f(2)]/h를 사용합니다. h=0.1에서 f(2.1)=4.41, f(2)=4이므로 약 4.1입니다.

중앙 차분은 [f(2+h)−f(2−h)]/(2h)입니다. f(1.9)=3.61을 쓰면 (4.41−3.61)/0.2=4입니다. 이차식에서는 정확한 산술의 중앙 차분이 도함수와 일치합니다. 일반적인 충분히 매끄러운 함수에서 양옆을 사용하면 양쪽의 낮은 차수 오차가 상쇄돼 2차 정확도를 얻을 수 있지만, 중앙 차분 값과 참값이 항상 같지는 않습니다.

방식사용하는 위치이 예의 h=0.1 값
전진2, 2.14.1
중앙1.9, 2.14.0
분석 미분24.0

간격을 줄여도 한동안만 좋아진다

h가 너무 크면 함수의 휘어짐이 차이를 바꿉니다. 너무 작으면 가까운 함수값을 뺄 때 반올림과 상쇄가 커질 수 있습니다. 예로 이 환경에서 float 2+10⁻¹⁶은 2와 같습니다. 이 두 값을 사용하는 전진 차분은 0을 반환하지만 실제 기울기는 4입니다.

벡터에서는 한 좌표씩 바꾼다

f(a,b)=a²+2b²에서 (1,2)의 기울기는 (2,8)입니다. a 성분을 검산할 때는 b를 그대로 두고 a만 ±h로 바꿉니다. 다음에는 a를 되돌려 놓고 b만 ±h로 바꿉니다. 두 성분을 동시에 바꾸면 특정 방향의 변화가 되어 개별 미분과 같지 않습니다.

import numpy as np

x, h = 2.0, 0.1
forward = ((x+h)**2 - x*x) / h
central = ((x+h)**2 - (x-h)**2) / (2*h)
print("전진 · 중앙:", f"{forward:.4f}", f"{central:.4f}")
print("두 입력이 같아짐:", x + 1e-16 == x)

def f(point):
    a, b = point
    return a*a + 2*b*b

point = np.array([1., 2.])
h = 0.001
gradient = [(f(point+h*axis) - f(point-h*axis))/(2*h)
            for axis in np.eye(2)]
assert np.allclose(gradient, [2, 8], rtol=1e-9, atol=1e-9)
print("수치 기울기:", *(f"{v:.3f}" for v in gradient))

실행 결과

전진 · 중앙: 4.1000 4.0000
두 입력이 같아짐: True
수치 기울기: 2.000 8.000

자동미분 결과와 크게 다르면 먼저 같은 손실, 같은 입력과 단위를 사용했는지 봅니다. 계단처럼 불연속이 있는 계산이나 꺾이는 점에서는 기울기가 다르게 정의되거나 존재하지 않을 수 있습니다. 잡음이 있는 함수를 평가하면 간격을 줄일 때 분자에 잡음이 남을 수도 있습니다.

한 줄 정리

정확도와 반올림 사이에서 간격을 고르고, 각 좌표를 하나씩 움직여 기울기를 확인합니다.
