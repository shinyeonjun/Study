ML02·1

기준 모델과 훈련·검증·테스트

새 규칙으로 배송 시간을 예측했더니 평균 5분 틀렸습니다. 과거 주문의 평균만 답해도 5분쯤 틀리는지 먼저 확인하면, 거리 같은 특성이 보탠 정보가 얼마나 되는지 판단할 기준이 생깁니다.

이 장을 읽고 나면

  • 훈련 평균과 훈련 다수 클래스로 기준 모델을 만든다.
  • 훈련·검증·테스트의 역할을 구별한다.
  • 후보와 기준 모델의 점수를 같은 자료와 같은 지표에서 비교한다.

항상 같은 답을 내는 첫 번째 비교 기준

실제 배송을 흉내 낸 주문에서 훈련 자료의 정답이 12, 16, 24, 28분입니다. 거리를 전혀 쓰지 않고 이 값의 평균 (12+16+24+28)/4 = 20분을 모든 주문에 답하는 회귀 기준을 만들 수 있습니다. 이처럼 먼저 세우는 비교의 출발점을 기준 모델(baseline)이라고 합니다. scikit-learn의 DummyRegressor(strategy="mean")가 같은 전략을 씁니다.

25분을 초과하면 지연으로 분류하는 다른 질문이라면 훈련 자료는 정상 3건, 지연 1건입니다. 항상 훈련에서 가장 흔한 정상으로 답하는 다수 클래스 기준을 씁니다. 이 예에서 정상은 최빈 범주입니다. DummyClassifier(strategy="most_frequent")의 전략입니다. 훈련에서 동률이 생길 수 있으므로 동률 처리 규칙은 먼저 정하고 기록합니다.

기준 모델도 훈련에서 상수를 얻고, 평가 주문에 그 상수를 그대로 적용합니다. 다수 클래스 모델이 항상 정상이라고 해서 실제 최종 평가에서도 훈련과 동일한 3/4 정확도를 얻는 것은 아닙니다. 정확도는 평가에 들어온 정상과 지연의 건수에 따라 달라집니다.

훈련·검증·테스트의 역할을 나눈다

공부하는 동안 읽은 문제와 답으로 연습하고, 한쪽에 빼 둔 문제로 공부법을 고르고, 마지막에 처음 보는 문제로 실력을 점검하는 상황을 생각합니다. 모델 평가에서도 각각 다른 역할의 자료를 둡니다.

자료이 자료에서 하는 일
훈련(train)평균·회귀 계수처럼 모델이 사용할 값을 추정
검증(validation)후보 모델, 특성, 단계 설정이나 임계값을 비교해 선택
테스트(test)선택을 마친 방법이 새로운 자료에서 낼 성능을 한 번 평가

모델이 자료에서 스스로 정하는 평균이나 계수와 달리, 거리 구간의 경계나 나중에 배울 나무 모델의 최대 깊이처럼 학습 방식을 바깥에서 정하는 설정을 하이퍼파라미터라고 합니다. 후보를 고를 때 검증 점수가 쓰인 순간, 그 검증 점수에는 선택의 영향이 들어갑니다. 선택을 반복하다 보면 검증에 잘 맞는 규칙을 골라 성능을 높게 볼 수 있습니다.

한쪽에 뺀 검증 자료의 역할을 여러 번 바꿔가며 성능을 보는 교차검증도 쓸 수 있습니다. 예를 들어 개발 자료를 다섯 묶음으로 나눠 네 묶음에서 학습하고 남은 한 묶음에서 검증하는 일을 다섯 번 반복합니다. 각 실행의 훈련 분할에서만 전처리의 설정값과 모델을 배웁니다. 바깥의 최종 테스트는 이 과정에서 따로 둡니다.

같은 검증 자료로 기준과 후보를 겨룬다

검증 주문은 두 건입니다. 각각 실제로 15분, 25분 걸렸습니다. 평균 기준 모델은 둘 다 20분으로 예측합니다. 얼마나 틀렸는지 부호를 빼고 거리만 보면 5분과 5분입니다. 두 절대오차를 평균한 값은 5분입니다. 이 계산을 평균절대오차(MAE)라고 하며 평가 장에서 더 자세히 다룹니다.

거리로 가까움과 멂을 나누어 각 훈련 그룹의 평균을 쓰는 후보는 검증 주문 두 건을 14분, 26분으로 예측했다고 둡니다. 검증의 절대오차는 이 경우 1분과 1분입니다. 같은 검증 주문, 같은 MAE를 썼으므로 이 자료 안에서 비교할 수 있습니다. 검증이 두 건뿐이므로 실제 배송 전반에서의 우위를 말하려면 더 대표적인 자료가 필요합니다.

최종 테스트의 실제 시간은 20, 26, 32분입니다. 평균 기준 모델은 저장해 둔 20분을 써 (0+6+12)/3 = 6분의 MAE를 냅니다. 이 데이터의 정답을 보고 예측 상수를 26분으로 바꿔 (6+0+6)/3 = 4분으로 보고하면 새로운 주문을 접수할 때 불가능한 일을 한 셈입니다.

실행 예제

from collections import Counter
from statistics import mean

train = [12, 16, 24, 28]
validation = [15, 25]
test = [20, 26, 32]

def mae(actual, predicted):
    return mean(abs(y - pred) for y, pred in zip(actual, predicted, strict=True))

baseline = mean(train)
print(f"train mean: {baseline:.1f} min")
print(f"validation MAE, mean: {mae(validation, [baseline] * len(validation)):.1f}")
print(f"validation MAE, distance groups: {mae(validation, [14, 26]):.1f}")
print(f"test MAE, mean: {mae(test, [baseline] * len(test)):.1f}")

train_labels = ["late" if minutes > 25 else "normal" for minutes in train]
majority = Counter(train_labels).most_common(1)[0][0]
test_labels = ["late" if minutes > 25 else "normal" for minutes in test]
accuracy = sum(label == majority for label in test_labels) / len(test_labels)
print(f"majority: {majority}, test accuracy: {accuracy:.3f}")

실행 결과

train mean: 20.0 min
validation MAE, mean: 5.0
validation MAE, distance groups: 1.0
test MAE, mean: 6.0
majority: normal, test accuracy: 0.333

실무에서는 시험 전에 정한 규칙에 따라 모델 선택 뒤 훈련과 검증을 합쳐 다시 학습하기도 합니다. 이때도 테스트를 보지 않은 상태에서 재학습 절차와 평가 지표를 고정합니다. 새 자료의 지연 조건이나 대상 거점이 평가 자료와 다를 수 있으므로 어느 범위에 대한 점수인지 함께 남깁니다.

왜 그럴까?

테스트 점수를 본 뒤 같은 테스트에서 가장 좋은 후보를 보고하면 어떤 문제가 생길까요?

모범 답 보기

테스트가 후보를 고르는 과정에 들어갑니다. 그 후보는 그 테스트 자료에 우연히 맞았을 수도 있으므로 다른 새 자료의 실력을 알아보려면 다시 독립된 평가가 필요합니다.
