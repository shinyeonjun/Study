전처리 순서와 교차검증에서의 파이프라인

한 회차에는 거리 결측을 4로 채웠는데, 다음 회차에는 9로 채웁니다. 회차마다 훈련 그룹이 바뀌기 때문입니다. 전처리와 모델을 한 순서로 묶으면 어느 자료에서 무엇을 배웠는지 확인할 수 있습니다.

이 장을 읽고 나면

  • 훈련과 추론의 변환 순서와 fit·transform을 구별한다.
  • 교차검증의 각 회차에서 전처리를 새로 학습한다.
  • 테스트 전에 파이프라인을 고르고 평가 규칙을 고정한다.

입력의 종류마다 처리 순서를 정한다

배송 거리와 배송 유형을 함께 사용하는 모델을 생각합니다. 거리는 훈련에서 정한 중앙값으로 채우고, 채운 훈련 거리의 평균과 표준편차로 표준화합니다. 유형은 빈칸의 뜻을 정해 결측 범주로 바꾼 뒤 원-핫 열을 만듭니다. 두 경로의 열을 옆으로 붙여 모델 입력 X를 만듭니다.

여기서 fit은 변환 규칙에 필요한 값이나 모델의 계수를 자료에서 배우는 과정입니다. transform은 배운 규칙을 자료에 적용합니다. 결측 대치가 표준화보다 앞에 있는 이 파이프라인에서는 표준화가 대치한 훈련 자료의 평균과 표준편차를 배웁니다. 순서를 바꾸면 어느 숫자에서 평균을 냈는지 달라지므로 예측에 들어가는 열도 달라질 수 있습니다.

scikit-learn의 ColumnTransformer는 열 종류마다 다른 전처리를 적용하고 결과를 합칠 때 씁니다. Pipeline은 전처리와 모델을 정한 순서로 연결해 훈련과 예측을 같은 구조에서 실행합니다. 훈련 때는 변환을 배우며 적용하고, 예측에서는 변환으로 배운 값을 그대로 적용합니다.

각 회차를 별도 예측 문제처럼 구성한다

교차검증으로 전처리와 모델의 조합을 비교합니다. 연습용 주문의 거리 열을 두 묶음 A와 B에 담습니다. A의 거리 [2, 결측, 6], B의 거리 [결측, 8, 10]이고 두 묶음 각각의 정답은 [0,0,1]과 [0,1,1]입니다. 접수 시 거리를 이용해 지연 여부를 추정합니다. 이 연습에서는 두 묶음을 서로 바꾸어 훈련과 검증을 하기에 알맞다고 둡니다. 같은 거점이나 미래 시각을 분리해야 하는 자료는 먼저 그 평가 설계를 따릅니다.

첫 회차에 A로 훈련하면 결측을 4로 채웁니다. 채운 A의 거리 [2,4,6]에서 평균 4와 표준편차 √(8/3)을 배웁니다. B의 첫 행은 값이 없으므로 4로 채워 표준화 값 0을 얻습니다. 둘째 회차는 B를 훈련에 써 관측값 8과 10의 중앙값 9, 대치 후의 평균 9와 표준편차 √(2/3)을 얻습니다.

전체 개발 자료의 값 [2,6,8,10]에서 중앙값 7을 먼저 계산해 두 회차에 쓰면 검증 쪽 자료가 훈련 변환에 섞입니다. 검증 점수가 높아지는지 낮아지는지는 예마다 다를 수 있습니다. 어떤 행에서 설정을 배웠는지가 누출을 판단하는 기준입니다.

회차별 점수로 방법을 평가하고 테스트를 끝에 사용한다

예제는 숫자 열 하나에서 대치와 표준화 뒤 1-NN을 적용합니다. 회차 1은 B의 세 행을 모두 맞혀 정확도 1, 회차 2는 A의 첫 행을 틀려 2/3입니다. 두 회차의 검증 크기는 같아서 각 정확도의 평균 (1+2/3)/2=5/6은 합친 검증 정답률과 같습니다. 크기가 다를 때 회차별 평균을 쓸지 관측을 모아 평가할지 평가 목적에 맞춰 정합니다.

실행 예제

from statistics import median, mean, pstdev

a = [(2, 0), (None, 0), (6, 1)]
b = [(None, 0), (8, 1), (10, 1)]
test = [(None, 1), (12, 1)]

def fit(rows):
    fill = median(x for x, y in rows if x is not None)
    values = [fill if x is None else x for x, y in rows]
    center = mean(values)
    scale = pstdev(values) or 1
    neighbors = [((value - center) / scale, y) for value, (_, y) in zip(values, rows, strict=True)]
    return fill, center, scale, neighbors

def predict(x, state):
    fill, center, scale, neighbors = state
    z = ((fill if x is None else x) - center) / scale
    # 거리가 같으면 먼저 저장한 훈련 관측을 선택한다.
    return min(neighbors, key=lambda row: abs(row[0] - z))[1]

def evaluate(state, rows):
    guesses = [predict(x, state) for x, y in rows]
    return guesses, mean(y == pred for (_, y), pred in zip(rows, guesses, strict=True))

scores = []
for i, (training, validation) in enumerate([(a, b), (b, a)], start=1):
    state = fit(training)
    guesses, score = evaluate(state, validation)
    scores.append(score)
    print(f"fold={i}: fill={state[0]:.1f}, predicted={guesses}, accuracy={score:.3f}")
print(f"validation average={mean(scores):.3f}")

state = fit(a + b)
guesses, score = evaluate(state, test)
print(f"test: fill={state[0]:.1f}, predicted={guesses}, accuracy={score:.3f}")

실행 결과

fold=1: fill=4.0, predicted=[0, 1, 1], accuracy=1.000
fold=2: fill=9.0, predicted=[1, 0, 1], accuracy=0.667
validation average=0.833
test: fill=7.0, predicted=[0, 1], accuracy=0.500

이 합성 예의 수치 열 하나에서는 양의 표준편차로 나눠도 거리의 순서는 그대로입니다. 코드에서 보여 주는 것은 평가 회차마다 변환값을 다시 구하는 절차입니다. 이미 정한 방식으로 A와 B를 합쳐 재학습한 뒤, 이 절차에 참여하지 않은 테스트에서 한 번 평가합니다. 테스트 두 건의 50%는 그 자료에 대한 결과로만 읽습니다.

scikit-learn에서는 같은 절차를 Pipeline 하나로 씁니다. cross_val_score는 회차마다 파이프라인 전체를 복제해 그 회차의 훈련 행으로만 fit하고 검증 행에는 transform과 예측만 하므로, 위 손 계산과 같은 점수가 나옵니다. 결측은 np.nan으로 넣고, 회차는 행 번호 목록으로 직접 지정했습니다.

실행 예제

import numpy as np
from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import cross_val_score

X = np.array([[2], [np.nan], [6], [np.nan], [8], [10]])
y = np.array([0, 0, 1, 0, 1, 1])
folds = [([0, 1, 2], [3, 4, 5]), ([3, 4, 5], [0, 1, 2])]

model = make_pipeline(
    SimpleImputer(strategy="median"),
    StandardScaler(),
    KNeighborsClassifier(n_neighbors=1),
)
scores = cross_val_score(model, X, y, cv=folds)
print("fold scores:", scores.round(3))
print("mean:", round(scores.mean(), 3))
model.fit(X, y)
print("fill value:", model[0].statistics_)

실행 결과

fold scores: [1.    0.667]
mean: 0.833
fill value: [7.]

마지막 fit은 A와 B 전체로 다시 학습한 최종 모형이라 대치값이 7입니다. 수치 열과 범주 열이 함께 있으면 ColumnTransformer([("num", 수치 파이프라인, ["distance"]), ("cat", 범주 파이프라인, ["kind"])])를 이 파이프라인의 첫 단계로 넣어 첫 그림의 두 경로를 그대로 표현합니다. 파이프라인 밖에서 전체 자료로 fit_transform한 뒤 교차검증하면 이 장에서 본 누출이 그대로 생깁니다.

왜 그럴까?

검증에서 다른 결측 대치와 거리 변환을 고른 뒤 테스트 점수에 맞춰 한 번 더 바꾸면 무엇이 달라질까요?

모범 답 보기

테스트가 후보를 고르는 자료가 됩니다. 검증으로 방법을 고르고, 선택과 학습에 사용하지 않은 자료에서 마지막 점수를 얻어야 합니다.
