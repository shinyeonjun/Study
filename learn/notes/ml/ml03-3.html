ROC와 PR 곡선, AP와 면적 읽기

경보 기준을 어디에 두느냐에 따라 같은 모델도 다른 숫자를 얻습니다. 여러 임계값의 점을 차례대로 그리면 지연을 더 많이 찾는 대신 얼마나 많은 정상 주문에 경보를 내는지, 점수의 순위가 얼마나 적절한지 볼 수 있습니다.

이 장을 읽고 나면

  • 임계값별 혼동행렬에서 ROC와 PR 좌표를 계산한다.
  • 평가 목적과 양성 비율을 고려해 두 곡선을 해석한다.
  • AP의 가중합과 사다리꼴 PR 면적을 각각 계산한다.

같은 점수에 여러 임계값을 적용한다

합성 주문 4건의 점수가 높은 순서로 0.90, 0.80, 0.40, 0.30이고 실제 라벨은 1,0,1,0입니다. 지연이 양성 1입니다. 점수가 임계값 t 이상이면 경보를 냅니다. 두 지연과 두 정상이 들어 있습니다.

임계값을 가장 큰 점수보다 높게 시작해 조금씩 낮춥니다. 새로운 점수 값을 지날 때 그 점수에 해당하는 주문을 경보에 넣습니다. 같은 점수인 주문이 여럿이면 한꺼번에 넣습니다. 점수 사이에서 기준을 움직이는 동안에는 예측이 달라지지 않습니다.

ROC와 PR은 위처럼 임계값을 같게 움직여 얻은 표에서 출발합니다. 정해진 한 임계값에서 성능을 설명하려면 그 점과 함께 당시의 실제 경보 건수도 적습니다.

ROC는 정상의 경보율과 지연 탐지율을 같이 본다

ROC 곡선의 x축은 거짓양성률(FPR), y축은 참양성률(TPR)입니다. FPR = FP/(FP+TN)이므로 분모는 실제 정상 수입니다. TPR = TP/(TP+FN)은 실제 지연 중 맞힌 비율인 재현율입니다. 기준이 0.80일 때 (FPR, TPR)은 (1/2,1/2)입니다.

ROC-AUC는 ROC 곡선 아래 면적입니다. 이 예에서는 폭이 있는 두 구간의 넓이가 0.5×0.5 + 0.5×1 = 0.75입니다. 한 양성과 한 음성을 무작위로 뽑아 점수를 비교해도 이 수치가 나옵니다. 양성 둘과 음성 둘의 네 쌍 중 양성이 더 높은 세 쌍이 있습니다. 동률은 절반만 센다는 규칙을 씁니다. 실제 양성과 음성이 모두 있어야 두 축을 계산할 수 있습니다.

그림의 점선 대각선은 점수가 라벨과 무관한(무작위) 모델이 평균적으로 그리는 선이고, 그 아래 면적은 0.5입니다. ROC-AUC 1은 모든 양성이 모든 음성보다 높은 점수를 받은 경우, 0.5는 순위가 무작위와 다르지 않은 경우입니다. 0.5보다 작으면 점수 방향이 뒤집혔을 가능성을 먼저 의심합니다.

PR은 지연을 찾는 능력과 경보의 품질을 본다

PR 곡선의 x축은 재현율(recall), y축은 정밀도(precision)입니다. 임계값이 0.40이면 지연 둘을 모두 찾아 재현율은 1입니다. 경보 세 건 중 둘만 실제 지연이므로 정밀도는 2/3입니다. 모든 건을 경보로 잡으면 재현율이 1이고 정밀도는 자료의 양성 비율 2/4=0.5입니다. 아래 그림의 정밀도 0.5 점선이 이 기준선입니다. 무작위 점수 모델의 정밀도는 어느 재현율에서나 평균적으로 양성 비율 근처에 머무르므로, PR에서 비교할 바닥은 ROC처럼 0.5로 고정되지 않고 양성 비율에 따라 달라집니다.

경보가 한 번도 없는 경우 실제 정밀도는 분모가 0입니다. scikit-learn의 PR 그림에서는 재현율 0, 정밀도 1을 그리기 위한 관례의 끝점으로 넣습니다. 이 점은 실제 경보가 모두 맞았다는 뜻으로 해석하지 않습니다. 실제 양성이 0건이라면 재현율의 분모가 0이라, 재현율 증가량을 쓰는 AP도 이 정의로는 계산할 수 없습니다. scikit-learn 1.9.1의 average_precision_score는 이때 "양성이 없어 재현율을 1로 둔다"는 경고와 함께 0.0을 돌려주므로, 숫자만 보지 말고 경고와 정답 건수를 확인합니다.

정상 주문이 매우 많을 때 작은 FPR도 많은 경보가 될 수 있습니다. 정상 9,900건에서 FPR이 0.01이면 거짓 경보가 99건입니다. 지연 100건에서 TPR이 0.90이면 90건을 찾습니다. 정밀도는 90/(90+99) ≈ 0.476입니다. ROC의 두 비율과 함께 PR을 보면 나온 경보에서 실제 지연이 얼마나 되는지 바로 읽을 수 있습니다. TPR과 FPR은 각각 실제 양성 안, 실제 음성 안에서 센 비율이라 양성 비율이 바뀌어도(각 클래스의 점수 분포가 그대로라면) ROC 곡선은 변하지 않습니다. 정밀도는 두 클래스의 건수를 한 분모에 섞으므로, 비교하는 자료의 양성 비율이 크게 다르면 정밀도와 AP에 그 차이가 그대로 반영됩니다. 양성 비율이 다른 자료끼리 AP를 비교할 때는 각 자료의 양성 비율을 함께 적습니다.

PR 요약 수치가 계산된 방법을 확인한다

scikit-learn의 평균 정밀도(AP)는 임계값을 낮추는 순서로 각 점의 정밀도에 그 점까지 새로 늘어난 재현율을 곱해 더한 값입니다. 식으로 AP = Σ (Rᵢ−Rᵢ₋₁)Pᵢ입니다. 여기서 Rᵢ는 현재 점의 재현율이고 Pᵢ는 현재 점의 정밀도입니다. 앞 점과 재현율이 같으면 그 항은 0입니다.

재현율이 0→0.5로 늘어난 0.90에서는 정밀도 1, 0.5→1로 늘어난 0.40에서는 정밀도 2/3입니다. 따라서 AP = 0.5×1 + 0.5×(2/3) = 5/6 ≈ 0.8333입니다.

PR 점을 선분으로 이은 뒤 사다리꼴 PR-AUC를 구하면, 각 재현율 간격에 양끝 정밀도의 평균을 곱합니다. 재현율 0→0.5 구간은 양끝이 1이라 넓이 0.5입니다. 다음 구간 0.5→1은 시작 정밀도 1/2와 끝 정밀도 2/3을 씁니다. 0.5 + 0.5×(1/2+2/3)/2 = 19/24 ≈ 0.7917입니다. 동일한 자료의 PR 요약이라고 해도 방법을 함께 명시해야 숫자를 대조할 수 있습니다.

실행 예제

from math import inf

scores = [0.90, 0.80, 0.40, 0.30]
truth = [1, 0, 1, 0]
positives = sum(truth)
negatives = len(truth) - positives
roc, pr = [], []

for threshold in [inf, *sorted(set(scores), reverse=True)]:
    selected = [y for score, y in zip(scores, truth, strict=True) if score >= threshold]
    tp = sum(selected)
    fp = len(selected) - tp
    recall = tp / positives
    precision = tp / len(selected) if selected else 1.0
    roc.append((fp / negatives, recall))
    pr.append((recall, precision))

def trapezoids(points):
    return sum((x1 - x0) * (y0 + y1) / 2
               for (x0, y0), (x1, y1) in zip(points, points[1:]))

ap = sum((r1 - r0) * p1 for (r0, _), (r1, p1) in zip(pr, pr[1:]))
print("ROC:", [(round(x, 3), round(y, 3)) for x, y in roc])
print("PR:", [(round(x, 3), round(y, 3)) for x, y in pr])
print(f"ROC AUC={trapezoids(roc):.4f}, AP={ap:.4f}, PR trapezoid={trapezoids(pr):.4f}")

실행 결과

ROC: [(0.0, 0.0), (0.0, 0.5), (0.5, 0.5), (0.5, 1.0), (1.0, 1.0)]
PR: [(0.0, 1.0), (0.5, 1.0), (0.5, 0.5), (1.0, 0.667), (1.0, 0.5)]
ROC AUC=0.7500, AP=0.8333, PR trapezoid=0.7917

이 코드는 양성·음성이 모두 있고 유한한 점수를 가진 예를 대상으로 합니다. 정밀도 1을 넣은 첫 점은 그림을 위한 관례입니다. AP 합에서는 첫 점 자체를 더하지 않습니다. 순위를 볼 수 있는 면적 값에서도 운영 임계값이나 예측 확률의 정확성을 바로 얻을 수는 없습니다. 검증에서 실제 경보 건수와 탐지 기준에 맞는 점을 따로 고릅니다.

왜 그럴까?

임계값 0.90을 0.80으로 낮출 때 AP 합에서 왜 0을 더할까요?
