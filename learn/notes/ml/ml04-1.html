ML04·1

잔차와 설계행렬로 선형 회귀 읽기

대기 주문이 늘어날수록 처리 시간이 길어지는지 작은 자료로 확인합니다. 예측선을 하나 그려 실제값과의 차이를 잰 뒤, 모든 주문의 예측을 행렬 곱 하나로 나타냅니다.

이 장을 읽고 나면

  • 선형 회귀의 절편과 기울기를 단위와 함께 읽는다.
  • 잔차를 구하고 제곱합으로 후보 예측선을 비교한다.
  • 절편 열을 포함한 설계행렬에서 X @ beta로 예측한다.

대기 건수에 따라 예측 시간이 달라지는 모형

합성 주문 자료에서 접수 직전 대기 건수 x=[0,1,2]와 처리 시간 y=[2,2,5]분을 관측했습니다. 선형 회귀는 ŷ=b+w·x처럼 계수와 특성의 곱을 더해 예측하는 모형입니다. b는 x가 0일 때의 예측인 절편, w는 x가 1단위 늘 때의 예측 변화량입니다. 이 자료에서 각각 분, 분/건 단위입니다.

b=w=1.5면 세 예측은 [1.5,3,4.5]입니다. 관측값에서 예측을 뺀 r=y−ŷ가 잔차입니다. 표 가운데의 실제 2분에서 예측 3분을 빼면 −1분입니다. 잔차의 부호는 실제보다 과하게 예측했는지 낮게 예측했는지 알려 줍니다.

세로 방향의 잔차 제곱합으로 비교한다

최소제곱은 SSE = Σ(yᵢ−ŷᵢ)²가 가장 작아지는 계수를 구하는 방법입니다. 차이를 제곱하면 부호가 서로 상쇄되지 않고 큰 잔차가 더 많이 기여합니다. 이 예의 잔차 [0.5,−1,0.5]를 제곱해 더하면 1.5분²입니다.

다른 후보 ŷ=2+x의 예측은 [2,3,4], 잔차는 [0,−1,1], SSE는 0+1+1=2분²입니다. 모든 후보가 같은 행 수를 쓰므로 SSE를 관측 수로 나눈 MSE로 비교해도 순서가 같습니다. 다음 장에서 확인하듯 이 예제에서는 ŷ=1.5+1.5x가 최소제곱 해입니다.

왜 그럴까?

점과 직선 사이의 최단거리를 재는 대신 y 방향으로 차이를 재는 이유는?

모범 답 보기

이 문제는 대기 건수 x를 입력으로 주고 거기에 해당하는 시간 y를 예측합니다. 따라서 같은 x에서 맞혀야 하는 시간과 예측 시간을 비교합니다.

한 행씩 쓰던 식을 행렬과 벡터로 계산한다

행 하나에 특성 하나씩을 놓고 맨 앞에 1을 붙입니다. 이렇게 입력을 조립한 배열을 설계행렬 X라고 합니다. 두 계수는 순서대로 β=[b,w]입니다. n행에 절편을 포함한 열이 p개면 X는 (n,p), β는 (p,)이고, 예측 X @ beta는 길이 n입니다.

실행 예제

import numpy as np

queue = np.array([0, 1, 2])
actual = np.array([2, 2, 5])
design = np.column_stack((np.ones(queue.size), queue))
beta = np.array([1.5, 1.5])
predicted = design @ beta
residual = actual - predicted

print("shapes:", design.shape, beta.shape, predicted.shape)
print("prediction:", predicted.tolist())
print("residual:", residual.tolist())
print(f"SSE={residual @ residual:.1f}, MSE={np.mean(residual**2):.1f}")
print(f"new order with x=3: {np.array([1, 3]) @ beta:.1f} min")

실행 결과

shapes: (3, 2) (2,) (3,)
prediction: [1.5, 3.0, 4.5]
residual: [0.5, -1.0, 0.5]
SSE=1.5, MSE=0.5
new order with x=3: 6.0 min

@는 행렬 곱입니다. X * beta로 항별 곱을 하면 관측별 기여분은 나오지만 자동으로 행 합을 내지는 않습니다. 새 주문에도 훈련 때와 열의 이름·순서·단위를 맞춥니다. 대기 3건은 이 예제에서 본 0~2건의 범위 밖이므로 6분이 얼마나 믿을 만한지는 별도 평가가 필요합니다. 관측에서 추정한 기울기를 곧바로 인과효과로 읽을 수도 없습니다.
