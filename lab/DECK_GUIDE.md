# 슬라이드 교재 덱 작성 기준

이 책(`lab/`)은 공부 교재(`learn/`)의 지식을 AI·머신러닝 흐름 위에 녹인 슬라이드 덱이다. 처음부터 쭉 넘기면서 생각하고, 이해하고, 자연스럽게 외워지게 하는 것이 목표다.
**기준 덱: `decks/s01.html` + `quiz/S01.js`.** 새 덱은 이 둘을 복사해서 만든다. 모양·부품·말투를 그대로 따른다.

## 읽는 사람
- 컴퓨터 계열 대학생. 고교 수학은 대략 안다. 직접 해 보며 '느끼면서' 배우는 걸 좋아한다.
- 글을 많이 읽지 않는다. 설명 글이 길면 넘겨 버린다.

## 슬라이드 원칙
1. **슬라이드 하나 = 생각 하나.** 제목이 곧 그 생각이다("곱해서 더하기 = 내적"처럼 `A = B` 꼴이 좋다).
2. **그림이 주인공.** 거의 모든 슬라이드에 SVG 그림 하나. 글은 그림이 못 하는 말만.
3. **글은 한두 줄**(`.say`). 문장보다 짧은 구. 나머지 개념은 낱말 칩(`.kw`)으로만.
4. **식은 크게 하나**(`.big`)만. 기호는 처음 나올 때 그림 안이나 `.say`에서 뜻을 붙인다.
5. **실제 숫자.** 기호보다 진짜 같은 예(집 (84, 3, 5), 가격 1200원)로 보이고, 같은 예를 덱 안에서 계속 이어 쓴다.
6. **AI가 먼저, 수학은 필요할 때.** "예측하려면 이게 필요하다 → 그래서 내적"처럼 수학이 왜 나오는지 AI 장면으로 시작한다.
7. **3~4장마다 '잠깐, 직접'**(`.check-slide`) 문제 하나. 숫자 예측(num) 또는 헷갈리는 개념을 가르는 객관식(mc).
8. **덱 하나 12~18장.** 순서: 표지(배울 것 길) → 내용 슬라이드와 확인 슬라이드 → 코드 한 장(numpy 몇 줄과 실제 출력) → 정리(표 한 개 + 다음 덱 + 개념 사전 링크).
9. 설명 문단, 안내 문장, 공부법은 쓰지 않는다. 이름·숫자·그림·짧은 구만.
10. 쉬운 걸 장황하게 풀지 않는다. 초보자 달래는 말 금지.

## 부품 (style.css에 있음, 새로 만들지 않는다)
| 부품 | 쓰는 곳 |
|---|---|
| `<section class="slide">` | 슬라이드 한 장 |
| `<section class="slide cover-slide">` + `.deck-no`, `h1`, `.road` | 표지 |
| `<h2>` | 슬라이드 제목(한 줄) |
| `<figure class="fig"><svg class="fig-svg" viewBox="0 0 760 H">` | 그림 |
| `<p class="say">` | 한두 줄 설명 |
| `<p class="big">` | 큰 식 하나 |
| `<p class="kw"><span>낱말</span>…</p>` | 낱말 칩 |
| `<section class="slide check-slide"><h2>잠깐, 직접</h2><div class="check" data-q="q1"></div>` | 확인 문제 |
| `<pre><code>` | 코드와 출력(출력도 따로 `<pre><code>`) |
| `.table-wrap > table` | 정리 표 |

## 그림 규칙
- 직접 그린 SVG. viewBox 가로 760, 세로는 내용만큼(200~260).
- 부품 클래스: `f-box`(흰 칸) `f-soft`(연한 칸) `f-over`(붉은 칸: 음수·오류) `f-line` `f-ink` `f-dash` `f-fill` `f-t` `f-s` `f-cap`, 화살표 `marker-end="url(#f-arrow)"`.
- 이름표는 가리키는 것 바로 옆. 좌표·눈금·길이는 실제 값과 비율이 맞아야 한다. 다르게 그렸으면 그 슬라이드 `.say`에 적는다.
- **SVG는 공백을 줄인다.** 숫자 여러 개를 띄어 쓰려면 `<text>`를 따로 나눈다(`84   3   5` 한 줄로 쓰지 않는다).
- `aria-label`에 그림 내용을 글로.
- 장식 그림, 아이콘 나열, 사진풍 금지.

## 문제 (`quiz/SNN.js`)
- 형식은 `quiz/S01.js`와 같다. id `q1, q2, …`는 한번 정하면 바꾸지 않는다.
- 덱 안의 `data-q`가 가리키는 문제가 모두 있어야 한다. 덱당 3~5문제.
- 객관식은 보기 4개, **모든 보기에 why**(왜 맞는지/틀리는지 한 문장). 오답은 실제로 헷갈리는 것. why를 "정답"으로 시작하지 않는다.
- 숫자 답은 딱 떨어지는 값이 좋다(소수 답은 반올림 차이까지 맞게 채점된다).

## 등록
- `notes.js`의 해당 단계 `notes`에 `{ id: "SNN", title, href: "decks/sNN.html", area }` 한 줄. `area`는 그 단계 `plan`의 몇 번째 묶음인지(0부터). 이전·다음 덱 링크와 목차는 자동.
- 덱 HTML의 `<body class="deck-body" data-note="SNN">`, 위쪽 `crumb`에 `덱 N`.

## 넘기기 전 확인 (만든 사람이 직접)
1. 덱의 모든 계산과 문제 정답을 다시 푼다.
2. 코드 슬라이드의 코드는 실제로 돌려서 출력을 그대로 붙인다(numpy).
3. `node -e "global.window={};require('./lab/quiz/SNN.js');console.log(window.BDA_QUIZ.SNN.length)"`로 문제 파일이 읽히는지, 정답 번호가 보기 범위 안인지, 모든 보기에 why가 있는지.
4. 브라우저에서 덱을 열어 슬라이드마다 그림 글자가 겹치거나 밖으로 나가지 않는지(`learn/tools/check_figures.js`를 슬라이드마다), 휴대폰 폭에서도 보는지.
5. 그다음 Claude가 내용(정의·수치·그림 비율·문제)을 독립 확인한다. 확인을 통과한 덱만 올린다.
