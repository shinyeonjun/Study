실험을 믿을 수 있게

잴 수 있는 질문 → 짝 비교 → 하나만 바꾸기 → 우연이라면? p값 → 다 보고하기 → 다시 실행

LayerNorm을 넣은 모델 B가 기준 A보다 2.5점 높다. 이 말을 믿으려면 무엇이 필요할까.

'더 좋다'를 잴 수 있게 = 연구 가능한 질문

무엇을 잴지, 무엇과 비교할지, 어떤 결과면 '틀렸다'고 할지를 실험 전에 적는다.

조작적 정의: 좋다 → 검증 정확도(%)반대로도 나올 수 있어야 질문

같은 모델도 시드마다 점수가 흔들린다

시드 = 초기 가중치·자료 순서를 정하는 난수의 시작값. 한 번 돌린 점수 하나에는 운이 섞인다.

차이가 흔들림보다 큰가 = 질문

짝 비교 = 같은 시드끼리 빼기

따로 보면 겹치던 두 무리가, 짝으로 보면 네 선이 모두 올라간다. 비교할 단위 = 시드 짝 4개.

짝 = 같은 조건끼리 묶은 블록실험 단위 = 독립으로 다시 뽑는 것

잠깐, 직접

하나만 바꾸고 나머지는 고정 = ablation

ablation = 부품 하나를 빼거나 넣어 차이를 재는 실험. 같게 묶어 두는 조건 = 통제변수. 예산(학습 단계·튜닝 횟수)도 맞춘다.

기준 모델 = baseline

잠깐, 직접

차이가 없다면? = 부호가 동전 던지기

귀무가설 H₀ = '차이 없음'이라는 기준 세계. 그 세계에서 나올 수 있는 결과를 전부 늘어놓는다.

ST04 동전 8번과 같은 계산

p값 = 차이가 없을 때 이만큼 극단적일 확률

p = 2 / 16 = 0.125

양쪽을 다 센다(B가 낮은 쪽으로 극단이어도 '차이'라서). 극단이 드물수록 p가 작다.

양측 검정

p = 0.125는 'H₀일 확률'이 아니다

0.125 > 0.05 → 기각 못 함. 기각 못 함 ≠ 차이 없음: 시드 4개로는 애초에 기각이 불가능했다. p는 크기도 아니다: +2.5점은 따로 보고한다.

α = 실험 전에 정한 기준

잠깐, 직접

미리 정하고 다 보고 = 골라 보고 금지

시드 목록·지표·실패 처리 규칙을 결과 보기 전에 정한다. 좋은 것만 고르면 같은 자료로 +6도 만든다 = 선택 편향.

p-hacking = p가 작아질 때까지 분석 바꾸기

시드 = 난수 생성기의 시작 상태

한 실행을 똑같이 되살릴 때 = 같은 시드. 운의 크기를 잴 때 = 미리 정한 여러 시드. GPU 병렬 계산처럼 시드만으로 다 같아지지 않는 곳도 있다.

생성기·호출 순서도 같아야

git diff = A와 B가 정확히 무엇이 다른가

commit = 그 순간 코드의 사진. diff가 한 줄이면 ablation이 정말 하나만 바꿨다는 증거.

실패한 실행도 기록

잠깐, 직접

부호 뒤집기 검정과 시드를 코드로

from itertools import product
import random
d = [1, 2, 3, 4]                                  # 시드별 B − A (점)
sums = [sum(s * x for s, x in zip(sign, d))
        for sign in product([-1, 1], repeat=4)]   # 부호 16가지
extreme = sum(abs(t) >= sum(d) for t in sums)
print(sum(d) / 4, extreme, len(sums), extreme / len(sums))
for seed in (7, 7, 11):
    r = random.Random(seed)
    print(seed, [round(r.random(), 4) for _ in range(3)])
